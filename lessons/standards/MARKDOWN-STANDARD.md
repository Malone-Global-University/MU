# MGU Interactive Lesson Markdown Authoring Standard v1.0

**Source of truth:** A UTF-8 `.md` file registered in the central lesson catalog.  
**Scope:** Features supported by the November 2026 MGU `dashboard.js` Markdown renderer. This is **not** a full CommonMark, GitHub-flavored Markdown, or MDX engine.

## 1. Separate metadata from narrative

- The dashboard obtains **lesson title, level, estimated minutes, identity, and file location** from `catalog.json`.
- Do not put JSON metadata, YAML front matter, HTML `head` tags, scripts, CSS, `<h1>` headings, logo markup, or global navigation in a lesson file.
- The suggested first Markdown heading is `## Lesson introduction` or `## 1. [Topic]`; the dashboard already supplies the page-level title.
- Put only content that belongs in the instructional article into the `.md` file. Use `templates/lesson-template.md` as a starting point.

## 2. Supported Markdown syntax

| Purpose | Syntax | Notes |
| --- | --- | --- |
| Main content headings | `## Heading` | Rendered as `<h2>`; heading IDs are automatically generated |
| Subheadings | `### Heading`, `#### Heading` | Avoid deeper heading levels |
| Paragraphs | Blank-line-separated text | Consecutive lines merge into one paragraph |
| Bold, italic | `**bold**`, `*italic*` | Inline support only |
| Code | `` `name` `` and triple-backtick fenced blocks | Fenced blocks are escaped rather than executed |
| Links | `[label](/site/path)` or `[label](https://...)` | Do not put spaces or `)` in the URL; verify all links |
| Bulleted list | `- Item` | Flat lists only; do not nest |
| Numbered list | `1. Item` | Flat lists only; numbering is generated by HTML |
| Block quote | `> Short statement` | Use for a single-paragraph note or teaching emphasis |
| Horizontal rule | `---` | Separates sections |
| Table | Pipe-table with `| --- |` separator row | No column spans, nested Markdown, or inline HTML |

Avoid embedded HTML, images (`![...]()`), footnotes, Mermaid diagrams, nested lists, task checkboxes outside quizzes, LaTeX math notation requiring rendering, nested directives, and arbitrary markdown extensions: the current renderer does not implement them. It escapes literal `<tag>` text. If a course requires a new content feature, add renderer support centrally and then release an updated authoring standard.

## 3. Interactive answer disclosures

```markdown
:::answer Reveal the solution
**Answer:** 5.

Briefly explain the reasoning.
:::
```

- `:::answer` must begin at the start of a line, with an optional short label.
- The first line after the directive is content. Close with `:::` on its own line.
- Each disclosure can contain supported headings, paragraphs, flat lists, and tables.
- Answers are accessible without JavaScript through HTML's native `<details>` element. **No nested directives.**
- Prefer a descriptive label such as `Show Activity 2 answers` rather than a generic `Open`.

## 4. Auto-scored multiple-choice quizzes

```markdown
:::quiz
? Which value is five?
- [ ] 3
- [x] 5
- [ ] 8
! Five is the quantity represented by the numeral 5.

? What is two plus three?
- [ ] 4
- [x] 5
- [ ] 6
! Addition combines the two quantities to make five.
:::
```

- `? ` opens a question. Each requires **at least two** `- [ ]` or `- [x]` choices.
- **Exactly one** choice is marked `- [x]` (case-insensitive `x` accepted; lowercase recommended).
- `! ` supplies the explanatory feedback; require it editorially even though the renderer does not technically demand it.
- A quiz ends with `:::` on its own line.
- No nested quiz blocks, checkbox answers outside a quiz, multi-select items, point weights, images in choices, or automatic storage of grades.
- The quiz grades in the student's browser. **Source Markdown exposes `[x]` answers**, so this is a self-study knowledge check, not a secure exam.
- When a lesson also includes a visible answer key, use a separate `:::answer` block below the quiz.

## 5. Contextual vocabulary popovers

Create the definition registry in a single `:::terms` block (normally at the end of the lesson):

```markdown
:::terms
processor | Processor | A component that executes computer instructions. | /library/encyclopedia/computer-science/hardware-systems/central-processing-unit
input | Input | Information supplied to a system. |
:::
```

Use a term in the narrative with:

```markdown
A [[processor|processor]] follows instructions and produces results.
```

- Each definition row has `id | display label | definition | optional-link`.
- Term IDs are lowercase kebab-case and unique inside one lesson.
- Every `[[term-id|visible word]]` must match a registered term ID.
- Keep definitions brief, factual, and readable without external navigation.
- Encyclopedia links are optional. Include only verified, safe site-relative or `https://` references. Do not put `|` inside definitions; it is a field separator.
- The term block is removed from visible Markdown and used to render popovers. The separate visible glossary is optional.

## 6. Tables and internal links

```markdown
| Device | Role |
| --- | --- |
| Microphone | Input |
| Speaker | Output |
```

Heading anchors are computed automatically by lowercasing headings, removing punctuation other than hyphens, converting spaces to hyphens, and appending `-2`, `-3`, etc. for duplicates. Example: `## 1. How computers work` becomes `#1-how-computers-work`.

A link to an internal section can use `[Review the explanation](#1-how-computers-work)`. The validator checks these anchors against the current renderer's slugging convention.

## 7. Recommended pedagogy and editorial QA

A standard instructional lesson should usually include: introduction, 2–6 measurable learning objectives, clearly segmented teaching, at least one worked example, a learner practice task, an expandable answer key, a knowledge check when appropriate, a summary, and verified references. These are **authoring guidelines**, not universal hard-coded section counts.

Before publication:

1. Validate `catalog.json` and all registered Markdown with `py .\tools\validate_lessons.py`.
2. Check factual accuracy, terminology, instructional progression, and referenced sites.
3. Confirm answer keys and quiz correct choices match the narrative.
4. Test keyboard navigation, mobile rendering, interactive popovers, and quiz reset.
5. Confirm lesson route: `/lessons/?content=<lesson-id>`.

## 8. Current limits and future changes

This first standard documents the features that actually work **today**. It deliberately does not promise audio/video embeds, image assets, durable completion tracking, instructor-gradebooks, printable worksheets, offline caching, or secure testing. Such functions require a dashboard feature release, new tests, and a new specification revision.
