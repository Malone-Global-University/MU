## Lesson 6: Cloud Storage Basics

You create a short practice document on a computer. Later, you want to open it on a phone, but you cannot remember whether it was saved in Downloads, Documents, or an online account. You see a small cloud symbol beside another file and wonder whether that file is actually on the computer. You might also assume that because a file is in the cloud, it can never be lost. These are common, understandable questions. The answers depend on **where the file is stored, which account is being used, and whether a synchronization process has finished**.

[[cloud-storage|Cloud storage]] lets an authorized person store files using an online service rather than relying only on a particular device. Cloud storage can make it easier to retrieve a document from another device, organize materials, and work with others. However, it is not automatically a separate [[backup|backup]], unlimited free space, permanent availability, or permission to upload confidential information. Some services show cloud files in the computer's ordinary file manager; others require a browser or app. This lesson teaches you how to distinguish these arrangements before taking action.

This is Lesson 6 of MGU's Everyday Productivity course. It builds on *Taking Screenshots*, *Copy, Paste, and Clipboard*, *Keyboard Shortcuts*, *Managing Windows and Tabs*, and *Notes and To-Do Lists*. Windows 11 and OneDrive provide the principal guided desktop example, with parallel instruction for Google Drive, Chromebooks, Apple iCloud Drive, Mac, iPhone, iPad, and Android. Every required exercise has a **fictional or local-only alternative**, so learners do not have to create an account, buy a plan, upload personal information, or give anyone access to their files.

**Level:** Beginner · **Estimated study time:** 90–120 minutes · **Prerequisites:** Everyday Productivity Lessons 1–5 recommended · **Equipment:** A file manager or web browser, a text editor, and optional access to a cloud account already approved for use · **Safety:** Practice with invented text only; do not change existing sync, deletion, billing, or sharing settings without permission

> **Essential idea:** **Identify the file and its location → choose a suitable destination → save or upload deliberately → check the transfer or sync status → confirm the file is retrievable → keep a separate backup when the material matters.** Seeing a cloud icon or a filename is not the same as verifying that a usable copy is available.

### Learning objectives

After completing this lesson, you should be able to:

1. Explain cloud storage in everyday language and distinguish it from local device storage, an online website, an account, and a backup.
1. Identify upload, download, synchronization, file availability, and common cloud-storage status indicators without confusing them.
1. Locate a file using a familiar file manager or an authorized cloud-storage website and explain which account and folder contain it.
1. Create, name, upload, download, and retrieve a harmless practice file when an approved service is available, or describe the same procedure offline.
1. Compare the beginner workflows for OneDrive, Google Drive, iCloud Drive, and their common desktop and mobile interfaces.
1. Explain how online-only files, locally available files, and deliberate offline copies affect internet use and device storage.
1. Recognize why synced deletion, version changes, wrong accounts, storage limits, and unfinished transfers can cause confusion or data loss.
1. Apply basic security, privacy, accessibility, backup, and account-ownership checks before using cloud storage.

## 1. What is cloud storage and what does it do?

In basic computing, the word [[cloud|cloud]] refers to computing resources provided over a network by remote systems. When you use [[cloud-storage|cloud storage]], your files are held by a service operating on computers that you do not physically manage. You reach them through an [[internet-connection|internet connection]], a browser, or a compatible application. Providers maintain their own equipment and systems, but you remain responsible for choosing an appropriate account, understanding the terms that apply to your material, and keeping an adequate recovery plan.

A document saved to a folder on the internal drive of a laptop is an example of [[local-storage|local storage]]. A document uploaded into a folder in OneDrive, Google Drive, or iCloud Drive is a cloud-stored item. Some applications keep both a local and a remote copy. A cloud service may also offer web-based documents, collaborative editing, file previews, or storage for photos, but the beginner's first question should always be: **where is the authoritative copy, and how can I find it again?**

### Everyday reasons to use cloud storage

A person may save a school worksheet online so they can open it on another device. A small organization may keep approved shared reference documents in a managed account. Someone traveling may retrieve a public itinerary or training notes without carrying a separate [[usb-drive|USB drive]]. A person replacing a computer may use an appropriate cloud service to retrieve files that were already uploaded. These benefits are real, but they depend on completed uploads, the correct login, compatible software, available internet access, and applicable account permissions.

Cloud storage is not required for every task. A personal draft can remain in a local folder. A confidential organizational document may be restricted to a managed system. A large media file may be inconvenient to transfer over a slow connection. The most effective choice balances **accessibility, reliability, privacy, capacity, and cost**, not merely popularity.

| Storage arrangement | Where the file is mainly held | Typical way to access it | Important limitation |
| --- | --- | --- | --- |
| Local computer folder | Internal drive or attached local storage | File Explorer or Finder | A device failure can make the only copy unavailable |
| Removable storage | USB drive or external disk | Connected device and file manager | The device can be misplaced or damaged |
| Cloud-only file | Provider-managed remote system | Website or connected app | Usually needs internet access to retrieve its contents |
| Synced cloud folder | Remote service plus selected local copies or file placeholders | File manager, browser, or app | Edits and deletions may propagate across devices |
| Independent backup copy | Separate recovery destination or backup system | Restore process chosen for the backup | A backup is useful only if it can actually be restored |

### Accounts, providers, and folders are different things

A [[provider|provider]] is the organization operating the service. A [[cloud-account|cloud account]] is the identity and associated storage space you use with that service. A [[folder|folder]] is an organizational container inside that space. A single person may have separate personal, school, and workplace accounts. Two accounts from the same provider are **not necessarily interchangeable**: a file uploaded into one may not appear in the other, even if the person uses the same computer.

For example, a fictional student signs into a personal account and uploads `Practice-Outline.txt`. When they later open a school-managed account, the file is absent. This does not mean the upload failed. It may have succeeded in the first account. The student should inspect the account identity and the original destination before uploading again or changing settings.

### A cloud icon is a clue, not a universal rule

A [[status-icon|status icon]] might indicate online-only content, successful synchronization, an active transfer, or a problem. The precise icon depends on the service, operating system, app version, and configuration. For OneDrive's Files On-Demand on Windows, for example, a blue cloud denotes an online-only item; a green check can represent a locally available file; and an additional solid green circle is associated with always keeping a file on the device. Other products use different conventions. **Read the provider's label or status description rather than assuming every cloud icon means the same thing.**

### Worked example: choose the right location

Imagine an invented document called `Community-Garden-Ideas.txt`. The learner needs to edit it from both a home desktop and a permitted school laptop. An approved cloud account could make that convenient if both devices are allowed to access the service. If the learner has no permission to sign into a personal cloud account on the school machine, the alternative is to follow the institution's approved file-transfer procedure. The question is not simply “Can the cloud hold this file?” It is “Which location is appropriate for this file and these devices?”

## 2. How do cloud files, uploads, downloads, syncing, and backups differ?

Cloud storage becomes easier to understand when you separate four common actions: **save, upload, download, and sync**. In ordinary use, [[save|saving]] writes changes to the destination selected by an application. An [[upload|upload]] sends data from a device to a remote service. A [[download|download]] retrieves data from an online source to a device. [[synchronization|Synchronization]], often shortened to *sync*, is an ongoing process that attempts to keep selected content or changes consistent across connected locations.

A saved file may be local. An uploaded file may remain online. A downloaded file may be an independent copy—or may be part of an app's managed sync location. The location and product matter. Never assume that selecting Save automatically creates an online copy or that downloading a file necessarily disconnects it from future edits.

### Follow one fictional file through its journey

Suppose you create `Practice-Travel-Plan.txt` in a local Documents folder. At first, the file exists only in that folder. If you open an approved cloud website and choose **Upload**, you select the local file and send a copy to a cloud folder. When the service reports success and you confirm the file appears in the intended account, you have evidence of an upload. If you later sign in on a different permitted device and choose **Download**, a local copy is saved to that device's download destination, typically Downloads unless you or the browser selected elsewhere.

If instead the first computer has a sync app configured for a particular folder, placing the file there may trigger an automatic upload. Editing the synced file may then update the cloud copy and eventually update other connected devices. But the app can be paused, offline, signed out, restricted by an organization, or encountering a conflict. The visible file may therefore represent a completed transfer, a queued action, or an incomplete state. **Look for successful completion rather than assuming the icon is enough.**

| Action | Direction or purpose | What to verify | Common confusion |
| --- | --- | --- | --- |
| Save | Write a file to the chosen destination | File name, folder, and actual saved result | Thinking every save also uploads |
| Upload | Device to online service | Correct account, folder, and completed upload | Selecting a file but not finishing the transfer |
| Download | Online service to a device | Destination folder and opening the local copy | Assuming a browser preview is a saved file |
| Sync | Reconcile selected changes across locations | App state, completion, and which folders participate | Believing sync is a separate archival backup |
| Backup | Preserve a recoverable copy separate from ordinary working changes | Backup date, independence, and ability to restore | Treating a synced mirror as protection from all mistakes |
| Restore | Retrieve an earlier or protected copy after loss | Correct item, version, and destination | Overwriting the only remaining good copy |

### What does “automatically sync” actually mean?

A [[sync-client|sync client]] is software that monitors designated files and communicates changes with a service. When you edit a file in a synchronized folder, the client may upload the change without a separate manual Upload action. On another device that is signed into the same account and participating in the same sync arrangement, the changed file may appear later. This is **not necessarily immediate**, and some files are displayed as [[placeholder|placeholders]] until opened.

Synchronization also means that an unwanted change can spread. If you delete a synchronized document, the cloud service may delete its corresponding item and propagate that state to other devices. If you overwrite a draft with incorrect content, the new version may replace the old current version. Some services offer a [[recycle-bin|Recycle Bin]], Trash, or [[version-history|version history]], but recovery windows and permissions vary. They are helpful features, not guarantees that a file can always be recovered.

### Why sync is not the same as backup

A good [[backup|backup]] supports recovery when a working file disappears, becomes damaged, or is altered incorrectly. A synchronized folder usually aims to show consistent current content; it is not specifically designed to preserve an untouched historical copy. In some circumstances, a service offers file versions and limited deletion recovery, but those features have their own rules and expiration dates. Important files should have an additional, independent recovery method authorized by the owner of the data.

For a personal learning project, this might mean preserving a dated copy on a separate drive that is not continuously synchronized. For organizational records, it may mean a managed backup system with tested recovery procedures. A useful guideline is to keep multiple copies on more than one storage medium, including at least one separately maintained or offsite copy where appropriate. **The goal is recoverability, not a particular number of cloud accounts.**

### Version history is not a time machine without limits

[[version-history|Version history]] is a feature that may let a person inspect or restore earlier revisions. Its availability depends on the file type, service, account plan, and organizational policies. Even when a version list exists, the exact revision you want may not be retained. Similarly, a Trash folder only holds items for a defined time or until someone with permission empties it. In beginner practice, do not delete a real file merely to test recovery; use a fictional example or a disposable practice copy that you are authorized to modify.

### Worked example: the mistaken deletion

A fictional learner syncs a folder on two devices. They delete `Week-2-Notes.txt` from the synced folder on the first device, believing that this frees only local disk space. The delete reaches the service and the file disappears from the other device as well. The key lesson is that **deleting an item and making it online-only are different operations**. To reduce local storage without deleting a cloud file, use the provider's supported “Free up space,” “Remove download,” or online-only option if the service provides one. Verify what the command does before confirming it.

## 3. How do you use OneDrive with Windows 11?

[[onedrive|Microsoft OneDrive]] is a cloud file-storage service that can appear inside Windows 11 [[file-explorer|File Explorer]] when an account and the sync app have been configured. It can also be used through its official website. The purpose of this section is to learn the observable workflow, **not to require Windows users to enable folder backup or connect an account**. A computer managed by a school or employer may already have an approved account and policies; beginners should not change them without permission.

### Recognize the working locations

Open File Explorer, often with **Windows + E**. In the navigation pane, you may see a location labeled OneDrive, sometimes with a personal name or an organization's name. You may also see Documents, Desktop, Downloads, and other locations. The presence of those names does not mean their contents are identical. A local Documents folder and a cloud-backed Documents folder can coexist; automated folder-backup settings may redirect or synchronize certain locations in ways that are not obvious from their display names.

Before moving or saving a file, inspect its [[file-path|file path]] or location in File Explorer. Consider whether the folder is under the approved OneDrive location, the ordinary local drive, or another service. If you are unsure, leave the existing file in place and ask the person responsible for the computer's configuration. **Do not toggle Desktop, Documents, or Pictures backup merely to complete a class activity.**

### Guided procedure: observe OneDrive without changing settings

1. Open File Explorer on a Windows 11 computer where you have permission to inspect file locations.
1. Look for a OneDrive location in the left navigation pane. If it is absent, do not assume something is broken; the app or account may not be configured.
1. If a OneDrive location is visible, inspect the folder names. Do not open personal or organizational content that you do not own or have permission to view.
1. Observe the status column or file icons, if shown. Identify a cloud symbol, check mark, circular progress indicator, or an error icon only if the interface displays one.
1. Open the cloud-app status menu only if permitted. Note whether it reports that files are up to date, uploading, downloading, paused, or in need of attention.
1. Close the window without changing settings or deleting files. Write down the **meaning of the observed status**, not any private filenames.

This observation-first procedure teaches navigation without requiring a transfer. It can be completed through an instructor's fictional screen description when there is no configured OneDrive account.

### Guided procedure: make a safe practice file

If you already use an authorized cloud account and an approved folder, you may practice with a disposable document. In a simple text editor such as Notepad, type the following invented content:

```text
MGU Cloud Storage Practice
This document contains no personal information.
Purpose: learn where a file is stored.
Verification: confirm the name, account, and folder.
```

Save the file as `MGU-Cloud-Practice.txt` in a location you can identify. If you choose an authorized OneDrive folder, wait for the sync client to finish. If the item begins in a local folder instead, it has **not** automatically been uploaded simply because OneDrive is installed. If the computer is managed or you have no approved cloud folder, leave the document local and practice describing the steps without transferring it.

### Upload or retrieve through the website

You can use OneDrive in a web browser by visiting its legitimate address through a trusted route and signing into a permitted account. When using the service's own interface, look for an option such as **Upload**, then choose the file and destination folder; commands differ among account types and versions. After the transfer, confirm that the name and destination appear in the correct account. A successful browser upload does not necessarily install a sync client or place a complete local copy on a different computer.

To retrieve a file, locate it in the online account, select its **Download** option, and use the browser's download list or file manager to locate the saved copy. The download might be placed in Downloads, a user-selected folder, or another configured location. Previewing the document online is not the same as locating the downloaded copy. When using a shared computer, consider the local copy you have left behind and follow the institution's rules for authorized cleanup.

### Understand the common OneDrive availability states

OneDrive's [[files-on-demand|Files On-Demand]] can show files in File Explorer without storing their full contents locally until needed. The exact appearance changes with settings and software versions. The following states are useful for beginners:

| OneDrive state | Typical Windows indicator | What it means for offline work | Beginner response |
| --- | --- | --- | --- |
| Online-only | Blue cloud | Full content generally requires internet access first | Open while connected or choose an appropriate offline option |
| Locally available | Green outlined check or comparable status | The downloaded local content may be opened offline | Verify the item actually opens without the network if needed |
| Always available on device | Solid green circle with a white check | Intentionally retained on local storage for offline access | Remember that it consumes local disk space |
| Sync in progress | Circular or rotating status mark | Change may not yet be available elsewhere | Wait for completion and inspect the status message |
| Sync needs attention | Warning, error, or paused indicator | Recent changes may be incomplete | Read the message; do not delete or overwrite the file |

Microsoft documents the **Always keep on this device** command for an appropriate offline copy and **Free up space** for an online-only arrangement. Neither command should be treated as a replacement for backup. Marking a file online-only does not mean deleting it from OneDrive; deleting the file is a separate action that can affect its online and other synced copies.

### A safe decision sequence before editing

Before relying on an important document, check the service and account, the file's name, the most recent expected edits, and whether the status is fully synchronized. If offline work is planned, arrange offline availability **while connected** and test opening the item before leaving the network. If an app reports a sync error or conflicting copies, preserve both versions until you can determine which is correct. Do not make repeated blind edits because the visible filename appears unchanged.

### Common Windows misconception: “My Desktop is always local”

A Windows computer may be configured to protect or synchronize Desktop, Documents, and Pictures through OneDrive. Another computer may not. The same visual Desktop can therefore involve different underlying storage locations. The correct action is not to guess from the folder name; inspect the location and approved configuration. When you need a local-only practice area, use a clearly identified local folder that is not included in a sync arrangement, subject to the device owner's instructions.

## 4. How do you use Google Drive, iCloud Drive, and other devices?

There is no single universal “cloud storage screen.” Some learners open cloud files through a browser, others use a [[files-app|Files app]], and others view them in a desktop file manager. This section compares the pathways without requiring any new account. Interface wording, device operating systems, and permissions change; treat the steps as a process to recognize, and consult the provider's current instructions if your screen differs.

### Google Drive in a browser

[[google-drive|Google Drive]] is accessible through an authorized Google account and an official web interface, commonly `https://drive.google.com/`. A user can view the files and folders that the account is permitted to access. In an appropriate account, the New or Upload interface may let you add a file or create a folder. After uploading, confirm that the file appears under the intended location, such as My Drive, and not merely in a Recent list. Use search or the folder hierarchy to find the file again rather than assuming that the latest item always remains at the top.

Google Drive can contain uploaded Word documents, PDFs, images, and other files as well as Google Docs, Sheets, and Slides. These may open in different editors and do not always behave like locally saved files. An online Google Doc should not be assumed to exist as an independent downloadable Word or text file unless you have deliberately exported or downloaded an appropriate copy. Export formats and permissions depend on the document and account.

### Google Drive for desktop: streaming versus mirroring

Google's optional [[drive-for-desktop|Drive for desktop]] app can integrate selected cloud content into File Explorer on Windows and Finder on Mac. Two configurations have different local-storage effects. In [[streaming|streaming]] mode, cloud files are chiefly stored online, with local cache or individually enabled offline copies as needed. In [[mirroring|mirroring]] mode for supported My Drive content, the selected files are also stored on the computer, consuming local disk space. **Both arrangements can synchronize changes**, so a full local mirror is not the same as an independent backup.

| Google Drive mode | Typical local storage | Offline availability | Trade-off |
| --- | --- | --- | --- |
| Browser-only use | Downloads or cached website data as applicable | Depends on selected app and downloaded files | Simple access, but browser visibility is not proof of a local copy |
| Stream files | Primarily online with local cache or designated offline items | Selected files can be prepared offline | Saves local space but depends on a running app and configuration |
| Mirror supported files | Full local copies of supported My Drive content | Generally locally available after sync | Uses more space and changes can sync back to the cloud |

Do not switch between streaming and mirroring as a beginner experiment. A configuration change can alter file locations, consume substantial storage, and require care to prevent file loss. The observation-first alternative is to describe the effect of each mode on **disk space, access without internet, and synchronization**.

### Google Drive on a Chromebook

Chromebooks include a [[files-app|Files app]] that can display local items such as Downloads and, when configured, Google Drive content. A local item stored in Downloads is not necessarily online. If the learner uses an approved Google account, they can examine the Drive section in Files or visit the official Drive website. Google documents options for preparing supported Drive files for offline access, but availability differs with file type, account, device storage, and settings.

When looking for a file, distinguish **My files / Downloads** from **Google Drive / My Drive**. If you cannot find the item in one location, inspect the other rather than immediately creating a duplicate. Storage constraints matter: a Chromebook with very little free space may be unable to retain requested offline content.

### iCloud Drive on Mac

[[icloud-drive|Apple iCloud Drive]] can appear in the Finder sidebar on a Mac after it is enabled for the appropriate Apple Account. The user may also reach supported files through iCloud.com. A file in Finder's iCloud Drive location is not automatically identical to one in every local folder. Mac settings may optionally synchronize Desktop and Documents folders; beginners should not turn this on, off, or change an existing cloud provider's settings solely for a lesson. Such changes can move content or produce confusing duplicate locations if they are not managed carefully.

To study the process without modifying an account, open Finder and identify the difference between a locally stored folder and iCloud Drive. On an authorized account, you can create a harmless practice folder in iCloud Drive, place a practice file there, wait for the service to finish, and look for it again. Review the visible availability and permissions if the interface provides them. Do not share or delete anything while merely learning to recognize the storage location.

### iCloud Drive on iPhone or iPad

On iPhone and iPad, the [[files-app|Files app]] can show **On My iPhone**, **On My iPad**, and **iCloud Drive**, depending on setup and app support. A file under a local device location is not automatically the same as one in iCloud Drive. When iCloud Drive is enabled and the correct Apple Account is active, compatible files can be found there. The Files app can also present third-party locations when separately configured; one Files app does not imply one storage provider.

On a phone or tablet, choose **Browse** or its equivalent, identify the location, and check the folder name before opening or saving. A document viewed in a messaging app, browser tab, or preview is not necessarily a saved file in Files. Use supported Save to Files or download actions deliberately when a retained copy is required. The steps vary by app and operating-system release; do not assume every Share button publishes the document to other people. Some Share controls simply present file-transfer or save destinations. The next lesson covers sharing permissions in depth.

### Android devices and cloud apps

Many Android devices use a system file manager and optional cloud apps such as Google Drive or OneDrive. Names and menus differ by device maker, operating system, and installed software. The core questions remain the same: **Which account? Which folder? Is the item online or on the device? Has the upload or download completed?** A phone's photo-gallery backup service may behave differently from general-purpose file storage, so do not assume a camera photo is automatically present in the same folder as an uploaded text document.

### Cross-platform reference table

| Device or platform | Typical local entry point | Typical cloud entry point | What to verify |
| --- | --- | --- | --- |
| Windows 11 | File Explorer | OneDrive folder, Drive for desktop, or provider website | Account, file path, and sync completion |
| Mac | Finder | iCloud Drive, optional provider app, or website | Account, storage mode, and local availability |
| Chromebook | Files app / Downloads | Google Drive in Files or browser | Local versus Drive location and offline settings |
| iPhone or iPad | Files app / On My device | iCloud Drive or approved installed provider | Location, Apple Account, and download state |
| Android | Device file manager / Downloads | Approved Drive, OneDrive, or other cloud app | Account, destination, and transfer status |

### Worked example: retrieve a file on another device

A fictional learner uploads `Practice-Reading-List.txt` into an approved Google Drive folder on a Chromebook. They later open Google Drive on an authorized Windows computer. Before searching, they confirm that the **same account** is active. They find the folder, open the document, and inspect its contents. If a separate local copy is needed, they select a suitable Download option, then locate the result in the destination folder. If the file does not appear, they first examine the account and upload status rather than concluding that the cloud is unreliable.

## 5. How do you organize cloud files and work offline?

Organization is the difference between merely having storage and being able to use it. A cloud account with hundreds of unnamed documents can be harder to navigate than a small, clearly labeled local folder. Begin with a simple [[folder-hierarchy|folder hierarchy]] based on subjects or projects, not a complex system. For example, a learner might keep `Practice`, `Reference`, and `Completed` folders, with small project-specific subfolders only when needed. Avoid deeply nested structures that make the location difficult to remember.

### Name files so they can be found

A good filename communicates the subject and, when helpful, a date or revision stage. `Reading-Notes-2026-11.txt` is easier to recognize than `New Document 4.txt`. `Budget-Draft-Practice.xlsx` tells you that the file is an example rather than a live financial record. For important projects, do not create many copies named `final`, `final2`, and `final-FINAL`. Use a meaningful title and rely on a well-understood revision or version-control method when available.

File names may be exposed in shared links, browser history, recent-file lists, search results, or screen shares. Do not put passwords, complete account numbers, confidential client names, or unnecessary identifiers in filenames. If the system rejects a name because it contains invalid characters or is too long, shorten it using ordinary letters, numbers, spaces, or simple punctuation supported by the provider.

### Online-only, cached, and offline-ready files

An [[online-only|online-only file]] may appear in your file manager even when its contents are not downloaded. A [[cached-file|cached file]] may have been temporarily stored for performance, but temporary cache behavior is not an assurance of offline access. An [[offline-copy|offline copy]] is content that the relevant application has deliberately made available for use without an active connection. A folder can contain a mixture of these states.

**Prepare offline before disconnecting**: choose the provider's supported offline option for the specific authorized files, allow the download to complete, and if possible test opening a disposable practice file while disconnected. Reconnect before leaving the session and verify synchronization has finished after offline edits. Some web apps need their own offline enablement and may not support every feature or file type when disconnected.

### Practice without consuming cloud storage

In a local practice folder, create three harmless files: `Lesson-Summary.txt`, `Shopping-Example.txt`, and `Project-Outline.txt`. Pretend the practice folder is a cloud destination. Decide which item should be available offline during travel and which could remain online-only. Record the reason for each choice. This exercises the decision-making process without enabling sync or using any quota.

### Storage capacity is not the same as available device space

[[cloud-quota|Cloud quota]] is the storage allowance associated with an online plan or account. [[disk-space|Disk space]] is capacity available on the computer or phone. A cloud plan may have free space while the device is nearly full, and vice versa. Mirrored files and offline copies consume local space. Items that are only online may use little local space but still count against the service's quota. Some cloud services share quota across multiple products; the actual policy depends on the provider and account.

| Symptom | Possible reason | Sensible next check |
| --- | --- | --- |
| Online upload will not finish | Network interruption or cloud quota exceeded | Connectivity, account quota, transfer status |
| File will not open offline | Online-only item or offline setup incomplete | Availability label and prior download state |
| Computer storage is low | Many offline or mirrored files | Local disk usage and provider's supported space controls |
| Document missing on second device | Wrong account or unfinished sync | Account identity and status on the original device |
| Two differently named copies exist | Conflict or duplicate upload | Modification details and file contents; preserve both pending review |
| File appears in Recent but not expected folder | Recent is a view, not the original storage path | File information and actual parent folder |

### Avoid duplicate and ambiguous copies

A duplicate may result from downloading the same file repeatedly, uploading with the same name into different folders, or saving a conflict copy when edits could not be merged. Before deleting a duplicate, compare **contents, locations, timestamps, and purpose**; timestamps alone are not definitive. Keep separate copies until you understand which is complete. In shared workflows, ask the document owner before reorganizing material that others use.

### A three-check retrieval routine

When you need to find a cloud file, first confirm the account, then locate the folder, and finally confirm the filename and expected contents. If something is missing, use the service's own search and file information rather than assuming the item was deleted. Only after examining the correct account should you investigate Trash, Recent, Shared, offline status, or provider support options. This procedure prevents many unnecessary re-uploads and accidental overwrites.

## 6. How do you use cloud storage safely and reliably?

Cloud storage can contain information that is valuable to you or to an organization. Treat [[account-security|account security]], [[privacy|privacy]], and [[data-ownership|data ownership]] as routine parts of file management. A file being easy to access does not mean everyone should be allowed to access it. A provider maintaining secure infrastructure does not remove your responsibility for strong sign-in habits, appropriate sharing choices, device security, and the rules governing the material.

### Choose an authorized account

Before uploading anything, decide whether it belongs to your personal, school, or workplace account. Avoid moving organizational documents into a personal cloud account simply because the personal interface seems easier. A workplace may restrict data destinations, retention, access, backups, and external collaboration. An instructor may provide a test environment or synthetic documents for learning. **If ownership or permission is uncertain, do not upload the file.**

### Protect the account, not only the file

A strong, unique [[password|password]] or a provider-supported [[passkey|passkey]], combined with [[multi-factor-authentication|multi-factor authentication]] where supported, helps protect access. Use official sign-in routes and be alert to [[phishing|phishing]] messages claiming your cloud storage is full or your account is about to be closed. A fake notification can direct you to a look-alike sign-in page. Avoid entering credentials into links in unexpected messages; open the service through a known, trusted location and inspect its actual account notices.

### Sharing is a separate decision from storage

Cloud services may allow sharing with named people, groups, an organization, or anyone possessing a link. A [[permission|permission]] may allow viewing, commenting, or editing, depending on the product and account. Copying a cloud link does not necessarily make it public, and conversely an “anyone with the link” choice may permit much broader access than intended. The user should review **who can access, what they can do, and whether access can be changed or revoked** before distributing the link. The next lesson, *Sharing Files Safely*, teaches these decisions in greater detail.

For now, do not share an actual file as part of this lesson. In practice activities, explain the safest permission for a fictional scenario. Be aware that sharing an entire folder may expose more contents than sharing one intended file, and permissions may be inherited from parent folders or organizational rules.

### Think before using public or shared computers

A [[shared-device|shared device]] can leave behind downloaded copies, browser sessions, recent filenames, or cached content. If you use an approved computer in a library or classroom, follow the institution's security and cleanup procedure. Do not use a private-browsing window as a guarantee that files or online activity cannot be recovered or observed. Do not store real passwords in a practice document or rely on merely closing a browser tab to sign out of a cloud account.

### Review sharing and storage permissions

Cloud services may ask to back up entire folders, photos, or device contents. These features can be useful, but enabling them may move substantial information to an online account. Review what the app wants to access, what content would be transferred, and whether the account is appropriate. If you are only learning a single-file upload, you do **not** need to enable automatic photo backup, whole-device sync, or continuous monitoring of all Documents and Desktop files.

### Encryption, recovery, and provider responsibility

[[encryption|Encryption]] is a technique for protecting data against unauthorized reading, but it does not by itself prevent mistaken sharing, weak login security, accidental deletion, or all provider failures. Products differ in how they encrypt stored and transferred material and how they handle access keys. Do not assume that every service uses end-to-end encryption for every file. For highly sensitive material, use approved storage and security practices established by the responsible organization.

A [[recovery-plan|recovery plan]] explains how you would regain a document after a wrong edit, device failure, unauthorized account access, or deletion. It may include a separate backup, version retention, account recovery details, and a named administrator. An account's Trash folder or version history can be part of recovery, but it should not be the only protection for irreplaceable records. If a file is truly critical, test that an authorized restoration process works before an emergency occurs.

### Keep a practical cloud-storage routine

1. Identify the account and destination before placing a file online.
1. Use clear filenames and limited folders rather than an expanding pile of unlabeled documents.
1. Confirm that uploads and sync operations finish; do not rely on a spinner or a filename alone.
1. Prepare permitted offline files before losing internet access.
1. Check permission settings before sharing, and avoid sending broad-access links casually.
1. Maintain separately recoverable copies of important material.
1. Review unusual errors, storage warnings, or duplicate files before reorganizing or deleting anything.

### Worked example: a shared folder request

Suppose a fictional teammate asks you to upload a list containing other students' personal contact details into a personal cloud account. The list belongs to a class, and no one has confirmed permission to transfer it. You should **not upload it to complete the request immediately**. Instead, ask the instructor or responsible administrator which approved account, destination, and sharing procedure should be used. The goal is to complete the legitimate task through an authorized workflow, not to assume that a familiar cloud app is a safe destination for all data.

## 7. Guided practice: learn the cloud-storage workflow

These six activities move from recognizing storage locations to planning a reliable, safe workflow. Each can be completed **without a cloud account** by using fictional descriptions, an ordinary local text editor, and the expandable model responses. If an instructor authorizes a live demonstration, use only newly created, disposable practice files, and do not enable new account settings or invite real recipients. Record a short explanation of each choice rather than sending private screenshots or account information.

### Activity 1: Identify what is stored where

**Goal:** Distinguish local storage, cloud storage, and synchronized locations.

**Scenario:** A student is shown six fictional items:

- **A:** `Example-Notes.txt` saved in `C:\Practice` on a Windows laptop.
- **B:** `Example-Notes.txt` shown in a Google Drive web folder under a permitted account.
- **C:** `Example-Notes.txt` shown in OneDrive with a blue cloud icon in File Explorer.
- **D:** `Example-Notes.txt` downloaded from a website into the laptop's Downloads folder.
- **E:** `Example-Notes.txt` stored on a USB flash drive.
- **F:** `Example-Notes.txt` shown in a OneDrive folder as actively syncing.

**Steps:**

1. Classify each item by its apparent storage location or status.
1. Identify which ones might need an internet connection to open their contents.
1. State why item C may appear in File Explorer without occupying the same local storage space as item A.
1. Explain why item F does not yet establish that the latest version is available everywhere.
1. Describe one additional check you would perform before relying on B or F.

:::answer Show Activity 1 model answers
**A** is a local folder example. **B** is displayed in cloud storage through the website, but a browser may also cache some content. **C** is an online-only OneDrive item: its listing can appear locally while full content remains online. **D** is a downloaded local copy; it is not necessarily synchronized. **E** is removable local storage. **F** is in a sync-managed location, but the transfer is still in progress. Items B and C generally depend on internet access unless a supported offline copy has already been prepared; F may also need connectivity to complete syncing. Check the correct account, folder, latest expected changes, and completed transfer status before claiming that the file is safely retrievable elsewhere.
:::

**Success standard:** The learner distinguishes location, availability, and transfer state without treating them as the same property.

### Activity 2: Create and locate a practice file

**Goal:** Practice selecting a file name and verifying the destination rather than merely clicking Save.

**Scenario:** You are preparing a fictional class outline. No student or personal records are needed.

**Steps:**

1. Open a simple text editor or use a blank sheet of paper to simulate one.
1. Type the four-line practice message shown earlier, or create three short invented sentences about a library visit.
1. Save the file as `MGU-Cloud-Practice.txt` in a known **local** practice folder, if permitted.
1. Reopen the local file from that exact folder to verify the name and content.
1. Write down the folder location and whether an online service was involved.
1. If you already have authorization and a configured cloud account, explain—not necessarily perform—how you would upload the same file into a named practice folder and verify completion.

:::answer Show Activity 2 model answers
A successful record identifies the document name and the chosen local folder. Reopening the file verifies that it was saved where expected. If saved under a non-synchronized local folder, it should be classified as **local**, not uploaded. A correct optional upload plan names an authorized cloud account, selects a destination folder, transfers the harmless practice file, waits for completion, and checks the online location and contents. No new account, sync configuration, or real personal data is required.
:::

**Success standard:** The learner can explain which location actually contains the practice file and what additional action would create an online copy.

### Activity 3: Plan a two-device retrieval

**Goal:** Explain how to retrieve an uploaded file using another authorized device.

**Scenario:** An invented learner uploads `Fictional-Book-List.txt` to a cloud account on a laptop and wants it on a permitted tablet. The tablet shows a different account by default.

**Steps:**

1. State which account should be checked on the tablet and why.
1. Identify the folder to search before using a general Recent view.
1. Explain the difference between opening the file online and deliberately downloading a copy.
1. Name two signs that would make you suspect the upload has not yet completed.
1. Describe what you would do if the filename is visible but the contents differ from the laptop's latest version.

:::answer Show Activity 3 model answers
First confirm the same appropriate account and the specific folder used on the laptop. A Recent list is only a convenience view; the parent folder is the stronger location clue. Opening or previewing online does not necessarily create a durable local download. An ongoing progress indicator, pause notice, sync error, or failure message can indicate an incomplete transfer. If contents disagree, compare the versions and sync status, preserve both while investigating, and avoid overwriting the only correct copy.
:::

**Success standard:** The learner checks account, location, transfer status, and content before declaring that retrieval succeeded.

### Activity 4: Decide which files must work offline

**Goal:** Identify suitable offline-preparation choices without assuming all cloud files are downloaded.

**Scenario:** A fictional traveler has a tablet with limited free storage. The traveler plans to read a short itinerary while disconnected, view a large photo archive only after returning to Wi-Fi, and edit a medium-size practice document on a train.

**Steps:**

1. Choose which files need an offline-ready copy before departure.
1. Identify which files can remain online-only if they will not be needed during travel.
1. Explain the difference between online-only and intentionally offline-ready content.
1. Name one test to perform before losing the internet connection.
1. Explain what to do after reconnecting if the practice document was edited offline.

:::answer Show Activity 4 model answers
The short itinerary and practice document should be prepared offline if the user is authorized to store them on the tablet; the large photo archive can stay online-only if it will not be needed during the disconnected period. Online-only files may be listed but not fully present on the device. Offline-ready copies consume device space and must be completed in advance. Test opening a harmless file with connectivity disabled, then reconnect. After offline edits, allow synchronization to complete, look for conflicts, and confirm that the expected revision is accessible before deleting any local copy.
:::

**Success standard:** The learner matches offline preparation to actual needs and distinguishes local capacity from cloud quota.

### Activity 5: Handle a deletion and sharing warning

**Goal:** Choose safe actions when a synced file or its access controls may be misunderstood.

**Scenario A:** A learner wants to reduce local storage and plans to press Delete on a synced OneDrive file.

**Scenario B:** A teammate sends a cloud link labeled “Anyone with the link can edit” for a private fictional project that only two students should change.

**Scenario C:** A cloud service sends a surprise email asking the learner to enter their password through a shortened link because the account is supposedly full.

**Steps:**

1. Explain why deleting the synced file may not achieve the intended purpose in A.
1. Name the safer category of command to consider in A, subject to provider support and permission.
1. Identify what is wrong with the intended audience and permission in B.
1. State how to check the storage claim in C without using the unsolicited link.
1. Describe when to contact an instructor, account owner, or administrator.

:::answer Show Activity 5 model answers
In **A**, deletion can propagate to the cloud and other devices. If the goal is simply to save local space, review the service's supported online-only or Free up space control and confirm what it does. In **B**, broad-access editing is greater permission than a two-person project needs; the owner should review specific-person access and the minimum appropriate role. In **C**, open the provider through a known official website or trusted app and inspect account notices there, without clicking the unexpected sign-in link. Contact an authorized person when organizational settings, ownership, or data sensitivity are unclear.
:::

**Success standard:** The learner recognizes synced deletion, excessive sharing rights, and phishing risks without actually testing them on private content.

### Activity 6: Design a small end-to-end storage plan

**Goal:** Integrate storage location, file organization, retrieval, offline access, and recovery into one dependable routine.

**Scenario:** A fictional community workshop produces three documents: `Agenda-Practice.txt`, `Notes-Practice.txt`, and `Poster-Practice.pdf`. The organizer wants to view the agenda on an authorized phone, revise the notes on a laptop, and retain an independent recovery copy of the final poster. No personal information is in these files.

**Steps:**

1. Propose one clearly named online practice folder and list the three filenames.
1. Identify which account and approved devices may access the folder.
1. Explain how the organizer would verify the agenda uploaded and can be retrieved on the phone.
1. Decide whether the agenda should be made available offline before the event.
1. Explain how the organizer should handle note edits made on two devices and what to do if copies conflict.
1. Choose a separate backup destination for the final poster, and explain why it should not simply be the same synced working folder.
1. State one sharing rule and one account-security rule for the project.

:::answer Show Activity 6 model answers
A suitable folder might be `Workshop-Practice-2026` inside an approved account. It would contain the three fictional files with unchanged, recognizable names. The organizer confirms the correct account on both authorized devices, waits for the agenda upload to finish, then finds the folder and checks the file contents on the phone. If the agenda is needed without internet, it should be made offline-ready and tested ahead of time. Note edits should be made after checking sync completion; conflicting copies should be preserved and compared instead of overwritten blindly. The final poster should also have an independent dated recovery copy on a permitted backup destination not continuously altered by the same synchronization process. Sharing should be restricted to authorized recipients with the needed access, and the account should use secure sign-in measures such as MFA where supported.
:::

**Success standard:** The learner describes a sequence that is retrievable, privacy-conscious, and recoverable without confusing synchronization with backup.

### Optional live five-minute demonstration

If an instructor provides an authorized test account, open its cloud-storage interface and create a **new disposable practice folder** rather than touching existing content. Upload an invented text file, wait for the completed status, close and reopen the interface, and find the file in its destination folder. If the device supports it, inspect the availability status without changing any broader sync settings. End by confirming what was uploaded, the exact folder, and whether any local download was made. Do not share links, take screenshots of private folders, or use real credentials in submitted class work.

### Practice record and completion standard

For each activity, write four short statements: **(a)** the intended result, **(b)** where the file or data belongs, **(c)** the safe action or observation, and **(d)** how you would verify success. A learner can receive full credit for a thoughtful written simulation. An instructor should not require access to personal accounts or records. The skill is the ability to reason about where information lives and what happens when it moves.

## 8. Common mistakes and troubleshooting

### “Anything with a cloud symbol is backed up forever.”

A cloud icon may indicate availability status or a sync service. Neither proves that an independent, durable backup exists. File history and Trash retention are limited by product rules and account configuration. Make a recoverable additional copy for important material and know how it would be restored.

### “If a file appears in File Explorer, its full contents are on this computer.”

Some services display online-only placeholders. The filename and icon can be visible even when the full file is not locally stored. A disconnected device may be unable to open such an item. Use the specific service's offline control and verify that preparation has completed before relying on the file away from the network.

### “Deleting a synced file only removes it from this device.”

Deletion may synchronize and remove the cloud item and its counterpart on other devices. A command to make a file online-only or free local disk space has a different purpose. Read the command description rather than treating Delete as a storage-management shortcut.

### “The sync check mark means I have a second independent copy.”

A successful sync status may establish that working changes reached a connected location. It does not prove that an independent backup, prior version, or permanent archive exists. The synced service could reflect an incorrect edit or deletion. Use a deliberate backup strategy for valuable material.

### “A file is missing, so the service must have lost it.”

Check the account first: personal and school logins may show different content. Then check the expected folder, search, Recent, Shared, Trash, and the original device's status as appropriate. Some files were never uploaded, and some are visible only to a particular owner or organization. Avoid repeatedly uploading until you know what happened.

### “Seeing a browser preview means I downloaded the file.”

An online preview is not proof that a local copy was written to Downloads or another folder. Use the service's supported Download action when needed, then locate and open the downloaded file. On a shared device, an extra local copy also creates a privacy and cleanup responsibility.

### “More cloud storage means more free space on my phone.”

Cloud quota and device storage are different resources. Mirrored files, offline copies, downloads, and cached data can consume local space. If the device is nearly full, inspect its own storage and supported local-space controls. Do not delete unknown folders or remove app data randomly; that may remove useful or unsynced content.

### “My document updated on one device, so every device has the latest version already.”

Sync requires a suitable app or browser state, account, internet connection where needed, and successful transfer. A second device may be signed out, offline, configured for a different folder, or displaying an older copy. Verify the final content after synchronization rather than only trusting the newest-looking timestamp.

### “A shared file becomes private when I stop sending its link.”

A link already distributed may remain valid until permissions are changed or revoked. Some accounts support named access, group access, or broad link access that others can forward. The first sharing lesson will teach how to review and limit those permissions. For now, do not assume that a file is private merely because you stopped copying its link.

### “The most recent file is always the correct one.”

Modification dates help with investigation, but they cannot by themselves prove that content is correct. A corrupted or accidental edit can be the newest file. Preserve alternatives, read the contents, and use version-history or independent backup procedures when available.

### “Offline editing is impossible.”

Supported offline copies can often be opened or edited without a live connection. The changes may synchronize after reconnecting. However, availability depends on file type, editor, app state, and storage space. Prepare and test a safe sample before traveling. If the service creates a conflict, keep both versions until you understand the differences.

### “Every cloud service uses the same icons and menus.”

OneDrive, Google Drive, iCloud Drive, browser applications, and device file managers have different interface conventions. Even the same product may change between account types or software releases. Learn the durable questions—account, location, status, offline state, access, and recovery—rather than memorizing one screenshot.

### “An app asking to back up my whole device is required for one file upload.”

Single-file upload and broad automated backup are separate features. A whole-folder or whole-device setup can transfer much more data than expected. Use the least extensive authorized action necessary for the lesson and request approval before changing organization-managed settings.

### “If the cloud service asks for my password, the request must be genuine.”

Phishing messages can imitate providers and use urgent storage warnings. Do not sign in through an unexpected or shortened link. Navigate to a known legitimate service address or application and check the account's status there. Use MFA and a strong, unique credential for the account, and ask for help through an official support channel if suspicious activity is detected.

### “Cloud storage means files automatically belong to whoever uploaded them.”

Possessing a copy does not necessarily mean holding the copyright, license, or institutional authority to distribute it. Work, school, and client files can be subject to confidentiality, retention, and ownership rules. Follow the responsible organization's policies and the file owner's instructions before uploading or sharing.

### A practical troubleshooting sequence

| What you notice | Check first | Avoid doing immediately |
| --- | --- | --- |
| File is absent from the expected list | Correct account and folder | Re-uploading into several locations |
| Recent changes are missing | Sync status and latest file contents | Overwriting the original with an unverified copy |
| Upload is stuck | Connection, service error, quota | Repeatedly renaming or deleting the only copy |
| Offline file will not open | Whether the content was made offline-ready | Assuming every visible file is downloaded |
| Many duplicate files appear | Locations, contents, and conflict messages | Deleting all but the newest blindly |
| Cloud account appears compromised | Official account security and recovery channels | Entering credentials into a suspicious email link |
| Storage warning appears | Actual provider quota and local storage | Buying a plan through an unverified advertisement |
| You cannot access a shared file | Account identity and sharing permissions | Requesting public access to bypass an organization policy |

### The simplest reliable workflow

For a new file, say the planned location aloud: **“This is a practice document in my authorized cloud account, in the workshop folder.”** Save or upload it, verify transfer completion, and find it again. Before working away from the internet, prepare offline access. Before sharing, inspect the intended audience and role. Before deleting or reorganizing, confirm whether the file is synchronized and whether a recoverable copy exists. These short checks prevent many costly everyday mistakes.

## 9. Essential vocabulary

The dashboard's dotted-underlined vocabulary can be selected for a short explanation. The visible definitions below also work for learners who do not use interactive popovers. Every term used with inline vocabulary popovers is defined in the `:::terms` registry at the end of this file.

- **Cloud storage:** Online service that stores files on remote systems accessible using an authorized account and network connection.
- **Cloud:** General term for computing resources and services provided through network-connected remote systems.
- **Local storage:** Files kept on a particular computer, phone, removable drive, or other device.
- **Internet connection:** Network access that lets a device communicate with online services.
- **Provider:** Organization operating a particular storage or online service.
- **Cloud account:** A service identity and associated storage space that may be personal, school, or work managed.
- **Folder:** Container used to organize files and sometimes other folders.
- **File:** Named unit of saved digital information such as a document, photo, or spreadsheet.
- **Filename:** Name used to recognize an individual file.
- **File path:** Description of the directories or locations leading to a particular file.
- **File Explorer:** Windows program for browsing files and folders on connected storage locations.
- **Finder:** Mac application for browsing and managing files and folders.
- **Files app:** File-management application used on several platforms including ChromeOS and Apple mobile devices.
- **Upload:** Transfer of data from a device or app to a remote service.
- **Download:** Transfer of data from an online location to a receiving device or destination.
- **Save:** Write information or changed content to the destination chosen by an application.
- **Synchronization:** Process of reconciling chosen files or changes between connected locations.
- **Sync client:** Application that monitors selected local or cloud locations and sends or receives changes.
- **Backup:** A recoverable additional copy intended to help restore data after loss or damage.
- **Restore:** Return a file or system to a usable state from a previous or protected copy.
- **Recovery plan:** Planned way to regain information after deletion, corruption, a failed device, or account problem.
- **Recycle Bin or Trash:** Temporary location where some services hold deleted items before final removal.
- **Version history:** Service feature that may retain previous revisions of a document for review or restoration.
- **Status icon:** Small visual indicator representing a file state, transfer, error, or availability condition.
- **Placeholder:** Visible entry for a file whose full contents may be held elsewhere until requested.
- **Files On-Demand:** OneDrive functionality that can list online files without keeping every full file on the device.
- **Online-only file:** File primarily kept online and not necessarily accessible without an internet connection.
- **Cached file:** Temporary locally stored data retained for faster access without necessarily being a durable offline copy.
- **Offline copy:** Content intentionally made available on a device when the network is unavailable.
- **Offline access:** Ability to open or use an eligible file without current network connectivity.
- **Cloud quota:** Online storage allowance for a service or account under its current plan or policy.
- **Disk space:** Local capacity on a computer, phone, or connected storage device.
- **Folder hierarchy:** Arrangement of folders and subfolders used to group related files.
- **OneDrive:** Microsoft cloud file-storage service available through supported apps and a website.
- **Google Drive:** Google online file-storage service accessible through supported apps and its website.
- **iCloud Drive:** Apple cloud file-storage feature accessible through compatible devices and iCloud services.
- **Drive for desktop:** Google application that connects cloud Drive files with Windows File Explorer or Mac Finder.
- **Streaming mode:** Drive for desktop arrangement that mainly uses remote storage with local caching or selected offline files.
- **Mirroring mode:** Drive for desktop arrangement that also retains local copies of supported cloud files and synchronizes changes.
- **USB drive:** Removable device that stores files and connects through a compatible port.
- **Account security:** Measures used to prevent unauthorized access to an online account.
- **Privacy:** Control and appropriate handling of information about people and their activities.
- **Data ownership:** Rights and responsibilities governing who may manage, use, or distribute a file or dataset.
- **Password:** Secret sign-in string used to help verify account access.
- **Passkey:** Supported passwordless sign-in method based on cryptographic credentials bound to a device or credential manager.
- **Multi-factor authentication:** Account security that uses more than one independent factor to verify sign-in.
- **Phishing:** Deceptive messages or sites intended to trick people into disclosing information or taking unsafe actions.
- **Encryption:** Method of transforming data so unauthorized parties cannot readily read it without required keys.
- **Permission:** Rule controlling whether an individual or group may view, edit, share, or manage content.
- **Viewer:** Person or role permitted to read content without editing it.
- **Commenter:** Role that can provide comments where supported but may not edit the main content.
- **Editor:** Person or role permitted to change document content.
- **Shared device:** Computer or phone used by more than one person, potentially leaving local traces of activity.
- **Link sharing:** Granting or using access to content through a generated URL with particular permissions.
- **File owner:** Account or person with ownership-related control under a particular storage product and its rules.
- **File preview:** Temporary or in-app display of content that is not necessarily a local download.
- **Storage plan:** Service offering that determines eligible capacity and sometimes other features or costs.
- **Subscription:** Continuing paid arrangement for ongoing access to a product or service.
- **Sync error:** Condition in which a synchronization process cannot successfully complete some work.
- **Sync conflict:** Situation in which different changes cannot safely be combined into one current file.
- **Recent view:** Convenience listing of recently accessed or modified items rather than an actual folder location.
- **Account switching:** Moving between distinct signed-in identities inside an application or website.
- **Two-device retrieval:** Finding the same authorized online file from more than one device.
- **Device storage:** Available or occupied capacity on a specific local device.
- **Remote storage:** Storage maintained on computing systems away from the present device.
- **Data loss:** Unexpected disappearance, damage, or unavailability of needed information.
- **Retention period:** Length of time a service or organization keeps particular content or versions.
- **Shared folder:** Folder for which another person or group may hold access rights.
- **Storage location:** Specific device, account, folder, or service holding an item.
- **Offline editing:** Changing a locally available file without a live network connection.
- **Verified transfer:** Upload or download confirmed complete by checking status and the actual destination.
- **Recovery copy:** Separate retained copy preserved to support restoring damaged or missing working content.
- **Confidential information:** Material that should be accessed or handled only by authorized people.
- **Authorization:** Permission granted by an owner or appropriate authority to perform an action.
- **Authentic website:** Genuine site operated by the intended organization rather than an imitation.
- **Downloads folder:** Common local destination for files saved from browsers or apps.
- **Cloud link:** URL directing someone to cloud-hosted content, subject to its current permissions.
- **File format:** Structure used to encode a file such as TXT, PDF, DOCX, or JPEG.
- **File manager:** Application that displays and organizes files across visible storage locations.
- **Device backup:** Process of saving recovery copies of selected device data using a backup tool or service.
- **Storage limit:** Maximum allowed capacity or usage in a given storage location or service.
