## Lesson 6: Screens, Windows, and Menus

A computer screen can show a desktop, an application, a document, a website, several overlapping windows, and small menus containing commands. At first, these objects may seem like unrelated pictures and symbols. In fact, they form a visual system that helps you tell the computer what you want to do. This lesson explains how to recognize that system and move through it without accidentally closing work, changing important settings, or losing your place.

**Level:** Beginner · **Estimated study time:** 65–85 minutes · **Prerequisites:** Lessons 1–5 recommended · **Practice equipment:** A Windows PC, Mac, or Chromebook preferred; tablet, smartphone, or paper-based alternatives included

> **Essential idea:** A [[screen|screen]] is the physical display. A [[desktop|desktop]] is a workspace shown by the computer. A [[window|window]] is an on-screen area where an application or document may appear. [[menu|Menus]] present available commands. You can usually move between these areas without deleting anything—but **minimizing, closing, and saving are different actions**.

### Learning objectives

After completing this lesson, you should be able to:

1. Explain the difference between a physical screen, an on-screen desktop, and an application window.
2. Identify common interface elements, including icons, taskbars or docks, buttons, tabs, scrollbars, and notifications.
3. Distinguish minimizing, maximizing, restoring, closing, and switching windows.
4. Recognize different menus and select an appropriate command without guessing.
5. Use safe steps to move between two ordinary applications or browser windows.
6. Recognize basic differences among Windows, macOS, ChromeOS, tablets, and smartphones.
7. Use or describe accessibility options for easier reading and navigation.

## 1. What are the screen and desktop?

A [[screen|screen]] or display is the physical equipment that presents pictures, words, and controls. A laptop usually has its screen built into the device. A desktop computer may use a separate [[monitor|monitor]]. A phone or tablet has a small built-in display that often accepts touch. A screen is hardware; the objects that appear on it are created and managed by software.

When you turn on a computer, it may first show a sign-in area or [[lock-screen|lock screen]]. After you sign in, a desktop computer often shows a [[desktop|desktop]]: an on-screen working area where you can open programs and see windows. The appearance varies by operating system, user preferences, and whether the computer is managed by a school or employer.

### Physical screen versus on-screen desktop

Imagine an office desk and a sheet of paper placed on it. The *physical monitor* is like the surface on which something is displayed. The *desktop* is an electronic workspace; it is not a separate physical part. A program's *window* is a section of that workspace where the program presents its contents.

The same physical screen can show a desktop, one full-screen program, two windows side by side, or a video. Changing what is displayed does not mean the physical screen has changed.

### Wallpaper and desktop icons

The picture or plain color behind desktop items is often called [[wallpaper|wallpaper]] or the desktop background. It is mainly visual decoration and does not normally perform the work of an application. An [[icon|icon]] is a small picture representing an app, file, folder, command, or status. Icons may appear on the desktop, in a menu, in the taskbar or dock, or inside an application.

An icon's appearance alone does not tell you whether the associated application is running. Some icons simply provide a convenient way to open an app. Others may show a badge or dot indicating that an app is open or that something needs attention. These indicators differ by system.

> **Remember:** The screen is a physical device. The desktop, icons, and windows are elements of the [[graphical-interface|graphical user interface (GUI)]] shown on that device.

### What does the operating system do?

An [[operating-system|operating system]] is the main software environment that coordinates programs, files, hardware, and user interaction. Windows, macOS, and ChromeOS provide familiar desktop interfaces. iOS, iPadOS, and Android provide interfaces designed primarily for mobile devices. A desktop or phone home screen is not the entire operating system; it is one visible part of the experience.

You do not need to understand the operating system's internal engineering to use it. In this lesson, concentrate on what you can see: where an app opens, how it responds when you select a command, and how to get back to your work.

## 2. What do you see on a computer screen?

The organized collection of buttons, icons, text, menus, and windows is called a [[user-interface|user interface]]. You interact with it through a keyboard, mouse, touchpad, touchscreen, or other accessible input method. The same function may appear in a different location on another computer.

### Common visual elements

The table below describes typical interface elements. Exact names and placement vary. The tooltip definitions for these terms appear in the text and vocabulary section, not inside the table, to keep the Markdown table compatible with the MGU lesson renderer.

| Element | What it usually does | Example |
| --- | --- | --- |
| Desktop | Provides a main visual workspace | Background behind app windows |
| Icon | Represents an app, file, folder, or action | Calculator app picture |
| Button | Starts a particular action when activated | Save or Cancel |
| Taskbar, Dock, or shelf | Helps open or return to applications | Row of app icons |
| Window | Contains a program or document view | A notes editor on the screen |
| Tab | Switches between sections within an app or browser | Two webpages in one browser window |
| Scrollbar | Indicates that more content can be viewed | Bar beside a long page |
| Menu | Presents a collection of commands | File menu |
| Dialog box | Asks for a choice, information, or confirmation | Save changes? |
| Notification | Reports an event, message, or system condition | A low-battery warning |

### Buttons, links, and text fields

A [[button|button]] is a control that performs an action when you select it. A button marked **Save** may save your work; one marked **Cancel** often dismisses the current action. A [[link|link]] usually opens another page, view, or resource. On the web, links can be words, images, or other controls; do not rely only on blue underlined text to recognize them.

A [[text-field|text field]] is a place where you can type a name, search phrase, or other information. Before typing, confirm that the correct field has [[focus|focus]], meaning it is ready to receive your input. A blinking vertical insertion point often indicates an editable text position. Selecting a button is different from placing focus inside a field.

### Taskbar, Dock, and shelf

Windows commonly has a [[taskbar|taskbar]] that offers application icons, access to Start and search, and other system controls. A Mac has a [[dock|Dock]] with app icons, and a menu bar near the top of the screen. Chromebooks commonly have a [[shelf|shelf]] and a Launcher for opening applications. These are ways to reach apps or switch tasks, but they are not themselves documents or ordinary browser webpages.

A system may move or hide these bars automatically. Some organizations customize them. If an instruction refers to an icon that you cannot see, look for the equivalent app name through the system's search or Launcher rather than assuming the app is missing.

### Tabs, scrollbars, and page contents

A [[tab|tab]] lets you change between different sections of content, often without leaving the current application window. A web browser can have several tabs for different pages. A notes application may also have tabs, depending on the program. A *tab* is not automatically a separate *window*. Closing a browser tab typically closes that page's view, not the entire computer.

A [[scrollbar|scrollbar]] helps you move through content that extends beyond the visible area. You may also scroll with the mouse wheel, touchpad gesture, touchscreen swipe, or keyboard, depending on the device and application. Scrolling generally changes the part you can see; it does not normally erase or rewrite the content.

### Notifications and status information

A [[notification|notification]] may report an incoming message, completed download, battery condition, or request for attention. A [[status-indicator|status indicator]] may show network connection, volume, or available power. Notifications can be useful, but an unfamiliar pop-up is not automatically trustworthy. Read its source and wording before opening a link, installing anything, granting a permission, or entering a password.

> **Pause and identify:** On your own device, find one icon, one button, and one area used to switch apps. You do not need to activate any of them yet.

## 3. How do application windows work?

A [[window|window]] is a rectangular or otherwise defined on-screen area associated with an app, a document, or another interface view. A desktop can show several windows at once. One may overlap another. The window in which you are currently working is commonly called the [[active-window|active window]]. A selected or focused window may have a more prominent border, title bar, or controls.

### The title bar and window controls

Many desktop windows include a [[title-bar|title bar]] with an app name, document name, or area that can be used to move the window. Some windows integrate controls into other parts of the interface. On Windows, familiar controls often appear in the upper-right corner. On a Mac, colored window controls are commonly near the upper-left corner. Chromebook windows have similar functions but may use different layouts or symbols.

| Window action | Typical effect | Does it save your work? |
| --- | --- | --- |
| Minimize | Hides the window from the main workspace while generally leaving it open | No; not by itself |
| Maximize | Makes the window occupy a larger available workspace | No; not by itself |
| Restore | Returns a maximized window to a previous non-maximized size | No; not by itself |
| Resize | Makes the window wider, narrower, taller, or shorter | No; not by itself |
| Move | Changes the window's position on the desktop | No; not by itself |
| Close | Dismisses the window and may close a document or app view | Not necessarily; a prompt may appear |
| Switch | Brings another app or window to the foreground | No; not by itself |

**Important:** All these actions affect how a window is presented or which view is open. None should be treated as a substitute for using Save or checking that an app has autosaved your changes.

### Minimize: hide without necessarily closing

[[minimize|Minimizing]] a window makes it disappear from the main workspace. Usually the application is still available through the taskbar, Dock, shelf, or a window-switching view. A minimized browser, for example, can often be brought back without reopening the website. If sound is playing, it may continue, depending on the application.

If a window suddenly seems to vanish, do not conclude that the document was deleted. First check whether the program is still open and whether the window has merely been minimized or covered by another window.

### Maximize and restore: change the size

[[maximize|Maximizing]] expands a window to fill most or all of the available workspace. On Windows, a maximized window typically leaves the taskbar accessible unless that bar is set to hide. [[restore|Restoring]] returns it to a smaller size so you can see or arrange other windows. On a Mac, the green window control may enter full screen or offer other arrangement options rather than matching the exact Windows maximize behavior; the effect depends on the app and system version.

A large window may be easier to read, while a smaller window may help you compare two things. These are layout choices, not different file types.

### Close: dismiss a window, sometimes more

Selecting **Close** removes a window. What happens to its application depends on the operating system and app. On many Windows programs, closing the last window also ends the program. On a Mac, closing a document window often leaves its application running; **Quit** is a separate action. On a Chromebook, closing a browser window does not switch off the computer.

If you edited a document, closing it may produce a question such as **Save**, **Don't Save**, or **Cancel**. Read that prompt carefully. **Don't Save** can discard changes, and **Cancel** typically returns you to the document without closing it. Some apps save automatically; others do not. When unsure, save or verify the saved state before closing.

### Moving and resizing a window

In many desktop applications, you can move a window by dragging its title bar. You can often resize it by moving the pointer near a border or corner until a resize indicator appears, then dragging. Not all windows are resizable or movable, and a device may use touch or specialized controls instead.

Practice only with an ordinary, disposable window. Avoid dragging important files or icons: moving a **window** is different from moving a **file** from one folder to another.

### Window versus browser tab versus application

An [[application|application]] is the software performing a task. A browser is an application. A **browser window** is one visible instance of that application. Inside it, multiple **tabs** may show different websites. A word processor may open multiple document windows. The same application can therefore have more than one window, and one window can contain more than one tab.

For example, you might have one browser window with an MGU lesson tab and a dictionary tab, while a separate notes window is open beside it. These are three content views, but not necessarily three different applications.

> **Practical rule:** Before you close a window or tab, ask two questions: “Where will I return if this closes?” and “Have I saved anything I changed?”

## 4. What are menus and dialog boxes?

A [[menu|menu]] is a group of commands or choices displayed when you activate a menu heading, button, or other control. It helps you find actions without memorizing their keyboard shortcuts. Menus may be organized by purpose, and some contain further groups of choices.

### Application and menu-bar commands

Many desktop applications have menus with headings such as **File**, **Edit**, **View**, **Window**, and **Help**. A menu under **File** may contain New, Open, Save, Print, or Close. The exact commands depend on the app and what you are doing. On a Mac, application menus commonly appear in the menu bar along the top of the screen. On Windows and Chromebooks, menu locations vary by application.

A [[menu-item|menu item]] is one option within a menu. Pointing at a menu item may highlight it; activating it may run a command, open a [[submenu|submenu]], or display a dialog. Just opening a menu normally does not perform the command, but clicking a particular item might. Read the item before selecting it.

### Context menus

A [[context-menu|context menu]] offers actions related to the item or area you selected. It often appears after a secondary click—commonly called right-click—on a mouse, or through an equivalent touchpad, keyboard, or touch action. For example, a selected word may offer Copy; a file may offer Rename or Delete. Context menus change because different items support different actions.

In a safe exercise, you can open a context menu and inspect the available commands **without selecting one**. Then use Esc or click an appropriate area to dismiss it. A context menu is not a separate document; it is a temporary list of choices.

### Drop-down lists, the three-dot button, and other symbols

A [[drop-down|drop-down list]] presents a set of choices, such as a language or text size. A **three-dot** button, sometimes called a more-options menu, often reveals additional commands. Three horizontal lines may represent a navigation menu, sometimes called a hamburger menu. These symbols are conventions, not universal rules: you should inspect a control's label, tooltip, or accessible name when available.

Some menu choices show a check mark to indicate a selected setting. Others may be unavailable and shown in a lighter color. A right-pointing arrow often means there is another group of options, but icons vary across software and devices.

### Dialog boxes: decisions that need your attention

A [[dialog-box|dialog box]] is a temporary window or overlay requesting information or a decision. It may ask where to save a file, whether to discard changes, or whether to grant camera access. It can include buttons, fields, checkboxes, or a list of choices.

Before responding to a dialog:

1. Read the entire message, including the source application and what will change.
2. Identify the safest available action if you are uncertain. **Cancel** or **Not now** often dismisses a request without proceeding, but read the exact wording.
3. Avoid enabling permissions, deleting information, approving purchases, or installing software just to complete a practice activity.
4. If a message claims to be urgent and requests a password, payment, or remote access, stop and verify it through a trusted channel.

A familiar-looking dialog can still be misleading. Do not assume that everything on a screen is a genuine system message.

### The difference between a menu and an alert

A menu offers commands for you to choose from. An [[alert|alert]] or notification calls attention to information, a condition, or a possible problem. Some alerts include buttons and therefore resemble dialogs. The best way to interpret one is to read its message, understand which program presented it, and consider the consequences of the proposed action.

> **Decision habit:** Selecting **View** from an ordinary menu is not the same as approving **Delete**, **Reset**, or **Allow access**. Learn to read the action before clicking.

## 5. How do you navigate between windows and apps?

Moving through a graphical interface is a sequence of simple operations. You do not need to memorize every control. First find the content you want, then choose the safest way to bring it forward.

### Open or find an ordinary application

On a Windows computer, you might use Start, Search, or an existing taskbar icon. On a Mac, you might use the Dock, Finder, or another app launcher. On a Chromebook, you might use the Launcher or shelf. Depending on your settings, a desktop shortcut may open an app when activated. Opening an application may display a window immediately or may return you to an existing one.

If nothing appears, check whether another window is covering it or whether the app is still starting. Avoid repeatedly clicking an unfamiliar control, which might open multiple copies or trigger an action you did not intend.

### Switch between two open windows

To [[switch-window|switch windows]], you can often select a visible portion of the desired window or activate its taskbar, Dock, or shelf representation. Windows and many Chromebooks also support **Alt + Tab** to move among open windows. On a Mac, **Command + Tab** commonly switches applications, and an application may still have several separate windows. A Mac may offer additional window-switching controls, such as Mission Control or app-specific commands.

When switching, look for the window title or content to make sure the correct item is active. A program can continue running even when it is not the one in front of you.

### Compare two windows

If you need to read a webpage while writing notes, you may place a browser and notes window side by side. On Windows, [[snap|Snap]] can help arrange supported windows; dragging an ordinary window to a screen edge may also offer a layout. Macs and Chromebooks offer window-arrangement features, but their names and controls differ by version. You do not have to use these features to complete the lesson.

A simpler method is to make each window smaller and position them so both remain visible. On a narrow screen, it may be easier to switch back and forth instead. If you cannot fit two windows comfortably, that is a screen-space limitation, not a failure.

### Navigate within a browser window

A [[browser|web browser]] may show an address bar, Back and Forward controls, tabs, and page content. The browser's **Back** command commonly returns to a previous page in the same tab's browsing history; it does not necessarily reopen a desktop application or reverse a text edit. A site's own navigation links may move you somewhere else. An app's **Undo** command is a different function again.

Before closing an MGU lesson tab, consider whether you have unsaved notes elsewhere. Browser history is not a reliable backup for form content or temporary work. If you need a particular page later, use an approved bookmark or save its address in a harmless note.

### If you lose a window

Try these checks in order:

1. Look for the application icon on the taskbar, Dock, or shelf, and see whether it indicates an open window.
2. Check for overlapping windows or full-screen applications.
3. Use the available app or window switcher to find the missing view.
4. If you intentionally minimized the window, restore it by selecting the appropriate app or window representation.
5. Only reopen a file or page if you cannot find the existing view; when editing a document, confirm which version you are opening.

Do not immediately restart the computer to find a hidden window. A restart can interrupt unsaved work and is usually unnecessary for this problem.

### A simple navigation sequence

Imagine that you are reading a computer lesson in a browser and taking notes in a separate app. You read the lesson, switch to the notes window, type an explanation, return to the browser, and scroll to the next example. You have used a browser tab, two application views, and perhaps a taskbar or Dock—all without needing to close anything.

> **Try to explain:** Why is switching from a browser to a notes app different from closing the browser and opening it again? What work might be at risk if a file has not been saved?

## 6. How do screens and controls differ across devices?

Most modern devices use [[visual-navigation|visual navigation]], but their layouts are not identical. A desktop interface is optimized for several windows and pointer-based controls. A phone often uses one main app view at a time, with touch gestures and an app switcher. A tablet may support split views or other multitasking features, depending on its model and software.

### Windows computers

Windows commonly provides a desktop, taskbar, Start menu, application windows, and a notification or quick-settings area. Many windows have three familiar controls near the top right: minimize, maximize or restore, and close. A taskbar icon may open an app or let you return to an already-open window. **Alt + Tab** often switches among open windows. Features, button placement, and names can change across Windows editions and system updates.

### Mac computers

macOS commonly provides a desktop, a Dock, and a menu bar across the top. Application-window controls are generally near the upper-left corner. The red control closes a window; the yellow control minimizes it; the green control provides full-screen or other layout behavior. **Command + Tab** normally switches between apps rather than guaranteeing a switch between every window of the same app. Closing the last window of an app does not always quit the app. If you intend to stop the app, use its appropriate Quit command.

### Chromebooks

ChromeOS commonly provides a shelf, Launcher, browser windows, and an area for quick settings. Chromebook windows can often be resized, minimized, or arranged. **Alt + Tab** is commonly available to switch between windows. A Chromebook's keyboard may label special keys differently from a Windows or Mac keyboard. An app or website may run in its own window or as a browser tab.

### Tablets and smartphones

On many phones, the **home screen** contains app icons and widgets. Touching an icon usually opens its app. An [[app-switcher|app switcher]] helps you return to a previously used app; its opening gesture or button varies by device and settings. Swiping an app away from the app switcher is not a substitute for saving work or signing out of a sensitive account. Some tablets offer multiple windows or split-screen views, but not every mobile device supports them in the same way.

| Device environment | Common workspace | Common way to find apps | General navigation style |
| --- | --- | --- | --- |
| Windows desktop or laptop | Desktop and overlapping windows | Start or taskbar | Mouse, touchpad, keyboard, sometimes touch |
| Mac desktop or laptop | Desktop and app windows | Dock or app launcher | Trackpad or mouse and keyboard |
| Chromebook | Desktop-style workspace and browser windows | Launcher or shelf | Touchpad or mouse and keyboard, sometimes touch |
| Tablet | Home screen and app views | Home screen or app library | Primarily touch; some support a keyboard or pointer |
| Smartphone | Home screen and app views | Home screen or app drawer | Primarily touch and accessible gestures |

The table describes common patterns, not a promise that every device has an identical feature. Follow the controls and labels shown on the device you actually use.

### Accessibility: more than one way to navigate

[[accessibility|Accessibility]] features can make a computer easier to operate for people with different vision, hearing, mobility, or learning needs. Depending on the system, these may include larger text, display scaling, increased contrast, screen magnification, screen readers, keyboard navigation, voice control, and pointer adjustments.

For example, if small text is hard to read, you may be able to increase display scaling or use a browser's zoom controls. These options are different: browser zoom changes a webpage's displayed size, while system display scaling can affect many interface elements. If you rely on a screen reader, menus and dialogs may be announced rather than visually inspected. Keyboard users can often move focus among controls with Tab and activate the focused control with Enter or Space, depending on the interface.

Accessibility settings should support the learner's needs, not become another obstacle. You can complete the lesson by describing a control rather than manipulating it. If the device is shared or managed, ask the owner before changing lasting settings.

### Safe habits across every platform

- Use harmless, familiar apps for practice, such as a calculator or a blank note.
- Read command labels before activating them.
- Save or verify autosave before closing editable work.
- Do not disclose passwords or private information to complete exercises.
- Never approve unexpected access, payment, deletion, installation, or remote-control requests during a basic navigation lesson.
- Remember that software versions and accessibility preferences can change where controls appear.

## 7. Guided practice: Explore screens, windows, and menus

These activities are designed for a beginner. A Windows PC, Mac, or Chromebook is especially useful, but a tablet or phone can be used for the observation and menu exercises. If you do not have a device, read each situation and write what you would expect to see. **No activity requires deleting a file, changing a system setting, installing software, or entering an account password.**

### Activity 1: Identify what is on your screen (about 5–7 minutes)

1. Look at the screen you are using and name the device type.
2. Identify a background or home/desktop workspace if one is visible.
3. Locate one icon, one button, and one area displaying content.
4. Identify where you would go to open another app or switch to an existing one.
5. Write a brief explanation of the difference between the physical screen and the desktop or home-screen view.

*Observation worksheet*

| Item to identify | Your observation | Purpose |
| --- | --- | --- |
| Physical display | __________ | Presents visual output |
| Workspace or home area | __________ | Helps organize or access work |
| Icon | __________ | Represents an app or other item |
| Button | __________ | Starts a particular action |
| App access area | __________ | Opens or returns to applications |

> **Example:** “I use a laptop. The display is the physical screen. The desktop is the workspace shown on it. I can find a browser icon on the taskbar and select it to return to the browser.”

### Activity 2: Observe window behavior (about 7–10 minutes)

Use an already available, harmless application, such as a calculator or an empty note. If you cannot use a desktop computer, complete the exercise in writing.

1. Open or return to the application. Find the title or name of the active window.
2. If a **Minimize** control is available, use it once. Look for the app's representation on the taskbar, Dock, or shelf.
3. Bring the same window back without opening another copy if possible.
4. If **Maximize** and **Restore** are available, observe how they change the window's size. Do not worry if your application uses different controls.
5. Explain why the action you performed did not necessarily save the application's content.
6. Avoid closing any document that contains important unsaved work.

:::answer Show Activity 2 explanation
A minimized window usually remains available while hidden from the main desktop. Restoring it brings it back. Maximizing changes how much of the screen it occupies. These actions affect presentation and navigation; they do not themselves save files or guarantee that work is preserved.
:::

### Activity 3: Open a menu without making a change (about 5 minutes)

1. Choose a familiar, ordinary application with a visible menu or more-options button.
2. Open an appropriate menu and read at least three menu items.
3. Identify one command that would be safe to inspect and one that might alter or remove something.
4. Without selecting a consequential command, dismiss the menu using Esc, an available Back control, or a tap/click outside it, as appropriate.
5. Explain how a menu differs from a dialog that asks you to confirm an operation.

> **Example:** “A View menu contains ways to change what I see. A Delete command may remove information. A menu lists available actions, while a confirmation dialog asks me whether to proceed with a particular action.”

### Activity 4: Move between a lesson and a note (about 8–10 minutes)

If you can safely use two applications, keep this MGU lesson in the browser and open an empty note in a separate app. Do not enter sensitive information or overwrite an existing document.

1. Start in the browser and identify its tab containing the lesson.
2. Switch to the notes app using the taskbar, Dock, shelf, or another supported app switcher.
3. Type this harmless sentence: `A window displays part of an application.`
4. Switch back to the browser without closing either view.
5. Return to the note and check whether the text remains.
6. If the app provides a safe Save method, use it in an appropriate practice location or discard the test note intentionally after checking that it contains nothing important. If autosave is active, recognize that behavior.
7. Explain the difference between switching, minimizing, and closing.

:::answer Show Activity 4 explanation
Switching changes which app or window is active. Minimizing usually hides a window while leaving it available. Closing dismisses the window and may also end a document view or program, depending on the application. Text remaining visible after switching does not by itself prove it was saved to persistent storage.
:::

### Activity 5: Match the action to the desired result (about 5 minutes)

Try to answer these before expanding the explanation.

1. You want another window visible but may return to the current one soon. Which action is most suitable?
2. You want to read a document using more screen space. What window action might help?
3. You need to find Print or Save commands in a desktop application. Where might you look?
4. A page looks too long for the screen. What action lets you see another part of it?
5. A dialog asks whether to discard unsaved changes, and you are uncertain. What should you do?
6. You want to see a second webpage while keeping the first one available in the browser. What feature might help?
7. A Mac document window closes, but its app is still running. Does that necessarily indicate a problem?

:::answer Show Activity 5 answers
1. **Minimize**, switch to the other window, or place both windows where you can see them, depending on your aim.
2. **Maximize** or use an appropriate larger-window or full-screen option.
3. Look in the application's **File** menu or an equivalent clearly labeled menu or button.
4. **Scroll** or use an equivalent navigation control.
5. Read the message carefully; choose a non-destructive option such as **Cancel** when available and appropriate, and preserve your work before proceeding.
6. Open another **browser tab**, if the browser supports it; a separate browser window is also possible.
7. **No.** Many Mac applications remain running after their last window is closed; quitting is a distinct operation.
:::

### Optional activity: Mobile-device comparison (about 5 minutes)

If you use a tablet or smartphone, identify its home screen, an open app view, and its method for showing recently used apps. Compare that process with switching windows on a laptop. If you do not know how to display the app switcher, consult the device's own instructions rather than guessing gestures that might have another effect.

*Short comparison worksheet*

| Question | Desktop or laptop | Tablet or phone |
| --- | --- | --- |
| Where do you find apps? | __________ | __________ |
| How do you move to another app? | __________ | __________ |
| What is the usual input method? | __________ | __________ |
| Does switching apps automatically save changes? | Not necessarily | Not necessarily |

> **Safety during practice:** Use only your own device or one you have permission to operate. Do not close another person's work, change a shared computer's display settings, click unknown advertisements, or approve unexpected permission requests.

## 8. Common misconceptions

### “The desktop and the physical monitor are the same thing.”

No. The monitor is hardware. The desktop is the graphical workspace shown on that hardware. The same monitor can show many different applications and views.

### “Minimizing a window closes the application.”

Usually not. Minimizing typically hides the window while keeping it available. Closing and quitting are different operations, and their effects depend on the app and operating system.

### “Closing a window always saves everything I typed.”

Not necessarily. Some applications autosave, while others prompt you or may discard unsaved changes. Save or verify the saved state before closing important work.

### “A tab and a window are identical.”

No. A window can contain multiple tabs. Closing a browser tab generally dismisses one page view, while closing the browser window can dismiss all the tabs in that window. Some browsers can reopen closed tabs, but recovery is not guaranteed.

### “A window that I cannot see has been deleted.”

Not necessarily. It may be minimized, behind another window, on another virtual desktop, or inside a full-screen application. Use the taskbar, Dock, shelf, or app switcher before assuming it has disappeared.

### “Every app has the same menus and buttons.”

No. Common conventions help, but applications and operating systems may organize controls differently. Read labels and use the instructions appropriate to your device.

### “The Back button reverses any action I have taken.”

No. A browser's Back button normally navigates browsing history; it is not the same as Undo, closing a dialog, restoring a window, or retrieving unsaved text.

### “A pop-up that looks official must be safe.”

No. Notifications, prompts, and fake system warnings can resemble one another. Verify the source and avoid entering passwords or approving unexpected actions.

### “I must use a mouse to control menus and windows.”

No. Many interfaces also provide keyboard navigation, touch input, screen readers, voice controls, or other accessible methods. The available options depend on the device and software.

### “Closing all windows switches off the computer.”

No. A computer may remain powered on with no ordinary app windows visible. Shutdown is a separate process, covered in Lesson 4.

## 9. Essential vocabulary

Words with a dotted underline earlier in this lesson can be selected to open a concise definition. When a verified MGU Encyclopedia article is available, the tooltip also links to it. The definitions below serve as a quick-reference glossary.

- **Screen / display:** Physical equipment that presents visual information.
- **Monitor:** A display, often separate from a desktop computer, used to show text, images, and controls.
- **Desktop:** An on-screen workspace that can contain app windows, icons, and a background.
- **Graphical user interface (GUI):** A visual way to use software through windows, icons, menus, and other controls. [User Interface Design](/library/encyclopedia/computer-science/human-interaction-systems/user-interface-design).
- **Operating system:** Core system software that manages hardware, applications, and common user functions. [Operating Systems](/library/encyclopedia/computer-science/software-systems/operating-systems).
- **Icon:** A small symbol representing an application, item, or action.
- **Window:** A visible area in which an app or other content is presented.
- **Active window:** The window currently receiving the user's attention or appropriate input.
- **Title bar:** A region of a window often displaying a title and supporting window controls.
- **Taskbar / Dock / shelf:** System areas used to find, open, or return to applications.
- **Button:** A control that activates an action when selected.
- **Link:** A selectable reference that opens another page, view, or resource.
- **Text field:** An area where text can be entered.
- **Focus:** The interface element ready to receive keyboard input. [Human-Computer Interaction](/library/encyclopedia/computer-science/human-interaction-systems/human-computer-interaction).
- **Tab:** A selectable section or page within an application window.
- **Scrollbar:** A control or indicator used to navigate content outside the visible area.
- **Menu:** A list or group of available commands.
- **Context menu:** Commands relevant to a selected item or current position.
- **Submenu:** A secondary list of commands opened from a parent menu.
- **Drop-down list:** A control that reveals a selectable set of options.
- **Dialog box:** A temporary interface asking for information, a decision, or confirmation.
- **Notification:** A message reporting an event, request, or condition.
- **Minimize:** Hide a window from the workspace without ordinarily closing its app.
- **Maximize:** Expand a window to use more of the available screen space.
- **Restore:** Return a maximized window to a previous non-maximized size.
- **Switch windows:** Bring another open window or app view into focus.
- **Snap:** Arrange a supported window against a screen region or within a layout.
- **App switcher:** A system feature for viewing and returning to recently used or open applications.
- **Accessibility:** Features and practices that support effective interaction for diverse needs. [Human-Computer Interaction](/library/encyclopedia/computer-science/human-interaction-systems/human-computer-interaction).
