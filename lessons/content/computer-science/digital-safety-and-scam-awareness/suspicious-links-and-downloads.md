Basic Computer Skills / Digital Safety and Scam Awareness

## Lesson 4: Suspicious Links and Downloads

You receive a message that appears to come from a delivery company: “Your address is incomplete. Open this link to avoid a return fee.” Later, a search result advertises a free version of software you recognize, and a classmate sends you a document that asks you to install an additional program before you can read it. The three situations share an important decision: **before you follow a link, receive a file, or allow software to run, establish what you are opening, who provided it, and whether the action is necessary.**

A [[link|link]] can take you to a helpful website, a false sign-in page, an unexpected file, or another destination entirely. A [[download|download]] can be an ordinary picture or worksheet, a genuine application, a file that tries to persuade you to turn off protection, or [[malware|malicious software]]. The appearance of a message, a file icon, a popular search result, or a familiar brand does not settle whether an action is safe. Risk depends on the *source, destination, requested behavior, file content, device protections, and what happens afterward*.

This is Lesson 4 of MGU's nine-part **Digital Safety and Scam Awareness** course. The first three lessons introduced password safety, two-factor authentication, and phishing warning signs. This lesson narrows the focus to the practical steps between **seeing a link**, **deciding whether to open it**, **downloading a file**, and **deciding whether that file should run**. Microsoft Edge and Windows 11 provide the primary desktop examples. The same core habits apply to other browsers, macOS, ChromeOS, iPhone, iPad, and Android, although menu names and security features differ.

**Practice safety:** Every suspicious address, sender, organization, and file in the activities is fictional. No exercise requires clicking an untrusted link, opening a real attachment, downloading a questionable application, changing security settings, running a command, or uploading a personal file to an online scanning service. A learner may complete every activity using this lesson alone, on paper or in the MGU dashboard. If a device belongs to an employer or school, follow its approved security procedures rather than experimenting with protections.

**Level:** Beginner · **Estimated study time:** 115–150 minutes · **Prerequisites:** Password Safety, Two-Factor Authentication, and Phishing and Scam Warning Signs recommended · **Practice equipment:** Computer, phone, tablet, or printed worksheet; internet optional · **Safety:** Fictional, observation-first exercises; no dangerous links or downloads are required.

> **Essential idea:** **PAUSE → CHECK THE SOURCE → INSPECT THE DESTINATION → CONSIDER THE FILE OR REQUEST → VERIFY INDEPENDENTLY → ACT ONLY IF APPROPRIATE.** If an instruction is unexpected, urgent, asks you to weaken protection, or cannot be verified, stop. Not opening a questionable item is a successful security decision.

### Learning objectives

After completing this lesson, you should be able to:

1. Explain the difference among a link, a web address, a download, an attachment, an installation, and running a program.
1. Interpret a fictional web address, including its domain, subdomain, path, and misleading text, without visiting it.
1. Recognize limitations of link previews, HTTPS, search rankings, QR codes, and shortened addresses.
1. Distinguish ordinary file types from executable content and identify warning signs involving archives, scripts, double extensions, and requested security changes.
1. Find legitimate applications and updates through independently verified stores, vendors, and built-in update mechanisms.
1. Explain the purpose and limitations of browser, operating-system, and antivirus warnings without bypassing those warnings for class.
1. Match a sensible response to what actually happened: seeing a link, opening a page, downloading a file, running it, entering credentials, or losing money.
1. Complete six fictional exercises and a 30-question self-study knowledge check.

## 1. What are links, downloads, and installations?

### 1.1 A link is an instruction to go somewhere

A clickable word, button, picture, QR code, or search result may contain a [[url|URL]]: a web address that identifies a destination. The [[browser|browser]] uses that address to request a webpage or resource. A link's visible words are merely a label. The label may match the destination, summarize it, obscure it, or deliberately misrepresent it. For example, a button that says “View your account” could lead to the actual service, an unrelated advertisement, a copycat login page, or a file-download location.

Links are useful in lessons, news, email, search engines, and documents. The goal is not to reject all links. It is to be more deliberate when a link comes from an unexpected message, takes you toward a sign-in or payment, asks you to install something, or involves information you cannot afford to expose. A link from a friend is not automatically trustworthy: a friend's account may be compromised or the friend may have forwarded something without checking it.

### 1.2 Receiving, opening, downloading, and running are different actions

An ordinary [[attachment|attachment]] is a file sent alongside a message. A download saves or receives a file from another location, often into a Downloads folder or an application-managed storage area. [[installation|Installing]] adds software to a device, sometimes with background services or permissions. [[execution|Running]] starts software or instructions so that the device performs actions. These stages have different consequences.

| Stage | What usually happens | Sensible decision |
| --- | --- | --- |
| A message arrives | Its text and attachment names become visible | Evaluate the request before interacting |
| A link is previewed | Some or all of its destination may be displayed | Check the address; do not assume a preview is proof |
| A webpage opens | The browser loads content and may execute webpage code | Stop if the site is unexpected; avoid data entry or downloads |
| A file downloads | File contents arrive on the device | Do not open or run it unless the source and purpose are verified |
| A document opens | A program interprets document contents | Avoid unusual permission, macro, or software-enablement requests |
| An application runs | Program instructions operate on the device | Only use approved, verified software and respect security warnings |
| A permission is granted | The app may access selected device or account capabilities | Grant only permissions essential to a legitimate task |

**Important distinction:** A downloaded file is not necessarily installed or executed. Merely receiving a phishing message does not by itself establish a device infection. However, it is inaccurate to say that simply opening a page or a document is *always* risk-free: browser and document vulnerabilities can sometimes be exploited without a separate “Run” button. Updated software and protective controls reduce that risk.

### 1.3 Risk can travel through many familiar channels

An unexpected destination might appear in a text message, an [[email|email]], a social-media message, an online advertisement, an in-app chat, a shared document, a calendar invitation, or a printed code. A malicious file may be disguised as a school worksheet, job application, resume, delivery form, invoice, account statement, media player, browser extension, game modification, or supposed security update.

Some attacks aim to steal information through a fake webpage. Others aim to install software that accesses files or accounts. Others attempt to persuade a person to voluntarily grant [[remote-access|remote access]], run a copied command, or make a payment. Different objectives can start with the same seemingly harmless link, so consider what each page actually requests *after* it opens.

### 1.4 What source trust does—and does not—mean

A familiar website can be legitimate but host third-party advertisements or content. A reputable person can unintentionally share a bad link. A genuine cloud-storage service can host a document that attempts to deceive readers. A credible file extension is only one clue. Your task is to verify both the **route you use** and the **action you are being asked to perform**.

| Source or cue | What it may establish | What it does not establish |
| --- | --- | --- |
| Known sender name | A displayed account or label | That the actual person sent or approved the item |
| HTTPS connection | Encrypted communication with the addressed service | That the site's claims or payment requests are genuine |
| Professional logo | The page contains branding | That the brand owner controls the page |
| Search placement | A result is visible or promoted | That the software is authentic or recommended |
| Familiar file icon | A program associates an icon with a file type | That the contents are safe |
| Valid-looking app-store page | An item is available in that marketplace | That every app is appropriate, harmless, or the one you need |
| Antivirus scan without detection | No threat was identified by that tool at that time | That the file is guaranteed safe |

### 1.5 Worked example: the “missing delivery details” notice

Suppose a fictional message reads: “MetroParcel: Your package cannot be delivered. Visit `https://parcel-update.example.test/confirm` within 15 minutes and download the delivery correction form.” The use of `example.test` is deliberate: it is a classroom illustration, not a real delivery service or an address to visit.

First, the sender's claim is not independently verified. Second, the deadline may be designed to create pressure. Third, the message proposes two potentially consequential actions: visiting an unverified destination and downloading a file. Fourth, the recipient has not confirmed that any package actually needs correction. **Safer response:** Do not open the supplied address or file. Check the order or shipping status using the retailer's or carrier's independently obtained official app or site. If a genuine issue exists, resolve it using the verified process.

## 2. How do you inspect a link without trusting its appearance?

### 2.1 Recognize the parts of a web address

Consider this fictional address, shown only as text:

`https://accounts.library.example.org/member/sign-in?source=notice`

The [[scheme|scheme]] `https://` indicates that the browser attempts to establish a protected connection. The [[hostname|hostname]] is `accounts.library.example.org`. Here, `example.org` is the registered base domain and `library` and `accounts` are labels to its left. The [[path|path]] `/member/sign-in` identifies a resource under that host. The [[query-string|query string]] `?source=notice` passes extra information. The browser does not decide who owns a site based on the most familiar word visible anywhere in the address.

Different domain suffixes and ownership structures exist; reading a URL correctly can be more complicated than finding the last two words. For beginners, a critical first step is to locate the **actual hostname**, not simply search for a reassuring brand in the entire link. When any meaningful doubt remains about a login, payment, or download destination, use the organization's established address independently rather than trying to prove authenticity through guesswork.

### 2.2 Misleading subdomains and imitation names

| Fictional written address | What to notice | Better response |
| --- | --- | --- |
| `https://accounts.library.example.org/login` | Host is under `example.org`; it is an example, not proof of a real library | Verify the known service separately |
| `https://library.example.org.alert-center.test/login` | Host ends in `alert-center.test`, despite earlier library-looking words | Do not treat it as the library's website |
| `https://example.org.account-fix.test` | `example.org` appears only as part of a different host | Do not sign in from this link |
| `https://parcel-check.test/verify` | Looks plausible but no independent ownership evidence is supplied | Check the true carrier independently |
| `https://shop.example.org/receipt` | The path includes “receipt”; that is a page label, not proof of authenticity | Verify the merchant and transaction separately |
| `https://docs.example.org/download` | Could be a legitimate file location, but context and the file still matter | Confirm who shared it and why |

All addresses in this table are for paper-only analysis. Even a technically valid-looking address can be wrong for the task. A website can also change the address you see by performing a [[redirect|redirect]] to another destination; therefore, verify the address at the point of sign-in or sensitive action, not only at the beginning of a browsing session.

### 2.3 Link text may conceal its true destination

An email can display the words “Official Student Portal” while the underlying destination points to an unrelated site. An [[embedded-link|embedded link]] is simply a link placed behind readable text, an image, or a button. It is convenient for navigation but also makes the destination less obvious. Similarly, an [[url-shortener|URL shortener]] replaces a long destination with a compact address that may not reveal where it ends. Neither feature is inherently fraudulent; both make independent verification more important.

On a desktop browser, moving a pointer over a link **without clicking** may reveal its destination in a status area. On some mobile devices, a touch-and-hold action may show a preview or menu. But previews vary by device and app, can truncate long addresses, may display only an intermediate redirect, and in some apps may fetch page content. **Do not treat previewing as a universal safety test, and never preview an actual suspicious link merely to complete this class.** Use the prewritten addresses in the exercises instead.

### 2.4 QR codes, sponsored results, and redirects

A [[qr-code|QR code]] can encode a link just as a printed web address can. A sticker placed over another QR code, a QR code in a message, or a code on an unfamiliar poster may lead to an unexpected site. A camera may present a destination before opening it; check what is displayed and, for consequential tasks, obtain the service's real address through another route. Do not scan untrusted codes for practice.

A [[sponsored-result|sponsored result]] may appear prominently in a search engine because someone paid for placement. That placement does not certify ownership. When seeking software, banking access, government forms, or technical support, advertisements and lookalike search results create an opportunity to send people toward unrelated sites. Prefer an independently verified official route rather than clicking the first result by reflex.

### 2.5 Why the lock symbol is not enough

[[https|HTTPS]] generally helps protect data transmitted to the addressed server. It is valuable: avoid sending passwords or payment information over a connection that fails appropriate browser security checks. But HTTPS does **not** certify that the site operator is honest, authorized to represent a brand, or offering a safe download. A deceptive site can establish an encrypted connection too. A valid certificate does not tell you whether a request for an identification number or remote access is appropriate.

### 2.6 A repeatable destination checklist

1. **Pause:** Is this link expected and relevant to a task I chose to do?
1. **Identify:** Who supposedly sent it, and what do they want me to do?
1. **Inspect:** What destination is actually displayed? Is the real hostname clear?
1. **Assess:** Does it involve signing in, payment, installation, a copied command, or a sensitive document?
1. **Verify:** Can I reach the same legitimate function using a previously known app, saved bookmark, official manual, or independently found contact?
1. **Decide:** If verification fails, do not proceed. Report or seek assistance through a trusted channel when appropriate.

Remember that independent verification is not merely searching the suspicious sender's name and trusting the next sponsored result. Use a reliable source established apart from the questionable message, such as an app already installed from a known source, an established organization's published contact details, or an approved workplace directory.

## 3. What makes a download or attachment risky?

### 3.1 A filename can conceal more than it reveals

A [[file-extension|file extension]] is the ending of a filename that often indicates the associated file type. Many documents end in `.pdf` or `.docx`; pictures commonly use `.jpg` or `.png`; some Windows programs use `.exe` or `.msi`; and some archives use `.zip`. However, an extension is a label, **not a security certificate**, and software may interpret a file differently from its name. Attackers can exploit confusing naming, icons, archives, and operating-system display settings.

A [[double-extension|double extension]] uses more than one suffix, such as `invoice.pdf.exe`. On Windows, hiding extensions may make a name appear to be a PDF when it is actually an executable file. An ordinary document filename may include several periods without being malicious, so the important distinction is the actual recognized file type and whether the source and purpose are credible.

### 3.2 Common formats and appropriate caution

| Example file ending | Typical role | What a beginner should remember |
| --- | --- | --- |
| `.txt` | Plain text | Usually simple content; still evaluate source and misleading instructions |
| `.pdf` | Portable document | Familiar format, not a guarantee against malicious content or manipulation |
| `.docx`, `.xlsx` | Office documents | Open only when expected; distrust requests to enable risky active content |
| `.docm`, `.xlsm` | Macro-capable Office documents | May contain automation; unexpected macro instructions warrant stopping |
| `.jpg`, `.png` | Images | Usually media, but don't assume any file is safe from its name alone |
| `.zip`, `.7z` | Archives containing other files | Inspect the sender and intended contents; compressed files can hide programs |
| `.exe`, `.msi` | Windows programs or installers | Can make device changes; require trusted sourcing and appropriate authorization |
| `.bat`, `.cmd`, `.ps1` | Windows command or script files | May execute system commands; do not run instructions from an unverified source |
| `.apk` | Android application package | Installing outside approved channels can increase risk and may violate device policy |
| `.dmg`, `.pkg`, `.app` | Common macOS application distribution formats | Verify source and respect Gatekeeper and other protections |

The table does **not** label every `.exe` malicious or every `.pdf` harmless. The same file type can be legitimate or dangerous depending on where it came from, what it contains, which program handles it, and whether you expected it.

### 3.3 Archives can conceal the important content

A [[compressed-archive|compressed archive]] groups or compresses files for transfer. It is useful for sharing class materials and backups. But `CoursePhotos.zip` might contain pictures, a document, a runnable program, or a mixture. [[password-protected-archive|Password-protected archives]] can make it harder for some security services to inspect contents before the recipient extracts them. A message that provides both an unfamiliar archive and a password is not thereby trustworthy. Do not extract or launch unexpected contents to learn whether they are harmful.

### 3.4 Documents can ask you to lower safeguards

A file that looks like an ordinary report may display instructions such as “Enable Content,” “Enable Macros,” “Turn off Protected View,” or “Disable antivirus to see the invoice.” A [[macro|macro]] is an automation feature used in some document formats; it is not automatically malicious, but it can perform actions and be abused. Microsoft Office and other applications may restrict active content from untrusted sources. Respect those controls. In a classroom or workplace, request a safer document or ask authorized IT staff to verify the file rather than following unexpected activation instructions.

Some attacks no longer depend on macros. A fraudulent document may simply tell the reader to visit a website, log in, buy a gift card, or copy commands into a terminal. **Instructions written inside an unverified document do not become trustworthy because the document opens successfully.** A screenshot or visible “security check” is not a substitute for legitimate operating-system or organizational instructions.

### 3.5 Installation permissions and scripts

An [[installer|installer]] may ask to modify the system or gain administrator permissions. This can be legitimate for software you deliberately obtained from a verified source. It is suspicious when a surprise caller, website banner, pop-up, or unknown message insists that you install a program immediately. A request to permit [[remote-access|remote control]] is particularly consequential: someone else may be able to observe a screen, operate programs, or access sensitive information.

Be especially wary of “helpful” steps directing you to copy and paste unfamiliar commands into PowerShell, Terminal, Command Prompt, or a browser's developer tools. A simple-looking command can download and execute other content. **Never run unexplained commands supplied by a webpage, document, chat message, or fake support alert.** This lesson deliberately provides no such commands for experimentation.

### 3.6 Worked example: an invoice with an extra step

A fictional message from “Campus Purchasing” attaches `November-Invoice.zip`, says that the file cannot be viewed until “real-time protection” is disabled, and demands immediate payment. The archive could contain anything. The supposed sender is not independently established; the security-bypass instruction is a strong warning sign; and the payment demand raises the stakes. Even if the account sending the message belongs to a real colleague, verify the attachment and invoice through established workplace channels. Do not lower protections, extract the file, or run its contents to investigate.

## 4. How do you obtain software and files more safely?

### 4.1 Begin with a legitimate task, not an unsolicited offer

Ask what you are trying to accomplish: update your browser, install a required learning application, read a teacher's worksheet, or open an account statement. Prefer a route you can establish independently. For a browser update, use the browser's built-in update function or its verified official website. For an operating-system update, use the system's supported update mechanism. For a phone app, begin with the device's approved marketplace or the developer's verified instructions. A school or employer may require its own managed application catalog.

A [[software-update|software update]] can close vulnerabilities and improve security, but fake update notices are also common. A random webpage saying “Your browser is critically outdated—download this repair tool” is not the same as the browser's own update interface. If unsure, close the page and consult the software's supported settings or official help documentation separately.

### 4.2 Evaluate the actual publisher and permissions

A store or vendor may display a [[publisher|publisher]] or developer name, version, user reviews, download history, privacy details, and permissions. These are signals to examine, not absolute guarantees. Reviews and rankings can be manipulated, and a genuine-looking name may belong to another organization. Compare the app to the institution's own published recommendation when possible.

| Your intended task | Preferred approach | Avoid this shortcut |
| --- | --- | --- |
| Update Windows | Use Windows Update and authorized device management | Install a “critical patch” from an unsolicited pop-up |
| Update a browser | Use the browser's built-in update or verified publisher route | Run a file from an unrelated search advertisement |
| Install learning software | Follow your school's or publisher's approved instructions | Choose the first similarly named app you see |
| Get a phone application | Use the supported official store or an authorized managed source | Install an unexpected package from a text message |
| Read an invoice or worksheet | Confirm that the sender and file are expected | Run an attached installer just to view a document |
| Restore a device | Consult official support or authorized IT staff | Follow an unknown caller's remote-control instructions |
| Add an extension | Identify the genuine publisher and necessary permissions | Install a browser add-on demanded by a random page |

### 4.3 App stores are useful, not infallible

App marketplaces can apply review procedures, publisher identities, and protections, but availability does not establish that a product is the right one or completely risk-free. An app requesting broad access to contacts, messages, photos, camera, or accessibility controls deserves additional scrutiny. On managed devices, approved software may be restricted by policy. Avoid “sideloading” or bypassing policy merely because a site promises that its version is free or faster.

On macOS, [[gatekeeper|Gatekeeper]] is part of the platform's application trust controls. On Windows, built-in security features help examine applications and downloads. On Chrome and other browsers, phishing and download checks can interrupt unsafe actions. These tools are **additional protection**, not a substitute for choosing a legitimate source.

### 4.4 When a file is expected, still verify the context

A known colleague might send a monthly spreadsheet. If that exact file is expected within a routine channel, opening it through an approved, updated application may be reasonable. If it arrives unexpectedly or asks to enable macros, download a companion program, or approve new permissions, verify separately. A familiar person's account could be compromised; a known website can host user-uploaded content; and file-sharing links may point to documents authored by someone else.

For sensitive work files, do not upload confidential attachments to public scanning websites without explicit authorization. Such uploads may disclose information to third parties or conflict with institutional policy. Use organization-approved security tools and reporting channels.

### 4.5 Find your downloads and inspect ordinary files safely

On Windows 11, open **File Explorer**, locate the Downloads folder, and use **View → Show → File name extensions** when available. This makes endings such as `.pdf` and `.exe` easier to distinguish. Looking at filenames and file properties is different from running an unfamiliar program. However, **do not open an unknown file for a class exercise or override security prompts to inspect it**. If you do not know why a download is present, ask a trusted device administrator or use the installed security software's guidance.

On a phone or tablet, downloads may live in a Files app, browser download list, or app-specific location. The exact path differs; the core rule does not: identify the source, the file's expected role, and any permissions or execution request before proceeding.

### 4.6 A reusable file decision record

| Check | Question to ask | If the answer is uncertain |
| --- | --- | --- |
| Purpose | Did I actually request or expect this file? | Stop and identify the legitimate task |
| Source | Can I independently identify the sender or publisher? | Contact them by a known route |
| Destination | Did I reach this site without relying on a questionable message? | Use an established official route |
| Type | Does the file type fit what I expected? | Do not open unexpected programs or scripts |
| Instructions | Does it demand disabling security or granting unusual access? | Refuse and seek authorized advice |
| Protection | Did the browser or system issue a warning? | Respect the warning; do not force the item through |
| Organization | Am I allowed to use this file or application on this device? | Follow workplace or school policy |

## 5. What do browser and device security warnings mean?

### 5.1 Browser checks are risk signals, not absolute verdicts

Browsers may evaluate addresses and downloads against known threats, unusual file histories, reputation systems, and other signals. [[smartscreen|Microsoft Defender SmartScreen]] helps evaluate potentially dangerous websites, downloads, and applications in supported Windows and Edge contexts. [[safe-browsing|Google Safe Browsing]] provides protections against dangerous websites, downloads, and some extensions in Chrome. A warning may indicate known harmful material, suspicious characteristics, or simply insufficient reputation evidence. It may also occasionally be mistaken: a [[false-positive|false positive]] is a benign item flagged as risky.

For an ordinary learner, the appropriate response to a warning is **stop and verify through an independent trusted channel**. Do not click “Keep anyway,” “Run anyway,” or turn off the protective feature merely because an unknown website or sender instructs you to. An organization's IT or security team may have procedures for evaluating false positives; those procedures are not a reason for learners to bypass warnings on their own.

### 5.2 Understand where a warning originates

A webpage can draw a box saying, “Microsoft has found 37 viruses,” even though it has not performed an authorized scan. This may be [[scareware|scareware]]. A genuine browser or operating-system warning is produced by the browser, system, or installed security product, not just by text inside the website. Distinguishing the source can be difficult when fake pages imitate real interface elements. When uncertain, do not interact with the page's buttons or call its displayed phone number. Close the suspicious page through normal browser controls when feasible and use your device's known security application separately.

| Situation | What it may indicate | Appropriate first response |
| --- | --- | --- |
| Browser warns that a site is dangerous | Known or suspected risk associated with the destination | Do not continue; use an independent route |
| Download is blocked or flagged | Malware detection, low reputation, or other concern | Do not force the download; verify purpose and publisher |
| File triggers an operating-system caution | Unknown source, app reputation, or permission concern | Stop and check with approved support |
| Webpage claims hundreds of infections and gives a phone number | Possible scareware or fake technical support | Avoid the page's number and instructions |
| Office document says to enable active content | Document may use code or active features | Do not enable unexpectedly; verify through trusted channels |
| “Installer” demands disabling antivirus | Source wants security safeguards removed | Refuse; do not continue |
| No warning appears | No warning has been triggered | Still verify source and expected behavior |

### 5.3 Antivirus, scans, and quarantine

[[antivirus|Antivirus]] and other [[antimalware|antimalware]] systems attempt to detect or block malicious software. Regular updates and supported scans are useful, but detection is not perfect. A [[quarantine|quarantine]] action isolates an identified file so it cannot run normally. If a trusted security tool quarantines something, follow its recommended response or organizational support guidance. Do not restore or allow a flagged file simply to finish a class activity.

Security checks are only one part of a layered routine: updated software, unique passwords, two-factor authentication, reliable backups, cautious downloads, and rapid reporting help reduce the chance and impact of problems. A clean scan at one moment does not prove that a file is safe or that an account was not phished.

### 5.4 Protective tools differ by platform

Windows may expose Windows Security, Microsoft Defender Antivirus, SmartScreen, and related app controls. Chrome uses Safe Browsing, while Edge has SmartScreen protections. macOS includes Gatekeeper, built-in malware protections, and app permission controls. iPhone, iPad, Android, and ChromeOS have their own platform restrictions, store protections, and permission systems. The labels, scope, defaults, and available features may vary by device and software version.

A beginner does not need to memorize every setting. The durable behavior is to **keep protections updated and enabled, respect warnings, and use the device maker's or institution's official support channel when something is unclear**. Do not look for hidden bypass options or attempt to defeat protections for this course.

### 5.5 Worked example: an unfamiliar program is blocked

Imagine that you deliberately obtained a school-approved application, but Windows reports that the downloaded installer is not commonly downloaded. That message does not by itself prove the file is malicious. It also does not authorize running it. A suitable decision is to stop, confirm that the school or publisher actually recommends this specific version and source, and follow the approved support process. If there is no way to verify the download, do not install it.

## 6. What should you do if you already interacted?

### 6.1 First establish what actually occurred

A safe response should be proportional to the event. There is a meaningful difference between *seeing a suspicious message*, *opening a website*, *downloading a file*, *opening or running it*, *entering a password*, *granting remote access*, and *sending money*. Do not assume the worst without evidence, but do not ignore a genuine compromise. Seek timely help when account access, finances, or sensitive information are at risk.

| Event | First priorities | Additional considerations |
| --- | --- | --- |
| You only received a suspicious message | Do not engage; use provider reporting tools if appropriate | Receipt alone does not prove infection |
| You visited an unexpected page but gave no information | Stop interacting; close the page; keep security updated | Watch for unexpected downloads or permission prompts |
| A file downloaded but was not opened | Do not open, extract, or run it; use trusted security guidance | Removal or quarantine may be appropriate; avoid risky inspection |
| You opened a suspicious document | Stop interacting and avoid enabling active features | Run trusted checks; seek technical support if unusual behavior follows |
| You ran unknown software or granted remote control | Stop using suspicious software; promptly seek trusted incident help | If compromise is plausible, isolate network access when feasible and safe |
| You entered an account password or code | From a trusted device and verified site, secure the affected account | Change compromised credentials, review sessions, and verify MFA and recovery settings |
| You provided card details or sent money | Contact the actual financial provider promptly using verified contact information | Ask about available protective steps; recovery is not guaranteed |
| A school or work device was involved | Report promptly through the organization's official security channel | Follow policy and preserve relevant evidence; do not conduct independent experiments |

### 6.2 If you merely clicked a link

Opening a suspicious webpage is a reason to stop and assess, not automatic proof that every account or file is compromised. Do not enter credentials, approve authentication prompts, allow browser notifications, install suggested helpers, or follow “cleaning” instructions from the page. If a site claims infection and asks you to call a number, ignore its claims and consult the security tools you already trust. Keep the browser and operating system updated. If the page initiated a download, consider the downloaded-file row above.

### 6.3 If a file downloaded or executed

If a questionable file is only present in Downloads, do not double-click it or try to extract it. Consult the device's trusted security software or approved support. If unknown software actually ran, or an untrusted person obtained remote access, risk can be higher. Where feasible and consistent with organizational policy, **disconnect a plausibly compromised device from Wi-Fi or other networks** to limit further communication, and obtain professional or approved technical assistance. Do not blindly delete system folders, install another “repair” program from a pop-up, or restore quarantined items. A security scan is useful, but some incidents may require additional investigation or a verified system recovery process.

### 6.4 If account credentials were entered

On a **different trusted device** if the first may be compromised, open the genuine account service using a bookmark or independently verified address. Change the exposed password, ensure it is not reused elsewhere, review recent sign-ins and account sessions, and check recovery contact information. Enable or reconfigure supported [[multifactor-authentication|multifactor authentication]] as appropriate. If a one-time code was shared or an unexpected approval was accepted, notify the service's official support or security function; a password change alone may not remove every active session or unauthorized change.

### 6.5 If financial or personal information was disclosed

For payment-card exposure, suspicious transfers, or fraudulent charges, contact the legitimate bank or payment provider immediately using a trusted number or official app. Ask what dispute, card replacement, account protection, or recovery options apply. If a government identifier or other sensitive personal information was exposed, consult the appropriate identity-theft response resources. If a workplace vendor invoice or customer record was involved, follow institutional escalation requirements. **Reporting does not guarantee that funds can be recovered**, but prompt action can preserve options.

### 6.6 Preserve useful information without spreading the hazard

When reporting, note the time, the claimed sender, the channel, the requested action, the address as text if already known, and what you actually did. An authorized support team may ask for screenshots or message headers using an approved submission method. **Do not forward a malicious attachment to others, re-open the site to collect proof, paste live credentials into a support chat, or upload sensitive records to a random service.** On organizational devices, follow the incident-response team's instructions about preserving evidence and system changes.

### 6.7 A calm recovery decision process

1. **Stop the activity:** Do not continue with an unverified page, file, or caller.
1. **Classify the event:** Was there only exposure to a message, a webpage visit, a download, execution, account disclosure, or financial action?
1. **Protect the next action:** Use verified contacts and, when appropriate, a known-clean device.
1. **Contain and report:** Use installed security tools and the proper provider or organizational reporting channel.
1. **Recover deliberately:** Follow genuine support instructions for account recovery, scans, backups, payments, or identity protection.
1. **Review the cause:** Improve the process that allowed the unexpected link, file, or request to be trusted.

> **Security principle:** A safe reaction is specific to what happened. Panic, forced downloads, indiscriminate deletion, and surrendering more information to an unverified “recovery specialist” can make an incident worse.

**Logo:** No. Logos and formatting can be copied.

### Activity 5 — Interpret warning messages

Label each fictional observation as **a protective warning**, **a claim inside a webpage**, or **insufficient evidence of safety**. Then give a safe response.

1. Chrome displays its own warning that a download could be dangerous.
1. A website itself shows a full-screen image saying “Windows has found 27 viruses” and lists a telephone number.
1. A Windows dialog warns that a downloaded program is not recognized.

**5. Suspicious instruction inside a document:** The file is attempting to change your behavior or application security settings. Decline and verify through authorized channels.

### Activity 6 — Plan a proportionate response

Use the fictional case below. You are helping a relative who reports that they opened an unfamiliar website, downloaded a program, ran it, and gave the site an account password. They do not know whether they granted remote-control access. There is no reported payment, and the device is personally owned rather than school- or employer-managed.

Prepare a **six-step response plan** that does not require dangerous experimentation. Your plan should address stopping activity, network containment if appropriate, trusted help, protecting the account from a different device, checking financial or personal-data exposure, and documenting the event. State what remains unknown and what would change the urgency.

:::answer Show Activity 6 model answers
**Step 1:** Stop interacting with the questionable website and program. Do not follow any more instructions from the original sender or page.

**Step 2:** Because unknown software actually ran, treat possible compromise as credible. If feasible and safe, disconnect the device from networks while arranging trusted technical assistance. Do not assume disconnection fixes the device.

**Step 3:** Contact a legitimate support provider or trusted security professional using independently verified contact information. Use installed security tools as advised; avoid random downloadable cleaners.

**Step 4:** From another trusted device, visit the real account service independently. Replace the exposed password, review sessions and recent activity, and check multifactor authentication and recovery settings. Address any other account where that password was reused.

**Step 5:** Review whether any payment, sensitive personal information, or other accounts were exposed. If funds or payment information are implicated, contact the genuine provider promptly.

**Step 6:** Record what was downloaded and run, approximate times, observed prompts, the claimed organization, and reported account activity without reopening the suspicious material. Report through appropriate channels.

**Uncertainties:** Whether remote access was granted, whether malware is present, which privileges the program obtained, and whether account sessions were taken over remain unconfirmed. Actual remote control, continuing unauthorized sign-ins, exposed financial data, or new device symptoms increase urgency and may require specialized help. A file being run raises risk but does not by itself establish precisely which harm occurred.
:::

### Practice review and mastery standard

A satisfactory activity response should identify the decision point, explain the concern without claiming unsupported certainty, and select an independent route or appropriate reporting action. An effective learner can describe why they would stop, not merely pronounce something “suspicious.” In particular, do not confuse the observation **“a file downloaded”** with the stronger claim **“a malicious program executed.”**

## 8. Common misconceptions and avoidable mistakes

### “If a link uses HTTPS, the page must be genuine.”

HTTPS helps protect communication with the addressed service. It does not confirm that the operator is who they claim to be or that a download is safe. Inspect the actual destination and use independent verification for sensitive actions.

### “A familiar brand anywhere in the link proves ownership.”

A name inside a subdomain, path, or query string may be unrelated to the actual organization. A deceptive address can include familiar words without being controlled by the named organization.

### “Hovering over a link guarantees it is harmless.”

A preview can help identify a destination, but it can truncate addresses, omit later redirects, or operate differently across applications. Do not hover over, preview, or click actual suspect content solely to complete an exercise. There is no requirement to test a dangerous link.

### “The first search result is the safest download.”

Search rankings and advertisements are not software-authentication systems. Obtain downloads through a known official publisher, approved store, or organizational catalog.

### “A file with a PDF or image icon cannot be dangerous.”

File icons can be misleading; extensions can be hidden; and document formats, readers, or instructions can be abused. Choose sources carefully, update your applications, and avoid unexpected active-content prompts.

### “A ZIP file is safe if the sender gives me a password.”

A password may protect an archive's confidentiality but does not establish the trustworthiness of its contents. Do not extract or launch an unexpected archive just because it is encrypted.

### “Downloads infect a computer immediately and automatically every time.”

Receiving a file is not the same as installing or running it. Yet claiming that downloading or viewing is *always* harmless is also false. Software vulnerabilities and automated behavior can create other risks. Respond to what actually happened.

### “I must disable protection if the installer says so.”

A request to disable antivirus, browser warnings, or document protections is a serious reason to stop. Seek an independently verified official alternative or authorized technical advice.

### “No antivirus warning means the file is clean.”

Detection tools are not perfect. A scan may miss a threat; an earlier scan may no longer reflect a file's current status; and the real problem may be a fraudulent request rather than malicious code.

### “Every security warning proves malware, so I should delete everything.”

A warning is a risk signal, not a complete diagnosis. Deleting large groups of files, changing system settings blindly, or restoring quarantined software can cause damage. Follow verified security guidance appropriate to the event.

### “Only a computer can be harmed by suspicious downloads.”

Phones, tablets, and other connected devices also face risks from deceptive app installations, unsafe permissions, fake websites, and account theft. Platform safeguards differ, but verifying the source is still essential.

### “A successful app-store download proves the app has no risks.”

Store review processes help but are not guarantees. Verify the publisher, purpose, permissions, and organizational authorization.

### “If I clicked a link, I must have been hacked.”

A visit does not automatically establish account compromise or malware installation. Examine whether you downloaded or ran software, granted permissions, entered secrets, or observed unusual activity. Act promptly if risk is present, but do not invent exposure details.

### “If a message comes from a friend, its links and files are safe.”

Friends can make mistakes or lose control of their accounts. Confirm unexpected files or requests through a known separate communication route.

### A compact decision table

| If you see... | Avoid assuming... | Prefer this action |
| --- | --- | --- |
| A delivery or bank link | The brand name verifies the destination | Use the real service independently |
| A short URL or QR code | The compact format is safer | Verify the purpose and destination before action |
| A blocked installer | The browser must be mistaken | Stop and confirm the publisher through a trusted route |
| A document requesting macros | Enabling code is routine | Refuse and verify with the sender's authentic channel |
| A file from a familiar person | Their account cannot be compromised | Confirm unexpected material separately |
| An antivirus scan reporting no threats | Every risk is eliminated | Continue evaluating source, permissions, and purpose |
| A webpage's virus warning | Its telephone number is official support | Leave the page and consult known security tools |
| A file saved into Downloads | It has already been run | Determine whether it was only downloaded or executed |
| A suspicious app was executed | A simple password change fixes everything | Seek trusted technical help and secure accounts appropriately |
| A suspicious payment request | A small amount is harmless | Verify the merchant and request before paying |

> **Final safety principle:** The most reliable question is not “Does this look like a normal link or file?” It is “Do I know the real source, understand what action is being requested, and have a trusted reason to proceed?”

## 9. Essential vocabulary

The dotted-underlined terms in the reading can display short definitions in the MGU dashboard. The visible glossary below provides the same core meaning for learners using printed materials or a device without interactive popovers. Definitions describe security concepts, not instructions to experiment with suspicious content.

### Web addresses and navigation

- **Link:** Clickable or selectable content directing a browser or app to another resource.
- **URL:** A web address identifying a resource and its location.
- **Browser:** Software used to retrieve and display websites and web applications.
- **Scheme:** Initial portion of a URL, such as `https`, indicating the method of access.
- **Hostname:** Address portion naming a destination server or service.
- **Domain name:** A named part of an internet address, often associated with an organization or service.
- **Subdomain:** A label to the left of a larger domain name.
- **Path:** Portion of a URL identifying a location or resource under a host.
- **Query string:** Additional information passed in a URL after a question mark.
- **HTTPS:** A connection method typically using encryption to protect data in transit.
- **Redirect:** A change from one web destination to another.
- **Embedded link:** A link hidden behind visible words, pictures, or other selectable content.
- **URL shortener:** A service that turns a longer web address into a compact link.
- **QR code:** A machine-readable graphic that may encode a URL or other information.
- **Sponsored result:** Advertising placement associated with search or browsing results.
- **Link preview:** A partial display of a destination or page information before navigation.
- **Independent verification:** Checking a claim through a route not controlled by the questionable sender.

### Files, applications, and executable content

- **Download:** Receiving content from a remote resource onto a device or into an application.
- **Attachment:** A file included with or associated with a message.
- **File extension:** Ending of a filename, often indicating an associated format.
- **Double extension:** A name ending in multiple suffixes, which can mislead about file type.
- **Compressed archive:** A container used to group or compress one or more files.
- **Password-protected archive:** An archive whose contents require a password to access.
- **Executable:** A file or component that the system can run as program instructions.
- **Execution:** Starting instructions or software so a computer performs actions.
- **Installation:** Adding software or components to a device.
- **Installer:** Program or package used to place software on a device.
- **Script:** Text or code interpreted as instructions by a computer program.
- **Macro:** A document or application feature for automating actions.
- **Active content:** Document or webpage features that perform operations beyond displaying passive text.
- **Permission:** Authorization for software or a website to use a capability or access information.
- **Publisher:** Entity named as responsible for releasing a software application or package.
- **Software update:** A supported change to software that may add improvements and security fixes.
- **Sideloading:** Installing software through a method outside the device's usual approved distribution channel.
- **Browser extension:** Software that adds features or changes the behavior of a browser.
- **Remote access:** Ability to observe or operate a device from elsewhere.
- **Downloads folder:** Common local location where browsers place downloaded files.

### Threats, warnings, and protections

- **Malware:** Software designed or used to cause harm or unauthorized actions.
- **Phishing:** Deception used to induce disclosure of secrets or other harmful actions.
- **Scareware:** Fake or misleading threat warnings that pressure users into risky responses.
- **Social engineering:** Manipulation aimed at causing people to bypass normal safeguards.
- **SmartScreen:** Microsoft protection that checks certain websites, downloads, or applications for possible risk.
- **Safe Browsing:** Browser protection designed to identify unsafe sites and certain dangerous downloads.
- **Gatekeeper:** macOS application trust control used when opening downloaded apps.
- **Antivirus:** Software that detects, prevents, or removes known or suspected malicious software.
- **Antimalware:** Broader category of protective tools for identifying harmful software.
- **Quarantine:** Isolation of a file or threat so that it cannot run normally.
- **False positive:** A legitimate item incorrectly identified as threatening.
- **Security warning:** An alert issued by a protection mechanism about an action or item.
- **Protected View:** A restricted document-opening mode used by some Office applications.
- **Real-time protection:** Monitoring that attempts to detect threats as they are encountered.
- **Vulnerability:** A weakness that can sometimes be exploited to cause unintended behavior.
- **Reputation check:** Protective evaluation based on known file or website history and associated signals.

### Accounts and response

- **Email:** Electronic message that can include text, links, and attachments.
- **Account credentials:** Information used to prove identity to an online service.
- **Multifactor authentication:** Account verification using more than one category of evidence.
- **One-time code:** Short-lived value used in some verification processes.
- **Account session:** Ongoing signed-in relationship between a user and a service.
- **Account takeover:** Unauthorized access to or control of an account.
- **Containment:** Steps intended to limit an incident's spread or consequences.
- **Incident response:** Coordinated actions to identify, limit, report, and recover from a security event.
- **Identity theft:** Fraudulent use of identifying information belonging to another person.
- **Trusted device:** A device reasonably believed to be under proper control and free of known compromise.
- **Recovery channel:** Official method for regaining access or receiving help after an incident.

A learner does not need to memorize every definition before taking the knowledge check. Instead, try explaining a realistic decision: *“A file ended in `.exe`, although the message described it as a PDF. I stopped, did not override the warning, and contacted the verified sender through a separate route.”*

## 11. MGU Library connections and next steps

### Summary: a practical security workflow

You can reduce unnecessary risk by separating the **claim** that a person or page makes from the **verified action** that you have decided is appropriate. A link can be genuine while the request is inappropriate; a file can display a recognizable icon while containing executable content; and a security product can block real dangers while occasionally flagging benign programs. None of these facts demands that you become a technical investigator. They require that you know when to stop and which trusted service or person to consult.

| Before you... | Verify... | If you cannot verify... |
| --- | --- | --- |
| Follow a surprising link | The authentic destination and legitimate purpose | Use an independent known route or stop |
| Enter an account password | The true service, sign-in context, and expected request | Close the page and consult the actual account provider |
| Save a file | Its sender, purpose, type, and expected location | Decline the download |
| Open a downloaded document | That it is expected and appropriate for your task | Ask the real sender or authorized support |
| Run an installer or script | The actual publisher, permissions, and institutional authorization | Do not execute it |
| Override a security warning | Whether qualified trusted support has verified the item | Keep the warning in place |
| Respond to a suspected incident | What actually happened and which real organization can help | Seek a trusted escalation channel without further experimentation |
