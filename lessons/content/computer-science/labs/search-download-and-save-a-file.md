Beginner Practice Labs / Lab 7

## Lesson introduction

Searching for a document online is not the same as keeping a dependable copy of it. You might find the right page, open a document in a browser tab, and still be unable to locate it the next day. This lab connects three skills into one complete workflow: **find an appropriate source, intentionally download a harmless file, and verify that it was saved in an organized location**. The objective is to leave the browser with a file you can identify, reopen, and find again without repeating the search.

This is the **seventh MGU Beginner Practice Lab**. Earlier labs introduced folders, documents, spreadsheets, presentations, email attachments, and calendar events. Here, those skills converge. You will use a search engine to locate a known test document, judge whether you have reached its expected publisher, save a real file, locate it with the file manager, organize a separate practice copy, and confirm the result. The principal example uses **Windows 11**, a contemporary web browser, and a small test PDF published on the **World Wide Web Consortium (W3C)** website. Instructions for Chrome, Microsoft Edge, Firefox, Safari, Chromebook, and mobile devices are included where their steps differ.

The exercise does **not** require downloading software, installing applications, signing in to a new service, creating an online account, or giving a website personal information. The sample is a one-page document bearing the words `Dummy PDF file`; it is deliberately not a real application form or personal record. You may instead use an instructor-approved harmless file, and there is a fully described written simulation for learners who cannot download anything on their device.

> **Lab deliverable:** Locate the official W3C practice PDF at `https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf`; save a genuine local copy; place one verified copy in `Documents > MGU Beginner Practice Labs > Lab 7 Downloads`; and, if the device allows, name the organized copy `mgu-lab7-w3c-sample.pdf`. Open that saved file from its destination and confirm it displays **Dummy PDF file**. Record the source address, destination, original filename, and verification result. A paper-based simulation satisfies the planning exercise but is not evidence of an actual download.

**Level:** Beginner · **Suggested study and lab time:** 90–120 minutes · **Recommended prior work:** Beginner Practice Labs 1–6, especially folder organization · **Equipment:** An authorized computer or mobile device, a browser, accessible file storage, and an ordinary PDF viewer (often built into the browser) · **Safety:** Download only the specified sample or an instructor-approved equivalent. Do not bypass security warnings, install a new application, or use someone else's private or shared storage without permission.

### Learning objectives

After completing this lesson, you should be able to:

1. Distinguish an [[online-page|online page]], a [[search-result|search result]], an online [[document-preview|preview]], and a stored [[downloaded-file|downloaded file]].
2. Construct a focused [[search-query|search query]] and identify a source that matches the expected publisher and document.
3. Interpret a [[web-address|web address]], [[domain-name|domain name]], [[file-extension|file extension]], and visible security warning without relying on superficial appearance.
4. Use a browser's [[download-control|Download control]] or an appropriate Save command and identify where it will store the resulting file.
5. Locate a completed download using the browser's downloads list and the device's [[file-manager|file manager]].
6. Create or choose an authorized destination, copy or move the harmless file, use a recognizable name, and avoid accidental [[duplicate-file|duplicates]].
7. Reopen the stored file, confirm its content and actual location, and distinguish verification from merely seeing it online.
8. Explain why a browser warning, an unexpected software installer, or a suspicious download prompt should interrupt the procedure.
9. Demonstrate six guided tasks and document the final result accurately with the practical assessment rubric.

### Materials and preparation

- Use your own computer or an expressly authorized learning device. On a school or workplace computer, follow local download and storage policies; an instructor may require simulation rather than a live transfer.
- Choose a practice destination you can edit. A suggested example is `Documents > MGU Beginner Practice Labs > Lab 7 Downloads`. Your device may display Documents within a cloud-synchronized area; check before placing material there.
- Use the supplied sample link only when permitted: [W3C dummy PDF](https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf). It is an intentionally minimal PDF, not an executable program or a product installation package.
- Know how to open the file manager: **Windows + E** opens File Explorer on Windows; Finder is used on macOS; the Files app is used on many Chromebooks, phones, and tablets.
- Do not use actual passwords, financial statements, account documents, photographs of people, private medical files, or confidential work materials in this exercise.
- If you cannot use the internet, read the practice scenario and complete the written activity answers. State clearly that no transfer was performed.

## 1. What does downloading accomplish?

A [[download|download]] transfers data from a remote source, such as a website or online storage service, to a destination available to your device or account. In the everyday browser example, the result is a file stored in a folder on your computer. Downloading does **not** necessarily make an online page permanent, prove that its content is trustworthy, or automatically back it up. A successful transfer is only the beginning: you also need to know the filename, location, and contents.

### The three-stage workflow

For a beginner, it is helpful to divide the operation into three distinct stages. **Search** means find an appropriate resource and evaluate its publisher. **Download** means intentionally save the resource to a location you can reach. **Verify and organize** means inspect the resulting file and place it where you can find it later. Leaving out the third stage produces a common problem: a student says "I downloaded it," but the file is lost among unrelated items.

| Stage | Central question | Observable evidence |
| --- | --- | --- |
| Search | Did I find the intended source? | Expected publisher and exact resource address |
| Download | Did data actually reach storage? | Completed download entry or saved file |
| Locate | Where did the file go? | File visible in a known folder |
| Organize | Can I find it again? | Clear name and sensible project folder |
| Verify | Does it contain the expected content? | Saved file reopened independently |

A browser may display the PDF in a tab before you download it. That is a useful preview, but it is not sufficient to claim that the lab file is saved. Some browsers may automatically download the PDF; others show it in an integrated viewer first. The practical outcome matters more than the exact button label.

### Related actions that are not identical

A [[bookmark|bookmark]] stores a pointer to a page so you can return to it, usually while connected to the internet. **Download** obtains a file that can ordinarily be reopened without retrieving that same remote content again. **Save Page As** may save a webpage's HTML, and sometimes associated resources; it is not necessarily the correct method for acquiring a PDF that a website presents in its viewer. **Print** sends content to a printer or produces a print-formatted PDF, which may differ from the source file. **Screenshot** records what is visible on screen, not the original downloadable document. Each command produces a different kind of evidence.

| Action | Typical result | Does it satisfy this lab? |
| --- | --- | --- |
| Open web page | Content displayed in browser | Not by itself |
| Bookmark page | Revisit link saved in browser | No |
| Preview remote PDF | Document displayed online | Not by itself |
| Browser's Download or Save file command | Local copy of the intended file | Yes, once verified |
| Save entire webpage | Webpage file and possibly resources | Not if the required PDF is missing |
| Print webpage to PDF | New print output | Not the same as downloading the W3C original |
| Screenshot PDF | Image of what was displayed | No |

### File types and filenames

A [[file-type|file type]] describes the kind of information a file stores. Common [[filename-extension|filename extensions]] include `.pdf` for portable documents, `.txt` for plain text, `.jpg` or `.png` for images, and `.docx` for many word-processing documents. An extension is a clue, not an absolute guarantee of safe content or its real format. An unexpected `.exe`, `.msi`, `.bat`, `.cmd`, or another program-like file when you expected a PDF is a reason to stop and investigate rather than run it.

The W3C sample's expected original filename is **`dummy.pdf`**. It is intentionally short and generic because the document exists to test PDF handling. After downloading, you may create a working copy with the clearer name `mgu-lab7-w3c-sample.pdf`. Changing the name does not change its contents or convert its format. Always keep the actual extension appropriate to the file, and use your system's command to show full file extensions if necessary.

### What a successful lab looks like

Imagine opening File Explorer after completing the exercise and navigating through Documents to a folder named `MGU Beginner Practice Labs`, then `Lab 7 Downloads`. Inside is a single practice PDF named `mgu-lab7-w3c-sample.pdf`. You open that local item and see the words `Dummy PDF file`. You know which website supplied it, and you have a record of the folder where you placed it. That is a complete, repeatable result; merely locating the search-result page is not.

## 2. How do you search for a trustworthy practice file?

A [[search-engine|search engine]] helps discover relevant pages and files. It does not independently certify the correctness, safety, ownership, or quality of every result. A [[search-result|search result]] usually includes a title, link, and short description. These are clues for selection, not guarantees. Search results can include sponsored placements, outdated pages, unrelated file mirrors, and documents uploaded by people who are not the original publishers.

### Use a focused search query

Instead of searching simply for `PDF download`, enter specific words that identify the known source and purpose. For this exercise, suitable queries include `W3C dummy PDF file` or `site:w3.org dummy.pdf`. The second query uses a [[site-operator|site operator]] to focus results on a domain. Search engines may interpret operators differently, so do not assume every returned item complies perfectly; read the destination address before opening it.

| Broad query | Better query | Why the second is more precise |
| --- | --- | --- |
| `pdf` | `W3C dummy PDF file` | Specifies publisher and target |
| `sample document` | `site:w3.org dummy.pdf` | Narrows likely publisher domain |
| `computer file` | `W3C WAI dummy.pdf PDF` | Includes identifying path clues |
| `download test` | `W3C dummy pdf one page` | Adds expected document type and purpose |

A [[search-snippet|snippet]] may summarize a page, but it can omit context, contain stale wording, or emphasize the wrong part of a document. You should judge the destination, not just the snippet. If the search engine suggests an unrelated software download instead of the official document, ignore that result.

### Recognize the publisher and the address

A [[web-address|URL]] specifies a location on the web. A typical secure URL begins with `https://`, followed by the [[host-name|hostname]] and a path. In the practice address below, the expected hostname is `www.w3.org`. The letters `w3.org` identify the registered domain used by the W3C, a web standards organization. The path points to a test resource. You do not have to memorize the whole path, but you should be able to compare the host and filename to the expected values.

```text
https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf
        ^^^^^^^^^^^                                 ^^^^^^^^^
        expected host                               expected file
```

A page can contain the words "W3C" in its title while being hosted by someone else. A misleading address such as `w3.org.example.invalid` does **not** end at `w3.org`; its actual host belongs to another domain. The symbol of a lock or the presence of HTTPS indicates a protected connection to the named host, **not** proof that every file on the site is harmless or useful. A legitimate-looking search result can still lead to an unexpected destination, so verify before downloading.

### Search, then use the supplied official resource

1. Open a browser you are permitted to use.
2. Search for `W3C dummy PDF file` without adding words such as `free installer` or `codec`.
3. Inspect the results and identify an entry whose source is genuinely hosted at `www.w3.org`.
4. Compare its address with the exact sample link supplied in the introduction. You may navigate directly through that supplied link instead of trusting a different result.
5. Open the resource. If it shows a simple PDF preview with the words `Dummy PDF file`, you have located the expected practice content, but you have **not yet completed the storage step**.
6. If the destination redirects somewhere unexpected, requests credentials, asks for a software installation, or offers a different file type, stop and use the written simulation instead. Do not attempt to defeat the site's protections or your device's security controls.

### Source reliability is a decision, not a decoration

For everyday downloads, ask: **Who publishes this? Is it the official source? Is this the exact document I intended? Does the file type match? Am I authorized to keep it?** The W3C sample meets the training need because its host and file are known and it contains no personal information. In professional work, add questions about document date, relevance, version, copyright or license, and whether the resource is approved for your organization's use. An official domain is a positive signal, but it does not make critical evaluation unnecessary.

## 3. How do you prepare a safe destination?

The [[download-location|download location]] is the folder or account area into which your browser puts a downloaded file. Many Windows browsers save downloads in a personal `Downloads` folder unless the user or administrator changed the setting. The exact path can vary, including on a cloud-managed or organization-controlled computer. An important first skill is **observing where the browser actually saves** rather than assuming the location from memory.

### Create a practice workspace before beginning

On Windows 11, open **File Explorer** with **Windows + E**. Navigate to the Documents location belonging to the account you are allowed to use. Create a folder named `MGU Beginner Practice Labs` if it does not already exist, then a subfolder named `Lab 7 Downloads`. If these folders already exist, reuse them; do not create repeated versions just because the lesson is being practiced again.

The planned hierarchy is:

```text
Documents/
  MGU Beginner Practice Labs/
    Lab 7 Downloads/
      mgu-lab7-w3c-sample.pdf   (expected after organization)
```

The indentation in this illustration represents [[folder-hierarchy|parent and child folders]]. The original `dummy.pdf` may first land in Downloads, and that is acceptable. The final assessed copy should appear in the Lab 7 folder. If you do not have access to Documents, ask an instructor which practice location is permitted or complete the written alternative. Do not change device-wide settings just to satisfy the example.

### Make a reasonable folder decision

A folder named after the course and lab gives the file context. A folder named `Stuff`, `New Folder (15)`, or `Misc` provides less information. By contrast, a very long hierarchy with a separate directory for every small step creates unnecessary complexity. Aim for a location that you could explain to another authorized person in a sentence: "My verified PDF is in Documents, under MGU Beginner Practice Labs, Lab 7 Downloads."

| Candidate location | Suitable for practice? | Main consideration |
| --- | --- | --- |
| Personal Documents folder | Usually, with permission | Confirm whether it is cloud-synced |
| Personal Downloads folder | Useful temporary landing area | Easy to lose files among other downloads |
| An approved class folder | Yes, when expressly assigned | Follow ownership and retention rules |
| Employer shared drive | No, without approval | May expose or replicate test files |
| System, Program Files, or application folders | No | Do not experiment in protected locations |
| An unknown USB drive | Not until ownership is confirmed | It may be untrusted, removable, or read-only |
| Paper or text simulation | Yes for planning | Not a real downloaded file |

### Check whether your browser will ask where to save

Browsers commonly offer either an automatic download location or an **ask where to save each file** setting. Both can meet this lab's objective. The automatic method sends the file to the configured folder; the other asks you to choose a folder during the transfer. Do not assume that choosing a new browser setting retroactively moves files that were already downloaded.

For Microsoft Edge, the published support path is **Settings and more > Settings > Downloads**, where the location and ask-before-saving option may be available. For Google Chrome, choose **More > Settings > Downloads** to inspect the default destination or ask-before-saving option. Firefox has download location settings in its Preferences or Settings pages. Exact wording may change with versions and device policies. If the computer is managed and you cannot change settings, use the existing destination and organize the file afterward; you do not need to override restrictions.

### Privacy and storage boundaries

Some Windows computers redirect Documents or Desktop to a cloud service such as OneDrive. A file created there may be synchronized to other devices signed in to the same account, or visible under organizational rules. That behavior is not inherently wrong, but beginners should not assume a folder is local or private merely because it appears in File Explorer. In this exercise, the content is harmless; still, checking its location reinforces habits that matter when managing real documents later.

## 4. How do you download the sample PDF?

The central workflow is **open the W3C file, activate a download command when needed, allow the transfer to finish, and identify the saved item**. The browser's action may happen immediately when the PDF link is opened, or it may first show a PDF viewer. You should not be required to install Adobe Reader or any other program to acquire this simple test document. Many contemporary browsers include PDF viewing capability.

### Windows 11 worked example: Edge or Chrome

1. In your browser, open the official sample link: [W3C dummy PDF](https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf).
2. Observe what happens. If a browser downloads the PDF immediately, go to the downloads list. If the PDF displays in a browser viewer, use that viewer's **Download** icon or a clearly labeled option to save the source document. Do not use a third-party advertisement or a pop-up that requests software installation.
3. If a Save dialog appears, navigate to your authorized `Lab 7 Downloads` folder. If you prefer to land in the default Downloads folder first, that is also acceptable. Confirm the folder before selecting **Save**.
4. If no Save dialog appears, wait for the browser to finish its transfer to the configured location. Do not repeatedly click the link while the download is progressing, because that may create additional copies.
5. Open the browser's Downloads list from its toolbar or menu. On many Windows browsers, **Ctrl + J** opens the downloads view. If your browser has a different shortcut or layout, use the menu labeled **Downloads**.
6. Look for the expected filename `dummy.pdf` or a clearly associated variant. A numbered filename such as `dummy (1).pdf` can indicate an earlier copy already exists; it does not automatically mean the first download failed.
7. Confirm that the download status shows completion. Use **Show in folder**, **Show in File Explorer**, or the equivalent control to display the actual saved file. Avoid opening any unexpected installer, archive, or executable.
8. Once the file has been located, continue to the separate verification steps. **A completed browser entry is evidence of a transfer, not yet proof that you have examined the saved contents.**

### If the file opened instead of downloading

A PDF can appear inside Chrome, Edge, Firefox, or Safari as a [[browser-preview|browser preview]]. A preview can look identical to a saved file. The practical test is: **Can you identify the document as an ordinary file in your chosen folder and open it from there?** If not, you are still in the search or preview stage. Find the viewer's download control or use the browser's explicitly offered save-file action, then inspect the downloads list.

In Chrome, the official guidance distinguishes browser handling of PDFs and allows a setting to open PDFs in Chrome or download them instead. You need not change that global preference for one lab. Firefox similarly supports file-handling preferences. Safari commonly places downloaded items in Downloads and has a downloads button to help locate recent transfers. Interfaces evolve, so select the command by its meaning rather than memorizing the shape of an icon alone.

### If the browser asks you to open, save, or keep

The labels **Open**, **Save**, **Save As**, and **Keep** may mean different things depending on the software and whether the file was flagged. A normal Save choice records a file in a destination. Opening may display a document without putting it in your chosen folder. A **Keep anyway** or **Allow unsafe download** action after a security warning is **not** an acceptable shortcut for this lesson. If a warning appears, stop. Check the address and file type, then seek instructor or organizational guidance. A positive-looking website title is not enough reason to ignore a browser or antivirus warning.

### Why the sample is suitable

The linked resource is a tiny, one-page demonstration PDF on an established standards organization's website. It should display the phrase **Dummy PDF file**; it does not request personal data and does not contain an installation wizard. It demonstrates source selection and normal browser download handling without introducing a real-world sensitive record. Nevertheless, any online resource may become inaccessible or change: if the link fails or does something different, record that fact rather than inventing a successful download.

### Avoid replacing the source file with another format

If the browser shows a preview, using **Print > Save as PDF** may produce a new document rather than the original `dummy.pdf`. For this exercise, download the original file if possible. If an instructor substitutes another approved sample, document the substitute's actual source and filename. A correct report distinguishes the original, a copied file, and a newly generated output instead of treating all items with `.pdf` as the same file.

## 5. How do you locate and verify the result?

A file is useful only if you can retrieve it. Locating the file does not require guessing. Begin with the browser download record, move to the operating system's file manager, and confirm both its name and folder. Then open it from the file manager rather than by clicking the original website.

### Locate the download in a browser

In **Chrome**, you can open the Downloads page from the three-dot menu and select Downloads; the browser's recent-download panel also provides access. In **Edge**, use Downloads from the menu or the download control. In **Firefox**, open the Downloads panel and select the folder or Finder control for a completed file. In **Safari** on Mac, use the downloads list and a Finder-reveal control where available. Menus may move as applications update; search for **Downloads** rather than relying solely on icon placement.

| Browser | Where to start | What to confirm |
| --- | --- | --- |
| Microsoft Edge | Downloads menu or panel | Completed filename and show-in-folder action |
| Google Chrome | More menu > Downloads | Expected item and local destination |
| Mozilla Firefox | Downloads panel or Library | Completed item and show in folder or Finder |
| Safari on Mac | Downloads list | Item shown in its Finder location |
| Browser on a phone | Browser downloads view | File available in an authorized device or cloud storage location |

### Locate it directly in Windows 11 File Explorer

1. Press **Windows + E** to open File Explorer.
2. Open **Downloads** in the navigation pane if that is where your browser saves. If the folder has been customized, follow the path shown by the browser instead.
3. Sort by **Date modified** or another useful column if the folder is crowded. Sorting helps, but confirm the filename rather than assuming the newest item is the correct one.
4. Identify `dummy.pdf` or the filename reported by the browser. Do not confuse an internet shortcut or a `.url` file with the actual PDF.
5. Inspect the folder location in the address or breadcrumb bar. Record that location in your lab notes.
6. If available, turn on file extensions using **View > Show > File name extensions** in Windows 11. This reduces the risk of confusing `dummy.pdf.exe` with a real PDF.
7. Check the file's Properties or file-information panel if needed to confirm its type and that it is a normal stored item. Do not treat a filename or extension alone as a complete security inspection.

### Open the local file and compare its content

After locating the stored PDF, double-click it, press Enter when selected, or use **Open** in the context menu. A PDF viewer or browser may handle it. Confirm the words **Dummy PDF file**. If the file is blank, unreadable, a different document, or a request to install software, the verification has not passed. Do not ignore errors or call a malformed file a completed result.

A normal viewer may display a `file:` URL or a local file path instead of the W3C web address. That distinction is useful: you want to be sure you opened the item from your own storage. You do not need to disclose your personal username or full home-directory path to a teacher. It is sufficient to report a privacy-safe folder description such as `Documents > MGU Beginner Practice Labs > Lab 7 Downloads`.

### Verification questions to ask

- **Source:** Did I use the expected official W3C address or a permitted substitute?
- **Status:** Did the transfer finish without being blocked or interrupted?
- **Name:** Do I see `dummy.pdf` or the recorded variant as a file, not just a tab title?
- **Location:** Can I navigate to its folder with my file manager?
- **Format:** Is it still a PDF rather than an installer, web shortcut, or misnamed executable?
- **Content:** Does the stored file open and display `Dummy PDF file`?
- **Repeatability:** Can I close the original website and find the file again?

### Browser history is not a substitute for storage

A browser's [[download-history|download history]] may display entries for previously transferred items. Removing an entry from that list may leave the file in storage; conversely, an entry can remain even if the file has been moved or deleted. A web history entry or bookmark is not an archived copy of the document. You must look at the file manager's actual contents to know whether the document still exists where you think it does.

### When an item seems missing

Check the downloads panel for the exact file path. Then inspect the destination, including alternate storage such as a browser-specified custom folder. If the file has a numeric suffix, compare names carefully. Use File Explorer's search for the actual filename when necessary, but avoid searching the entire system if the browser already shows the destination. On managed machines, downloads may be blocked or redirected. Record a restriction and use the simulation instead of working around policy controls.

## 6. How do you organize and preserve the file?

The download may currently be in a crowded landing folder. This stage puts a clearly labeled practice copy in the course workspace, then verifies that copy. Organization should be deliberate and reversible. It should not delete unrelated items, overwrite someone's existing files, or create several confusing near-duplicates.

### Copy or move: know the difference

A [[copy|copy]] makes another stored instance and generally leaves the original in place. A [[move|move]] relocates the item so the source location no longer contains that item after a successful move. For a safe first lab, **copy the sample**, then verify the destination. This allows you to preserve the original download until you know the organized version works. If your device cannot copy in the chosen location, an authorized move is acceptable; record what you actually did.

| Command | Effect on original | Effect on destination | Appropriate use |
| --- | --- | --- | --- |
| Copy | Usually remains | New item created | Preferred in this lab |
| Move | Original location generally cleared after success | Item relocated | When authorized and understood |
| Rename | Same file, different name | No new location by itself | Add context after copying |
| Delete | Item may be removed | No organized copy created | Not required for this lab |
| Save As | App creates a saved output at chosen path | May create a separate version | Not a substitute for arbitrary file moves |

### Create the organized practice copy in Windows

1. In File Explorer, locate your completed `dummy.pdf` download. If the filename includes a suffix because you downloaded it multiple times, identify exactly which file is the verified source.
2. Select that file and use **Copy** from the context menu, toolbar, or **Ctrl + C**.
3. Navigate to `Documents > MGU Beginner Practice Labs > Lab 7 Downloads` or an approved equivalent.
4. Use **Paste** or **Ctrl + V**. Wait for the copy to finish. Never assume it succeeded just because the command was activated.
5. Locate the copied PDF in the destination. If the folder already contains a file of that name, **stop and compare** before accepting any replace or overwrite prompt. You do not need to replace an existing file to finish the exercise.
6. Rename the copied file to `mgu-lab7-w3c-sample.pdf`, preserving the `.pdf` extension. In Windows, **F2** may initiate renaming after you select a file. Choose a menu command instead if that is easier or more accessible.
7. Open the renamed copy directly from the destination and confirm **Dummy PDF file** still appears. Renaming should not change its contents.
8. Record the final folder path, filename, and successful or unsuccessful verification in your lab notes. This is the evidence used for the final assessment.

### If the first download was already saved directly to the lab folder

You do not need to copy a file just to create a second item. If `dummy.pdf` is already in the correct destination, simply rename it after you verify its identity. The learning objective is a correctly organized, valid file, not a mandatory number of copies. Instructors should give full credit for an equivalent safe route when the learner can explain how the file arrived there and demonstrate the result.

### File naming and extension safety

The name `mgu-lab7-w3c-sample.pdf` communicates the institution, exercise, source, and type. The `pdf` extension should remain visible after renaming. If Windows hides extensions and you type an additional `.pdf`, check that you have not created a redundant name such as `mgu-lab7-w3c-sample.pdf.pdf`. More importantly, do not rename an unfamiliar file with a program extension to `.pdf` and assume it becomes safe; changing a name does not change the bytes of the file.

A better naming policy has three features: **meaningful**, **consistent**, and **not misleading**. Do not include a password, account number, personal address, or other private identifier in a public-looking practice filename. Prefer short names that are understandable when the document is viewed outside its original folder.

### Minimal download log

For an instructional lab, a tiny [[download-log|download log]] provides evidence of good habits. It need not be a new app or formal spreadsheet. A notebook page or plain-text record is enough:

| Field | Example entry |
| --- | --- |
| Source organization | World Wide Web Consortium (W3C) |
| Source location | `www.w3.org` with path ending in `/dummy.pdf` |
| Source filename | `dummy.pdf` |
| Final name | `mgu-lab7-w3c-sample.pdf` |
| Final folder | `Documents > MGU Beginner Practice Labs > Lab 7 Downloads` |
| Content check | Opened local copy; displayed `Dummy PDF file` |
| Outcome | Verified, or document any error accurately |

If the sample came from an approved substitute, use its actual details. If there was a browser block, network failure, or simulation, do not record "Verified"; describe the true outcome. Accuracy is more important than making the report look complete.

### One successful copy is enough

Repeatedly downloading the same file may generate names such as `dummy (1).pdf` or `dummy (2).pdf`. Those variants can clutter Downloads and confuse students about which file is final. Avoid further transfers once the target works. You may clean up duplicate practice copies **only** when you can identify them confidently and have permission to remove them; deletion is not part of the required assignment. Do not remove the contents of an entire Downloads folder to make space.

## 7. Guided practice: find, save, and check

Complete the activities in order. Each has an observable result and an expandable model answer or verification criterion. The six mandatory activities can be completed using the authorized device. If your device does not permit downloads, use the simulated steps and record **simulation** rather than claiming the file was saved. An instructor may grade procedural reasoning separately from execution.

### Activity 1. Plan the destination and identify the target

**Goal:** Decide what you intend to obtain before operating the browser.

5. Draw or create the destination folder hierarchy under a personal or approved practice location.

**Evidence:** A target-and-destination plan showing the five required facts. The task can be completed entirely on paper.

:::answer Show Activity 1 model plan

## 8. Other devices and troubleshooting

The same decision process applies across operating systems: **evaluate the publisher, acquire the intended file, find the storage location, organize it, and independently verify it**. The exact menu labels and permissions depend on the browser, device, and account. If the software interface differs, use its download-management and file-management tools rather than guessing that every browser behaves identically.

### Google Chrome

Chrome usually stores files in a configured Downloads folder, unless the user or administrator changed it. The main menu offers a Downloads view; Chrome's settings include a downloads location and an option to ask where to save each file. Some PDFs appear in Chrome's integrated PDF viewer before being saved. To complete the lab, download the source PDF and reveal its folder. A site pop-up asking to install an extension is not the browser's ordinary download requirement.

### Microsoft Edge

Edge includes a Downloads interface and allows a default download location or a save-location prompt in Settings. A PDF can appear in its built-in reader without an immediate saved copy. Download the original source file if the viewer is showing a preview. The Windows file-management steps in Section 5 apply once the transfer finishes. On managed Windows devices, a security or organization policy may block file transfers; do not disable protections or request administrator rights just to complete an exercise.

### Mozilla Firefox

Firefox's Downloads panel and Library allow you to review saved items. For a completed file, Firefox offers a way to show it in the folder or Finder. Firefox also manages how different file types are opened or saved. Removing an entry from the downloads history is not the same as deleting the actual stored file. If Firefox warns that a download is potentially unsafe, stop rather than selecting an override action.

### Safari on a Mac

On macOS, Safari can show recent downloads through its toolbar and can reveal a downloaded item in Finder. Use **Finder > Downloads** or the folder specified in Safari settings, then move or copy the PDF to an approved practice folder in Documents. When a PDF is displayed within Safari, distinguish viewing it from saving it. Some Mac setups store Documents or Desktop in iCloud Drive; choose the location with awareness of synchronization and permissions.

### Chromebook and ChromeOS

A Chromebook commonly uses the **Files** app for local and accessible cloud-backed items. The browser's download location may be a Downloads area or another folder selected in settings. Locate the transferred PDF in Files, choose an approved destination, and open the saved copy. Files that appear through Google Drive may not be available without internet access unless specifically made available offline. An online file appearing in Drive does not automatically imply a local offline copy.

### iPhone, iPad, and Android

Mobile browsers may provide a Share or Download command and store items through **Files**, **Downloads**, **On My iPhone**, **iCloud Drive**, or the Android file manager, depending on device and app. An image saved to Photos may be managed differently from a PDF saved to Files. For this lesson, identify the actual PDF in the appropriate file-management application, place it in a folder under your control if permitted, and reopen it. Do not assume that browser history, a screenshot, or a Share sheet preview is the same as a downloaded file.

### Accessibility and alternative input

There is no requirement to use a particular pointer or keyboard shortcut. A screen reader user may navigate browser menus and the file manager by accessible labels. A learner who cannot reliably operate a drag-and-drop interface can use **Copy** and **Paste** commands or accessible menus. Enlarged text, high contrast, keyboard focus indicators, spoken instructions, and a slower pace are appropriate accommodations. Correctly locating and verifying the intended file is more important than physical speed.

### Common problems and safe responses

| Problem | Possible reason | Safe next step |
| --- | --- | --- |
| PDF opens in a tab but no file appears | Browser preview only | Use PDF viewer Download command; inspect Downloads |
| Browser shows a completed item but file is not in Downloads | Custom location or later move | Use Show in folder to reveal the actual path |
| Browser reports a network failure | Connection or server interruption | Record error; retry only when source and network are safe |
| The file's name ends in `(1)` or `(2)` | Earlier copies exist | Compare candidates; avoid creating more duplicates |
| File appears blank or corrupted | Incomplete transfer or wrong item | Stop, record issue, and recheck source and transfer |
| Download is blocked as unsafe | Browser or security tool rejected it | Do not bypass warning; use simulation and seek guidance |
| An installer or executable appears | Wrong result or malicious substitution | Do not open; report mismatch and stop |
| Save dialog says access denied | Folder permission restriction | Use an approved writable folder or simulation |
| File seems gone after browser history is cleared | History is not file storage | Inspect the actual storage location in file manager |
| Document opens only while online | Cloud-only item or browser preview | Confirm local availability and follow permitted offline settings |
| A replace-file warning appears | Destination has matching filename | Cancel and compare; never blindly overwrite |
| Saved name ends in `.pdf.pdf` | Extension was hidden during rename | Inspect full name and correct only with permission |

### Unexpected prompts and unsafe-file warnings

Do not click through a warning simply to finish an assignment. Browser and device protections are imperfect, but they are part of ordinary computer safety. If a file is unexpectedly blocked, the safe learning outcome is to recognize the warning and stop. A legitimate downloadable PDF should not demand administrative permissions, browser security deactivation, a payment card, or an unrelated installation. The next Beginner Practice Lab addresses suspicious messages more directly; the same principle applies here: **unexpected urgency and unnecessary permissions are warning signs**.

### Privacy, copyright, and records management

Public availability is not an unlimited license to redistribute every file. Different documents may have copyright, licensing, attribution, or institutional rules. Download only content you are permitted to access, do not copy protected material into shared workspaces without authorization, and do not upload someone else's files to a public site merely to demonstrate organization. A downloaded document may also contain private or sensitive information. The W3C sample avoids those concerns for this exercise; real work requires stronger discretion.

### No internet or no authorized file storage

If you cannot download the PDF, conduct the **written simulation**: use the known source and folder names, describe how you would distinguish browser preview from saved file, and produce a sample download log marked `Not executed`. Do not invent a file size, a completion timestamp, a path that your device did not actually use, or a successful content check. An instructor can assess planning and safety skills now and arrange an authorized live demonstration later.

### Quick troubleshooting decision sequence

When something goes wrong, ask three questions in order. **First**, did you reach the expected source, or has the page redirected somewhere strange? **Second**, did the browser report that the transfer finished, or was it blocked or interrupted? **Third**, is the resulting file actually in the location you are inspecting? This sequence separates search mistakes from transfer failures and storage-location problems. Repeating the same download without identifying the failed stage often adds confusion rather than solving the problem.

## 9. Essential vocabulary

The following terms are written in plain language. Some appear in the narrative as interactive dotted-underlined terms through the MGU lesson dashboard. The visible definitions remain useful when the lesson is printed or interactive popovers are unavailable.

- **Web browser:** Software for opening and navigating websites and web resources.
- **Webpage:** A page of information served on the World Wide Web.
- **Online page:** Content shown through a network connection that is not necessarily stored as a document on the device.
- **Website:** Related web pages or resources published under a common site identity.
- **Download:** Transfer of data from a remote source to a device or selected storage destination.
- **Downloaded file:** An item stored after a completed transfer from a remote source.
- **Upload:** Transfer of information from a device or local source to a remote service.
- **Remote source:** A website, server, or service from which content is retrieved.
- **Local file:** File accessible through storage attached to or available on the device.
- **Download location:** Folder or destination in which downloaded items are stored.
- **Default location:** Preselected storage folder used unless changed.
- **Save dialog:** Window or panel in which a filename or destination may be chosen.
- **Download control:** Browser or viewer command that saves a copy of the intended resource.
- **Download status:** Indicator showing whether a transfer is in progress, completed, paused, or failed.
- **Browser preview:** Display of a document inside the web browser that may not be a saved file.
- **Document preview:** Temporary or embedded view of a document before or without a confirmed save.
- **PDF viewer:** Software or browser feature for displaying Portable Document Format files.
- **PDF:** Portable Document Format, a common format for sharing fixed-layout documents.
- **Bookmark:** Saved web address intended to make a page easy to revisit.
- **Browser history:** Record of some pages visited by a browser.
- **Download history:** Browser record describing previous downloads, distinct from stored file contents.
- **Search engine:** Service that finds and ranks online content for a user query.
- **Search query:** Words or symbols entered to search for information.
- **Search result:** Entry returned by a search engine pointing to a page or resource.
- **Search snippet:** Short text excerpt or description shown with a search result.
- **Site operator:** Search modifier used to focus results on a specified site or domain.
- **Sponsored result:** Paid search placement that should not be mistaken for proof of authority.
- **Source:** Original publisher or location from which information is obtained.
- **Publisher:** Organization or individual responsible for making content available.
- **Official source:** Resource distributed by the responsible publisher or organization.
- **Web address:** A URL indicating where a web resource can be found.
- **URL:** Uniform Resource Locator, an address identifying an online resource.
- **Domain name:** Registered name used in a website address, such as w3.org.
- **Hostname:** Part of an address that names the server or service host.
- **HTTPS:** Protocol that encrypts data in transit between a browser and website, without proving the site is trustworthy.
- **Redirect:** Automatic forwarding from one web address to another.
- **Link:** Clickable text or control that opens another location or resource.
- **File:** Named item that stores information.
- **File type:** Category or format of data stored within a file.
- **File extension:** Suffix after a file name that often indicates the expected format.
- **Filename extension:** Characters after the final period commonly associated with a file format.
- **Filename:** Name by which a file is identified in a storage location.
- **Hidden extension:** File extension not currently shown by a file manager setting.
- **File manager:** Program for finding, organizing, and managing stored files and folders.
- **File Explorer:** Windows application for working with files and folders.
- **Finder:** Primary macOS application for managing files and folders.
- **Files app:** File-management application found on various phones, tablets, or Chromebooks.
- **Folder:** Storage container used to organize files and subfolders.
- **Folder hierarchy:** Arrangement of folders containing other folders at successive levels.
- **Parent folder:** Folder containing a specified file or subfolder.
- **Subfolder:** Folder within another folder.
- **Path:** Sequence of folders or location identifiers used to reach a file.
- **Breadcrumb:** Set of location labels showing where the file manager is currently browsing.
- **Destination:** Location to which a download, copy, or move is directed.
- **Copy:** Create another instance of an item while generally keeping the original.
- **Paste:** Insert previously copied or cut material into a chosen location.
- **Move:** Relocate an existing file or folder from one location to another.
- **Rename:** Change an item identifying name without inherently changing its contents.
- **Duplicate file:** Additional copy that may be redundant or confused with the intended original.
- **File conflict:** Situation in which destination and source names or paths collide.
- **Overwrite:** Replace existing stored content with a new version or file.
- **Delete:** Remove a file or record according to the system deletion process.
- **Shortcut:** Reference to another item or location, not necessarily a copy of that item.
- **Sort:** Arrange displayed items by a property such as name, size, or date.
- **Metadata:** Descriptive information about a file, such as name, type, date, or size.
- **File properties:** Details that a file manager shows about a stored item.
- **File size:** Amount of storage data associated with a file.
- **Verification:** Checking observed evidence against an expected result.
- **Evidence:** Observable facts supporting a claim that a task was performed.
- **Download log:** Short record of where a file came from, where it was saved, and how it was checked.
- **Offline:** Operating without an active connection to online services.
- **Cloud storage:** Files maintained through a remote account-based service.
- **Synchronization:** Coordinating changes among connected file locations or devices.
- **Permissions:** Rules deciding whether a user can view, create, change, or remove items.
- **Read-only:** Status allowing inspection but restricting ordinary changes.
- **Managed device:** Device whose settings or permissions are administered by an organization.
- **Malware:** Software designed to cause harm, steal information, or operate without authorization.
- **Executable file:** File capable of running program instructions under appropriate conditions.
- **Installer:** Program intended to add or configure software on a device.
- **Security warning:** Alert that an action or resource may pose a risk.
- **Browser protection:** Browser feature that warns about or blocks some risky sites and downloads.
- **Antivirus:** Security software intended to detect and respond to some forms of malicious code.
- **Phishing:** Deceptive communication meant to trick someone into revealing information or performing unsafe actions.
- **Download error:** Problem preventing a file transfer from completing as expected.
- **Retry:** Attempt an operation again after evaluating why it failed.
- **Authenticity:** Degree of confidence that content is from its claimed source.
- **License:** Permission terms governing how content may be used.
- **Copyright:** Legal rights relating to original creative works.
- **Accessibility:** Design and practices that make technology usable by people with varied needs.
- **Keyboard shortcut:** Key combination activating an action without using a pointer.
- **Screen reader:** Assistive technology that presents interface content through speech or another accessible output.
- **Practice simulation:** Written or conceptual rehearsal rather than a completed operation in software.
- **Rubric:** Criteria and point allocations used to evaluate a practical task.
- **Backup:** Separate recoverable copy retained to guard against data loss.

## 11. Completion review and further learning

The goal is a specific, demonstrated file-management outcome: you intentionally selected a known resource, downloaded its original PDF when authorized, confirmed where the browser saved it, placed an organized copy in the planned folder, and reopened that saved copy. The download does not become reliable simply because a notification appears. The strongest evidence is the independently retrieved and verified file.

### Final practical assessment

Use the rubric to evaluate observable work. The total is **100 points**. The assessor should distinguish tasks performed in software from tasks described in a written simulation. Students should not be encouraged to bypass security warnings for points.

**Suggested proficiency interpretation:** 90–100 demonstrates strong independent performance; 75–89 demonstrates a useful working skill with some support; 60–74 indicates partial understanding and a need for targeted practice; below 60 indicates that major steps remain unverified. These bands are instructional guidance, not an institutional grading policy. A simulation can show conceptual proficiency but cannot, without a real transfer, demonstrate all criteria requiring observable file operations.

### Self-check before declaring completion

1. Can I state the official publisher and source address of the sample?
2. Did I obtain the PDF without installing any unrelated application?
3. Did I see a completed transfer rather than only a browser preview?
4. Can I open the actual file manager and locate the saved PDF?
5. Does the item have the expected file type and a meaningful name?
6. Can I open the organized file and see `Dummy PDF file`?
7. Can I explain exactly where the file is stored without disclosing private directory information?
8. Did I avoid bypassing warnings, overwriting old content, or placing private data in a shared location?
9. If the exercise was restricted or simulated, did I describe that honestly?

### Practical transfer to everyday work

The same workflow supports downloading a public class handout, a job description, a user manual, a government form, or a legitimate work report. For real documents, however, add appropriate source verification, permissions, privacy, and version tracking. A government form may be sensitive; a work report may be confidential; a software installer may be dangerous if downloaded from an unauthorized site. The skills of **find, verify source, acquire, locate, organize, and reopen** stay the same even when the stakes change.

Suppose you need a copy of a public instruction sheet for an upcoming appointment. A successful approach is to start from the agency's official website, find its document, save it into a clearly named personal folder, and open the saved file to ensure it is usable. If the form changes over time, you may also note the publication or download date and return to the official site for updated versions. Downloading a copy is not proof that the document will remain current forever.
