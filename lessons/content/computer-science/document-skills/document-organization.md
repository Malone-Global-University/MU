## Lesson 9: Document Organization

Creating a document is only the beginning. A useful document must also be easy to find, identify, update, protect, and retrieve when needed. You may write an excellent letter, schedule, or application, but if it is buried among hundreds of downloads—or if you cannot tell which copy is the newest—using it becomes difficult. [[document-organization|Document organization]] is the everyday practice of keeping related files in sensible places, giving them understandable names, recognizing different versions, and checking that important work can be recovered. You do not need to become a computer technician to do this well. A few consistent habits can make your files much easier to manage.

This final lesson brings together the earlier Document Skills lessons. You will use a **fictional community-workshop notice**—the same kind of practice document used in previous lessons—to build a simple folder structure, name its editable and PDF copies, find them again, and decide which copy belongs in a finished-work folder. **You may complete all exercises with fictional files or paper diagrams; no real personal records, cloud account, purchase, or paid software is required.**

**Level:** Beginner · **Estimated study time:** 90–120 minutes · **Prerequisites:** Document Skills Lessons 1–8 recommended · **Practice equipment:** A computer with Windows File Explorer, Mac Finder, Google Drive, or another available file manager; a fictional document or empty practice files; paper and pencil (optional)

> **Essential idea:** **Make a sensible place → use a clear name → save or move carefully → verify the new location → keep the correct version → protect and back up important work → retrieve it when needed.** A file is not truly organized until you can find it again without guessing.

### Learning objectives

After completing this lesson, you should be able to:

1. Explain the difference between a [[file|file]], [[folder|folder]], [[subfolder|subfolder]], [[file-path|file path]], and [[file-extension|file extension]].
1. Distinguish [[local-storage|local storage]], [[cloud-storage|cloud storage]], and a [[synced-folder|synchronized folder]] without assuming they are interchangeable.
1. Design a small, understandable folder structure around projects or activities.
1. Use a consistent [[filename|filename]] that identifies a file's purpose, subject, and (when useful) date or [[version|version]].
1. Recognize the difference between the [[source-document|editable original]] and a finished [[pdf|PDF]] copy.
1. Create and rename folders; copy, move, or rename practice files without losing the original.
1. Search for, identify, open, and confirm the correct document rather than trusting a filename alone.
1. Distinguish saved copies, [[version-history|version history]], [[backup|backups]], and cloud synchronization.
1. Describe the safe use of [[trash|Trash/Recycle Bin]], recovery options, and responsible cleanup.
1. Choose appropriate [[permission|sharing permissions]] and avoid exposing private or confidential documents.
1. Complete an end-to-end organization exercise and explain how another authorized person could locate the final file.

## 1. What are files, folders, and locations?

A [[file|file]] is a stored item of information. A word-processing document, spreadsheet, photograph, PDF, and text note are different kinds of files. Each has a name and is stored somewhere on a computer, removable device, or online service. The content of a file might contain several pages of writing, a table of numbers, a picture, or a short list of tasks. A file does not need to be large or complicated to be worth organizing.

A [[folder|folder]] holds files and, optionally, other folders. Folders let you group items by their purpose. For example, a folder named **Workshop Materials** might contain the editable workshop notice, a PDF handout, and a separate **Pictures** folder. A folder inside another folder is a [[subfolder|subfolder]]. The arrangement is called a [[folder-structure|folder structure]].

| Term | Simple meaning | Example | Question to ask |
| --- | --- | --- | --- |
| File | One stored item | `workshop-notice.docx` | What information does this contain? |
| Folder | A container for items | `Workshop` | Which related files belong here? |
| Subfolder | A folder inside another | `Workshop/Final` | Does this extra group help me? |
| File location | Where an item is stored | `Documents/MGU-Practice` | Where will I look for it later? |
| File path | A description of the route to an item | `Documents/MGU-Practice/Workshop/Final/workshop-notice.pdf` | Can I follow the route? |
| Extension | A suffix that often signals file type | `.docx` or `.pdf` | What kind of file is this? |

### Think of a file location as a set of directions

Imagine a filing cabinet. To find a printed notice, you might open a drawer marked **Community Events**, then a folder labeled **Workshop**, then find the final notice inside. A computer's folder system serves a similar purpose, although files can also be searched by name, type, or other information. The sequence of folders is sometimes shown as a [[file-path|path]]. Different systems display paths differently; the idea remains the same.

For example, `Documents / MGU-Practice / Workshop / Final` is a readable description of a destination, **not a command to type into every application**. A Windows location may appear with backslashes and a drive letter; a Mac path may appear with slashes; a cloud service may show a clickable trail of folder names. Do not worry about memorizing every symbol. Learn to recognize **where you are now** and **which folder contains the item**.

### The most common places beginners encounter

| Place | Typical purpose | Important caution |
| --- | --- | --- |
| Desktop | Temporary visibility for items in current use | Can become cluttered; may be synced or publicly visible when screen-sharing |
| Documents | General location for personal or work documents | The exact location may be local or cloud-backed, depending on settings |
| Downloads | Files received from websites, email, or apps | A holding area, not an ideal permanent archive |
| Pictures | Photos and graphics | Keep unrelated images separate from final handouts when useful |
| USB drive | Portable storage | Can be lost, removed, or damaged; may need safe ejection |
| Cloud drive | Internet-linked file storage | Requires access permissions, correct account, and often a connection |
| Shared folder | Files accessible to other authorized people | Confirm who can view or change contents |

Some computers display familiar folders in a navigation sidebar. Their names do not guarantee where the actual bytes live. For example, a Documents folder might be backed up or synchronized with OneDrive or another provider. If you are using a school, workplace, or library computer, **ask what storage location is approved for practice**. Never assume your files will remain available after signing out of a public device.

### File formats and extensions

The final letters after a period in a filename are usually the [[file-extension|file extension]]. An editable Word file often ends in `.docx`; a LibreOffice Writer file often ends in `.odt`; a PDF often ends in `.pdf`; a basic text file may end in `.txt`. A cloud-native Google Docs file may appear in a web application without an ordinary local `.docx` file until you download or export one.

| Example filename | What it commonly represents | Typical use |
| --- | --- | --- |
| `workshop-notice.docx` | Editable Word document | Revising text and formatting |
| `workshop-notice.odt` | OpenDocument Text file | Editing in compatible word processors |
| `workshop-notice.pdf` | PDF document | Reviewing, distributing, or printing a stable copy |
| `workshop-outline.txt` | Plain-text file | Keeping a basic note without rich formatting |
| `workshop-photo.jpg` | Image file | A photograph for a handout |
| `attendance-plan.xlsx` | Spreadsheet | Managing table-like data; not a Word document |

**Do not change a file's actual type simply by renaming its extension.** Changing `notice.docx` to `notice.pdf` in a file manager does not convert the document into a PDF. Use the application's Save As, Export, or Download function when conversion is needed. Likewise, if an extension is hidden in the file manager, be careful not to remove it or accidentally add it twice while renaming a file.

### Local, online, and synchronized are not identical

[[local-storage|Local storage]] refers to information stored on the device or directly attached storage. [[cloud-storage|Cloud storage]] refers to files managed through a service on remote computers. A [[synced-folder|synced folder]] connects a location on your device to a service and attempts to keep changes aligned. Depending on account settings, some synchronized files may be represented by online-only placeholders rather than having all their content stored locally.

| Situation | What it means | What to verify |
| --- | --- | --- |
| File saved only on this computer | It may not appear on a different device | Is there an independent backup? |
| File stored in a cloud account | It may be accessible through that account | Correct account, permissions, and availability |
| File synchronized between computer and cloud | Changes may propagate between locations | Sync status and whether the latest edit reached the service |
| File downloaded from the cloud | A separate local copy may now exist | Which copy should be edited or shared? |
| File visible as an online-only item | The filename may appear before content is downloaded | Internet access may be required to open it |

A useful mental model: **a place tells you where to look; a filename tells you what to look for; the document's contents tell you whether it is the right one.** All three matter.

## 2. How do you plan a simple folder system?

The best [[folder-structure|folder structure]] is one that a beginner can understand and maintain. It should make common tasks easier, not force you to click through many levels. Start with broad categories that reflect how you work—such as **School**, **Work**, **Household**, and **Practice**—then create a subfolder when several related files would otherwise be mixed together.

### Organize by purpose rather than creating endless categories

For this lesson, use one parent folder named `MGU-Practice`. Inside it, place one folder named `Workshop-Notice`. Within the workshop folder, create three smaller groups:

```text
Documents/
  MGU-Practice/
    Workshop-Notice/
      Working/
      Final/
      Archive/
```

This is a **sample diagram**, not a requirement that every computer display the same separator characters. It is intentionally small: there is one practice area, one project, and three meaningful stages. More complex projects may need additional folders. A one-page practice task may not need all three.

| Folder | Purpose | Example contents | Avoid putting here |
| --- | --- | --- | --- |
| `MGU-Practice` | Separates exercises from personal files | Course practice projects | Sensitive real-world records |
| `Workshop-Notice` | Collects one project's material | Related source, PDF, and approved examples | Unrelated class assignments |
| `Working` | Editable material still being revised | `workshop-notice-v02.docx` | A published PDF presented as final |
| `Final` | Copies approved for the intended audience | `workshop-notice-approved.pdf` | Unreviewed rough drafts |
| `Archive` | Older copies retained for a clear reason | `workshop-notice-v01.docx` | Every accidental duplicate |

The names **Working**, **Final**, and **Archive** are examples, not software features that automatically control publication. Simply moving a file to `Final` does not make its content correct. You must still review it and decide which version is approved. In a shared project, agree on the status with the responsible person before labeling anything final.

### Other reasonable arrangements

A person completing coursework might choose `Documents / Courses / Computer Skills / Assignments`. Someone keeping household records might choose `Documents / Household / Utilities` and `Documents / Household / Repairs`. A community organization could group files by event or year. There is no universal correct arrangement; organization succeeds when it supports a predictable way to save and retrieve work.

| Organization method | Works well for | Potential limitation |
| --- | --- | --- |
| By project or event | Workshop packets, application sets, reports | May need a home for cross-project resources |
| By activity | School, employment, personal administration | Some activities overlap |
| By year or date | Reports and regularly repeated forms | Harder to find without knowing the time period |
| By document stage | Working drafts, approved outputs, archives | Must clearly define when a document changes stage |
| By file type only | A small reference collection of images or PDFs | Can separate related files from the same project |

For most beginners, **organizing related materials together by project** is a strong starting point. Avoid using only file types (one giant folder for all PDFs and another for all Word files) when that would scatter one project's materials across several places.

### Avoid making the structure too deep

Suppose a folder arrangement looks like `Documents / Classes / Year / Program / Topic / Module / Week / Assignment / Drafts / Version 3`. A person may forget the route. A simpler version such as `Documents / MGU-Practice / Workshop-Notice / Working` can be easier to remember. Add folders only when they solve a real organization problem. If a folder contains only one or two files and no recurring need, ask whether the extra level is helpful.

### A five-question planning test

Before creating folders, answer:

1. **Purpose:** What work belongs in this group?
1. **Boundary:** Which files do *not* belong here?
1. **Naming:** Would another authorized person recognize the folder's purpose?
1. **Growth:** If five new files appeared tomorrow, could I sort them naturally?
1. **Retrieval:** Could I find the completed notice without remembering when I last edited it?

If the answers are unclear, change the folder name or simplify the arrangement. You can refine it later without reorganizing the entire computer at once.

### A short and realistic naming plan

A [[filename|filename]] should identify a file without opening it. You do not need complicated codes. A useful pattern is:

`topic-purpose-version.extension`

Examples include `workshop-notice-v01.docx`, `workshop-notice-v02.docx`, and `workshop-notice-approved.pdf`. In a project where date matters, a date such as `2026-11-19` can be useful in the name. Dates in **YYYY-MM-DD** order usually sort chronologically when names otherwise follow the same pattern; the date should describe a known event such as creation, approval, or scheduled use, not an invented fact.

| Difficult name | Clearer example | Why it improves retrieval |
| --- | --- | --- |
| `Document1.docx` | `workshop-notice-v01.docx` | Gives the purpose and working version |
| `final-final2.pdf` | `workshop-notice-approved.pdf` | Avoids an unclear sequence of “final” labels |
| `stuff.docx` | `workshop-agenda.docx` | Names the subject |
| `11-19-26-notice.docx` | `2026-11-19-workshop-notice.docx` | Uses an unambiguous, sortable date |
| `myfile2.docx` | `workshop-signin-instructions.docx` | Explains content instead of a creation order |

Use a style that works on the systems you actually use. Letters, numbers, hyphens, and underscores are usually safer across services than specialized punctuation. Avoid names containing slashes, backslashes, or characters that the file system forbids. Avoid extremely long names, leading/trailing spaces, personal account details, passwords, and unnecessary personal information. Some systems treat uppercase and lowercase differently; do not rely on case alone to distinguish important files.

### The difference between naming and classifying

A descriptive filename is not the same as a folder. For example, `2026-11-19-workshop-notice-approved.pdf` gives information about one file; placing it in `Workshop-Notice / Final` gives the file a home. Use both without repeating every category unnecessarily. If you choose a standard such as `project-subject-stage`, apply it consistently for new files. Consistency matters more than inventing a perfect scheme.

> **Practical rule:** One project, one predictable home. One approved document, one clearly identified distribution copy. Keep editable work separate when appropriate, but do not delete the source merely because a PDF has been made.

## 3. How do you name and manage documents?

Moving a document into the right place involves a few ordinary actions: **create a folder, rename a file, copy it, move it, and verify the result**. You can practice these operations safely with fictional files. You should not reorganize somebody else's work, a shared organizational directory, or computer system folders without permission. The purpose of this lesson is to develop control over your own practice materials.

### Step 1: Check what you selected

Before changing a file, look at its name, location, and if possible its [[file-type|type]]. File managers may show items in list, icon, or detailed view. Selecting one file usually highlights it. If several files are highlighted, a command such as Delete or Move may affect *all* of them. Beginners should practice with **one file at a time** until selection is comfortable. If you are uncertain about a command, look for the application's contextual menu or Help feature instead of clicking rapidly.

### Step 2: Create a new folder

A folder is often created using **New Folder**, **New**, or a similar menu command. Give it a short, meaningful name, such as `MGU-Practice`. Open it and create `Workshop-Notice`, then its three subfolders. If the folder already exists, do not create another one automatically. Look for the correct existing location first.

| Environment | Open the file area | Typical way to create a folder | Important detail |
| --- | --- | --- | --- |
| Windows 11 | Open File Explorer, commonly with `Windows + E` | Navigate to the intended parent and choose **New > Folder** | Check the address or breadcrumb before creating it |
| macOS | Open Finder | In the target location use **File > New Folder** or `Shift + Command + N` | Names and locations reflect the selected Finder folder |
| Google Drive on the web | Open your Drive and navigate to the target area | Choose **New > New folder**, if permitted | Your account and access rights determine where you can create items |
| OneDrive on the web | Open the correct OneDrive account and location | Use **New** or **Add new**, then **Folder** when available | Shared or managed locations may restrict the action |
| Other file managers | Open the storage or file browsing area | Look for **New Folder**, **Create**, or an equivalent | Menu labels and available locations vary |

Application menus change over time, and managed devices may restrict some options. The table identifies common workflows, **not a guarantee that every device has the same buttons**. If you cannot create a folder in a shared location, use an approved personal practice area instead.

### Step 3: Rename files and folders carefully

[[rename|Renaming]] changes the label used to identify an item; it normally does **not** change the file's contents or convert its type. In Windows File Explorer, you can typically select a file and use **Rename** or the `F2` key. On a Mac, selecting a Finder item and pressing `Return` commonly begins renaming, and the contextual menu also offers a rename command. On Google Drive, use the file's actions menu or a supported keyboard command. Always confirm the displayed name after the change.

For a practical example, rename an editable notice to `workshop-notice-v01.docx` if it is actually a Word document. If the source is an `.odt` file, keep `.odt`. If it is a Google Docs document, use the document title in Drive and **do not fabricate a local extension**. You may use `workshop-notice-v01` as the cloud document title. Do not rename a file that is currently needed by an unfamiliar application, automated workflow, or shared process without understanding the consequences.

> **Keep the extension:** If the operating system displays `.docx`, `.odt`, or `.pdf` during renaming, change only the name portion unless you have a deliberate, valid reason to adjust the extension. Exporting or converting is performed separately.

### Step 4: Understand copy, move, and shortcut

A [[copy|copy]] creates another file with the same content at that moment. A [[move|move]] changes the file's location. A [[shortcut|shortcut or alias]] normally provides a reference to an item at another location rather than creating a full independent content copy. These actions solve different problems.

| Action | What generally happens | Best beginner use | What to verify |
| --- | --- | --- | --- |
| Rename | Item receives a different name | Correct an unclear filename | File still opens; extension is right |
| Copy | Another content copy is created | Keep a deliberate snapshot or place a copy in a separate permitted area | Original still exists and destination copy opens |
| Move | Item is placed in a different folder | Put a draft in its project folder | Appears in destination and no longer occupies old location |
| Create shortcut / alias | A reference to the original is created | Reach one file from another convenient place | Target still exists and permission is available |
| Delete | An item is removed from its usual location | Remove a verified, unnecessary practice duplicate | Item is truly unneeded; recovery rules are understood |

The exact results of **moving or copying across cloud services, storage devices, or shared folders can be more complex**. Permissions may change, links may stop working, or files may need time to transfer. For this introductory lesson, practice moving only within one approved practice area; do not assume that moving an item between organizations preserves access settings.

### Step 5: Use Cut, Copy, and Paste with care

On many desktop systems, a common approach is to select a file, choose **Copy** (`Ctrl + C` in Windows or `Command + C` on Mac), navigate to the destination, and choose **Paste** (`Ctrl + V` or `Command + V`). Windows also supports **Cut** (`Ctrl + X`) followed by Paste to move a file. On macOS Finder, moving a copied file can involve **Option + Command + V** after copying; moving by dragging is also possible. In cloud services, the menus and support for keyboard commands vary.

These are **file-manager commands**. They are related to, but different from, cutting and pasting text inside a document. A move on some systems can be implemented as a copy followed by deletion of the source after transfer. If the operation stops halfway, verify both locations before retrying. With unfamiliar software, a menu action may be safer than memorizing shortcuts.

### Step 6: Verify after every meaningful change

A dependable organization process ends by checking its results:

1. Navigate to the destination folder.
1. Confirm the expected file appears with the correct extension or type.
1. Open it and check a recognizable detail from its content.
1. If you intended a move, check that the original location no longer shows that file.
1. If you intended a copy, verify that the source file remains.
1. If an application remains open, check whether it now points to the moved or renamed file; some apps show a new location only after reopening.

**Do not delete the original immediately after copying**, especially when transferring between services or devices. First confirm the new copy opens and contains the complete document. For an important document, confirm that a separate backup exists before permanently removing older copies.

### A demonstration: three versions of the workshop notice

Imagine that you finished the fictional notice, proofread it, and saved it as a PDF in earlier lessons. Now you want to organize it. You might use this arrangement:

| Location | Example item | What it means |
| --- | --- | --- |
| `Workshop-Notice/Working` | `workshop-notice-v02.docx` | Editable file for revisions |
| `Workshop-Notice/Final` | `workshop-notice-approved.pdf` | Reviewed PDF for distribution |
| `Workshop-Notice/Archive` | `workshop-notice-v01.docx` | Older, intentionally retained working copy |

If you use `.odt`, Pages, or Google Docs instead of Word, substitute the real editable file type or cloud document title. **Never manufacture a file by changing its suffix.** The example describes a workflow, not a requirement to create a particular proprietary format.

## 4. How do you find the right document?

Organizing matters because you will eventually need to retrieve a file. You may remember its title but not its folder, or remember the folder but not the exact name. A [[search|search]] function can help, but searching well includes checking the [[search-scope|search scope]] and verifying the result. A filename that looks right is only a clue.

### Begin with the most likely location

For a workshop notice you created recently, start with `Documents / MGU-Practice / Workshop-Notice`. If you used Save As, inspect the folder you selected in the Save dialog. If you downloaded a PDF from Google Docs or another web service, check **Downloads**. If you cannot find it there, check the browser's recent downloads list, remembering that a download can be renamed or saved elsewhere. For a cloud-native document, search **inside the account where the document was created**, not only the local Documents folder.

### Search by part of the name

If you cannot recall a full filename, start with a distinctive word such as `workshop`, `notice`, or `agenda`. Avoid overly broad terms such as `file` or `document`. A search for `workshop` may return the working source, the PDF, and older copies; that is useful if you then distinguish them by location and content.

| You remember | Search or browse strategy | Next verification |
| --- | --- | --- |
| Exact name | Search the full filename or browse the known project folder | Open it to confirm contents |
| Part of a title | Search a distinctive word such as `workshop` | Inspect folder and file type |
| Only the general subject | Browse the subject or project folder first | Read or preview likely results |
| It was recently downloaded | Check Downloads and recent downloads | Verify source and filename |
| It was created online | Search the correct cloud account or shared drive | Confirm ownership and edit rights |
| It was recently edited | Use recently opened items or sort by modification date | Do not mistake another person's edit for yours |
| It is a PDF | Search filenames, type filters, or a known final-work folder | Check pages and content, not just `.pdf` |

### Search from a file manager

In **Windows File Explorer**, navigate to a sensible starting folder or drive, then use the search area. Windows also offers searches through the taskbar or other operating-system tools. A search started inside a particular folder may search that area and its contents; the precise behavior depends on the interface and indexing configuration. File Explorer may be able to find local files, cloud-backed entries, and other indexed items, but **not every online-only file is guaranteed to appear in a local search**.

On **macOS**, Finder offers searching by names and other criteria, and the system may offer Spotlight search. Pay attention to whether the search covers the current folder or a wider location. In **Google Drive**, use the Drive search field and available filters, then inspect the item's location, owner, and type if shown. Some searches show files shared with you as well as those you own. In **OneDrive**, use the search function for the correct account; if an item is missing, check whether it belongs to a different personal, school, or work account.

### Check the correct account and storage area

A common source of confusion is having more than one account. A person may use one cloud account for school and another for personal files. A document does not automatically appear in every account because the same device is signed in to multiple services. Before assuming a file was deleted, confirm:

1. Which application originally created the document?
1. Was it saved to a local folder or a cloud account?
1. If cloud-based, which account was selected at the time?
1. If shared, is the item still accessible through the shared location?
1. Did you download a separate copy onto this computer?

Do not enter someone else's account or bypass permissions to look for a missing file. Ask the owner or administrator for appropriate access if needed.

### Use file details as evidence

A [[file-details|details view]] or information panel may display filename, type, size, location, created date, and [[modified-date|last modified date]]. These can help distinguish two similar files, but they are not perfect proof of which copy is approved. Copying, transferring, synchronizing, or editing can change some dates. For important work, use a combination of the file's content, the agreed project location, and a clear approval label or record.

| Result | Filename | Location | What you should infer |
| --- | --- | --- | --- |
| A | `workshop-notice-v01.docx` | `Archive` | Older retained working copy |
| B | `workshop-notice-v02.docx` | `Working` | Current editable source in this example |
| C | `workshop-notice-approved.pdf` | `Final` | Intended distribution copy, pending content check |
| D | `workshop-notice (1).pdf` | `Downloads` | A downloaded duplicate whose approval status is unclear |

**Which is the correct copy to send?** Result C is the best candidate *because* it sits in Final and has a clear name, but you must still open it and verify its content. Do not assume that result D is more current because it has a number in parentheses. Browsers sometimes add `(1)` automatically when a filename is already taken. It does not certify a newer or better version.

### Confirm using the workshop details

The practice notice from earlier lessons describes a **fictional** Tuesday workshop scheduled for **10:00–11:30 a.m., Room 204**. Use these known details as a retrieval check. If a supposed final copy lists the wrong room or an old time, stop before sharing it. Return to the correct editable source, make the authorized correction, save it, and create a new verified distribution copy. **Never rename an incorrect file “approved” just to make it appear final.**

### Retrieval as an everyday skill

A useful test is to close the document and return to a neutral location such as the file manager's Home screen. Without relying on the Recent Files list, navigate to the project folder and reopen the intended file. If you can do so twice, you have practiced true retrieval rather than relying on the application remembering your last file. For a class or workplace, record the folder route in plain language rather than sending an absolute private device path that others cannot use.

## 5. How do you manage versions and recover work?

Documents change. You may correct a time, revise a paragraph, insert a table, or receive approval from an instructor. [[version|Version control]] helps you distinguish the file you are editing from a previous copy and a distribution-ready copy. Beginners do not need a complicated software system. A clear naming pattern, deliberate snapshots when needed, and knowledge of recovery options provide a sound foundation.

### Understand “Save,” “Save As,” and saved versions

**Save** normally updates the current document or saves changes according to the application's model. **Save As**, **Make a Copy**, or equivalent commands create or save a separately named file, depending on the app. [[autosave|Autosave]] may record ongoing changes automatically, but its presence does not establish that an independent older copy exists. In a cloud document, there may be [[version-history|version history]] for earlier changes, but how far back it goes and who can restore versions depend on the service, account, and policies.

| Method | What it helps with | What it does not guarantee |
| --- | --- | --- |
| Save | Preserving current edits | An independent backup or older version |
| Save As / Make a Copy | Creating a separately named source or snapshot | That the new file is approved or backed up |
| Autosave | Saving ongoing work within the app's model | Protection against every accidental change or deletion |
| Version history | Inspecting or restoring earlier saved states when available | Permanent retention across all accounts and file types |
| Archive copy | Keeping an intentionally retained earlier file | Protection if archived on the same failing device only |
| Backup | Recovering data from another protected copy or location | Instant or automatic restoration without testing |

In Word, features vary between locally stored files and files saved through OneDrive or SharePoint. Google Docs commonly provides a revision-history model for cloud documents, while downloaded exports are separate files. Other editors and cloud platforms may offer different behavior. **Do not assume an old version can be recovered until you have checked that your particular application and account support it.**

### Use a practical version sequence

For a short lesson exercise, you may choose:

| Stage | Example filename | Location | Intended use |
| --- | --- | --- | --- |
| First draft | `workshop-notice-v01.docx` | Working, later Archive | Original classroom exercise |
| Revised source | `workshop-notice-v02.docx` | Working | Active editable version |
| Approved distribution | `workshop-notice-approved.pdf` | Final | Reviewed sharing or printing copy |
| Later corrected PDF | `workshop-notice-approved-v02.pdf` | Final | Approved replacement if a revision is formally issued |

For a simple personal note, you may never need four files. Avoid making a new file for every small keystroke. Create a separate version at **meaningful milestones**: before a substantial rewrite, after formal review, or when a delivered copy must be preserved. If the project requires an approval trail, follow the organization's own policy rather than inventing labels such as “authorized” or “official.”

### Distinguish “current,” “approved,” and “archived”

A draft can be the most recently edited file but still not be ready for distribution. An approved PDF can be older in modification time than an accidentally edited working draft and still be the correct version to give to readers. A file in Archive is retained for reference, not presented as the current publication. These status concepts are decided by workflow and responsibility, not automatically by file dates.

### What if you accidentally delete a file?

Many desktop systems initially move ordinary deleted files into the [[recycle-bin|Recycle Bin]] (Windows) or [[trash|Trash]] (macOS), where recovery may be possible. Cloud services often have a Trash or Recycle Bin area, but retention periods and permissions vary. Some deletions bypass these areas or become permanent. Shared files may also be removed from your view when access is revoked, without necessarily having been deleted by the owner.

A safe recovery sequence is:

1. **Stop making unnecessary changes** in the affected folder.
1. Search the original folder and likely alternate locations to make sure the file was not merely moved or renamed.
1. Check the appropriate Trash or Recycle Bin in the correct account or device.
1. If available, locate the exact item and choose **Restore** or the supported recovery action.
1. Inspect the restored item's location and content.
1. If it is not there, check an approved backup or ask the authorized account owner or administrator.

Do not empty Trash, overwrite a possible backup, install random “recovery” software, or attempt advanced disk repairs as a beginner. These operations can increase risk or require privileges you do not have. If the file contains important legal, medical, educational, or business information, seek responsible assistance early rather than experimenting.

### Cleaning up duplicates thoughtfully

[[duplicate-file|Duplicate files]] can arise from downloads, copying, sharing, or Save As. The presence of several similarly named files does not itself mean one is unnecessary. One might be the editable source, another a required PDF, and another a valid backup. Before removing any item, determine its purpose and whether another verified copy exists.

| Symptom | Possible explanation | Safe first response |
| --- | --- | --- |
| `notice.pdf` and `notice (1).pdf` | Browser downloaded a name twice | Open both and compare content before deciding |
| Two folders both named `Workshop` | A folder was created in the wrong parent location | Check their paths and contents |
| Same name appears in Documents and OneDrive | Folders may be synchronized or separately copied | Check sync setup; do not assume two independent backups |
| A shared file disappeared | It was moved, deleted, or access changed | Check correct account and permissions |
| An older draft has a newer date | File was copied or modified later | Compare document content and purpose |

**Cleanup is not a race.** Organizing a small set of files accurately is more valuable than quickly deleting hundreds of items. Never bulk-delete a shared directory or remove files because an automated suggestion calls them duplicates, especially when permissions or retention requirements matter.

### What is an archive?

An [[archive|archive]] is a deliberate place or process for retaining material no longer in active use. In this lesson, `Archive` is simply a folder. Some organizations have specific rules for retention, deletion, records management, and secure disposal. A classroom Archive folder does not satisfy legal recordkeeping requirements on its own. Keep information only as appropriate for its purpose, access restrictions, and applicable rules. Periodically review the folder instead of treating it as a permanent dumping ground.

## 6. How do you keep documents safe and organized?

A file system should remain useful after more files are added, a device is replaced, or an account changes. That requires more than tidy names. You also need safe storage practices, [[backup|backup]] planning, sensible sharing settings, privacy awareness, and a maintenance routine.

### Backup versus synchronization

A [[backup|backup]] is a separate copy of information kept so that it can be recovered if the primary copy is lost, damaged, or changed. [[sync|Synchronization]] attempts to keep files or changes aligned across devices or services. Sync can be convenient, but **a mistaken deletion or overwrite may propagate to synchronized copies**. Some services include restore and version-history features; those features are useful but should not be treated as identical to a separately managed backup.

| Protection method | Main benefit | Important limitation |
| --- | --- | --- |
| Save to the current device | Keeps current work available locally | Device loss or failure may destroy the only copy |
| Sync to a cloud service | Makes files available through a connected account | Mistakes and deletions can propagate |
| Cloud version history | May allow recovery from earlier changes | Retention, permissions, and coverage vary |
| External backup drive | Keeps a separate copy on another device | Can fail, be stolen, or be outdated |
| Managed organizational backup | Provides centrally governed recovery | Depends on the organization's configuration and recovery procedures |

For documents that matter, keep more than one usable copy in suitably separate places. A commonly taught approach is the **3-2-1 principle**: three copies of important data, on at least two types of storage, with one copy in a separate location. This is a planning idea, not a requirement to buy equipment for the lesson. A reliable backup also needs periodic checking that files can actually be restored. Never use an unapproved personal drive or personal cloud account for confidential workplace data.

### Ask whether it is truly backed up

If you say, “My workshop notice is in Documents and therefore safe,” ask what would happen if the device stopped working. If the folder is synchronized, ask what would happen if you accidentally deleted the document. If you copied it to a USB drive, ask when the last copy was made and whether the drive still works. A file's backup status must be based on actual arrangements, not assumptions about a folder's name.

### Sharing is a separate decision

[[sharing|Sharing]] makes a file accessible to someone else. You may attach a file to a message, place it in an approved shared folder, or generate a cloud sharing link. These methods can provide different degrees of access. Cloud services may offer [[view-permission|viewer]], [[comment-permission|commenter]], or [[edit-permission|editor]] roles, but exact options vary.

| Permission or method | What the other person may typically do | When it may be appropriate |
| --- | --- | --- |
| View-only link or viewer role | Read or download if permitted | Sharing a finished notice for review |
| Commenter role | Leave feedback without directly editing the main text | Requesting suggestions on a draft |
| Editor role | Modify or reorganize content under the service's rules | Authorized collaboration on the editable source |
| File attachment | Receive a separate copy at send time | Distributing a specific reviewed PDF |
| Public link | Access may extend beyond named recipients | Only when content is deliberately approved for public release |

**Least privilege** means giving people only the access they need. If someone only needs to read the approved workshop notice, editor access is usually unnecessary. If a file contains names, contact details, financial information, or other sensitive material, check the recipient list and sharing settings carefully. A PDF is not automatically confidential, encrypted, or protected merely because it is harder to edit than a Word document.

### A safe sharing checklist

Before providing a document or link, verify the intended audience and use this sequence:

1. Open the exact file you intend to share.
1. Confirm the title, version, contents, and any private information.
1. Check whether it contains tracked changes, comments, hidden notes, or document metadata that should not be distributed.
1. Prefer a reviewed PDF for fixed distribution when that suits the task; retain the editable source appropriately.
1. Choose named recipients and the minimum necessary permission when available.
1. Confirm whether the link is restricted or available broadly.
1. Make sure the file is actually approved to share and that you are using the correct account.
1. After sharing, verify access with an authorized recipient if appropriate; revise or revoke access if a problem is discovered.

Do not practice by distributing actual personal records, and do not upload employer, school, or client files to unapproved services. **A shared folder can reveal more than the single file you intended to send**, so examine the scope of any folder-level link.

### Device and account safety

When working on a shared or public computer, use an approved location and follow sign-in and sign-out rules. Do not leave documents with sensitive information in Downloads, Recent Files, a printer tray, or a public shared folder. Do not assume that simply closing a browser window signs you out. Do not email files to yourself through an unapproved personal account to work around restrictions. If a message claims you must open a suspicious attachment or grant access immediately to “recover” a document, verify the request through a trusted channel instead of trusting the link.

### Keeping document names accessible

[[accessibility|Accessibility]] also matters in file organization. Prefer meaningful words over unexplained codes, and keep folder structures shallow enough for a keyboard user or screen reader user to navigate. Differentiate files by names rather than color alone. If you use tags or color labels, treat them as optional additional information rather than the only way to recognize an important file. Make file titles understandable when read aloud. Avoid confusing names such as `finalfinalREALnew3`.

### A five-minute recurring routine

At the end of a document session, follow a manageable routine:

1. **Save:** Confirm the working document is saved in its intended location.
1. **Name:** Make sure the filename describes the content and status.
1. **Sort:** Move finished outputs to the appropriate folder.
1. **Check:** Reopen the distribution copy and check key details.
1. **Protect:** Verify that important work is covered by an appropriate backup and sharing controls.

For regular work, revisit Downloads occasionally; move only the materials you intend to keep and delete unneeded items only after review. For a long-term project, review versions and archives at sensible intervals. Resist reorganizing an entire device when five minutes of consistent handling will prevent most new clutter.

> **Completion standard:** You have learned document organization when you can tell **where the file belongs, what its name means, which copy is approved, how to find it again, and what protection it has**. Organizing documents is an ongoing habit, not a one-time cleanup.

## 8. Common mistakes and troubleshooting

### “My document is saved because I can still see it on the screen.”

Not necessarily. An open document might have unsaved changes, or the application might be showing a temporary or autosaved state. Check the application's save status and file location, and reopen the file when possible. Some apps save automatically, but that does not eliminate the need to know where the document is stored.

### “Everything in Documents is automatically backed up.”

The folder name alone tells you nothing conclusive about the backup arrangement. Documents may be stored locally, redirected into a synchronized service, or covered by a separate backup process. Verify the actual setup. Synchronization may propagate deletions, so it is not a substitute for a well-tested recovery plan.

### “I should keep all my documents in Downloads.”

Downloads is often a temporary landing place for files obtained from the internet or other applications. It can become difficult to navigate when many unrelated items accumulate. Review downloads and move the documents you intend to keep into their appropriate project folders; avoid indiscriminate cleanup.

### “An organized computer needs dozens of folders.”

Too many layers can make files harder to find. Use a simple structure that reflects active projects and add a subfolder only when it has a clear purpose. A project with one file may need only one folder.

### “Renaming a DOCX to PDF will convert it.”

No. Changing the extension changes its label, not the internal document format. Use Export, Download, or Save As in a capable application to create a real PDF. If a file no longer opens after renaming, restore the original extension if you know it, or seek help rather than trying random suffixes.

### “The file named `final-final-NEW.pdf` must be the newest approved copy.”

A filename can be inaccurate or informal. Look at the agreed location, documented workflow, and actual content. If approval matters, obtain confirmation from the responsible person. “Final” should describe a verified status, not an optimistic guess.

### “The most recently modified file is always the correct one.”

A recently changed draft may not be approved. Copies and transfers can also alter dates. Use the purpose and contents of the file together with the intended workflow. Do not use timestamps alone as proof of approval.

### “Copy and move are the same.”

Copy ordinarily creates another file; move changes location. After either operation, inspect the destination. After a move, check the original folder; after a copy, confirm the source still exists. Across devices and cloud services, wait for transfers and permissions to be resolved before cleanup.

### “If I see a file twice, I have a backup.”

Not necessarily. Two views may reference one synchronized file or one shortcut, rather than two independent recoverable copies. A useful backup should be separately protected, current enough for its purpose, and recoverable. Ask how it would behave if the primary file were accidentally deleted.

### “I cannot find the file, so it has been deleted.”

It may be in a different folder, account, drive, or app; it may have been renamed, moved, or downloaded to another location. Search a distinctive name, inspect the save/download history, check the correct cloud account, and look in authorized shared locations before considering deletion recovery.

### “Emptying the Recycle Bin is the first step in cleaning up.”

Emptying it can make recovery substantially harder or impossible through normal controls. Review the items, understand their importance, and follow any organizational retention requirements before permanently deleting them.

### “I can share the whole project folder when someone needs one PDF.”

A folder-level link may expose drafts, archives, comments, or other materials. Prefer sharing the specific reviewed file with the minimum appropriate access. Check the recipient and link scope before sending anything.

### “A read-only PDF contains no personal information.”

A PDF can include names, contact details, comments, metadata, embedded links, or other sensitive content. Review the actual file. Read-only presentation is not the same as confidentiality or encryption.

### “A file on an external drive is safe forever.”

External drives can be lost, damaged, infected, or outdated. One external copy may form part of a backup plan, but it is not a guarantee of indefinite preservation. Use appropriate storage practices and periodically verify recovery.

### “If I use Google Docs, I can always find a DOCX file in Documents.”

A Google Docs document can exist natively in a cloud account without a conventional local Word document. You may need to access Drive with the correct account or download/export a copy. The downloaded file and the cloud document can then change independently.

### “I should rename and reorganize a shared team's folders to match my own system.”

Shared files may be governed by team conventions, permissions, retention requirements, links, or automated workflows. Coordinate changes with the responsible owner. Practice only in areas explicitly set aside for your work.

### Troubleshooting decision guide

| Problem | Possible reason | First safe action | What not to assume |
| --- | --- | --- | --- |
| Can't see the saved file | Wrong folder or account | Revisit Save As location and search by title | The file is permanently gone |
| Search returns too many items | Search word is too general | Use a distinctive term and narrow the location | The first result is correct |
| A renamed file won't open | Extension altered or type mismatch | Check original type and restore known correct name | Changing extension converts formats |
| File exists in two folders | Copy, sync, shortcut, or duplicate download | Compare paths, contents, and file roles | Both are independent backups |
| Cloud file looks unavailable | Offline state, account mismatch, or permission issue | Check connection and correct account | The file has been deleted |
| A shared folder cannot be edited | Permissions restricted | Ask the authorized owner or use a permitted area | You should bypass restrictions |
| Old draft appears newer than final PDF | Editing or copying affected dates | Inspect content and approval status | Latest timestamp means approved |
| Move appears incomplete | Transfer or synchronization still processing | Wait for supported status and verify locations | Source can safely be deleted |
| File accidentally deleted | Recycle Bin or Trash may retain it | Check authorized recovery area | Recovery is guaranteed |
| Backup cannot be opened | Copy may be damaged or incomplete | Use an approved alternate copy or administrator help | A copied filename means success |
| PDF is in Final but contains wrong details | Premature approval label | Correct source, export and verify again | Folder placement makes it valid |
| Shared link reveals too much | Link scope or permission too broad | Restrict or revoke through authorized controls | A link is private by default |

**Troubleshooting principle:** Read the exact message, verify the current location and account, and make one reversible change at a time. Avoid experimenting with important files or making rapid multiple moves. If the system is managed by an institution, follow its support and records procedures.

## 9. Essential vocabulary

The following vocabulary brings together the lesson's main ideas. Words underlined earlier in the lesson may be selected to show the short, in-dashboard definition. A term does not require an external website to be useful: understanding it in ordinary language is the priority.

### Files, folders, and locations

- **Document organization:** A consistent way to name, group, locate, update, and protect documents.
- **File:** A single stored item such as a letter, PDF, image, or spreadsheet.
- **Folder:** A container used to group files and other folders.
- **Subfolder:** A folder located inside another folder.
- **Folder structure:** The arrangement of folders and subfolders.
- **File path:** Directions describing the location of a file through a folder hierarchy.
- **File location:** The storage place or folder where a file exists.
- **Filename:** The name used to identify a stored item.
- **File extension:** The suffix after the final period in many filenames, such as `.docx` or `.pdf`.
- **File type:** A description of the format or kind of information a file contains.
- **Editable source:** A document in its editable form, retained so changes can be made.
- **PDF:** A widely used page-oriented document format for viewing, sharing, and printing.
- **Local storage:** Storage on a computer or another directly attached device.
- **Cloud storage:** Files stored and accessed through a service on remote computers.
- **Synchronized folder:** A folder whose contents are coordinated between a device and a service.
- **Drive:** A storage device or an interface representing a storage location.
- **Downloads folder:** A typical location for material saved from websites or applications.
- **Desktop:** The operating system's visible workspace, which can also display file and folder shortcuts.
- **Parent folder:** The folder that contains a given file or subfolder.
- **Breadcrumb:** A navigation trail showing the current location and its containing folders.

### File-management actions

- **File manager:** An application for browsing and managing files, such as Windows File Explorer or Mac Finder.
- **Rename:** Change a file's or folder's name without converting the underlying format.
- **Copy:** Create another file holding the same content at the time of copying.
- **Move:** Change an item's storage location.
- **Cut and paste:** A common sequence for relocating an item in a supported file manager.
- **Shortcut:** A reference that helps open an item located elsewhere; not necessarily an independent copy.
- **Alias:** A Mac-style reference that points to another item.
- **Search:** Look for matching files or folders using a name or other criteria.
- **Search scope:** The set of locations included in a search.
- **Search filter:** A constraint such as file type, owner, or date that narrows results.
- **Details view:** A way of displaying file information such as size, type, and modification date.
- **Modified date:** A time recorded to indicate when a file was last changed, subject to system behavior.
- **File preview:** A way of examining some file contents without a full editing workflow.
- **Duplicate file:** Another item containing identical or similar information, whether intentional or accidental.
- **Archive:** A designated collection of material retained after active use.
- **Trash / Recycle Bin:** A holding area where some deleted items can be recovered before permanent removal.
- **Restore:** Return a recoverable file or previous state through a supported process.

### Revisions and recovery

- **Version:** One recorded state or edition of a file.
- **Version control:** Practices for identifying and managing different states of a document.
- **Version history:** A feature that may display or restore earlier versions in supported systems.
- **Autosave:** Automatic saving of changes by an application or service.
- **Save As:** An application operation that saves a file using a specified name or location and may create a separate copy.
- **Working draft:** An editable document that may still change.
- **Approved copy:** A reviewed version identified as suitable for an intended use by an authorized person.
- **Final folder:** A folder chosen to hold versions ready for a particular audience or purpose.
- **Backup:** A separate recoverable copy of information maintained for protection against loss or damage.
- **Recovery:** The process of regaining access to information after a problem.
- **Synchronization:** Keeping changes aligned between connected locations or devices.
- **Offline:** A state in which a device or application is not connected to the relevant network or service.
- **Online-only file:** A file whose entry may be visible but whose complete contents require retrieval from a connected service.
- **Retention:** The policy or decision governing how long information is kept.

### Sharing, privacy, and responsible work

- **Sharing:** Making a file accessible to another person through an authorized method.
- **Sharing link:** A link intended to provide access to a file or folder subject to its settings.
- **Permission:** A rule defining who can view, change, share, or manage a file.
- **Viewer:** A role that commonly permits access to read a file without editing its main content.
- **Commenter:** A role that may permit comments without full editing privileges.
- **Editor:** A role that may permit changes to the shared content.
- **Least privilege:** Giving users only the access needed to complete their task.
- **Account:** A person's or organization's identity within a service, associated with access and settings.
- **Ownership:** The identity or role with responsibility or authority over a file or resource.
- **Privacy:** Appropriate control over the disclosure and use of personal information.
- **Confidentiality:** Protection against unauthorized access to sensitive information.
- **Metadata:** Information describing a file, such as type, size, or timestamps.
- **Accessibility:** Making systems and documents usable by people with different abilities.
- **Verification:** Checking that an action produced the intended result.
- **Handoff:** Providing a document or its location to an authorized person for a next step.
