## Lesson 5: Inserting Images and Tables

A document can communicate more clearly when its words are supported by an appropriate picture or by information arranged in rows and columns. A photograph can help readers recognize an object or place. A table can make a schedule or comparison easier to inspect. Yet adding either object creates new responsibilities: the image should be relevant and readable, the table should be structured correctly, and the finished document should still work for someone who reads it with assistive technology. This lesson teaches you to insert, adjust, describe, and verify images and tables in an ordinary word-processing document. You will continue improving a fictional community-workshop notice from earlier Document Skills lessons.

**Level:** Beginner · **Estimated study time:** 85–115 minutes · **Prerequisites:** Lessons 1–4, *Creating a Document*, *Typing, Editing, and Saving*, *Formatting Text*, and *Headings, Lists, and Spacing*, recommended · **Practice equipment:** A computer with Microsoft Word, Google Docs, LibreOffice Writer, Apple Pages, or another word processor; an authorized, non-sensitive practice image is optional; no printer, purchase, or online account is required

> **Essential idea:** Add an image only when it helps the reader understand something. Add a real table only when the information belongs in rows and columns. Preserve readable text, provide an appropriate text alternative for meaningful images, identify table headings, and verify that objects remain usable after saving and reopening the document.

### Learning objectives

After completing this lesson, you should be able to:

1. Decide whether an [[image|image]], a [[table|table]], a list, or ordinary text best serves a piece of information.
1. Choose an appropriate [[source-file|source file]] and insert an image without altering the original image file.
1. Distinguish the image's [[selection-handle|selection handles]] from the text [[insertion-point|insertion point]].
1. Resize an image while protecting its [[aspect-ratio|aspect ratio]] and explain why excessive enlargement can reduce clarity.
1. Use a basic [[text-wrapping|text-wrapping]] option to make a picture behave predictably with nearby paragraphs.
1. Explain the difference between a visible [[caption|caption]] and descriptive [[alternative-text|alternative text]].
1. Recognize [[copyright|copyright]], [[permission|permission]], and [[privacy|privacy]] concerns when choosing pictures.
1. Create a simple table with the correct number of [[row|rows]], [[column|columns]], and [[cell|cells]].
1. Give a data table descriptive [[column-header|column headers]], and insert, delete, or edit a row without rebuilding the table.
1. Review image placement, table readability, and [[accessibility|accessibility]], then save and reopen a finished practice document.

## 1. When should a document use images or tables?

Before inserting a picture or a table, decide what information you want readers to understand. In a community-workshop notice, readers might need a description of the session, a short list of supplies, and a schedule. A photograph of the workshop room could be useful if it helps someone identify where to go. A schedule table could help readers compare the start times and lengths of several activities. On the other hand, an unrelated decorative photograph might take up space without adding information.

An [[image|image]] is visual content such as a photograph, drawing, screenshot, diagram, icon, or scanned picture. A [[table|table]] organizes information in a grid of [[row|rows]] and [[column|columns]]. The fact that something looks like a table does not always mean it is a usable data table: a picture of a spreadsheet, a sequence of tabs, and a real table object are different things.

### Choose the simplest useful presentation

| Information to communicate | Usually best represented as | Why this is a good choice | What to avoid |
| --- | --- | --- | --- |
| One short announcement | Paragraph | A reader can follow it as ordinary text | A one-cell table used only as a box |
| Materials to bring | Bulleted list | Items do not require a specific order | A complicated table with mostly empty cells |
| Steps to prepare | Numbered list | Sequence matters | A table used only to simulate numbering |
| Activity, start time, and length | Table | Each row has the same kinds of facts | Spaces or tabs pretending to form columns |
| Recognizable room entrance | Photograph with description | The picture can help with identification | An irrelevant stock photo or an uncaptioned image |
| Detailed instructions | Text, possibly with a supporting image | Text remains usable when images are unavailable | Important directions supplied only in a picture |

The choice depends on the reader's task. If the relationship between rows and columns makes comparison easier, a real table is often appropriate. If there is only one piece of information, a sentence is usually better. A list is often the clearest way to present several supplies or actions, and it preserves a simple reading order.

### A real table is not a screenshot of a table

Suppose you have three activities, each with a start time and a duration. You could arrange those facts in an image of a table, but readers generally could not select the words as ordinary text, and a screen reader would not automatically have access to the individual row and column relationships. A real [[data-table|data table]] contains actual text in distinct cells. It can normally be edited cell by cell and may support row and column header information.

A table and an image are both [[document-object|document objects]] in many word processors, but they do different jobs. An image depicts something. A table relates values. Neither should replace the document's readable introduction and meaningful headings.

### Ask three questions before inserting anything

1. **Purpose:** What will the reader learn from this object that they cannot learn as easily from surrounding sentences?
1. **Simplicity:** Could a paragraph or short list communicate it with less effort?
1. **Access:** Can someone understand the important information without depending entirely on color, image appearance, or spatial position?

For the practice project, we will keep the existing heading and supplies list, add one optional image, and create one small schedule table. This combination gives each element a reason to exist. The notice remains useful if the image is omitted or the reader uses a text-only representation.

### What this lesson does not require

You do not need photo-editing expertise, advanced graphic design, a spreadsheet program, or specialized publishing software. You do not need to find pictures on the internet. A harmless picture you already own or an image supplied for practice with appropriate permission is sufficient. If no image is available, follow the insertion procedure in theory and complete the table activities using text alone.

> **Remember:** The goal is not to fill the page with objects. It is to help a reader find accurate, understandable information.

## 2. How do you insert an image?

[[insert|Inserting]] means placing content into the document at a chosen location. A word processor normally offers an **Insert** command for pictures. The exact control might be called **Pictures**, **Image**, **Photo**, **Media**, or something similar. Some programs also support dragging a file into the document or pasting an image from the clipboard. Start with an application-provided Insert command because it gives you a clear opportunity to select the correct file.

### Prepare a safe practice image

Choose an image that is appropriate for an educational document. Good examples include a photo you took of a notebook and pencil on a clear desk, an illustration from a licensed practice collection, or a simple image supplied by an instructor. Avoid photographs of identity documents, private workspaces, computer screens showing accounts, children's faces without authorization, or any other sensitive content.

Before you insert the image, ask whether you have the right to use it. A picture appearing in an image-search result is not automatically free to reuse. If you do not know the license or cannot confirm permission, select another image. For this beginner lesson, you may use a local practice image you own and keep it in a private document.

When possible, choose a common format that your application supports, such as [[jpeg|JPEG]] or [[png|PNG]]. JPEG often works well for photographs. PNG is commonly used for screenshots, drawings, or pictures where crisp edges matter. Some programs also accept other formats, but support varies by version, operating system, and document type.

| Before insertion | What to check | Reason |
| --- | --- | --- |
| Source | You own the image or have appropriate permission | Avoids unauthorized reuse |
| Content | No sensitive information appears | Protects privacy |
| Relevance | The image supports the notice | Avoids distracting decoration |
| Format | The word processor can open the file | Prevents failed imports |
| Clarity | The image is readable at the intended size | Reduces blur and guesswork |
| Destination | You are editing a practice copy | Protects the earlier lesson's file |

### The basic insertion sequence

1. Open the copy of your community-workshop notice, or create a new practice document if needed.
1. Click in the document near the paragraph where the image should appear. This sets the [[insertion-point|insertion point]].
1. Open the application's **Insert** menu or toolbar and locate **Image**, **Pictures**, **Photo**, or a comparable command.
1. Choose the option to insert from your computer or device, when available.
1. Navigate to a safe practice image. Check the filename or preview before selecting it.
1. Confirm **Insert**, **Open**, or the equivalent command.
1. Click the inserted picture and inspect the outline or [[selection-handle|selection handles]] that show it is selected.
1. Save your work after the picture appears in the intended document.

If you accidentally insert the wrong image, select the image and delete only that object, or use [[undo|Undo]] immediately. Do not delete the entire paragraph or original source file. Inserting usually places a copy of the visual content in the document, but some applications also support [[linked-image|linked images]] that depend on an external file. Be aware of that difference when moving documents between devices.

### Instructions across common word processors

| Application | Common route for an existing image | Practical note |
| --- | --- | --- |
| Microsoft Word | **Insert → Pictures** and choose a source | Word commonly starts new pictures inline with text, but layout settings may vary |
| Google Docs | **Insert → Image** and choose a source | Options may include upload, Drive, Photos, or other permitted sources |
| LibreOffice Writer | **Insert → Image** | A file chooser normally opens for local images |
| Apple Pages | Use the **Media** or image insertion control, or an available file-insertion method | The object may need a placement adjustment after insertion |

These are general routes, not a promise that every installed version displays identical labels. Browser and mobile interfaces may differ. If a route is missing, search the application's help for *insert image* rather than experimenting with unrelated settings.

### Why a picture may appear very large

Image files have their own dimensions. A photograph captured by a phone can be much larger in pixels than the space available on a letter-size page. The application may automatically scale it, or it may appear larger than expected. This does not necessarily indicate that the image is broken. You will resize it in Section 3, aiming for an appropriate width and enough surrounding space for the text.

### Copy, paste, drag, or insert?

Several routes can lead to the same visual result, but they create different risks:

- **Insert from file:** Usually the most controlled choice for this exercise because you can identify the exact file before adding it.
- **Copy and paste:** May bring hidden formatting, an unexpected image size, or content copied from a site whose reuse terms are unclear.
- **Drag and drop:** Can be convenient but may drop the picture in the wrong paragraph or create a floating object, depending on the application.
- **Image search inside the editor:** Can be useful, but visibility in search results does not establish permission for distribution.
- **Link to a remote image:** May require a network connection later and may stop displaying if the remote image is removed or access changes.

For your first attempt, use one image from an identifiable, permitted source. Save, close, and reopen the document to confirm that it still appears. You will repeat that check after making layout changes.

> **Practical rule:** If you cannot confidently answer where the image came from and why it belongs in the document, do not insert it yet.

## 3. How do you resize and position an image?

After insertion, click the picture once. Many word processors display a frame with small squares or circles around it. These are [[selection-handle|selection handles]], used to adjust size. They are different from the blinking text insertion point. When the picture is selected, an image-formatting toolbar, contextual menu, or sidebar may appear.

### Resize without distorting the image

[[resize|Resizing]] changes the displayed width or height of the image. The [[aspect-ratio|aspect ratio]] is the relationship between those two measurements. If you stretch the picture only horizontally, a round object might look oval. If you stretch only vertically, people or equipment may appear unnaturally tall.

For a beginner exercise:

1. Select the image, ensuring that its resize handles are visible.
1. Find a corner handle and drag it inward in a way that preserves the original proportions; use a **lock aspect ratio** setting if needed and available.
1. Make the image narrower than the available text area so it does not overlap margins or obscure nearby words.
1. Release the handle, click away, and observe the result.
1. If the image is distorted, use Undo or reopen the size controls and restore proportional dimensions.

Some programs preserve proportions automatically when corner handles are used; others expose a separate lock. Do not assume the same keyboard modifier or drag behavior applies everywhere. When precise measurement is needed, a height-and-width panel with a proportional lock may be more reliable than freehand dragging.

### Cropping is not the same as resizing

[[crop|Cropping]] hides or removes part of the picture's visible area so the reader sees the relevant subject. Resizing changes its displayed size without intentionally changing which parts are visible. For example, you might crop empty space around a photographed notebook to make the notebook easier to see. Cropping must not cut off the part of an image that provides the important instruction.

| Editing action | What it changes | Suitable beginner example | Caution |
| --- | --- | --- | --- |
| Resize | Displayed dimensions | Make a desk photo fit under a heading | Keep proportions consistent |
| Crop | Visible portion of the image | Remove extra empty desk space | Do not hide essential information |
| Rotate | Image orientation | Correct a sideways photo | Verify any included writing still reads correctly |
| Move | Position on the page | Place image below the workshop description | Keep reading order understandable |
| Wrap text | Relationship between image and paragraphs | Keep the picture in a predictable location | Some modes cause confusing movement |
| Replace | Image content | Swap an unrelated image for a relevant one | Check that the description still matches |

For this lesson, you are not expected to adjust brightness, filters, color profiles, advanced transparency, or photo-editing layers. These can be learned later. A clear, appropriately sized image is more valuable than an elaborate design.

### Understand inline and floating placement

A picture may behave **[[inline-image|inline with text]]**, similar to a large character in a paragraph. It participates in the text's reading flow. When words before it are added, it typically moves along with that paragraph. Inline positioning is a sensible starting point for beginner documents because it is predictable.

A [[floating-image|floating image]] may be positioned more freely on the page. The text can wrap to its left or right, or the image may be placed in front of or behind paragraphs. The apparent freedom can make editing more complicated: an image may jump to another location when surrounding text changes or when the document is opened in different software.

[[text-wrapping|Text wrapping]] describes how text flows around an inserted object. A program might offer *In line with text*, *Square*, *Tight*, *Break text*, *Above and below*, or comparable options. Wording varies. For the exercise, choose an inline or equivalent straightforward option first. If you explore a wrap-around option, return to a simpler placement before the final verification if the result becomes unstable.

### Keep important information outside the picture

Do not place the workshop's only start time, room number, or attendance instructions inside the image. Text embedded within a photograph or screenshot may be hard to resize, search, select, translate, or read using assistive technology. If a diagram needs labels, repeat essential labels and meaning in ordinary document text or an appropriate description.

A clear photograph can complement the instruction *“Bring a notebook and a pen or pencil.”* It should not replace the written supply list. A reader who cannot view the picture should still understand what to bring.

### Verify at different zoom levels

Zoom changes how large the page looks on the screen; it does not necessarily change the actual size of the image in the document. After resizing, view the page at a comfortable zoom and, if possible, at a page-fit view. Check the picture's edges, readability, and relationship to the surrounding paragraphs. Also inspect the page boundary so you do not accidentally place an important part beyond the printable area.

If the image looks blurry, it may have too few pixels for its displayed size. Reducing its display size may help; enlarging a low-resolution picture usually does not reveal new details. Obtain a better authorized source file if sharpness is important rather than repeatedly stretching the same image.

### A simple placement test

Insert the picture immediately after the paragraph beginning **“The community center will host...”**. Put a short caption below it, if your chosen image calls for one. Type a new sentence in the paragraph above the image. Watch whether the picture moves logically with the text. If it obscures the next heading or overlaps another element, undo the last layout change and use a predictable inline arrangement.

> **Remember:** A stable, readable page layout is more important than making text flow tightly around a picture. Simple placement is a professional choice, not a beginner limitation.

## 4. How do you make images understandable and responsible?

An image has at least three separate questions to answer: **What is shown? Why does it matter? Can everyone obtain its important information?** The answers guide its descriptive text, visible caption, and source information. You do not need to write an essay for every picture, but you do need to communicate its purpose.

### Alternative text explains a meaningful picture

[[alternative-text|Alternative text]], usually called *alt text*, is a text description associated with a meaningful visual object. Depending on the application and output format, a [[screen-reader|screen reader]] may use it to communicate the image's information to a reader who cannot see it. This text is generally not displayed as an ordinary paragraph on the page.

A useful alt-text description describes the image's role in the document. Consider a hypothetical photograph that shows a notebook beside a pencil and a closed laptop on an uncluttered table. If the photograph illustrates the items to bring, a suitable description might be: **“Notebook and pencil beside a closed laptop on a desk.”** If a photo is included only for an ornamental border and carries no meaning, it may be appropriate to mark it [[decorative-image|decorative]] in applications that support that function.

| Image situation | Appropriate treatment | Reason |
| --- | --- | --- |
| Photo showing workshop supplies | Brief, accurate alt text describing the relevant supplies | Readers can understand the picture's purpose |
| Decorative flourished border | Mark decorative when supported, or omit if not needed | Prevents irrelevant descriptions from interrupting reading |
| Diagram showing a process | Alt text explaining the important sequence; longer text nearby if necessary | The relationships matter more than a list of colors |
| Photograph with a visible sign | Describe or reproduce the sign's relevant words in accessible text | Important wording should not depend only on pixels |
| Screenshot showing a settings control | Explain the setting and required action in regular text as well | Instructions remain useful without visual access |

Avoid descriptions that say only “picture,” “image 1,” or “a nice photo.” Those statements tell the reader little about content. Also avoid automatically generated descriptions that you have not reviewed. An automated tool can misidentify objects or omit the very detail that matters to the lesson.

### Alt text and a caption serve different purposes

A [[caption|caption]] is visible text placed near a picture, often beneath it. It might identify the subject, supply context, give a figure number, or identify the image source. A caption is useful for all readers who want that information. Alt text serves a different purpose: it communicates the image's relevant visual information when the picture cannot be perceived.

For example, the caption might read **“Example items for the workshop.”** The alt text might read **“Open notebook and pencil next to a closed laptop on a table.”** The caption explains the figure's function; the alt text communicates what it visibly contains. They can share information, but neither should be needlessly repetitive. For purely decorative images, a caption and alt text may both be unnecessary.

Not every application has a dedicated caption command. A beginner may place a short sentence directly below the image while keeping it in the correct reading order. More advanced caption features can link a figure number and caption to an object. The critical point here is that the visible text must remain associated with the intended image when you edit the page.

### Where to find alternative-text controls

Usually, first select the image. Then look for **Alt Text**, **Alternative Text**, **Description**, **Accessibility**, **Format Picture**, or a contextual menu. In some applications, right-clicking or opening an image-formatting pane exposes the description field. The field location and the available options vary by version and platform.

Write one or two direct sentences that fit the picture's purpose. Read them aloud. If you would not know why the picture was inserted after hearing that description, revise the wording. If you cannot find an alt-text control, preserve the essential information in the document's visible text and consult the official help for your specific application.

### Responsibility includes permission, attribution, and privacy

[[copyright|Copyright]] is a legal framework protecting certain original creative works, including many photographs, drawings, and illustrations. [[permission|Permission]] is authorization to use a work in a particular way. An [[image-license|image license]] describes permitted uses and may include conditions, such as attribution. Credit or [[attribution|attribution]] identifies the creator or source; giving credit alone does not necessarily grant permission to use a work.

If you are preparing a notice for publication or distribution, record relevant image-source details: creator or publisher, title or description, where obtained, the license or permission, and any required credit. An image that is acceptable in a private exercise may not be authorized for a public flyer, website, or commercial promotion. The same caution applies to pictures copied from search engines or social media.

Do not place identifying personal information in a practice image, even when it is your own photograph. Check backgrounds for addresses, identity cards, school records, account numbers, visible messages, and other private details. If the program offers a cloud upload, understand that uploading may move the file to an online service. Students may instead use a local image in a local document where practical.

### Distinguish quality from appearance

An image can be attractive and still be inaccurate or misleading. If a picture purports to show the actual workshop location, use only a verified picture of that location with appropriate authorization. A generic stock image should be identified as illustrative rather than presented as a photograph of a specific room or event.

Before sharing the notice, verify that the picture matches the caption and alt text. If you replace an image, review both descriptions: a correct description for the old picture may become wrong after replacement. If you crop away an important detail, revisit the description accordingly.

> **Responsibility check:** A useful image is relevant, legible, appropriately sourced, correctly described, and safe to share. If any one condition is uncertain, repair it or omit the image.

## 5. How do you create a table?

A [[table|table]] is a grid for organizing facts that share the same kinds of information. A [[row|row]] runs across the table, and a [[column|column]] runs vertically. A [[cell|cell]] is one box at the intersection of a row and a column. Rows often represent items or events, while columns describe properties of those items.

In the practice notice, each workshop activity has three properties: its name, its start time, and its approximate duration. This relationship makes a compact table reasonable. It would be harder to compare the schedule if the activity, time, and duration were scattered across separate paragraphs.

### Plan the columns before inserting the grid

A table should begin with a question: what does each row represent, and what does each column tell us? For the fictional workshop, choose three columns: **Activity**, **Start time**, and **Duration**. Then identify four schedule entries. The resulting table needs one header row and four data rows, for a total of five rows and three columns.

| Activity | Start time | Duration |
| --- | --- | --- |
| Welcome and introduction | 3:00 p.m. | 10 minutes |
| Document practice | 3:10 p.m. | 25 minutes |
| Review and questions | 3:35 p.m. | 15 minutes |
| Wrap-up | 3:50 p.m. | 10 minutes |

This schedule is fictional and lasts 60 minutes. The table above is a demonstration inside the learning material. **In your word processor, create an actual table object** using its table command; simply copying the visible bars and hyphens into a document is not the same task.

### Insert a real table into the document

1. Click below the **Workshop Details** heading, or another suitable place before the supplies list.
1. Type a short introduction, such as “The one-hour session follows this schedule.”
1. Move to a new paragraph where the table should begin.
1. Open **Insert → Table** or the application's equivalent table command.
1. Select **3 columns** and **5 rows**, or insert a smaller grid that you can later extend.
1. In the first row, enter **Activity**, **Start time**, and **Duration** in separate cells.
1. Enter the four activity records in the rows beneath, with each value in the correct column.
1. Move through the cells using the application's keyboard or touch controls. Avoid using repeated spaces to simulate columns.
1. Click outside the table and inspect whether the heading and introductory sentence still read naturally.
1. Save the practice copy.

Many desktop word processors let you use Tab to move between cells. In some programs, pressing Tab in the last cell may create another row, while in others it may move focus to a different control. If an extra row appears, remove it using the table-row controls rather than erasing unrelated text. Keyboard behavior can differ in web and mobile versions.

### What belongs in a header row?

A [[header-row|header row]] identifies what each column means. In the example, the top row contains **Activity**, **Start time**, and **Duration**, not another event. Those labels should remain accurate if the document changes. Many applications provide a table-design setting to mark a row as a header; some provide explicit accessibility options and others use table styles or a header-row property. Visually bolding the first row may improve appearance, but it is not always equivalent to correctly identifying a structural header.

For a simple table, use one clear header row and a straightforward rectangular grid. Avoid [[merged-cell|merged cells]] or nested tables during this beginner exercise. Complex cell structures can interfere with navigation, accessibility, and conversion between file formats.

### Tables are not a substitute for page layout

A table with invisible borders is sometimes used to push text into a particular page position. That can appear convenient, but it may make reading order and accessibility more complicated. Use paragraphs, headings, page margins, tab stops where appropriate, or the word processor's actual layout features instead. Choose a table because values relate across columns, not because you want to imitate a poster design.

### Avoid putting essential schedules only into an image

A screenshot of a schedule might look similar to the table above, but it is harder to edit and does not automatically expose cells and headers to a reader using assistive technology. A real table supports selection and editing of individual values. It is also easier to update a single time without rebuilding an image.

When a schedule becomes large, a spreadsheet may be a more suitable tool for calculations and extensive data management. For a four-activity workshop schedule, a word-processing table is sufficient and keeps the information together with the explanatory notice.

> **Decision rule:** Plan the information first, insert the correct grid second, and apply appearance changes last. Structure should not be an afterthought.

## 6. How do you edit, format, and check a table?

After inserting a table, you may need to correct a value, add an activity, remove an empty row, or adjust the column widths. These are ordinary table-editing tasks. The key is to distinguish between changing **content** inside a cell and changing the **structure** of the grid itself.

### Enter and revise values carefully

Click inside a cell to edit its text. For example, to change *Review and questions* to *Group review and questions*, select the relevant words in that cell and type the corrected phrase. This should not affect the other rows. You can move between cells and inspect that times remain in the Start time column and durations remain in the Duration column.

For accurate scheduling, keep the distinction between a start time and a duration. **3:10 p.m.** is a clock time; **25 minutes** is a length of time. Using clear headers prevents the table from becoming ambiguous even when the cells are short.

### Insert and delete rows or columns

Suppose the organizer adds a five-minute pause. You may need a new row and revised times. Select a cell in the appropriate row and look for commands such as **Insert Row Above**, **Insert Row Below**, or an equivalent table control. Enter the new activity, then revise later start times so the schedule remains internally consistent.

For a simpler editing exercise, add a row named **Equipment check**, give it a plausible start time, and then remove it again without changing the original schedule. This tests structural editing without requiring the whole timing plan to be rewritten.

Be cautious about deleting. Some programs distinguish **Delete Cell**, **Delete Row**, **Delete Column**, and **Delete Table**. Deleting the entire table is not the same as clearing one value. If a command does something unexpected, use Undo immediately and inspect the grid before proceeding.

| Task | Select or place cursor in | Look for | Verify afterward |
| --- | --- | --- | --- |
| Correct a time | Relevant time cell | Ordinary text editing | No other cells changed |
| Add an activity | Row near insertion point | Insert row above or below | New row has three cells |
| Remove an extra activity | Cell in unwanted row | Delete row | Required activities remain |
| Add a field | Cell in relevant column | Insert column left or right | Header added for new column |
| Resize columns | Table or column boundary | Width or layout controls | Text remains visible and readable |
| Identify headers | First row | Header row or table-design option | Labels still match their columns |
| Change borders | Table selection | Borders or table style | Structure remains visible without relying on color |

### Use restrained table formatting

[[table-formatting|Table formatting]] includes borders, background shading, cell padding, alignment, column widths, and sometimes reusable table styles. Good formatting helps readers follow a row without mistaking adjacent values. It should never conceal text or make a table look more complicated than its information.

For the workshop schedule, use enough contrast to distinguish words from the cell background, a simple grid or light row separators, and consistent alignment. Let activity names have enough horizontal room. Avoid a very narrow first column that forces every activity name into multiple lines. A shaded header row can improve scanning, but do not use shading as the only way to identify a header.

[[cell-padding|Cell padding]] is the small amount of space inside a table cell around its contents. It differs from a page margin and from the space between paragraphs. A modest amount of padding may make the rows easier to read. If text is cut off or the table becomes much larger than expected, check cell size, padding, and wrapping rather than inserting extra blank lines inside cells.

### Keep the structure accessible

An accessible beginner table normally has one consistent row for column names, no blank rows used for decoration, and no unnecessary merged cells. The reader should be able to follow it in a logical order: header labels first, then data values row by row. If the table is too complicated to explain in a sentence, consider simplifying the data.

Many applications can mark a header row and, for tables extending across pages, repeat headers on subsequent pages. The exact accessibility semantics preserved in a saved file or PDF can vary, so an attractive layout alone is not proof that assistive technology will recognize the structure correctly. Use available built-in accessibility checks when possible, and test an exported file if the document is intended for wider distribution.

A simple [[table-summary|table summary]] can sometimes help readers: “The one-hour workshop has four activities, beginning at 3:00 p.m. and ending at 4:00 p.m.” This sentence conveys the overall meaning without replacing the detailed table. It also provides context when the table is read separately.

### Compare table controls across applications

| Application | Typical way to add a table | Where to look for adjustments |
| --- | --- | --- |
| Microsoft Word | **Insert → Table** | Table Design, Layout, and contextual table controls |
| Google Docs | **Insert → Table** | Table properties, cell menus, and available formatting controls |
| LibreOffice Writer | **Table → Insert Table** or a table insertion control | Table Properties, context menu, and Table menu |

## 8. Common mistakes and troubleshooting

### “I clicked Insert, but the image went into the wrong paragraph.”

The insertion point was probably somewhere other than you expected, or the program used a floating placement mode. Select and move the image using the application's object controls, or Undo the insertion and place the insertion point correctly before retrying. Avoid dragging randomly through other paragraphs.

### “I selected text instead of selecting the picture.”

You may have clicked the caption, the area next to the image, or the text box containing the image. Click directly on the image. Look for resizing handles or an image-formatting pane. If the cursor still blinks inside a word, you are editing text rather than the picture.

### “The picture looks stretched.”

One dimension may have changed independently of the other. Use Undo or reopen the image-size controls, restore or lock the aspect ratio, and resize from a corner if that method preserves proportions in your program. Check that circles look round and objects appear natural.

### “The image is blurry after I made it larger.”

The source may not have enough pixel detail for the requested display size. Shrink it to a readable size or select a clearer authorized original. Stretching the same low-resolution file does not add missing detail.

### “The image moves every time I type.”

It may be floating or anchored in a way that allows it to shift when paragraphs change. Choose an inline or simple text-wrapping setting, then test by adding and removing a short sentence above the image. Save after a stable arrangement is confirmed.

### “I placed the image behind the text, and now the words are hard to see.”

Return to inline or another straightforward placement. A picture behind words can reduce contrast and legibility. Do not use the picture as a textured background for important instructions.

### “The original image disappeared when I moved the document to another device.”

The document may refer to a linked source file rather than contain an embedded copy, or the export may not have preserved the object. Check the image's link or embedding behavior and consult your application's help. Open the actual file on the second device before assuming the transfer succeeded.

### “I added a caption, but it describes the wrong photo.”

Reposition the visible caption next to the intended picture and edit its wording. Also check alt text. Replacing or cropping an image can make an earlier description inaccurate.

### “I cannot find Alt Text.”

Select the image and inspect a context menu or image-formatting/accessibility sidebar. If the control is unavailable in the version or device you use, keep the essential information in visible text and consult the program's official help. Do not assume the image is accessible merely because the caption exists.

### “I typed spaces between the start times, but the columns will not line up.”

Spaces and tabs are not a substitute for a true table when values belong to repeated fields. Insert a table with appropriate rows and columns and place each value in its own cell.

### “I copied the sample Markdown table, and it is just a collection of bars.”

The learning page displays a Markdown table, but a word processor may paste those characters as plain text. Use **Insert Table** and enter the values into the actual grid. A pasted Markdown table and a structured table object are not automatically equivalent.

### “My table has an extra blank row at the bottom.”

You may have pressed Tab from the final cell, or selected too many rows initially. Use the table's **Delete Row** command for that specific row. Before deleting, inspect that the row is genuinely empty and not part of the required schedule.

### “I deleted the whole table while trying to remove one row.”

Use Undo immediately, then select only the unwanted row and choose the explicit row-deletion command. The difference between deleting a value, a cell, a row, a column, and the whole table matters.

### “My column headers look bold, but a screen reader may not recognize them.”

Visual emphasis is not necessarily a semantic header assignment. Look for a **Header Row** or accessibility-oriented table setting. Some software and output formats preserve table semantics better than others. Use a simple grid and verify the actual document when accessibility is important.

### “The table is wider than the page.”

Reduce excessive column widths, shorten verbose headings where possible, and use the application's table-fit or column-size controls. Do not make text unreadably small just to squeeze a complex table onto one page. Consider simplifying the contents instead.

### “The table breaks awkwardly across pages.”

Inspect the page layout. Short tables are usually best kept together when practical. For a table spanning pages, use appropriate header repetition and row-breaking controls where supported. Check the actual output rather than assuming every application will paginate identically.

### “The table uses beautiful colors, but I cannot distinguish the information.”

Increase readable contrast, use clear borders or separators, and keep text labels. Color should support understanding, not be the only way to identify a heading, status, or value.

### “The image or table looks different after saving or exporting.”

Different applications and file formats can change positioning, font metrics, wrapping, or accessibility metadata. Reopen the editable file and inspect the result. If you export to another format, verify that copy too. Keep the original editable document available for corrections.

### Quick troubleshooting reference

| Symptom | Likely issue | First corrective action |
| --- | --- | --- |
| Wrong picture inserted | Incorrect file chosen | Undo and select the authorized source |
| Picture stretched | Aspect ratio not preserved | Restore proportions in size controls |
| Image overlaps paragraphs | Floating or wrapping mode | Return to inline or simpler placement |
| Missing image after transfer | Link or compatibility issue | Verify whether image is embedded |
| No useful image description | Alt text absent or generic | Describe the picture's actual purpose |
| Schedule appears as typed symbols | No true table object | Create an actual table using Insert Table |
| Time appears under Duration | Wrong cell selected | Move the value to the correct column |
| Header looks decorative only | Header setting not configured | Apply supported header-row semantics |
| Extra empty row | Too many rows or Tab in final cell | Delete the unwanted row |
| Words cut off in a cell | Width or padding too narrow | Adjust column width or table layout |
| Layout changes after reopening | Placement or format difference | Recheck image/table arrangement |

### A repeatable repair procedure

When something goes wrong, first identify whether you are editing **text**, an **image**, or a **table**. Stop making unrelated changes. Use Undo for the most recent error, select the correct object or cell, change one setting, and inspect the result. Save a known-good copy before exploring another unfamiliar control. This deliberate sequence is more reliable than changing many layout settings at once.

## 9. Essential vocabulary

Words with a dotted underline earlier in the lesson can be selected to display a brief explanation. The definitions here provide a second way to review the most important ideas. The wording is intentionally concise; you should be able to explain each term using your own practice document.

- **Image:** A picture or visual object placed inside a document; it may be a photo, drawing, screenshot, or diagram.
- **Table:** A structured grid of rows, columns, and cells that relates information.
- **Source file:** The original file from which an image or other content is obtained.
- **Insert:** Place an object, text, or other content into the current document.
- **Insertion point:** The position where newly entered content is placed.
- **Selection handle:** A control on an image or object that assists with resizing or adjustment.
- **Resize:** Change an object's displayed width or height.
- **Aspect ratio:** The proportional relationship between an image's width and height.
- **Crop:** Change which part of an image is visible without necessarily resizing the whole source.
- **Text wrapping:** The way surrounding text flows relative to an image or another object.
- **Inline image:** An image positioned in the flow of a paragraph.
- **Floating image:** An image positioned more freely relative to paragraphs and page layout.
- **Caption:** Visible explanatory text accompanying an image, table, or other figure.
- **Alternative text:** Text describing meaningful visual information for readers who cannot perceive it.
- **Screen reader:** Assistive software that communicates interface and document content through speech or another supported output.
- **Decorative image:** A visual object with no necessary information for the reader, which may be marked decorative where supported.
- **Copyright:** Legal protection that may apply to original photographs, illustrations, and other creative works.
- **Permission:** Authorization to use content in a specified manner.
- **Image license:** Terms governing permitted use of a particular image.
- **Attribution:** Acknowledgment of the creator or source, when appropriate or required.
- **Privacy:** Control over and protection of information that should not be exposed to others.
- **JPEG:** A common image-file format frequently used for photographs.
- **PNG:** A common image-file format used for images such as graphics and screenshots.
- **Linked image:** A picture that refers to an external source file instead of containing the complete visual content within the document.
- **Document object:** An editable or selectable element such as an image, shape, or table.
- **Row:** A horizontal group of cells in a table.
- **Column:** A vertical group of cells in a table.
- **Cell:** One position at the intersection of a row and a column.
- **Column header:** A label identifying the kind of information in a table column.
- **Header row:** A row of labels identifying the table's columns.
- **Data row:** A row containing the values for a single activity, item, event, or record.
- **Data table:** A table whose rows and columns represent related information rather than page layout.
- **Table formatting:** Visual and layout settings that affect a table's borders, widths, spacing, or styling.
- **Cell padding:** Space inside a table cell between its boundary and its contents.
- **Merged cell:** A table cell formed by combining multiple positions in a grid.
- **Table summary:** A brief statement explaining what a table communicates overall.
- **Accessibility:** Practices and features intended to make content usable by people with different abilities.
- **Heading:** A label introducing the topic of a document section.
- **Bulleted list:** A structured list of items without necessary sequence.
- **Numbered list:** A structured list showing an order or numbered reference points.
- **Reading order:** The intended sequence in which content is encountered or announced.
- **Contrast:** Difference in visual appearance that helps text or features stand out from backgrounds.
- **Resolution:** Amount of image detail available, often associated with pixel dimensions.
- **Pixel:** A basic unit of raster-image information.
- **Embedded image:** Picture content stored within the document file rather than only referenced externally.
- **Undo:** Reverse a recent edit when supported by the application.
- **Save:** Preserve the current document state for later use.
- **Autosave:** Automatic preservation of changes when supported by software and storage arrangements.
- **Verify:** Inspect the actual result to confirm that it matches the intended outcome.
- **Word processor:** Software for writing, editing, formatting, and saving documents.
- **Page margin:** The space between document content and the page boundary.
- **Table properties:** Settings controlling the behavior, layout, and appearance of a table.
- **Border:** A visible line around a cell, image, or other document element.
- **Shading:** Background color or pattern applied to an area such as a table cell.
- **Print preview:** A view used to inspect the likely printed layout before printing.
- **Export:** Create an output file in another format while retaining the source document when appropriate.
- **File format:** A way of encoding and organizing file contents that affects which programs can read or edit them.
