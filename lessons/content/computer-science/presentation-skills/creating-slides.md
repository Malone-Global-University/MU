## Lesson 2: Creating Slides

A neighborhood library is preparing a five-minute introduction to its fictional Saturday Reading Hour. A staff member needs a simple set of digital slides: a title, the purpose of the program, the schedule, what participants should bring, and an invitation to attend. The information is already known. The practical task is to turn it into a file that can be edited, saved, checked, and shown in the intended order.

This lesson teaches the basic operations that make that possible. You will open a [[presentation-editor|presentation editor]], start a new [[presentation-file|presentation file]], recognize the main working areas, create and select [[slide|slides]], enter and revise text, [[duplicate-slide|duplicate]] useful slides, move or remove slides, and check that your work is saved. You will also learn how to recover from ordinary editing mistakes. **You do not need to know graphic design or public speaking to create your first functioning slide deck.**

In Lesson 1, *What Is a Presentation?*, you learned that slides support a message intended for an audience. Here you will perform the basic construction steps. Later lessons cover the visual choices behind layouts and themes, the detailed insertion of images and media, deliberate narrative flow, design standards, speaker notes, presenting, and exporting or sharing. This lesson concentrates on getting the foundation right. A plain, accurate, editable deck is a successful beginning.

Microsoft PowerPoint on Windows 11 is the main desktop example. Google Slides and LibreOffice Impress are introduced wherever their workflows differ materially. Available commands, screen arrangements, keyboard shortcuts, online services, and licensing can change by application, account, device, or version. If no presentation software is available, the paper-based activities remain fully usable. The example information and organization are invented for teaching purposes.

**Level:** Beginner · **Estimated study time:** 90–120 minutes · **Prerequisites:** Presentation Skills Lesson 1 recommended; basic clicking, typing, and file navigation · **Practice equipment:** Paper and pencil or an available presentation application; internet connection needed only for browser-based tools · **Safety:** Work with fictional program details. Do not upload private records, enable public sharing, or install unfamiliar software merely to complete an exercise.

> **Essential idea:** Creating slides is a repeatable workflow: **start a deck → select a slide → enter or edit content → add or duplicate slides → arrange them → review → save and verify**. A slide can be attractive and still communicate the wrong message, so accuracy and order matter before decoration.

### Learning objectives

After completing this lesson, you should be able to:

1. Explain the difference between creating a new presentation, opening an existing one, and saving another copy.
2. Locate the slide thumbnail pane, central editing area, placeholder, and common command controls.
3. Start a blank presentation and add a useful title to its first slide.
4. Add a new slide and enter concise text in the intended text area.
5. Select a slide without confusing selection of the whole slide with selection of text or an object.
6. Distinguish a blank slide, a slide containing placeholders, and a duplicated slide.
7. Duplicate, reorder, and delete slides while protecting the intended content.
8. Explain how undo, redo, saving, and file naming support reliable editing.
9. Produce and check a short fictional slide deck using software or a paper equivalent.
10. Recognize common beginner mistakes and choose a safe corrective action.

## 1. How do you start a new presentation?

A [[presentation-file|presentation file]] stores a sequence of digital slides and related editing information. You ordinarily create or edit that file using a [[presentation-editor|presentation editor]] such as Microsoft PowerPoint, Google Slides, or LibreOffice Impress. Some applications run on your computer, while others run in a browser and store work through an online account. The first decision is simple: **Do you need a new deck, or do you need to continue an existing one?**

### New, open, and copy are different actions

When you choose **New**, the software generally makes a fresh presentation. When you choose **Open**, it loads a presentation that already exists. When you choose **Save a Copy**, **Save As**, or a similarly named command, you preserve a different version or file rather than starting from nothing. Browser-based services may provide **Make a copy** instead. These operations answer different questions and should not be treated as interchangeable.

| Action | What it is for | Beginner example |
| --- | --- | --- |
| New presentation | Begin a separate deck | Start Saturday Reading Hour slides from scratch |
| Open presentation | Continue a saved deck | Return to yesterday's Reading Hour slides |
| Save | Record the current work in its intended location | Keep edits to the existing practice file |
| Save As or Save a Copy | Create another named or located file, where supported | Preserve a draft before a major revision |
| Duplicate slide | Copy one slide within the deck | Make another schedule slide with similar content |
| Make a copy of the deck | Create a separate whole presentation | Produce a new practice version from a prior file |

A copy of a *slide* does not necessarily create another *file*. A copy of a file does not necessarily add a slide to the original deck. Beginners often confuse these because both operations may use the word **duplicate** or **copy**. Always identify whether the command acts on the selected slide or the complete presentation.

### Starting with PowerPoint on Windows

If PowerPoint is available and you have permission to use it, a typical desktop process is:

1. Open PowerPoint through Windows Start or an existing shortcut.
2. Look for **New** or the opening start screen.
3. Select **Blank Presentation** or a similarly named blank option.
4. Wait for the editing window to appear. A new deck commonly begins with one title slide.
5. Find the first slide in the left-hand slide list and the larger slide in the middle.
6. Click inside the title area to begin editing, rather than repeatedly clicking New.
7. Give the presentation a meaningful filename and location when you first save it.

A blank *presentation* means the file has no information from your project yet. It does not necessarily mean the screen has no visual structure. Many programs start with an empty title slide containing instructional prompts such as **Click to add title**. These prompts are [[placeholder|placeholders]], not content that you must delete manually before you type.

PowerPoint's commands frequently appear on a [[ribbon|ribbon]] with tabs such as **Home**, **Insert**, or **File**. Your installed version may have a slightly different appearance. The underlying goal is to recognize the command by its name and purpose rather than memorizing every icon or exact screen coordinate.

### Starting with Google Slides

Google Slides typically operates through a browser and a Google account with appropriate access. You can start from the Slides application and select a blank presentation. The deck is associated with the account and online storage. It may save edits automatically while the service is functioning and synchronized. **Do not interpret the presence of a browser tab as proof that recent changes are saved.** Verify the displayed save or sync status when relevant and reopen the file if there is doubt.

Browser-based use differs from a desktop file workflow. Closing the tab does not itself place an ordinary `.pptx` file in your computer's Downloads folder. Exporting or downloading a separate file is another operation, introduced later in the course. If you are using a shared computer, use only an authorized account and sign out through the service's supported method when finished.

### Starting with LibreOffice Impress

LibreOffice Impress is a desktop presentation editor. A common route is **File > New > Presentation**, or opening Impress directly and selecting an appropriate starting option. Depending on settings, you may see a presentation or template selection dialog. You can select an uncomplicated starting deck, work within the Slides pane, and save a file in the program's normal editable format, commonly `.odp`.

The commands for creating a new slide may appear in a toolbar, the **Slide** menu, or a contextual menu. Use the interface labels visible in your version. You need not install another application just because its controls differ from those in a textbook example.

### Blank presentation or template?

A [[template|template]] is a reusable starting structure that may contain sample slides, color choices, title styles, or organization branding. A blank presentation begins with minimal prepared content. Both can be valid starting points; for this first hands-on lesson, a blank presentation is usually easier to learn because you can see each slide added and each field changed.

A template is not automatically accurate or appropriate for your purpose. If it contains old sample dates, placeholder names, or sample statistics, those are **not** verified facts. Do not present them as actual information. Lessons on layouts, themes, and design later explain how to choose and adapt visual structures deliberately.

| Starting point | Advantage | Limitation | Good first use |
| --- | --- | --- | --- |
| Blank presentation | Easy to see the basic mechanics | Requires you to enter the content | Learning the editing process |
| Built-in template | Supplies a prepared visual structure | May include elements you do not need | A familiar school or office format |
| Existing presentation | Preserves earlier work | Editing may accidentally change the original | Continuing an authorized draft |
| Copy of an existing file | Gives you a separate starting point | Old information may remain | Making a practice variation safely |

### Recognize the intended working file

Suppose you already have `reading-hour-draft.pptx` and want to experiment. Opening that file and changing it may overwrite the intended draft when you save. A safer choice is to use a copy with a clear name, such as `reading-hour-practice.pptx`. If you are working in a shared cloud folder, creating a copy may also affect permissions and where the new version is stored; review the result before editing.

The point is not to collect dozens of unnecessary files. It is to know which document you are changing. Treat the filename, storage location, and visible title as an identity check. Similar names such as `Presentation1`, `Presentation1 (2)`, and `Presentation1-final-new` quickly become confusing.

### Working without an application

Draw a rectangle on a sheet of paper and label it **Slide 1**. Inside, write **Saturday Reading Hour** and, beneath it, **A neighborhood library program**. Draw three more rectangles for later slides. You have not created a digital presentation file, but you have begun a [[storyboard|storyboard]] that makes the eventual computer tasks much simpler. The paper method is a valid preparation and troubleshooting exercise; a digital file must still be created in software if the assignment specifically requires one.

> **Starting rule:** If you cannot tell whether you are editing a new deck, the original deck, or a copy, stop before making major changes. Check the title, location, and file identity first.

## 2. What do you see in a slide editor?

Most presentation editors divide the window into working areas. One area shows the order of slides; another displays the slide you are editing; menus, tabs, or buttons supply commands. Learning these regions helps you avoid the frustration of typing in the wrong place or deleting the wrong item.

### The slide pane, canvas, and controls

The [[slide-thumbnail-pane|slide thumbnail pane]] is usually a column of small slide previews. Selecting one thumbnail normally displays that slide in the larger [[editing-canvas|editing canvas]] or workspace. The canvas contains text areas and other slide objects. Commands at the top or side help you insert, duplicate, rearrange, or delete material. A [[status-bar|status bar]] or status indicator may display slide counts, zoom, editing mode, or save information.

| Editor area | What it shows | Common beginner action |
| --- | --- | --- |
| Slide thumbnail pane | Small previews of the slides in sequence | Select or rearrange a whole slide |
| Editing canvas or workspace | The currently selected slide at a larger size | Enter a title or edit slide content |
| Ribbon, menus, or toolbar | Editing and file commands | Choose New Slide, Undo, or Save |
| Placeholder | A prepared region for title or content | Click or focus the area and type |
| Text box | A movable container for typed text | Edit the words inside the box |
| Status or save indicator | Information about state or synchronization | Check whether saving appears complete |

The editor may also have optional panels for themes, properties, notes, or comments. If a sidebar is closed, the slide has not been erased. A change in the interface layout is not the same as a change in the document's underlying slide content.

### Whole-slide selection versus text selection

This distinction is essential. When you click a thumbnail in the left panel, you select a **whole slide** for operations such as duplicate, move, or delete. When you click inside a text placeholder on the canvas, you work with the **text or object** on that slide. A selected text box may have an outline or handles showing it can be moved or resized. A blinking [[insertion-point|insertion point]] generally indicates where typed characters will appear.

Imagine two instructions:

- **Delete Slide 3:** Select the Slide 3 thumbnail and invoke the slide-delete command.
- **Delete the words on Slide 3:** Select the text within its text box and remove the selected text.

The first action removes an entire slide. The second changes only part of the content while the slide itself remains. If the slide disappears unexpectedly, use **Undo** before proceeding. Do not attempt to rebuild the deck from memory without first checking whether the action can be reversed.

### What does a placeholder do?

A [[placeholder|placeholder]] is a designated space in a prepared slide structure. A typical starting slide has a title placeholder and a subtitle placeholder. Other slides may include a heading and a body text area. The prompts inside are instructions telling you where to put content; they are not normally part of the finished presentation.

When you click **Click to add title**, the prompt should yield to the title you enter. You do not need to write the literal words "Click to add title" in the deck. If you type into the wrong placeholder, you may put a heading where a subtitle belongs. You can usually select and edit that text, or undo the action, without throwing away the presentation.

A [[text-box|text box]] is a container for words on the slide. Some boxes are supplied by a chosen layout; others can be inserted manually. This lesson focuses on using existing placeholders rather than mastering custom text-box placement. The detailed handling of multiple text elements appears in the later lesson on adding text and media.

### Slide number and order

The first slide in the sequence is usually numbered 1 in the editing interface. Moving a slide earlier or later may change its displayed sequence number. The slide's **content** and its **position** are different properties. If the schedule slides were originally third and fourth but you swap them, their numbers may change even though their text stays the same.

Likewise, a number next to a thumbnail is generally not the same thing as an optional visible slide-number label printed on the slide for the audience. The software may use numbers privately to help you edit; later settings may display numbers to viewers. Do not assume every audience member sees the same editing controls that you do.

### Zoom changes your view, not the slide's real importance

A [[zoom|zoom]] control makes the slide appear larger or smaller on your editing screen. Reducing zoom does not mean the presentation text is now a smaller font for the audience; it means the editor is showing the slide at a different scale. Conversely, a readable title at 250% zoom may be difficult to read when projected. The design lesson will address actual text size and presentation viewing conditions.

Use a comfortable editor zoom to see the whole slide or focus on a detail. If items appear too tiny, check both the zoom and actual font settings before changing the content. This distinction prevents unnecessary edits.

### Mouse, keyboard, and touch methods

A mouse user may select thumbnails and click fields. A keyboard user may use standard focus navigation and application commands. A screen-reader user may rely on accessibility-specific navigation and spoken element names. A touch-screen user may tap and drag. The exact steps vary by application and accessibility setup; the important thing is to **confirm which control has focus or is selected before activating a command**.

If you rely on keyboard navigation or a screen reader, consult the program's current accessibility guide and practice with disposable slides. Some editing actions have multiple equivalents; none should require unsafe workarounds or guesswork about whether an entire slide was deleted. A screen reader's announcement of a slide or textbox can provide an important confirmation.

### Worked example: where should you click?

You have a presentation with three slides. Slide 2 contains a heading that says **Who can attend** and a body paragraph that contains a typo. You want to fix only that typo.

1. Find Slide 2 in the thumbnail pane and select it.
2. Confirm that **Who can attend** appears on the editing canvas.
3. Move into the body text area, not the thumbnail pane.
4. Locate and correct the typo.
5. Check the slide and confirm the other two slides remain.

Do not right-click Slide 2 and choose **Delete Slide**. That command operates on the whole slide. Learning the distinction between the thumbnail pane and the canvas prevents many beginner errors.

> **Selection check:** Before a destructive command, ask: **Have I selected the whole slide, a content box, or only part of the text?**

## 3. How do you create and edit slides?

Once you recognize the workspace, the core editing task is simple: provide a clear heading, add a few supporting details, then create another slide when the subject changes. There is no requirement that every slide contain an image, animation, or elaborate design. A short text-only deck can be a good way to master the process.

### Begin with the title slide

Your first slide introduces the subject. For the fictional library example, use these entries:

| First-slide field | Example text | Purpose |
| --- | --- | --- |
| Title | Saturday Reading Hour | Names the presentation's subject |
| Subtitle | A neighborhood library program | Clarifies what the activity is |
| Optional context | Program overview | Distinguishes the deck from a full timetable or sign-up form |

Click or focus the title placeholder and type the title. Then click or focus the subtitle placeholder and enter the supporting phrase. Read the result once. Does it show the intended name, with words spelled correctly? If the title is accidentally placed in the subtitle field, revise the text in the correct fields rather than guessing that the software will rearrange it automatically.

You can leave optional elements blank if they are unnecessary. A title slide does not become invalid merely because it lacks an illustration or the presenter's name. For a real presentation, any name, date, or affiliation should be accurate and authorized; this example deliberately uses no real person's details.

### Add a new slide

A [[new-slide|new slide]] is an additional page within the same presentation. In desktop PowerPoint, you can commonly select a slide thumbnail and use **Home > New Slide**; the new slide will usually appear after the selected slide. Other applications offer a New Slide button, menu option, or slide-pane contextual command. Some allow you to pick the new slide's layout while adding it. You will study layouts and themes later; for now, choose a straightforward heading-and-content arrangement if available.

After adding the slide, check two things:

1. Has the thumbnail count increased by one?
2. Is the new slide selected on the editing canvas, ready for content?

If you still see the original title slide, you might have added the new one somewhere else in the order or failed to select it. Check the thumbnail pane before clicking the command repeatedly. Accidentally creating three extra slides is easy if you mistake a slow screen response for a failed action.

### Type a heading and a few supporting points

For Slide 2, use the heading **What is Reading Hour?** and these short points:

- A welcoming time to enjoy stories.
- Designed for families and beginning readers.
- Includes time to ask questions about books.

If the editor automatically displays bullets in the body placeholder, you can type the first point, press Enter, and type the next. If it does not, do not spend the entire lesson troubleshooting bullets. You can use short lines of text and confirm the meaning first. More detailed text formatting is addressed separately in the course.

Avoid copying this entire lesson into a slide. Slides are not typically full textbook pages. Short labels and useful supporting facts are easier to inspect for mistakes and modify later. Do not treat a sample sentence as a confirmed fact about an actual library program.

### Text editing: insert, select, replace, and remove

The core word-processing skills you already use are useful inside a slide text box. Clicking in text can place the insertion point. You may type new characters, use Backspace or Delete to remove characters, and select a word or phrase before replacing it. The exact keyboard behavior depends on focus and software; check visually or with assistive feedback that the intended field is active.

Consider an error:

- Intended: **Bring a favorite book if you have one.**
- Typed: **Bring a favorit book if you have one.**

Edit `favorit` to `favorite` without deleting the entire slide. If you inadvertently select the text box rather than the text inside it, a key press might act on the object. Use Undo if necessary, then enter text-editing mode explicitly.

### Text boxes, shapes, and content objects

Presentation software treats many slide elements as separate [[object|objects]]: title boxes, text boxes, photographs, shapes, and charts. You can often select an object without selecting the content inside it. That distinction is useful, but a beginner need not master alignment handles and grouping yet. The reliable starting habit is to use the prepared fields and keep the content simple.

Objects may overlap, move outside the visible slide area, or change location when a layout is edited. If your new text seems missing, first confirm the correct slide is selected and the insertion point appears where expected. Do not repeatedly paste the same text into several possible locations. If the text box is outside the slide or obscured, Undo or resetting to an appropriate simple layout may be more efficient than random dragging.

### Add a third slide without repeating everything

Create Slide 3, **When and where?** Use a fictional schedule that is internally consistent:

- Saturdays at 10:00 a.m.
- Community room at the neighborhood library.
- About 30 minutes of shared reading.

Now verify that Slide 2 remains **What is Reading Hour?** and Slide 3 is **When and where?** You should have a three-slide deck in this order: introduction, program description, schedule. The order conveys a useful sequence even before custom design is added.

### When to use a new slide instead of more text

If a slide contains a title, schedule, required supplies, volunteer details, and a long paragraph about future events, its message may become hard to follow. Consider splitting the material across slides when the main subject changes. That does not mean you need a new slide for every sentence. The decision should be guided by the intended message and audience, not by a fixed required slide count.

| Content idea | Reasonable beginner choice | Why |
| --- | --- | --- |
| Program name and short subtitle | One title slide | Provides orientation |
| A few points explaining the program | One content slide | All points answer the same question |
| Meeting time and place | One schedule slide | Keeps logistics together |
| Items participants may bring | One optional supplies slide | Focuses on preparation |
| Invitation or next step | One closing slide | Ends with the audience action |

A deck of five coherent slides may be more useful than a deck of twenty nearly empty slides. On the other hand, five slides containing unreadably crowded paragraphs will not solve the problem. The slide-construction skill is to choose a reasonable unit of information and place it in a clear location.

### Errors that do not require starting over

If the title is misspelled, edit the title. If you added a slide in the wrong place, move it. If you created a duplicate accidentally, remove it after checking its contents. If you changed the wrong box, undo or revise that edit. **Starting over is not the normal solution to every minor mistake.** Presentation editors are built for revision.

If the program crashes or stops responding, the recovery path depends on application and available autosave or recovery facilities. Reopen the known file, check what actually persisted, and use the app's supported recovery features rather than assuming all recent changes survived. Save important work periodically when the program requires manual saves.

> **Construction rule:** Make each slide intelligible before making it decorative. First verify the words, the slide count, and the sequence.

## 4. How do you manage slides in a deck?

After you can create slides, you need to control their order and remove mistakes without losing useful work. The basic operations are [[select-slide|select]], [[duplicate-slide|duplicate]], [[move-slide|move]], and [[delete-slide|delete]]. These actions usually work through the thumbnail pane, not by typing directly on the canvas. Think of the thumbnail pane as a small map of your deck.

### Why the thumbnail pane matters

Suppose your slide list contains:

1. Saturday Reading Hour
2. What is Reading Hour?
3. When and where?
4. What should I bring?
5. Join us

The list is a reasonable sequence: introduce the topic, explain it, give logistics, prepare attendees, then close. If the closing invitation accidentally appears before the schedule, the words on each slide might be correct but the deck may feel confusing. You can move a slide into a better position without retyping it.

### Selecting the correct slide

A single click on a thumbnail usually selects that slide. The program may show a colored border or highlight around the selected thumbnail and display the same slide on the canvas. Verify the slide's heading before any action that could remove or replace content.

Some applications let you select multiple slides with keyboard modifiers or ranges. Those features are helpful for advanced editing, but they can also make it possible to delete several slides at once. Begin by practicing with one disposable slide at a time. If the interface says several slides are selected, do not assume the command applies to only one.

### Duplicate a slide

[[duplicate-slide|Duplicating]] copies the selected slide, generally including its current content, into the same deck. The new slide is usually placed next to the original. The operation is useful when two slides share a similar structure, such as two sessions that need matching headings and details.

For example, imagine Slide 3 has a heading **Morning session**, along with a time and location. You could duplicate it and rename the copy **Afternoon session**, replacing the relevant details. This may be quicker and more consistent than rebuilding the same content arrangement from scratch.

A typical process is:

1. Select the thumbnail of the slide you intend to copy.
2. Choose **Duplicate Slide** from the available menu or contextual command.
3. Look for another thumbnail and confirm the slide count increased.
4. Select the duplicate, not the original.
5. Replace every detail that is different in the new slide.
6. Review the two slides to make sure old information was not carried over accidentally.

Duplicating a slide with the label **Saturday at 10:00 a.m.** does not change that label automatically when you create an afternoon version. The original values are still present until you edit them. **Duplication saves mechanical effort; it does not verify facts.**

### Add a fresh slide instead of duplicating

A new slide normally starts with an empty content arrangement defined by its layout. A duplicate reproduces content that is already present. If you need a different topic, creating a fresh slide may reduce the risk of leaving unrelated old text behind.

| Editing goal | Better first choice | Important caution |
| --- | --- | --- |
| Start a completely different topic | New Slide | Select a suitable simple layout |
| Make a second session with similar fields | Duplicate Slide | Replace old times and labels |
| Edit one spelling mistake | Edit existing slide text | Avoid deleting the slide |
| Keep both versions of a single slide | Duplicate Slide | Identify which version is current |
| Make a separate presentation file | Save a Copy or Make a copy | Whole-deck copy is different from slide copy |

### Move a slide to a new position

Moving a slide changes the order in which it appears. With a mouse, many editors let you drag the selected thumbnail up or down the slide list and release it at a new location. Some offer cut-and-paste, move commands, or a slide sorter view. The exact interface is application-dependent.

Practice first with a short deck. Suppose **Join us** is currently Slide 3, between the program explanation and the schedule. Move it to the end. Confirm the final order using the actual headings, not merely the numeric labels. A slide that was **Slide 3** may become **Slide 5** after moving; its original number is not a permanent identity.

Be aware that selecting and dragging a text box on the canvas moves the *text box*, not the *whole slide*. If the slide's text suddenly shifts but the thumbnail order does not change, Undo the accidental object movement and try again using the thumbnails.

### Delete a slide carefully

To delete an unnecessary slide, select its thumbnail and choose **Delete Slide** or the supported equivalent. In some applications, pressing the Delete or Backspace key while a slide thumbnail is selected deletes the entire slide. If the cursor is inside text, the same key may remove only text. This is another reason to verify the current selection.

Before deleting, answer three questions:

1. Is this truly the unwanted slide?
2. Does it contain anything that must be preserved elsewhere?
3. Is there a saved or otherwise recoverable copy if I make a mistake?

If you delete a slide unintentionally, stop and try [[undo|Undo]] immediately. After further changes, Undo may no longer reverse the specific action you want, and the stored undo history may not persist after closing or reopening the file. If undo is unavailable, check for legitimate version history or backups where your application supports them.

### Remove an extra empty slide

Beginners sometimes click **New Slide** repeatedly while waiting for a response, then discover multiple blank slides. To fix this, inspect the thumbnails, select an unwanted blank slide, and delete it. Repeat only after the list refreshes and you confirm the number of remaining slides. Deleting one at a time makes the effect easier to verify.

A slide with little visible text is not always empty. It may contain notes, an image not immediately visible at the current zoom, a shape matching the background, or other content. Be deliberate rather than deleting by appearance alone.

### Duplicating versus copying and pasting slide content

Copying a whole slide within a presentation often preserves its layout and objects. Copying selected text may paste only that text into another box. Copying a slide into another presentation may use formatting from the source or destination, depending on software choices. This lesson does not require importing slides between files; it requires knowing the difference between content editing and entire-slide operations.

The distinction matters when a learner wants to create a second slide with the same heading style. If you only copy the text, you may not reproduce its positioning. If you duplicate the entire slide, you may carry over unwanted details. Choose the action that matches the actual goal.

### Simple recovery decisions

| Problem | First check | Sensible response |
| --- | --- | --- |
| Wrong slide deleted | Is the action still undoable? | Try Undo; inspect restored thumbnails |
| Unwanted duplicate appears | Which thumbnail is extra? | Delete the verified unwanted duplicate |
| Slide in wrong place | Did its content remain intact? | Move the thumbnail to the intended position |
| Text box moved instead of slide | Did the thumbnail order remain unchanged? | Undo the object movement; drag the thumbnail |
| Several slides highlighted | Is a multi-selection active? | Clear the selection and choose one intended slide |
| Two slides show identical old details | Did duplication carry over content? | Edit each slide's copied information carefully |

> **Slide-management rule:** Verify the selected slide, perform one operation, and inspect the result. The editor is more predictable when you do not stack several unverified commands.

## 5. How do you save and reopen a presentation?

Creating slide content is useful only if you can find and reopen the finished work. A [[save|save]] operation records the document in a place supported by the application. Some programs save to a local folder; others save to cloud storage; some can do both. The essential beginner skill is to know the file's identity and its expected location.

### Give the deck a useful name

A name such as `Presentation1` may work for a temporary experiment but is not helpful when your folder contains many projects. Use a descriptive filename, such as `reading-hour-practice.pptx` or `reading-hour-practice.odp`, depending on the program and chosen format. Do not manually change the extension merely to make it look like another file type; use the program's supported file format or export command.

A practical naming rule is **subject + purpose**, optionally followed by a meaningful version or date. For example:

- `reading-hour-practice.pptx`
- `reading-hour-draft-2026-11.pptx`
- `reading-hour-revised.odp`

Avoid names that promise a version is final when no review has occurred. The filename is a navigation tool, not a guarantee of quality.

### What does Save actually do?

In many desktop programs, the first save asks you to choose a filename and destination. Later saves update that same file. In cloud applications, editing may be autosaved, but synchronization depends on the service, network, permissions, and account state. A spinning icon, error banner, or offline notification can indicate that changes are not yet safely synchronized.

| Environment | Typical save behavior | What to verify |
| --- | --- | --- |
| Desktop PowerPoint with local file | Save updates the chosen file | Filename and folder location |
| PowerPoint with supported online storage | Autosave may be available when enabled | Storage location and save status |
| Google Slides in a browser | Changes normally save to the online presentation | Account, document title, connection, sync state |
| LibreOffice Impress | Manual saving is typically needed | File location and editable `.odp` or chosen format |
| Printed paper storyboard | No digital save occurs | Store the paper safely if needed for later work |

Do not assume every application has the same autosave function. Even when it does, **autosave is not the same thing as a tested backup**. It may record changes you did not intend to keep, and a shared online file may be editable by others according to its permissions.

### Choose a sensible folder

For a personal desktop practice task, an authorized Documents folder or a dedicated training folder is usually easier to manage than scattered files across the desktop, Downloads, and temporary directories. The chosen folder should be one you can access later. On a workplace or school computer, use the assigned location and follow organizational storage rules.

If the file is in the cloud, note the application account and folder rather than assuming you can find it on any computer without signing in. A document stored in one account's drive is not necessarily visible when you open a different account. You need not enable public sharing just to confirm the file exists.

### Reopen to verify

After saving a new presentation, the strongest simple check is to locate it through the editor's **Recent** list or the file system and open it again. Confirm the title and slide count. A file can have an appropriate name but contain an earlier revision if you saved the wrong copy.

Use this short verification sequence:

1. Confirm the current slide headings and order.
2. Save or verify successful autosave.
3. Identify the name and storage location.
4. Close the document only when the application indicates it is safe to do so.
5. Reopen the intended file or online document.
6. Check that the correct slides and recent edits are present.

For important work, you may also maintain an authorized backup or version, following the applicable privacy and school or workplace rules. Do not create a public share link simply to demonstrate that a file was saved.

### Common file formats at this stage

PowerPoint commonly uses `.pptx`, and LibreOffice Impress commonly uses `.odp`. A PDF may preserve an output view for reading, but it is not an equivalent replacement for the original editable presentation. Google Slides typically uses a cloud-native document rather than a normal local `.pptx` file until you download or export one. All applications may have compatibility differences when a file is moved between tools.

| Type or format | Main role | What a beginner should know |
| --- | --- | --- |
| `.pptx` | Editable PowerPoint presentation | Widely used, though another editor may render it differently |
| `.odp` | Editable OpenDocument presentation | Common native format for LibreOffice Impress |
| Cloud-native Google Slides file | Online editable presentation | Access depends on account, sharing permission, and service availability |
| `.pdf` | Fixed-layout document or viewing copy | Usually not the right source file for later slide editing |
| `.txt` | Plain text | Useful for an outline, not a complete slide deck |

The distinction between saving, exporting, downloading, and sharing is the focus of a later course lesson. Here your success criterion is modest: **create a named editable presentation and confirm that it can be reopened**.

### Do not mistake closing for saving

When a desktop editor warns that changes have not been saved, read the options rather than dismissing the prompt. Closing a window without saving may discard recent work. In a browser-based editor, closing the tab during an unresolved sync problem may leave a remote copy without the last changes. These behaviors differ, but the safe principle is the same: verify rather than assume.

### Privacy and file ownership

A practice file should use fictional details. A real presentation may contain names, photos, contact information, financial information, school records, or unpublished organizational plans. Save and share those materials only according to the relevant permissions and policies. A cloud app may involve storage outside your own computer; decide whether it is appropriate for the information involved before entering it.

On a public or shared computer, do not leave a private cloud account open and do not save confidential files into a public downloads directory. Follow the approved sign-out process and any device-specific policies. For this course's fictional exercises, no sensitive information is necessary.

> **Saving rule:** A file is not reliably finished merely because you typed the last sentence. You should know **what it is called, where it is stored, and whether it reopens with the expected content**.

## 6. How do you build and check a short deck?

We will now combine the basic operations into one complete project. Imagine the neighborhood library has given you this fictional request: **Prepare a short introductory slide deck for Saturday Reading Hour. Explain what the activity is, when it happens, what to bring, and how to participate.** You have a small set of sample facts, not a real organization to contact or an actual event to promote.

### Step 1: Set a simple scope

Choose five slides. Resist the temptation to begin with a complicated template or search for stock photographs. The purpose of the exercise is to establish the mechanics of creating and managing slides. A simple text deck will make errors easier to spot.

The desired outcome is not to fill time or impress the audience with effects. It is to create a compact, meaningful order with all requested details present.

### Step 2: Draft the content

Use the following fictional content plan:

| Slide | Heading | Content to enter |
| --- | --- | --- |
| 1 | Saturday Reading Hour | A neighborhood library program |
| 2 | What is Reading Hour? | Stories together, questions, and time to explore books |
| 3 | When and where? | Saturdays at 10:00 a.m.; community room; about 30 minutes |
| 4 | What should I bring? | Curiosity; a favorite book if available; no purchase required |
| 5 | Join us | Ask library staff for current program information |

The schedule and program are invented. **Do not interpret these details as an actual invitation or current library service.** This example also avoids including a made-up phone number or real person's personal information. For real-world use, verify dates, eligibility, addresses, accessibility arrangements, and contact procedures against the organization responsible.

### Step 3: Create the file and title slide

Open an available presentation editor and start a blank presentation. Enter the title on Slide 1. Choose a descriptive name such as `reading-hour-practice` through the editor's supported naming process. If using paper, draw the five slide boxes and write the title in the first one.

Check that you did not accidentally make five separate presentation files. **Five slides belong to one deck** for this exercise. In a desktop editor, the slide thumbnails should form a sequence within the same window. In a browser editor, the slide list should belong to one named document.

### Step 4: Add the content slides

Create Slide 2, enter its heading and supporting details, and then add Slide 3. Continue with Slides 4 and 5. The slides may contain short lines or an appropriate small bullet list. Do not add unnecessary personal names, copyrighted images, or decorative animations. This is a mechanics exercise.

At the end, count the thumbnails and read the headings. You should have **five slides**, not five files or five pages of a word-processing document. If there are extra blank slides, remove them carefully. If a content slide is missing, add it at a suitable position.

### Step 5: Practice one correction

Intentionally change Slide 4's heading to **When and where?**, temporarily creating two slides with the same heading. Then correct Slide 4 to **What should I bring?** This practice demonstrates that you can select and revise the right content without deleting the slide.

If desired, duplicate Slide 4, observe the duplicate appear, and then delete the extra slide. The project should return to five slides. Confirm that Slide 4 still contains the intended supplies message. This checks the difference between a duplicate and an accidental permanent extra slide.

### Step 6: Practice reordering and restoring

Move the **Join us** slide temporarily before **When and where?**. Read the order and consider whether the closing invitation arrives too early. Then move the closing slide back to the end. If you are using a keyboard or screen reader, use the application's documented accessible method rather than attempting mouse-only dragging.

This exercise proves that you can change slide order without rewriting the content. It also teaches you to check the outcome after a move rather than trusting that the slide went exactly where you intended.

### Step 7: Review your deck

Review these questions one at a time:

- Does the first slide clearly name the subject?
- Does each slide have the intended heading?
- Are the fictional times and locations internally consistent?
- Is the purpose easy to understand without reading an entire paragraph on every slide?
- Are there duplicate or empty slides that were added by mistake?
- Is the final slide an appropriate closing invitation rather than another introduction?
- Have you kept actual personal or confidential information out of the practice deck?

A deck may pass the mechanical check yet remain unfinished as a real presentation. You have not yet learned the full visual design, accessibility review, delivery practice, or sharing workflow. Do not call an unreviewed practice deck a published organizational announcement.

### Step 8: Save and verify

Save the presentation in the format supported by your editor, or confirm cloud synchronization where applicable. Locate the deck by name and reopen it. Confirm there are five slides in the correct sequence. If you are working on paper, review the complete five-box storyboard and clearly identify that it is a plan rather than a stored digital file.

The complete beginner workflow is:

**New → title → additional slides → text edits → slide management → review → save → reopen and verify.**

### What does completion mean?

For this lesson, **completed** means that you can operate the editing workflow, produce or storyboard five distinct slides with the required information, correct an intentional mistake, restore the intended order, and—when working digitally—locate a saved editable file. It does not mean you have mastered professional design, audience delivery, or file-sharing permissions. Those are separate skills with their own lessons.

### Quality checklist for a basic digital deck

| Check | Pass condition | Example of a problem |
| --- | --- | --- |
| File identity | You know its name and location | Three copies have nearly identical names |
| Slide count | Five required slides are present | Extra blank Slide 6 remains |
| Slide sequence | Introduction precedes details and closing | Join us appears before the program description |
| Text accuracy | Titles and fictional details match the plan | The schedule was copied incorrectly |
| Text placement | Each item appears in the intended slide field | Subtitle is accidentally used as a main title |
| Editing control | You can fix text without deleting a whole slide | Delete removes the selected slide instead of a word |
| Saving | Deck reopens with the latest work | Only yesterday's revision appears |
| Responsible use | No private or unauthorized material included | Real contact details are pasted into a sample |

> **Completion standard:** An effective beginner can explain what action they performed, see the result, correct a mistake, and recover the file later. Mechanical control comes before elaborate styling.

## 7. Guided practice: build and repair a deck

These activities progress from recognizing controls to completing the fictional Reading Hour project. You can do the observation exercises on paper, using a description of an editor, or in available software. **Do not create real accounts, install paid software, publish a presentation, or enter personal information for these exercises.** When the instruction refers to a particular application control, use the functionally equivalent command in the application you have.

### Activity 1: Identify the working areas

**Task:** Imagine a presentation editor showing a narrow strip of five thumbnails on the left, a large selected slide in the center, and a row of commands above it. The selected slide contains two prompts: **Click to add title** and **Click to add subtitle**.

1. Identify which region you would use to select the whole third slide.
2. Identify where you would type a new title on the first slide.
3. Identify which area contains New Slide, Undo, or Save commands.
4. Explain what the placeholder prompts mean.
5. State how you would confirm the correct slide is selected before editing.

**Success check:** You can distinguish a whole-slide operation from editing words within a slide.

:::answer Show Activity 1 model answers
**Model answers:** The left thumbnail strip is where you choose Slide 3 as a whole slide. The large central canvas is where you click or focus the title field and type. The ribbon, menu, or toolbar contains commands such as New Slide, Undo, and Save. The prompts are placeholders that identify expected content; you replace them with your own words. Confirm selection by matching the selected thumbnail with the slide heading shown on the canvas.

A learner using a keyboard or screen reader may navigate to the same regions differently. Correctly identifying the intended region matters more than using a particular pointer device.
:::

### Activity 2: Draft the first three slides

**Task:** Make the first three slides for the fictional Reading Hour program. Use a presentation editor if one is available. Otherwise draw three slide boxes on paper.

1. Start a new deck rather than opening an unrelated existing one.
2. On Slide 1, enter **Saturday Reading Hour** and **A neighborhood library program**.
3. Create Slide 2 with **What is Reading Hour?** and two or three brief supporting points.
4. Create Slide 3 with **When and where?**, **Saturdays at 10:00 a.m.**, and **Community room**.
5. Inspect all three slide headings in order.
6. If working digitally, identify where the new file will be stored when saved.

**Success check:** You have three distinguishable slides in one deck, and their headings match the expected order.

:::answer Show Activity 2 model deck
**One acceptable model:**

- Slide 1 — **Saturday Reading Hour**; subtitle: **A neighborhood library program**.
- Slide 2 — **What is Reading Hour?**; details: **Enjoy stories together**, **Ask questions**, **Explore books**.
- Slide 3 — **When and where?**; details: **Saturdays at 10:00 a.m.**, **Community room**.

The exact wording of the explanation on Slide 2 may vary, provided it stays consistent with the fictional assignment and is easy to understand. A single slide with all three headings is not equivalent to three separate slides.
:::

### Activity 3: Diagnose selection errors

**Task:** Consider these three situations. Explain what was probably selected and how to correct the problem without starting the entire deck over.

- Situation A: You pressed Delete intending to remove one word, and an entire slide disappeared.
- Situation B: You tried to reorder Slide 2, but the heading box moved across the canvas.
- Situation C: You typed a title, but the words appeared below the subtitle on another slide.

For each situation, identify the likely confusion between slide, object, and text selection. Decide whether Undo should be your first action.

**Success check:** Your response preserves as much existing work as possible.

:::answer Show Activity 3 model reasoning
**Situation A:** The entire slide thumbnail was probably selected instead of text inside a box. Try Undo immediately, verify the restored slide, then select the intended text and edit it.

**Situation B:** You probably dragged a content box on the editing canvas rather than the slide thumbnail. Undo the object movement and move the thumbnail using the supported method.

**Situation C:** The wrong slide or wrong text field had focus. Check the selected thumbnail, undo the misplaced text if appropriate, then click or navigate to the correct title placeholder and enter the title there.

The precise recovery command can differ across programs, and undo history may be unavailable after reopening. Confirm the result after each corrective action.
:::

### Activity 4: Duplicate and correct a slide

**Task:** You want two similar slides for the fictional Reading Hour project. The original slide says:

- Heading: **Morning session**
- Time: **10:00 a.m.**
- Room: **Community room**

1. Duplicate the whole slide within the same deck.
2. Change the duplicate's heading to **Afternoon session**.
3. Change the duplicate's time to **2:00 p.m.**
4. Keep the room unchanged.
5. Explain which information must be checked in the new version.
6. Decide whether you have made a second slide or a separate presentation file.

**Success check:** The original remains intact, and the copied slide has the revised heading and time.

:::answer Show Activity 4 model answer
**Original slide:** Morning session; 10:00 a.m.; Community room.

**Duplicated slide after editing:** Afternoon session; 2:00 p.m.; Community room.

The action created a second slide in the same presentation, not a separate file. The copied time and heading would have been incorrect for the afternoon session unless they were deliberately replaced. This demonstrates why duplicating reduces repetitive setup but never eliminates the need for fact checking.
:::

### Activity 5: Repair the order and remove an extra slide

**Task:** A deck has these six slides:

1. Saturday Reading Hour
2. Join us
3. What is Reading Hour?
4. When and where?
5. What should I bring?
6. Empty slide

Reorder or remove slides to make a five-slide presentation with a logical beginning, middle, and ending. You may use a slide thumbnail interface or write the corrected order on paper. Explain how you would avoid deleting the wrong slide.

**Success check:** The final sequence contains five meaningful slides and ends with the invitation.

:::answer Show Activity 5 corrected order
**Corrected order:**

1. Saturday Reading Hour
2. What is Reading Hour?
3. When and where?
4. What should I bring?
5. Join us

The empty sixth slide can be removed after verifying that it is unwanted. The existing **Join us** slide should be moved to the end instead of rewritten from scratch. On a computer, inspect the currently selected thumbnail, perform one move or deletion at a time, and verify the updated list before proceeding.
:::

### Activity 6: Complete the file handoff check

**Task:** A learner has finished five slides in PowerPoint, named the deck `Presentation1`, and closed the program without checking where the file was stored. Another learner has finished a Google Slides deck and sees an unresolved network-sync warning. A third learner has a saved `.odp` file in an authorized folder.

For each learner:

1. Identify whether a reliable saved result has been established.
2. Recommend one immediate verification action.
3. Explain why the document title or file extension alone is insufficient evidence that the work is current and complete.
4. Describe the minimum evidence you would want before declaring the digital exercise complete.

**Success check:** You distinguish a file that is visibly open from one known to be safely retrievable.

:::answer Show Activity 6 model checks
**First learner:** The saved result is unverified. Reopen the intended file using the program's recent list or a known folder and compare the slide count and contents. A generic name does not show where or whether the latest work was saved.

**Second learner:** The unresolved synchronization warning means the latest changes may not be stored remotely. Follow the service's supported recovery or reconnect process, verify the save state, and reopen the same document when appropriate. Do not assume that closing the tab fixes synchronization.

**Third learner:** A file has been saved, but its contents still need verification. Reopen the `.odp` file and check the expected five slides and edits.

**Completion evidence:** Correct file identity, known location or account, intended slide sequence, and a successful reopen showing the latest content. This is an operational check, not proof that the presentation is publication-ready.
:::

### Optional application challenge

If you have a working editor, complete the full five-slide Reading Hour deck from Section 6, intentionally duplicate one slide and then remove the extra copy, reorder one slide and restore it, then save and reopen the file. Record the action you used for each task in an ordinary note. A learner using only paper can map the same operations with numbered index cards: add a card, duplicate a card, move a card, cross out an unwanted card, and check the final sequence. Paper practice demonstrates understanding, while actual software practice demonstrates operation of the digital tool.

## 8. Common misconceptions and avoidable problems

### Misconception 1: A new slide is the same as a new file

**Correction:** A new slide usually appears inside the current presentation. A new presentation is a separate document or deck. Check the thumbnail count to see whether another slide was added to the same file.

### Misconception 2: A blank presentation has to be a completely empty screen

**Correction:** Many editors start with a title slide containing empty placeholders. Those prompts are a prepared structure, not accidental content. Click or focus the correct field and replace the prompt with your text.

### Misconception 3: Clicking a thumbnail always selects the words on the slide

**Correction:** Selecting a thumbnail ordinarily selects the whole slide. Selecting a text box or placing the insertion point inside it are different operations. This difference determines what Delete and other commands affect.

### Misconception 4: Duplicate Slide creates a backup of the entire presentation

**Correction:** It usually creates another copy of one slide within the same deck. A separately stored version of the complete presentation requires a whole-document copy, supported backup, or other appropriate file operation.

### Misconception 5: Copying a slide also updates the information on it

**Correction:** Duplication generally reproduces existing words, numbers, and objects. You are responsible for revising copied dates, times, names, and claims so the new slide is correct.

### Misconception 6: Moving a text box is how to rearrange slide order

**Correction:** Moving an object on the canvas changes its placement within a slide. To rearrange slides, use the thumbnail pane, slide sorter, or the application's supported slide-order command.

### Misconception 7: Delete is harmless because Undo always works

**Correction:** Undo can often reverse a recent mistake, but not every action or program state can be reversed, and undo history may disappear after closing. Confirm selection before deleting and maintain reliable copies where appropriate.

### Misconception 8: A generic filename is good enough for important work

**Correction:** The application may accept `Presentation1`, but a meaningful title makes the right file easier to find, distinguish from revisions, and verify. File naming is part of basic information management.

### Misconception 9: Autosave means the file has been fully backed up

**Correction:** Autosave may record the current state to a particular location, but it does not guarantee the existence of an independent backup, successful synchronization, or recovery from every problem. Check the actual saved or synced result.

### Misconception 10: A PDF is an editable replacement for the source deck

**Correction:** A PDF can be an effective viewing or distribution format, but it generally lacks the same editable slide structures and presentation-authoring features as `.pptx`, `.odp`, or the cloud-native presentation file. Preserve the appropriate source when continued editing is expected.

### Misconception 11: A visually attractive template guarantees a correct presentation

**Correction:** A template may provide useful styling but also contain irrelevant placeholders, old sample content, or misleading decoration. Verify the message and facts before relying on the appearance.

### Misconception 12: I should publish the deck to prove it is saved

**Correction:** Publication or public sharing is not necessary for a private editing exercise. Saving, locating, and reopening the intended document demonstrates basic file handling without exposing information to an audience.

### Misconception 13: Every slide needs an image and animation

**Correction:** Text-only slides can be sufficient for basic instruction. Animation is not a prerequisite for making a slide, and decorative effects can distract from the message. Separate lessons address richer content and presentation behavior.

### Misconception 14: The desktop, web, and mobile versions must have identical menus

**Correction:** The basic tasks are similar, but screen layout and feature availability differ. Follow your application's current controls rather than assuming a screenshot from another version must match perfectly.

### Misconception 15: The fastest way to fix a typo is to recreate the slide

**Correction:** Enter text-editing mode and correct the characters or selected words. Recreating slides unnecessarily can introduce new errors, disrupt order, or remove useful content.

### A practical troubleshooting sequence

When an editing action does not produce the expected result, use this sequence: **confirm the file → confirm the current slide → confirm selected text or object → identify the intended command → perform one action → inspect the outcome**. If the action was wrong, use a supported Undo or recovery option, then repeat more deliberately. Do not solve a simple selection problem by changing every application setting.

## 11. MGU Library connections and next steps

### Lesson summary

A slide deck is a file containing an ordered collection of slides. You can begin from a blank presentation, identify the thumbnail pane and editing canvas, type in placeholders, add new slides, and correct text without rebuilding the presentation. Whole-slide operations such as duplicate, move, and delete require selecting the correct slide. Reliable saving means knowing the document's identity and location and checking that the expected content survives reopening.

### Review before continuing

You are ready for the next lesson when you can create and name a new deck, make at least three distinct slides, select the intended title or content area, duplicate a slide without carrying over incorrect information, reorder slides, delete only an unwanted slide, and verify an editable file after saving. If you practiced with paper rather than software, you should be able to explain each operation and identify what would need to be performed in an editor.
