## Lesson 3: Attachments and Downloads

An email can carry more than a written message. Someone might send a class handout, a photograph, a completed form, a résumé, or an appointment document. These items may arrive as **attachments**, or the message may contain a **link** to a file stored online. Knowing how to recognize the difference, open an appropriate file, save it in a place you can find, and send your own file correctly makes email much more useful. It also reduces the risk of opening a dangerous file or sharing private material with the wrong person.

This lesson teaches the full beginner workflow: **identify the file, verify its source, choose a safe action, locate the saved copy, and check what you are sending**. The examples apply broadly to webmail, desktop email applications, and mobile devices. You do not need to own a printer, install software, buy storage, or contact a real person to complete the required exercises. All sample messages and files are fictional.

**Level:** Beginner · **Estimated study time:** 85–115 minutes (including guided practice) · **Prerequisites:** *Email Basics* and *Writing Clear Emails* recommended · **Practice equipment:** Paper and pen or notes app; optionally, a personal email account and a small, nonprivate practice file

> **Essential idea:** An [[email-attachment|email attachment]] is a file included with or associated with a message. A [[download|download]] saves a file from a service to your device or another chosen destination. A [[cloud-link|cloud link]] may provide access to a file without attaching that file directly. Before opening or sending any file, verify **who provided it, what it is, whether you need it, and who will be able to access it**.

### Learning objectives

After completing this lesson, you should be able to:

1. Recognize attachments, attached file names, file sizes, and common [[file-type|file types]].
1. Explain the differences among an attached file, a cloud-sharing link, an inline picture, and a downloaded file.
1. Describe how to attach a file to a new email and check that the intended file was included.
1. Locate the Downloads folder or another saved-file location on a familiar device.
1. Describe how to safely preview, save, open, rename, and organize a trusted file.
1. Recognize common [[file-extension|file extensions]] and understand that their names are clues, not proof of safety.
1. Explain why large files may require a sharing link, a smaller version, or an alternative delivery method.
1. Apply simple privacy checks before sharing a photo, document, or file-access link.
1. Identify suspicious attachments and know when **not** to download or open them.
1. Troubleshoot common attachment problems without bypassing security controls.
1. Complete a practice attachment workflow using fictional information and an optional harmless file.

## 1. What are email attachments and file links?

An [[attachment|attachment]] is a file sent along with an electronic message. The file is separate from the text written in the message itself. A person may read the email without opening the file, and some email services allow a file to be previewed in the message window. An attachment is commonly displayed as a small card showing a name and file icon, or near a [[paperclip-icon|paperclip icon]]. Where the file appears depends on the service, display size, and whether the file is shown as a thumbnail.

For example, a message with the subject **Practice worksheet for Thursday** could contain a two-sentence explanation and a file named `practice-worksheet.pdf`. The email body tells you why the file was sent; the attached PDF contains the worksheet. If you only read the body, you may have missed the actual material. If you only download the file without reading the body, you may miss instructions or a deadline.

### Four related things that are not identical

| Item | What you receive | Everyday example | What to remember |
| --- | --- | --- | --- |
| Attached file | A file associated directly with the email | `class-notes.pdf` shown in an attachment card | Check that you recognize the sender and expected the file |
| Cloud-sharing link | An address leading to a file stored in an online service | A shared Google Drive or OneDrive document | Access may require sign-in, permission, or a request for access |
| Inline image | A picture displayed within the message itself | A photo between paragraphs | It may also be saveable, but it may not appear as a separate attachment card |
| Downloaded file | A copy saved to a device or selected storage location | `class-notes.pdf` in your Downloads folder | The saved copy and the email are distinct places to find information |

An attachment can contain a picture, a document, a spreadsheet, an audio recording, or another file type. A single email may carry several attachments. Some email programs also allow an entire message to be attached to another message, but that is a specialized function outside this lesson.

### Understanding the paperclip and attachment card

A [[paperclip-icon|paperclip symbol]] often indicates that a message includes one or more attachments. It is useful, but not universal. Some messages include a file-sharing link with no paperclip. An embedded logo or image may appear differently from a conventional attachment. Do not assume a missing paperclip means that no file or file link exists.

An attachment card may show:

- A **file name** such as `budget-practice.xlsx`.
- A small **file icon** or thumbnail suggesting the kind of file.
- A **file size**, for example 120 KB or 2 MB.
- Commands such as **Preview**, **Download**, **Save**, **Open**, **Save to Drive**, or **Share**.
- A status message if the attachment is too large, blocked, or unavailable.

The exact button labels vary among Gmail, Outlook, Apple Mail, and other email programs, and may be different on a phone. Some providers scan attachments for potential threats, but scanning does not establish that every received file is harmless.

### A fictional example message

> **Fictional instructional example — do not send a reply**  
> From: Community Learning Desk (training@example.org)  
> To: Student (student@example.org)  
> Subject: Typing workshop materials  
> Message: “Hello. The practice sheet for our workshop is attached. Please save it to your class folder so you can find it next week. You do not need to fill it out today.”  
> Attachment: `typing-practice.pdf` (180 KB)

The domain `example.org` is reserved for examples. These are not real instructor contacts or files. From this information, you can identify the **purpose**, **file name**, **format**, **approximate size**, and **requested action**. Because the message is fictional, there is no actual file to open. In real life, the same details help you evaluate an expected attachment, but they do not prove that the sender is genuine.

### Receiving is not the same as opening

An email may arrive in your inbox even when you never choose to open its attachment. Reading an ordinary message and deliberately downloading or running a file are different actions. A dangerous file may attempt to exploit software when opened, previewed, or executed. A link may lead to a deceptive website. For a file you did **not** expect, stop at the message level and verify independently before interacting with it.

### File links and access permissions

A [[share-link|share link]] usually leads to material in a [[cloud-storage|cloud storage]] account. Sometimes you can view it in a browser; sometimes you need permission, an account, or a compatible app. A person may send a legitimate link that you cannot open because the owner shared it with the wrong account or set restrictive permissions. Conversely, some links are configured so that anyone with the link can access the file; such links must be handled carefully because they can spread beyond the intended recipient.

A link is not an attachment merely because it leads to a downloadable document. Before clicking a cloud link, verify that the request and service are expected. Never enter your email password into an unfamiliar page simply to view an allegedly shared document.

### Two questions before touching a file

First ask, **“Did I expect this file from this person or organization?”** Next ask, **“Does the file's purpose make sense?”** If either answer is uncertain, use a telephone number, existing contact record, or official service that you already know—not the contact details or link supplied in the questionable message—to check. The more urgent a message sounds, the more important this independent check becomes.

## 2. What do file names, types, and sizes tell you?

A [[filename|file name]] helps identify a file. Examples include `reading-list.pdf`, `family-photo.jpg`, and `practice-budget.xlsx`. The part after the final period is often the [[file-extension|file extension]], which can help software decide how to open the file. The extension is useful, but it can be misleading: a malicious file may use a deceptive name, and devices sometimes hide extensions by default.

### Common file types beginners may receive

| Example name | Typical type | Common use | Beginner handling note |
| --- | --- | --- | --- |
| `welcome-letter.pdf` | PDF document | Handouts, forms, printable documents | Often opens in a browser or PDF reader; still verify its source |
| `meeting-outline.docx` | Word document | Editable letters or outlines | May open in compatible word-processing software |
| `practice-table.xlsx` | Spreadsheet | Tables, budgets, calculations | May need a spreadsheet app; avoid enabling unexpected active content |
| `class-photo.jpg` | JPEG image | Ordinary photographs | May reveal private surroundings or identifying details |
| `diagram.png` | PNG image | Screenshots, graphics, diagrams | A screenshot can expose sensitive data if forwarded |
| `voice-note.mp3` | Audio | Spoken notes or recordings | Confirm permission before recording or redistributing |
| `short-video.mp4` | Video | Short visual recordings | Files can be large; be mindful of privacy and bandwidth |
| `practice-files.zip` | ZIP archive | Bundles of several files | Inspect source and contents before extracting; unknown archives carry extra risk |
| `instructions.txt` | Plain text | Simple written instructions | Usually opens in a text editor; still treat links and commands skeptically |

File types can vary by operating system and app. A `.heic` photo, for example, may be supported on one device but require conversion or compatible software on another. It is usually better to ask the sender for a common compatible format than to install an unfamiliar converter found through a search result.

### What an extension does—and does not—prove

An extension may suggest how to open a file, but it is **not a security certificate**. A file that appears to be `invoice.pdf` could be an unexpected invoice from a fake sender. A double extension such as `invoice.pdf.exe` is especially suspicious because `.exe` is normally an executable program on Windows. Some email systems block certain file types; do not work around those safeguards by renaming or compressing a blocked program.

Other file types can also carry risks. Office documents can sometimes contain [[macro|macros]] or other active content. A PDF or image may be malformed or exploit unpatched software. Archives may contain programs or scripts. Avoid instructions telling you to enable macros, disable antivirus protection, run a terminal command, or install a “viewer” just to access an unsolicited file. A familiar file extension or a polished sender name does not make those actions appropriate.

### File sizes in everyday language

File size describes how much digital storage a file uses. You may see [[byte|bytes]], [[kilobyte|kilobytes (KB)]], [[megabyte|megabytes (MB)]], or [[gigabyte|gigabytes (GB)]]. For everyday comparisons, think **small text document**, **medium photo**, and **potentially large video**. The exact size depends on content and compression; it is not guaranteed by extension.

| Approximate example | Illustrative size | Practical observation |
| --- | --- | --- |
| Short text instructions | 5 KB | Usually very small |
| Simple PDF worksheet | 180 KB | Often convenient to attach |
| Phone photograph | 3 MB | May be much larger than a short document |
| Several photographs | 18 MB total | May approach an email service's size limit |
| Long high-resolution video | 700 MB | Often better shared through a permission-controlled service |

These numbers are **illustrations, not required sizes**. Actual files vary widely. Some email providers count the size of the complete message and the extra encoding involved in sending attachments, so a file near the stated limit may still fail. A provider's rules can depend on the account type, organization, and recipient system.

### Why an attachment may be too large

Email services impose sending and receiving limits; [[compression|compression]] and [[file-conversion|file conversion]] are two possible ways to prepare alternatives. For example, Google's current help materials describe a **25 MB attachment limit for personal Gmail**, with larger files generally handled through Google Drive links. Other services and managed workplace accounts may have different rules. Limits and interface behavior can change, so treat the provider's current help page or account guidance as authoritative.

When a file is too large, safe choices include:

1. Remove an unnecessary duplicate or send only the relevant document.
1. Use a supported file-compression feature if the file type and recipient permit it; photographs and videos may not shrink much in a ZIP archive.
1. Create a smaller image or video version with tools you already trust, while preserving the required quality.
1. Use a trusted cloud-sharing service with intentionally chosen access permissions.
1. Ask the recipient which supported method and format they prefer.

Do **not** split private information across random websites or upload it to an unknown “free attachment converter.” A service that promises to make files smaller may keep copies or request more information than necessary. You should understand where a file goes before uploading it.

### Names that help humans find files

A descriptive file name is more useful than `document1` or `final-final-2`. Consider `job-application-practice.pdf` or `history-class-outline-2026-11.pdf`. Avoid putting a full Social Security number, account number, medical details, or other sensitive personal data in a filename. File names often appear in inbox previews, download histories, recently used lists, or shared links.

When you change the name of a file, preserve its expected extension unless a supported program is actually changing the file format. Renaming `photo.jpg` to `photo.pdf` does not convert the picture into a valid PDF. Conversion requires an app or service that understands both formats.

## 3. How do you attach and send a file?

The general sending workflow is similar across many email programs, even though buttons and menus differ. You write a message, choose the correct recipient, add the intended file, wait until the attachment is ready, check the result, and then send. The most important step is not the paperclip click; it is the **review before sending**.

### A transferable six-step procedure

1. **Prepare the file.** Save it in a folder you know, open your own copy if appropriate, and check that it contains the intended material. Rename it meaningfully if necessary.
1. **Start a new message.** Open Compose or New Email. Enter the intended recipient's address. Confirm the spelling and address carefully.
1. **Write a useful subject and short explanation.** For example: `Practice worksheet for Tuesday`. Say what is attached and what the recipient should do with it.
1. **Choose Attach.** Look for the paperclip icon or a menu labeled **Attach**, **Insert**, **Add file**, or similar. Some apps also offer **Insert from cloud storage**, which may create a link instead.
1. **Select the correct file.** In the [[file-picker|file picker]], navigate to the relevant folder, choose the named file, and confirm. Wait for any upload or preparation indicator to finish.
1. **Review, then send.** Verify recipient, subject, message body, file name, file count, and any sharing permissions. Use Send only after the review.

The file picker is a window or screen that helps you browse device storage or supported cloud locations. If a file is missing from the picker, you might be looking in the wrong folder, have selected a filter that hides its type, or be using an app that cannot access that location. Do not assume the file has been deleted.

### The compose screen: what to check

| Area or control | What to confirm | Common mistake |
| --- | --- | --- |
| To field | Exactly the intended recipient | Autocomplete selected a different person |
| Subject line | Specific and relevant | Subject says only “File” |
| Message body | Clear explanation of attachment | Recipient does not know why a file arrived |
| Attach control | Correct file chosen | Similar-looking older file selected |
| Attachment card | Correct name and count shown | File never finished attaching |
| Cloud permission message | Intended person can access it | Link allows broader access than intended |
| Send | Used after all checks | Sent while attachment still uploading |

Some modern services warn if the message says “attached” but no attachment is present. Do not rely on such a warning; it may not appear or may not detect your wording. A file name in the message body is not evidence that the file was attached.

### Example: the same message with and without the file

**Incomplete example:**

> To: classmate@example.org  
> Subject: Worksheet  
> Message: “Here is the worksheet.”  
> Attachment: none

**Improved example:**

> To: classmate@example.org  
> Subject: Typing practice worksheet — Thursday session  
> Message: “Hello. I am sending the typing-practice worksheet for Thursday. The file is a PDF and contains only practice material. Please let me know if you cannot open it. Thank you.”  
> Attachment: `typing-practice.pdf` (one file, confirmed attached)

Both examples are **fictional**. Do not use these addresses for real practice. The improved message states the purpose and makes the actual attachment explicit. It remains important to check the content of the attached file, not merely its name.

### Attaching on a desktop, phone, or tablet

On a desktop browser, the Attach command commonly opens a file-selection window. On mobile, it may offer **Files**, **Photos**, **Camera**, or a location within a supported storage provider. Apps differ in whether they insert a photo in the body or attach it as a separate file. Mobile devices may ask for permission to access photos or files; allow only the access you intend, and reconsider if a request seems unrelated.

If using a phone, check the **selected thumbnail**, especially when two photos look alike. In a folder with many similar documents, verify the version, file name, and content before sending. If a message is drafted but not sent, the file may remain attached to the draft; reopening the draft later should still be followed by a complete review.

### Sending multiple attachments

You may attach more than one document if the email service and recipient system allow it. Count the files and explain them in the body. If a student sends a worksheet and a separate photo of a completed activity, for instance, the message should state that there are **two** files. Avoid attaching an entire folder when the recipient needs only one document. Some email services do not support directly attaching folders; a ZIP file or sharing link may be necessary, but those choices add privacy and security considerations.

### Checking the actual content, not just the name

Suppose you have `application-final.pdf` and `application-practice.pdf`. Their names are similar, but one may contain private information. Before sharing, open the **local copy you intend to send**, confirm the pages, and close it. After attaching, check the name that appears. Some services permit previewing the attached item before sending; use this option when it is available and trustworthy. A screen showing the right filename does not prove the underlying content is the right version.

### If you attach the wrong file but have not sent the message

Remove the incorrect attachment from the draft, confirm it is gone, and attach the correct file. The removal control might look like an **X**, trash can, or Remove action. Removing an attachment from a **draft** generally does not delete the original file from your device. However, deleting a source file, moving it out of a synced folder, or changing cloud permissions can have different effects—know which action you are choosing.

If you realize you sent sensitive material to the wrong person, do not assume an unsend feature will recover it. If an organization is involved, follow its incident-reporting procedure promptly. Contact the intended supervisor or privacy team through an established route if appropriate, and avoid forwarding the mistake to more people.

## 4. How do you save and find a received file?

Receiving an attachment does not always mean a permanent copy has been saved in a folder you can find. Some email programs let you view a file inside the message, temporarily cache content, or open a preview without choosing a lasting save location. To use a document later, learn the difference among **previewing**, **downloading**, **opening**, and **saving a copy**.

### Preview, download, and open

- A [[preview|preview]] displays content within or alongside the email app when the file type is supported. It may not create a clearly findable copy in your usual folders. Even previews have risk; do not preview unknown suspicious files.
- A [[download|download]] transfers a copy to a device or chosen storage destination. A browser may place it in **Downloads** automatically or ask where to save it.
- [[open-file|Opening]] starts a compatible application or viewer to display or work with the file. Opening a file is not always the same as saving it permanently.
- [[save-as|Save As]] or **Save a Copy** may create an additional file in a chosen folder. Menu names and effects depend on the app and whether it uses cloud storage.

The word **Save** is context-dependent. In one service it means **save the attachment to your device**; in another it could mean **save to a cloud drive** or **save changes inside an app**. Read the full action label before choosing it.

### Safe receiving procedure

1. **Verify the message.** Was the file expected? Does the request make sense? Check an unexpected sender by an independent method.
1. **Read the filename and context.** Consider the extension, size, purpose, and whether you need the file.
1. **Choose an appropriate action.** For a trusted file, preview it with a supported viewer or download it if you need a reusable copy. Avoid untrusted executable files, macros, and unsafe instructions.
1. **Select or note the save location.** If prompted, choose a folder such as Downloads or a class folder. If not prompted, check the usual download location.
1. **Locate the saved file.** Open your device's [[file-manager|file manager]] and look for the name. Use a search only if needed.
1. **Open with an appropriate app.** If software is missing, consult the sender or a trusted official support source. Do not install a random viewer from an email link.
1. **Organize it.** Move or copy an appropriate trusted file to a descriptive folder, and keep only copies you are authorized to store.

### Where is the Downloads folder?

Many devices use a familiar downloads area, but it is not identical on every system.

| Device or environment | Common place to look | Useful caution |
| --- | --- | --- |
| Windows 11 | File Explorer → Downloads or your selected browser download folder | The browser's destination may have been changed |
| macOS | Finder → Downloads, commonly available in the Dock | Safari or another browser may use a different chosen location |
| iPhone or iPad | Files app → Browse → Downloads, On My iPhone/iPad, or iCloud Drive | The actual folder depends on the app and settings |
| Android | Files app / Files by Google / device file manager → Downloads | Names vary by manufacturer and app |
| Web-based email | A download arrow, browser download list, or Save action | Some views save to the cloud rather than the device |

These paths are typical starting points, not guarantees. A school or workplace device may have managed storage locations. If you download a file through a browser, the browser's download list can often help you find it. Only follow a download item if you have already verified that it is a file you intended to receive.

### Downloads folder versus an organized destination

The [[downloads-folder|Downloads folder]] is often a convenient **temporary arrival area**. It is not necessarily the best long-term home for classwork, records, and important forms. Once you know the file is legitimate and safe to retain, place it somewhere logical, such as `Documents/Computer-Skills/Email-Practice` or a folder your instructor specifies. Keep only material you have permission to store.

For an actual personal record, choose an appropriate protected location and follow organizational retention rules. Sensitive attachments may warrant encryption or a managed storage area; do not put them in a shared family computer's public folder or an open cloud link.

### A simple folder structure

You could use a modest structure like this:

```text
Documents/
  Computer-Skills/
    Email-Practice/
      typing-practice.pdf
      instructions.txt
    Calendar-Practice/
      schedule-practice.pdf
```

This is an **illustrative folder structure**, not a required existing path. It separates email exercises from calendar materials. The important thing is that you understand which folder holds your saved work. Making many unnecessary folders can be as confusing as keeping everything in Downloads.

### Renaming and keeping versions

Sometimes the sender uses an unclear name such as `scan003.pdf`. Once you have confirmed a file is appropriate to keep, you may rename your saved copy to `registration-practice-2026-11.pdf`. Retain the correct file extension, avoid sensitive information in the name, and do not imply it is an official original if it is merely a practice copy. For time-sensitive paperwork, use a date or descriptive version marker when helpful.

If two files have the same name, your device may rename the newer copy by adding `(1)` or another suffix. That does **not** necessarily mean the second copy is more recent or more correct. Compare the content and file dates before discarding anything. A filename is only one piece of evidence.

### Editing a downloaded file

A downloaded document may be a copy of the version that arrived with the email. Editing that copy generally does **not** automatically update the sender's original, and it does not necessarily replace the original attachment in the email. Cloud documents behave differently: if the owner grants edit access, changes may appear in the shared file for other authorized people. Before editing, decide whether you are working on **your own copy** or **someone else's shared document**.

A PDF form may support typing into fields, but a different PDF may be read-only. If you need to return a completed document, save a new version using an appropriate name, reopen it to confirm the changes persisted, and attach **that saved version** in a new message. If the document contains private information, use only an authorized delivery method and recipient.

### Printing is optional

An attachment may be printable, but printing is not required for most email tasks. If you print sensitive material, collect the pages immediately and dispose of unneeded copies securely. A printer is another possible destination for information and may be shared by others.

## 5. How do you share files and protect privacy?

Sending a file creates a copy or grants access to information beyond the place where you originally stored it. That is why a good attachment workflow includes not only selecting the correct file, but also choosing the correct **audience**, **permission level**, and **delivery method**.

### Attach a copy or share a link?

| Situation | Attachment may be appropriate | Cloud link may be appropriate |
| --- | --- | --- |
| Small practice worksheet | Yes, when recipient and file are trusted | Yes, if course uses a shared folder |
| Large video | Often exceeds service limits | Often more suitable if securely shared |
| Collaborative document | Recipient receives a separate copy | Allows supported real-time collaboration |
| Sensitive personnel file | Only through approved secure procedures | Only if organization approves access controls |
| File recipient must keep offline | Often convenient | May require the recipient to download a copy |
| Content that may change often | Each attached copy is a snapshot | A link may reflect current authorized version |

Neither method is automatically safer. An attachment can be misdirected or redistributed. A cloud link can expose too much information if permissions are broad or not reviewed. Choose the method that matches the file, the recipient's needs, and any applicable organizational rules.

### Understanding sharing permissions

A [[permission|permission]] determines what an authorized person may do with a file. Common categories include [[view-permission|View]], **Comment**, and [[edit-permission|Edit]], but exact labels and effects vary. A link configured for **specific people** may require the recipient to sign in with an approved account. A link configured as [[anyone-link|anyone with the link]] may be accessible to people beyond the intended recipient if it is copied or forwarded. Some services allow expiration dates, download restrictions, or access removal; such features have limits and may depend on your plan or organization.

Before sharing a cloud link, ask:

1. Does the intended person have permission to open the file?
1. Does that person need to **view** or **edit** it?
1. Could someone else open it if the link were forwarded?
1. Is the link permanent, time-limited, or managed by a workplace or school account?
1. Is any personal or confidential information present?
1. Do I understand what the selected permissions actually allow?

Do not treat disabling a download button or revoking a link as a guaranteed way to recall content. Someone may have already copied, photographed, or downloaded information while access was available.

### Privacy checks for photographs and screenshots

An image file might reveal more than its main subject. A class photo could show someone else's face, a house number, an identification badge, or an address in the background. A screenshot might show other open tabs, an email address, a financial balance, or private messages. Some photographs contain [[metadata|metadata]], which may include the device, date, or location where the image was taken; actual metadata varies by file and service, and some providers remove parts of it during sharing.

Before sending an image, check the visible contents and consider whether to crop, blur, or choose a less revealing photograph using a trusted built-in editor. Cropping on screen is not always equivalent to securely removing underlying information; use a genuine [[redaction|redaction]] process for confidential records when needed. Do not rely on drawing a translucent mark over sensitive text.

### Privacy checks for documents

A document may contain unseen [[document-properties|document properties]], author information, comments, tracked changes, hidden sheets, or earlier editing content. Depending on the application, the file can disclose more than what appears on the first page. For formal or sensitive documents, use an approved inspection or export workflow. For beginner practice, use fictional information and a document created specifically for the exercise.

**Never send a document simply because its filename looks harmless.** Look at its content and intended audience. Attachments containing account statements, identification documents, medical records, personnel details, or private correspondence require additional care and may be governed by institutional policies.

### School and workplace rules

An organization may require approved storage, password-protected transfer, a secure portal, or a particular file format. Follow those rules rather than trying to work around them. A recipient's email address alone does not establish that ordinary email is the approved channel for confidential information. When in doubt, ask the appropriate instructor or office which method is authorized.

### File ownership and courtesy

Receiving a file does not automatically give you permission to publish, redistribute, or modify someone else's work. Before forwarding a document, consider confidentiality, copyright, and the sender's instructions. This course's later lesson on Replying, Forwarding, and CC examines recipient visibility and forwarding decisions in more detail.

## 6. How do you handle files safely and fix common problems?

Files and file links are common tools in scams. A [[phishing|fraudulent]] email can look like an invoice, delivery notice, application update, job offer, or shared document notification. The most important safety rule is to **verify an unexpected request before opening, downloading, enabling content, or signing in**. If an email is suspicious, do not use its links, attachments, telephone numbers, or reply address to verify itself.

### Warning signs involving attachments

Be cautious when a message:

- Claims an urgent fee, overdue bill, or account lock and tells you to open an unexpected document.
- Arrives from an address that differs from the organization you expected.
- Uses a vague subject such as “Immediate Action Required” without a credible explanation.
- Contains a file you did not request, especially a program, script, or compressed archive.
- Tells you to enable macros, editing, or security exceptions to view an attachment.
- Demands that you enter a password, one-time verification code, or payment card into an unfamiliar website.
- Says you must install a special downloader, browser extension, or antivirus replacement.
- Asks you to keep a financial transaction secret or bypass an ordinary approval process.

No single feature proves fraud. Legitimate senders sometimes have poorly written messages, and fraudulent messages can be grammatically perfect. Judge the **combination of context, sender, request, and independent verification**.

### The safe decision path

| What you encounter | First action | What not to do |
| --- | --- | --- |
| Expected worksheet from verified instructor | Check message and file details, then use trusted viewer | Assume all file types are harmless |
| Unexpected `payment-invoice.zip` | Do not open; verify through a separate trusted channel | Extract contents to discover what it is |
| File says “Enable macros to continue” | Stop and seek approved guidance | Enable active content simply because the file demands it |
| A link requests a login you were not expecting | Open the known official service independently | Type credentials into the linked imitation page |
| A large file is blocked by an attachment policy | Ask about an approved alternative | Rename an executable to defeat the block |
| File preview fails | Check supported format and official app guidance | Install an unknown viewer from the same email |

### What antivirus and scanning can—and cannot—do

[[malware-protection|Malware protection]] and the security scanning performed by an email service may detect known threats. Updated operating systems, browsers, and document viewers reduce exposure to vulnerabilities. They are valuable, but **no scan guarantees safety**, particularly for new threats or a convincing request to reveal information. The person using email must still decide whether the file was expected and whether the requested action makes sense.

Never disable protection because a sender says doing so is required. Managed work devices may forbid certain file types or downloads for a reason. A file that your organization blocks should not be moved to a personal email account to bypass policy.

### If you clicked or downloaded something suspicious

The correct response depends on what happened. **Simply downloading a file does not always mean it ran**, but some file viewers or software may have vulnerabilities. If you suspect a harmful file or misleading login page:

1. **Stop interacting.** Do not run installers, approve prompts, enable macros, or enter more information.
1. **If you entered a password**, go independently to the genuine service and change it from a trusted device or session. Review account recovery settings and enable multifactor authentication where available.
1. **If you installed or executed something**, contact your organization's support team or a trusted technician; use the device's legitimate security tools and follow instructions for isolation or scanning.
1. **If you disclosed payment information**, contact the financial institution through its established official channel and follow its fraud process.
1. **Report the message** through the email service's Report Phishing feature or relevant institutional process, if available.
1. **Preserve appropriate information** for authorized help, such as the date and description of the incident, without forwarding dangerous files to other people.

A suspicious file still sitting unopened in Downloads does not become safe because several days have passed. Likewise, deleting the file does not reverse a password disclosure or undo an installation. Use the response that matches the type of exposure.

### Common attachment problems and practical responses

| Problem | Likely explanation | Appropriate next step |
| --- | --- | --- |
| Attachment missing from sent email | File never finished attaching or was not selected | Review Sent message; if truly missing, send a clear correction with the right file |
| Wrong file attached | Similar names or versions | Remove from draft before sending; if already sent, use appropriate incident response |
| File does not open | Unsupported type, damaged file, or unavailable app | Verify source and format; ask for a supported version |
| File size exceeds limit | Message or provider attachment restriction | Reduce file if appropriate or use approved secure sharing |
| Download disappeared | Saved elsewhere, renamed, or browser location changed | Inspect download history and file manager; search by known filename |
| Attachment appears blank | Preview or application issue | Try another trusted supported viewer after verifying safety |
| Cloud file says “Request access” | Permission does not include your account | Ask the verified owner to adjust access for the intended account |
| File changed after you sent it | Cloud collaboration or differing local copies | Confirm whether the recipient received a snapshot or shared live file |
| Phone asks for photo permission | App needs access to selected media | Grant only intended access when trusted; decline unrelated requests |
| Security product blocked a file | Potential threat or organizational policy | Stop and consult trusted help; do not bypass the block |

### An attachment did not arrive: what should you say?

A clear response is often enough: “Thank you for your message. I can see your instructions, but I do not see the worksheet attached. Would you please send the file again?” Avoid accusing the sender of an error; sometimes an attachment is blocked, still processing, or delivered as a cloud link. If the exchange involves sensitive information, verify the recipient and delivery method before asking for another copy.

### The one-minute pre-send and pre-open checks

**Before sending:** Right person → right document → correct version → appropriate content → correct access → upload finished → send.

**Before opening:** Expected sender → expected purpose → sensible format → safe file/link → verified through a trusted channel if uncertain → view or save using supported software.

These habits take little time compared with correcting a disclosure or recovering from an unsafe file. With repetition they become routine rather than a special procedure.

## 8. Common misconceptions

### “Anything in an email with a paperclip is safe to open.”

No. The paperclip indicates an attachment in many interfaces; it does not authenticate the sender or verify a file's contents. Email providers may block some malicious attachments, but users should still verify unexpected files and requests.

### “Clicking Download and viewing a preview always do the same thing.”

No. A preview displays content in a supported viewer, while a download creates a copy at some destination. The app may use temporary data to display previews, but you should not assume you have a permanent, organized file until you locate it.

### “Once a file reaches my inbox, it is already in my Downloads folder.”

Not necessarily. The message and its attachment may remain on an email service until you intentionally save a copy. Some apps automatically download attachment data, but the resulting location and visibility vary.

### “A file ending in `.pdf` cannot contain anything dangerous.”

False. PDFs can be malicious or exploit outdated software, and a deceptive message can use a perfectly ordinary PDF as bait. File type alone is not proof of legitimacy.

### “Renaming a file changes its type.”

No. Changing `photo.jpg` to `photo.pdf` does not turn the picture into a valid PDF. Real conversion requires compatible software that produces the new format.

### “I should enable macros if an email attachment tells me to.”

No. An unexpected instruction to enable macros or disable protection is a major warning sign. Stop and verify the request through an independent trusted contact, following any workplace or school rules.

### “A cloud-sharing link is the same as an attached copy.”

No. An attached copy and a cloud-hosted file have different access, storage, and update behavior. A cloud link may change over time, expire, or require permissions.

### “If only one person receives the link, only that person can open it.”

Not always. A link configured for “anyone with the link” may be usable by whoever obtains it. Review the actual permission setting rather than relying on the number of email recipients.

### “If a file is too large, I should send it through any website that offers a free upload.”

No. Unknown upload and compression services may expose information. Use a provider and transfer method that the recipient and your organization recognize and authorize.

### “The newest-looking filename is always the correct version.”

No. File names can be confusing or deliberately misleading, and automatic suffixes such as `(1)` do not establish the contents. Compare the file itself and relevant source information.

### “Deleting an email will always delete the downloaded copy.”

No. Copies already saved elsewhere may remain on the device or in another storage service. Conversely, changes to a shared cloud document may affect a single collaborative file, so the storage arrangement matters.

### “If I made a mistake sending a private attachment, I can always undo it.”

No. Some email products offer limited unsend or recall features, but they do not guarantee that all copies are recovered. Treat sending as a disclosure decision, and use the appropriate reporting process promptly if private material went to the wrong recipient.

### “I must install a special program whenever I cannot open an attachment.”

No. A file may simply need a more common format or an already trusted compatible viewer. Ask the sender for an alternative or follow the software publisher's official support instructions rather than following an unsolicited installer link.

### “Compressing a file always makes it small enough to email.”

No. Some files, particularly compressed image and video formats, shrink little when placed in a ZIP archive. File-size restrictions may also apply to the whole message, and a ZIP file can itself contain dangerous content.

## 9. Essential vocabulary

The lesson uses clickable vocabulary tooltips for selected terms. The same concepts are summarized here for review. File-related commands and their exact names differ among email services, devices, operating systems, and institutions.

- **Email attachment:** A file included with or associated directly with an email message.
- **Attached file:** A specific document, picture, or other file that has been included in a message.
- **Cloud-sharing link:** A web address that directs an authorized person to a remotely stored file.
- **Inline image:** A picture shown inside the email body rather than only as a separate file card.
- **Downloaded file:** A file copy saved to a device or chosen storage location.
- **Download:** Transferring a file from a remote location into another location, commonly your device.
- **Upload:** Transferring a file from your device or location to an online service or recipient system.
- **Paperclip icon:** A familiar symbol that often indicates attachments or the Attach command.
- **Filename:** The visible name that helps people identify a file.
- **File extension:** The letters after the last period in many filenames, often associated with a file format.
- **File type:** The kind of content or format represented by a file.
- **PDF:** A widely used document format designed for consistent viewing or printing.
- **Word document:** A text document format commonly associated with Microsoft Word and compatible apps.
- **Spreadsheet:** A grid-based document format useful for numbers, tables, formulas, and structured data.
- **JPEG:** A common compressed photo format, typically recognized by `.jpg` or `.jpeg`.
- **PNG:** A common picture format often used for screenshots, diagrams, and graphics.
- **Audio file:** A file containing recorded sound.
- **Video file:** A file containing moving images and sometimes audio.
- **ZIP archive:** A file that packages one or more files, often using compression.
- **Plain text:** Text stored without rich document formatting.
- **File size:** A measurement of how much digital storage a file uses.
- **Kilobyte (KB):** A unit used for relatively small file-size measurements.
- **Megabyte (MB):** A unit commonly used for photos and many documents.
- **Gigabyte (GB):** A larger storage unit used for sizable videos and collections of files.
- **File picker:** An application window or interface for selecting a file from available storage.
- **Attach button:** A control that adds a file or compatible file reference to a message.
- **Attachment card:** A visual element displaying an attachment's name and available actions.
- **Preview:** Showing file content within a viewer, often without explicitly saving a new organized copy.
- **Open:** Displaying or processing a file with compatible software.
- **Downloads folder:** A common storage location for files received from browsers or other apps.
- **File manager:** An app used to browse, open, move, copy, rename, and organize files.
- **Save As:** An action that saves a file under a chosen name or location when supported.
- **Copy:** A duplicate file or the action that creates one.
- **Move:** Relocating a file from one storage location to another.
- **Rename:** Changing a file's visible name without necessarily changing its format.
- **Version:** A particular saved state of a file.
- **Duplicate:** Another copy of a file, possibly with a different name or location.
- **Recipient:** The person or account to which a message is addressed.
- **Subject line:** A short heading describing the email's purpose.
- **Message body:** The main text written in an email.
- **Send button:** A control that submits an email for delivery.
- **Share link:** A link that can provide access to remotely stored content.
- **Cloud storage:** A service that stores files on remote systems accessed over a network.
- **Access permission:** A rule determining who can view or modify a resource.
- **View permission:** An authorization to read a shared file without editing it.
- **Edit permission:** An authorization to modify content in a supported shared file.
- **Specific-people sharing:** A permission setting that limits access to selected accounts or identities.
- **Anyone-with-the-link sharing:** A setting that permits people possessing a link to access a file subject to service rules.
- **Metadata:** Information about a file, such as its name, date, type, or sometimes photo location data.
- **Document properties:** Information a document may store about authorship, editing, or other characteristics.
- **Macro:** Automated instructions associated with some document or spreadsheet applications that may execute active operations.
- **Executable file:** A program file that can run instructions when launched in a compatible environment.
- **Malware:** Harmful software designed to perform unauthorized or damaging actions.
- **Malware protection:** Software or services intended to identify, block, or remove certain malicious content.
- **Phishing:** Fraudulent messaging intended to induce unsafe actions or steal information.
- **Independent verification:** Checking a claim through a known reliable source separate from the message containing the claim.
- **File conversion:** Using appropriate software to produce the same material in another supported format.
- **Compression:** A method for representing information in fewer bytes, sometimes without any data loss.
- **Sync:** Keeping information updated between linked devices or services, depending on settings.
- **Backup:** An extra copy retained for recovery after loss, corruption, or other failure.
- **Redaction:** Removing or concealing sensitive information so it is not disclosed in a shared document or image.
- **Account password:** A secret used to authenticate a user account; never share it in an unsolicited attachment workflow.
- **Verification code:** A temporary authentication code that should not be shared with untrusted contacts.
- **File access error:** A message indicating the account or app cannot open or retrieve a file with current permissions.
