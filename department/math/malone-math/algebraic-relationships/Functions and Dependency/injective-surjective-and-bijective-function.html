Injective, Surjective, and Bijective Functions

Functions can be classified by how they connect inputs to outputs. Injective functions avoid output collisions, surjective functions reach every codomain value, and bijective functions do both.

The Central Idea

Suppose

\[ f:A\to B. \]

We already know that every input in \(A\) must receive exactly one output in \(B\).

Now we ask two stronger questions:

  1. Can two different inputs share the same output?
  2. Does every element of the codomain get used?

These questions lead to three important classifications:

  • injective — no two distinct inputs share an output;
  • surjective — every codomain element is reached;
  • bijective — both injective and surjective.

Injective Functions

A function is injective if different inputs always produce different outputs.

Symbolically,

\[ f(x_1)=f(x_2) \Rightarrow x_1=x_2. \]

An equivalent form is

\[ x_1\ne x_2 \Rightarrow f(x_1)\ne f(x_2). \]

Injective Means One-to-One

An injective function is also called a one-to-one function.

Each output in the range comes from at most one input.

Outputs cannot be shared by different inputs.

Injective Example

Let

\[ f(x)=2x+3. \]

Suppose

\[ f(a)=f(b). \]

Then

\[ 2a+3=2b+3. \]

Subtract \(3\):

\[ 2a=2b. \]

Divide by \(2\):

\[ a=b. \]

Therefore, \(f\) is injective.

A Function That Is Not Injective

Consider

\[ f(x)=x^2 \]

on domain \(\mathbb{R}\).

We have

\[ f(2)=4 \]

and

\[ f(-2)=4. \]

Different inputs produce the same output, so \(f\) is not injective on \(\mathbb{R}\).

Repeated Outputs Break Injectivity

A function may still be perfectly valid even when it is not injective.

For example,

\[ f(x)=x^2 \]

is a function because every input has exactly one output.

It fails injectivity only because some outputs come from more than one input.

The Horizontal-Line Test

A graph represents an injective real-valued function if every horizontal line intersects the graph at most once.

This is the horizontal-line test.

Why?

A horizontal line represents one output value. If it meets the graph twice, that output came from two different inputs.

Strictly Increasing Functions Are Injective

If a function is strictly increasing on an interval, then

\[ x_1So two distinct inputs cannot produce the same output.

Therefore, a strictly increasing function is injective on that interval.

Strictly Decreasing Functions Are Injective

Similarly, if

\[ x_1f(x_2), \]

then distinct inputs again produce distinct outputs.

So every strictly decreasing function is injective on that interval.

Nondecreasing Does Not Guarantee Injective

A function that is merely nondecreasing may have flat intervals.

On a flat interval, many inputs share the same output.

Therefore, nondecreasing behavior alone does not guarantee injectivity.

Domain Restriction Can Create Injectivity

Consider

\[ f(x)=x^2. \]

On

\[ \mathbb{R}, \]

it is not injective.

But if we restrict the domain to

\[ [0,\infty), \]

then the function is strictly increasing and therefore injective.

Why Domain Matters for Injectivity

Injectivity is a property of the whole function, including its domain.

The same formula can be injective on one domain and noninjective on another.

So we should say:

\[ f:[0,\infty)\to[0,\infty), \qquad f(x)=x^2 \]

is injective, while

\[ f:\mathbb{R}\to[0,\infty), \qquad f(x)=x^2 \]

is not.

Surjective Functions

A function

\[ f:A\to B \]

is surjective if every element of the codomain \(B\) is the output of at least one input from \(A\).

Symbolically,

\[ \forall y\in B, \quad \exists x\in A \text{ such that } f(x)=y. \]

Surjective Means Onto

A surjective function is also called an onto function.

The range fills the entire codomain:

\[ \boxed{\operatorname{range}(f)=\operatorname{codomain}(f)}. \]

Surjective Example

Consider

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=2x+1. \]

Take any output

\[ y\in\mathbb{R}. \]

Solve

\[ y=2x+1. \]

Then

\[ x=\frac{y-1}{2}. \]

This is a real input for every real \(y\).

So \(f\) is surjective onto \(\mathbb{R}\).

A Function That Is Not Surjective

Consider

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=x^2. \]

The codomain includes negative real numbers.

But the function never produces a negative output.

Therefore, \(f\) is not surjective onto \(\mathbb{R}\).

Changing the Codomain Can Create Surjectivity

Now define

\[ g:\mathbb{R}\to[0,\infty), \qquad g(x)=x^2. \]

Every nonnegative real number has at least one real square root.

So every codomain value is reached.

Thus, \(g\) is surjective.

Why Codomain Matters for Surjectivity

Surjectivity cannot be determined from the formula and domain alone.

It depends on the declared codomain.

The same formula and domain may be surjective onto one codomain and not surjective onto another.

Range Versus Codomain

If

\[ \operatorname{range}(f) = \operatorname{codomain}(f), \]

then \(f\) is surjective.

If

\[ \operatorname{range}(f) \subsetneq \operatorname{codomain}(f), \]

then \(f\) is not surjective.

Unused Codomain Elements

If even one codomain element is not reached by the function, surjectivity fails.

Surjectivity requires complete coverage of the declared target set.

Bijective Functions

A function is bijective if it is both injective and surjective.

That means:

  • no two distinct inputs share an output;
  • every codomain element is reached.

Bijective Means Perfect Pairing

For a bijection, every input has one output and every codomain output has exactly one input.

There is a perfect one-to-one correspondence between the domain and codomain.

Bijective Example

Consider

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=3x-2. \]

This function is injective because its slope is nonzero.

It is surjective because every real output can be produced.

Therefore, \(f\) is bijective.

Another Bijective Example

Consider

\[ f:[0,\infty)\to[0,\infty), \qquad f(x)=x^2. \]

On this restricted domain, the function is injective.

Every nonnegative codomain value is reached.

Therefore, the function is bijective.

Injective but Not Surjective

Consider

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=e^x. \]

The function is strictly increasing, so it is injective.

But its range is

\[ (0,\infty), \]

not all of \(\mathbb{R}\).

So it is not surjective onto \(\mathbb{R}\).

Surjective but Not Injective

Consider

\[ f:\mathbb{R}\to[0,\infty), \qquad f(x)=x^2. \]

Every nonnegative number is reached, so the function is surjective.

But

\[ f(2)=f(-2), \]

so it is not injective.

Neither Injective nor Surjective

Consider

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=x^2. \]

It is not injective because opposite inputs share outputs.

It is not surjective because negative codomain values are never reached.

Mapping-Diagram View of Injectivity

Suppose

\[ f:\{1,2,3\}\to\{a,b,c,d\} \]

with

\[ 1\mapsto a, \qquad 2\mapsto b, \qquad 3\mapsto c. \]

No two inputs share an output.

So the function is injective.

The codomain element \(d\) is unused, so the function is not surjective.

Mapping-Diagram View of Surjectivity

Suppose

\[ g:\{1,2,3,4\}\to\{a,b,c\} \]

with

\[ 1\mapsto a, \qquad 2\mapsto b, \qquad 3\mapsto c, \qquad 4\mapsto c. \]

Every codomain element is reached, so \(g\) is surjective.

But \(3\) and \(4\) share output \(c\), so \(g\) is not injective.

Mapping-Diagram View of a Bijection

Suppose

\[ h:\{1,2,3\}\to\{a,b,c\} \]

with

\[ 1\mapsto b, \qquad 2\mapsto c, \qquad 3\mapsto a. \]

Each codomain element is used exactly once.

So \(h\) is bijective.

Finite Sets and Counting

If finite sets \(A\) and \(B\) have the same number of elements, then any injective function

\[ f:A\to B \]

must also be surjective.

Likewise, any surjective function must also be injective.

So for finite sets of equal size, injectivity and surjectivity are equivalent.

Why This Happens for Equal Finite Sizes

If there are exactly as many outputs available as inputs, then avoiding collisions forces every output to be used.

Conversely, reaching every output leaves no room for repeated use without leaving some input unmatched.

Infinite Sets Behave Differently

For infinite sets, injective and surjective behavior can be more surprising.

For example,

\[ f:\mathbb{N}\to\mathbb{N}, \qquad f(n)=n+1 \]

is injective but not surjective if \(1\in\mathbb{N}\), because no input maps to \(1\).

Another Infinite-Set Example

Consider

\[ f:\mathbb{Z}\to\mathbb{Z}, \qquad f(n)=2n. \]

The function is injective.

But odd integers are never reached.

So it is not surjective onto \(\mathbb{Z}\).

Surjection with Repeated Outputs

A surjective function may have many inputs that share one output.

Surjectivity only asks whether every codomain element is reached at least once.

It does not require uniqueness.

Injection with Unused Outputs

An injective function may leave part of the codomain unused.

Injectivity concerns uniqueness of outputs among inputs, not complete coverage of the codomain.

Bijective Functions and Inverses

Bijective functions are exactly the functions that have inverses from the codomain back to the domain.

If

\[ f:A\to B \]

is bijective, then there is a function

\[ f^{-1}:B\to A \]

that reverses the assignment.

Why Injectivity Is Needed for an Inverse

If two inputs shared one output, then reversing the function would require that one output to return two different inputs.

That would not define a function.

So injectivity is necessary for a full inverse function.

Why Surjectivity Is Needed for an Inverse

If some codomain element were never reached, then the inverse would have no input-output assignment for that codomain element.

So surjectivity is needed when the inverse is defined on the entire original codomain.

Inverse Pairing

If

\[ f(a)=b, \]

then for a bijective function,

\[ f^{-1}(b)=a. \]

The inverse reverses the arrow.

Restricting Domain to Create an Inverse

The function

\[ f(x)=x^2 \]

on \(\mathbb{R}\) is not injective.

Restrict the domain to

\[ [0,\infty). \]

Then

\[ f:[0,\infty)\to[0,\infty) \]

is bijective, and its inverse is

\[ f^{-1}(x)=\sqrt{x}. \]

Injectivity Proof Method

One standard algebraic method is:

  1. assume \(f(a)=f(b)\);
  2. use algebra to show \(a=b\).

If this implication always works, the function is injective.

Injectivity Proof Example

Let

\[ f(x)=5x-7. \]

Assume

\[ f(a)=f(b). \]

Then

\[ 5a-7=5b-7. \]

So

\[ 5a=5b, \]

and therefore

\[ a=b. \]

Thus, \(f\) is injective.

Surjectivity Proof Method

To prove

\[ f:A\to B \]

is surjective:

  1. take an arbitrary \(y\in B\);
  2. solve \(f(x)=y\);
  3. show that at least one valid \(x\in A\) exists.

Surjectivity Proof Example

Let

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=4x+9. \]

Take any

\[ y\in\mathbb{R}. \]

Solve

\[ 4x+9=y. \]

Then

\[ x=\frac{y-9}{4}. \]

This is real for every real \(y\), so \(f\) is surjective.

Proving a Function Is Not Injective

To prove a function is not injective, one counterexample is enough.

Find distinct inputs

\[ a\ne b \]

such that

\[ f(a)=f(b). \]

Noninjective Counterexample

For

\[ f(x)=x^2, \]

take

\[ a=1, \qquad b=-1. \]

Then

\[ a\ne b \]

but

\[ f(1)=f(-1)=1. \]

So \(f\) is not injective.

Proving a Function Is Not Surjective

To prove a function is not surjective, identify a codomain value that cannot be produced.

One missing output is enough.

Nonsurjective Counterexample

For

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=x^2, \]

the codomain value

\[ -1 \]

has no real preimage.

Therefore, \(f\) is not surjective.

Preimages

If

\[ f(x)=y, \]

then \(x\) is called a preimage of \(y\).

Injectivity says each output has at most one preimage.

Surjectivity says each codomain element has at least one preimage.

Bijectivity says each codomain element has exactly one preimage.

Preimage Summary

Property Number of Preimages per Codomain Element
Injective At most one
Surjective At least one
Bijective Exactly one

Polynomial Examples

A polynomial can be injective on one domain and not on another.

For example,

\[ f(x)=x^3 \]

is strictly increasing on \(\mathbb{R}\), so it is injective.

Its range is also \(\mathbb{R}\), so

\[ f:\mathbb{R}\to\mathbb{R} \]

is bijective.

Even-Degree Polynomial Behavior

An even-degree polynomial such as

\[ f(x)=x^4 \]

is generally not injective on all real numbers because positive and negative inputs can share outputs.

Its range may also fail to cover all real numbers.

Exponential Example

For

\[ f(x)=2^x, \]

the function is strictly increasing and therefore injective.

Its range is

\[ (0,\infty). \]

Thus,

\[ f:\mathbb{R}\to(0,\infty) \]

is bijective.

Logarithmic Example

For

\[ f(x)=\ln x, \qquad x>0, \]

the function is strictly increasing.

Its range is all real numbers.

Therefore,

\[ \ln:(0,\infty)\to\mathbb{R} \]

is bijective.

Absolute Value Example

Consider

\[ f:\mathbb{R}\to[0,\infty), \qquad f(x)=|x|. \]

The function is surjective because every nonnegative number is attained.

But

\[ f(a)=f(-a) \]

for nonzero \(a\), so it is not injective.

Restricting Absolute Value

If we restrict the domain to

\[ [0,\infty), \]

then

\[ f(x)=|x|=x. \]

Now

\[ f:[0,\infty)\to[0,\infty) \]

is bijective.

Finite Table Example

Input Output
1 a
2 c
3 b

If the codomain is

\[ \{a,b,c\}, \]

then each output is used exactly once.

The function is bijective.

Another Table Example

Input Output
1 a
2 a
3 b

If the codomain is

\[ \{a,b\}, \]

the function is surjective but not injective.

Codomain Must Be Known

If a table lists outputs \(a\) and \(b\), we still cannot determine surjectivity unless the codomain is stated.

If the codomain is

\[ \{a,b\}, \]

the function may be surjective.

If the codomain is

\[ \{a,b,c\}, \]

it is not surjective because \(c\) is unused.

Composition of Injective Functions

If

\[ f:A\to B \]

and

\[ g:B\to C \]

are both injective, then

\[ g\circ f \]

is injective.

No collisions are introduced when one collision-free assignment is followed by another.

Composition of Surjective Functions

If both \(f\) and \(g\) are surjective, then

\[ g\circ f \]

is surjective.

Every target in \(C\) is reached through some value in \(B\), which in turn is reached from \(A\).

Composition of Bijections

The composition of two bijections is again a bijection.

This is one reason bijections are so important: they behave well under composition and can be reversed.

Identity Functions Are Bijective

The identity function

\[ I_A:A\to A, \qquad I_A(x)=x \]

is injective and surjective.

Every element maps to itself exactly once.

Bijections Express Structural Equivalence

A bijection pairs two sets without duplication or omission.

This makes bijections fundamental for comparing the sizes and structures of sets.

For finite sets, a bijection shows that the sets contain the same number of elements.

Bijections and Infinite Sets

For infinite sets, bijections lead to surprising comparisons.

For example, the positive integers can be paired bijectively with the even positive integers by

\[ f(n)=2n. \]

This reveals that infinite sets can have proper subsets with the same cardinality.

Worked Example: Classify a Linear Function

Let

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=7x+4. \]

The slope is nonzero, so the function is strictly increasing and injective.

Every real output \(y\) has input

\[ x=\frac{y-4}{7}. \]

Therefore, the function is surjective.

So \(f\) is

\[ \boxed{\text{bijective}}. \]

Worked Example: Classify \(x^2\)

Let

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=x^2. \]

Not injective:

\[ f(1)=f(-1)=1. \]

Not surjective:

\[ -1 \]

is not in the range.

Therefore, \(f\) is

\[ \boxed{\text{neither injective nor surjective}}. \]

Worked Example: Same Formula, New Codomain

Let

\[ f:\mathbb{R}\to[0,\infty), \qquad f(x)=x^2. \]

The function is surjective because every nonnegative output is attained.

It is still not injective because

\[ f(2)=f(-2). \]

So it is

\[ \boxed{\text{surjective but not injective}}. \]

Worked Example: Restrict the Domain

Let

\[ f:[0,\infty)\to[0,\infty), \qquad f(x)=x^2. \]

The function is strictly increasing on its domain, so it is injective.

Every nonnegative number has a nonnegative square root, so it is surjective.

Therefore, it is

\[ \boxed{\text{bijective}}. \]

Worked Example: Exponential Function

Let

\[ f:\mathbb{R}\to\mathbb{R}, \qquad f(x)=2^x. \]

The function is injective because it is strictly increasing.

But it is not surjective onto \(\mathbb{R}\) because its outputs are always positive.

So it is

\[ \boxed{\text{injective but not surjective}}. \]

A Reliable Injectivity Workflow

  1. Identify the domain.
  2. Look for repeated outputs from distinct inputs.
  3. Use the horizontal-line test when a graph is available.
  4. Use strict monotonicity when known.
  5. For an algebraic proof, assume \(f(a)=f(b)\) and show \(a=b\).
  6. Remember that restricting the domain can change injectivity.

A Reliable Surjectivity Workflow

  1. Identify the codomain.
  2. Determine the actual range.
  3. Compare the range with the codomain.
  4. For a proof, take arbitrary \(y\) in the codomain and solve \(f(x)=y\).
  5. Check that the resulting input lies in the domain.
  6. One missing codomain value is enough to disprove surjectivity.

A Reliable Bijectivity Workflow

  1. Check injectivity.
  2. Check surjectivity.
  3. If both hold, the function is bijective.
  4. Then an inverse function from codomain to domain can be defined.

Common Errors

Confusing Function with Injective Function

A function may allow different inputs to share an output.

Ignoring the Codomain When Testing Surjectivity

Surjectivity depends on the declared codomain, not only on the range.

Assuming Strictly Increasing Is the Same as Surjective

Strict increase gives injectivity, not necessarily surjectivity.

Using the Vertical-Line Test for Injectivity

The horizontal-line test checks injectivity.

Assuming the Same Formula Has the Same Classification on Every Domain

Domain restriction can change injectivity and bijectivity.

Assuming Every Injective Function Has an Inverse on Its Entire Codomain

A full inverse from the codomain requires surjectivity as well.

Forgetting That Bijective Means Both Conditions

Injective alone or surjective alone is not enough.

Key Ideas

  • An injective function never sends two distinct inputs to the same output.
  • Injective and one-to-one mean the same thing.
  • A surjective function reaches every element of its codomain.
  • Surjective and onto mean the same thing.
  • A bijective function is both injective and surjective.
  • Injectivity depends on the domain.
  • Surjectivity depends on the codomain.
  • The same formula can have different classifications under different domains and codomains.
  • Strictly increasing or strictly decreasing functions are injective on the interval of monotonicity.
  • The horizontal-line test checks injectivity for graphs.
  • Range equals codomain exactly when the function is surjective.
  • Bijective functions pair domain and codomain elements exactly once.
  • Bijectivity is the structural condition needed for a full inverse function.
  • Domain restriction can turn a noninjective function into a bijection.
  • Bijections are fundamental for inverse functions, set comparison, and structural equivalence.

Where This Leads

Injective, surjective, and bijective functions provide the structural language needed to understand when functions can be reversed and how sets correspond.

These ideas lead directly into inverse functions, composition, identity functions, restricted domains, cardinality, isomorphisms, coordinate transformations, and many higher-level settings where preserving or perfectly matching mathematical structure becomes central.
