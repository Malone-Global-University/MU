Forward and Inverse Models

A forward model starts with known or assumed parameters and predicts what we should observe. An inverse model starts with observations and asks what parameter values, states, sources, or hidden structures could have produced them. This reversal sounds simple, but inverse problems are often much harder: several unknowns can produce the same data, measurement noise can be amplified, and some features of the hidden system may never reach the observations at all.

The Forward Direction

Suppose a model depends on unknown or adjustable parameters

\[ \boldsymbol{\theta}. \]

The forward model maps those parameters to predicted observations:

\[ \boxed{ \hat{\mathbf{y}} = F(\boldsymbol{\theta}) }. \]

In this expression:

  • \(\boldsymbol{\theta}\) is the parameter vector;
  • \(F\) is the forward map;
  • \(\hat{\mathbf{y}}\) is the predicted data.

The Inverse Direction

In an inverse problem, we observe

\[ \mathbf{y}_{\text{obs}} \]

and try to infer

\[ \boldsymbol{\theta}. \]

Conceptually,

\[ \boxed{ \mathbf{y}_{\text{obs}} \longrightarrow \boldsymbol{\theta} }. \]

But this arrow is not usually an ordinary algebraic inverse.

Instead, we solve an estimation problem that asks which parameter values are most consistent with the observations.

Forward Models Predict; Inverse Models Infer

The distinction can be summarized as:

\[ \boxed{ \text{forward problem} : \boldsymbol{\theta} \rightarrow \mathbf{y} } \] \[ \boxed{ \text{inverse problem} : \mathbf{y} \rightarrow \boldsymbol{\theta} }. \]

Forward modeling asks: If these parameters were true, what would we observe?

Inverse modeling asks: Given what we observed, which parameters are plausible?

A Simple Linear Example

Consider the forward relationship

\[ y=3\theta+2. \]

If

\[ \theta=4, \]

then the forward model gives

\[ y = 3(4)+2 = 14. \]

This is a forward calculation.

The Corresponding Inverse Example

If instead we observe

\[ y=14, \]

then solving

\[ 14=3\theta+2 \]

gives

\[ \boxed{ \theta=4 }. \]

In this simple case, the inverse is exact and unique.

Why Real Inverse Problems Are Harder

Real inverse problems often include:

  • many parameters;
  • nonlinear forward models;
  • measurement noise;
  • incomplete observations;
  • parameter interactions;
  • hidden states;
  • model approximation error.

The inverse problem must handle all of these simultaneously.

Observation Noise

A more realistic observation model is

\[ \boxed{ \mathbf{y}_{\text{obs}} = F(\boldsymbol{\theta}) + \boldsymbol{\varepsilon} }. \]

The noise term

\[ \boldsymbol{\varepsilon} \]

means that the true parameter value may not reproduce the observations exactly.

Exact Inversion Versus Estimation

If there is no noise and \(F\) is exactly invertible, one might write

\[ \boldsymbol{\theta} = F^{-1}(\mathbf{y}). \]

But with noise, we usually seek

\[ \hat{\boldsymbol{\theta}} \]

that makes

\[ F(\hat{\boldsymbol{\theta}}) \]

sufficiently close to the observations.

Inverse modeling is therefore usually an estimation problem rather than a literal algebraic reversal.

Residuals

The residual vector is

\[ \boxed{ \mathbf{r}(\boldsymbol{\theta}) = \mathbf{y}_{\text{obs}} - F(\boldsymbol{\theta}) }. \]

Parameter fitting seeks values of \(\boldsymbol{\theta}\) that make these residuals acceptably small according to a chosen criterion.

Objective Functions

A common inverse formulation minimizes an objective:

\[ \boxed{ \hat{\boldsymbol{\theta}} = \operatorname*{arg\,min}_{\boldsymbol{\theta}} \Phi(\boldsymbol{\theta}) }. \]

For ordinary least squares,

\[ \Phi(\boldsymbol{\theta}) = \|\mathbf{r}(\boldsymbol{\theta})\|_2^2. \]

Forward Models May Contain Hidden States

The forward model may itself require solving for an internal state

\[ \mathbf{x}. \]

For example,

\[ G( \mathbf{x}, \boldsymbol{\theta} ) = \mathbf{0}, \]

followed by an observation map

\[ \hat{\mathbf{y}} = H(\mathbf{x}). \]

The full forward process is then

\[ \boldsymbol{\theta} \rightarrow \mathbf{x} \rightarrow \hat{\mathbf{y}}. \]

The Observation Operator

The function

\[ H \]

converts the model state into what the instrument actually measures.

The observation operator may:

  • select only some state variables;
  • average over space or time;
  • integrate along paths;
  • transform units;
  • apply sensor response functions.

Why Observation Operators Matter

A model can contain information that no sensor ever observes.

If a state component never influences

\[ H(\mathbf{x}), \]

then that component may be impossible to recover from the data.

This connects inverse modeling directly to identifiability.

A Linear Vector Model

A common forward model is

\[ \boxed{ \mathbf{y} = X\boldsymbol{\theta} }. \]

Here:

  • \(X\) is a known design or system matrix;
  • \(\boldsymbol{\theta}\) is the unknown parameter vector;
  • \(\mathbf{y}\) is the predicted observation vector.

Square, Overdetermined, and Underdetermined Systems

If \(X\) is \(n\times p\), then:

  • \(n=p\): the system is square;
  • \(n>p\): the system is overdetermined;
  • \(n

These cases behave differently in inverse estimation.

Overdetermined Inverse Problems

When

\[ n>p, \]

there are more observations than unknown parameters.

With noisy data, the equations generally cannot all be satisfied exactly.

Least squares finds the parameter vector that best compromises among the observations.

Underdetermined Inverse Problems

When

\[ n there are fewer observations than unknown parameters.

Many parameter vectors may reproduce the data.

Additional structure, constraints, regularization, or prior information may be needed.

Uniqueness

An inverse problem is unique if one admissible observation vector corresponds to at most one admissible parameter vector.

If

\[ F(\boldsymbol{\theta}_1) = F(\boldsymbol{\theta}_2) \]

implies

\[ \boldsymbol{\theta}_1 = \boldsymbol{\theta}_2, \]

then \(F\) is injective on the relevant domain.

A Nonunique Forward Map

Consider

\[ y=\theta^2. \]

Then

\[ F(3)=9 \]

and

\[ F(-3)=9. \]

The same observation corresponds to two parameter values.

Therefore, the inverse is not unique on all real numbers.

Domain Restrictions Can Restore Uniqueness

If physics tells us

\[ \theta\ge0, \]

then

\[ y=\theta^2 \]

becomes invertible through

\[ \theta=\sqrt{y}. \]

Physical constraints can therefore change an inverse problem from nonunique to unique.

Identifiability

In parameter estimation, uniqueness is usually discussed through identifiability.

A parameter is identifiable if the observation process distinguishes its value from competing values.

The next lesson develops this idea in detail.

Parameter Combinations

Sometimes individual parameters are not identifiable even though a combination is.

Consider

\[ y=(ab)x. \]

The data may determine

\[ ab \]

very accurately while leaving \(a\) and \(b\) separately ambiguous.

Forward Sensitivity

Sensitivity measures how strongly predicted data change when parameters change.

For a scalar model,

\[ S(\theta) = \frac{dF}{d\theta}. \]

Large sensitivity means the data respond strongly to parameter changes.

Small sensitivity means the parameter is weakly visible in the observations.

Jacobian Sensitivity

For vector parameters and observations,

\[ \boxed{ J = \frac{ \partial F }{ \partial\boldsymbol{\theta} } }. \]

Entry

\[ J_{ij} \]

measures how observation \(i\) changes when parameter \(j\) changes.

Sensitivity and Inverse Stability

If a parameter direction produces almost no change in the observations, the inverse problem must infer that direction from very weak evidence.

Measurement noise can then overwhelm the small parameter signal.

Low forward sensitivity often corresponds to high inverse uncertainty.

A Small-Sensitivity Example

Suppose

\[ y=0.001\theta. \]

Then

\[ \theta=1000y. \]

An observation error of only

\[ 0.01 \]

produces parameter error

\[ 10. \]

The forward model is simple, but the inverse is highly sensitive.

Well-Posed and Ill-Posed Inverse Problems

A classical well-posed problem has:

  1. a solution;
  2. a unique solution;
  3. stable dependence on the data.

If one or more conditions fail, the inverse problem is ill posed.

Forward Problems Can Be Easier Than Inverse Problems

A forward simulation may be stable and straightforward:

\[ \boldsymbol{\theta} \rightarrow \mathbf{y}. \]

But reconstructing

\[ \mathbf{y} \rightarrow \boldsymbol{\theta} \]

can be unstable because information may have been smoothed, averaged, or compressed by the forward process.

Information Loss

Many forward processes reduce information.

Examples include:

  • averaging;
  • integration;
  • projection;
  • blurring;
  • sampling at only a few locations;
  • measuring only selected state variables.

Inversion must work with whatever information survives this process.

Forward Models in Differential Equations

Suppose parameters determine a differential equation:

\[ \frac{dx}{dt} = f( x, \boldsymbol{\theta}, t ). \]

Solving the equation gives

\[ x(t;\boldsymbol{\theta}). \]

The observation model then produces

\[ y_i = H( x(t_i;\boldsymbol{\theta}) ) + \varepsilon_i. \]

Inverse Problems in Differential Equations

The inverse problem may estimate:

  • rate constants;
  • initial conditions;
  • forcing amplitudes;
  • boundary conditions;
  • material coefficients;
  • hidden states.

Each candidate parameter vector may require a new differential-equation solve.

Forward Models in Imaging

In imaging, the unknown may be a spatial field

\[ \mathbf{x}. \]

Measurements may satisfy

\[ \mathbf{y} = A\mathbf{x} + \boldsymbol{\varepsilon}. \]

The inverse reconstructs the hidden image from the indirect observations.

Forward Models in Data Assimilation

In a dynamical system,

\[ \mathbf{x}_{k+1} = f(\mathbf{x}_k) \]

is a forward evolution model.

Observations

\[ \mathbf{y}_k = h(\mathbf{x}_k) + \mathbf{v}_k \]

are then used inversely to update the hidden state.

Inverse Problems Need a Statistical Model

Once noise is present, a statistical observation model becomes natural:

\[ \boxed{ p( \mathbf{y} \mid \boldsymbol{\theta} ) }. \]

This distribution describes how likely different observations are for a given parameter value.

Maximum-likelihood and Bayesian methods build directly on this structure.

Least-Squares Inversion

If measurement errors are modeled with independent Gaussian noise of common variance, maximum likelihood leads to

\[ \boxed{ \hat{\boldsymbol{\theta}} = \operatorname*{arg\,min}_{\boldsymbol{\theta}} \sum_i \left[ y_i - F_i(\boldsymbol{\theta}) \right]^2 }. \]

This is nonlinear or linear least-squares estimation depending on \(F\).

Bayesian Inversion

Bayesian inverse problems combine the likelihood with prior information:

\[ \boxed{ p( \boldsymbol{\theta} \mid \mathbf{y} ) \propto p( \mathbf{y} \mid \boldsymbol{\theta} ) p( \boldsymbol{\theta} ) }. \]

Instead of producing only one estimate, the Bayesian solution describes a distribution of plausible parameter values.

Regularized Inversion

Weakly determined inverse problems often require regularization:

\[ \boxed{ \hat{\boldsymbol{\theta}} = \operatorname*{arg\,min}_{\boldsymbol{\theta}} \left[ \Phi_{\text{data}} ( \boldsymbol{\theta} ) + \lambda R( \boldsymbol{\theta} ) \right] }. \]

The regularizer adds structure that stabilizes weakly observed directions.

Constraints in Inverse Models

Physical knowledge may require:

\[ \theta_j\ge0, \]

or

\[ \theta_{\min} \le \theta_j \le \theta_{\max}. \]

Other constraints may enforce:

  • sum-to-one conditions;
  • monotonicity;
  • mass conservation;
  • smoothness;
  • known signs.

Constraints Add Information

If a constraint narrows the admissible parameter set, the resulting estimate is supported jointly by the observations and the constraint.

This is often desirable, but it should be acknowledged explicitly.

Inverse Problems and Optimization

Many inverse problems become optimization problems because the exact inverse is unavailable.

A solver repeatedly evaluates:

\[ \boldsymbol{\theta} \rightarrow F(\boldsymbol{\theta}) \rightarrow \mathbf{r} \rightarrow \Phi. \]

The optimizer then proposes a new parameter vector.

The Forward Model Is Inside the Inverse Loop

This is one of the most important computational facts:

\[ \boxed{ \text{inverse estimation repeatedly calls the forward model} }. \]

If one forward run is expensive, inverse estimation may be much more expensive.

Computational Cost

Suppose one forward model evaluation takes time

\[ T_F. \]

If the optimizer requires

\[ N \]

evaluations, then the total forward-model cost is approximately

\[ NT_F. \]

Gradient estimation, uncertainty analysis, and repeated fits can multiply this cost further.

Surrogate Models

If the forward model is expensive, one may construct a faster approximation

\[ \tilde F(\boldsymbol{\theta}) \approx F(\boldsymbol{\theta}). \]

Such a surrogate model can accelerate parameter sweeps, optimization, or uncertainty analysis.

The surrogate error must itself be checked.

Synthetic Data

Before applying an inverse method to real observations, generate synthetic data from known parameters:

\[ \mathbf{y}_{\text{syn}} = F( \boldsymbol{\theta}_{\text{true}} ) + \boldsymbol{\varepsilon}. \]

Then test whether the inverse method can recover

\[ \boldsymbol{\theta}_{\text{true}}. \]

Why Synthetic Recovery Is Important

Synthetic tests can reveal:

  • implementation errors;
  • parameter nonidentifiability;
  • optimizer failure;
  • noise sensitivity;
  • regularization bias;
  • poor uncertainty estimates.

Forward Validation

Even a successful inverse fit should be checked in the forward direction.

Compute

\[ F( \hat{\boldsymbol{\theta}} ) \]

and compare it directly with the observed data.

A plausible parameter vector must also reproduce the relevant measurements.

Inverse Validation

If possible, test the estimated parameters using independent data or a separate experiment.

This checks whether the inferred parameters describe reproducible system behavior rather than only one fitting sample.

Multiple Solutions

Nonlinear inverse problems may have several parameter vectors that fit the data similarly well.

This can produce:

  • multiple objective minima;
  • multiple likelihood modes;
  • disconnected posterior regions.

A single optimizer run may reveal only one of them.

Local Versus Global Inversion

A model may be locally invertible around one solution while remaining globally nonunique.

Local derivative information can establish only local behavior.

Global inverse structure requires broader exploration of parameter space.

Parameter Scaling

If parameters have very different numerical scales, inverse optimization can become difficult.

For example,

\[ \theta_1\sim10^{-6} \]

while

\[ \theta_2\sim10^5. \]

Dimensionless or scaled coordinates often improve conditioning and optimizer behavior.

Dimensionless Parameters

Introduce characteristic scales

\[ s_j \]

and define

\[ q_j = \frac{\theta_j}{s_j}. \]

Then solve the inverse problem in terms of the dimensionless variables

\[ \mathbf{q}. \]

Experimental Design

Inverse estimation improves when experiments are chosen to make parameter effects more distinguishable.

Useful design choices include:

  • measurement times;
  • sensor locations;
  • input amplitudes;
  • viewing angles;
  • multiple experimental conditions.

Better Forward Excitation Can Improve the Inverse

Parameters that are invisible under one experimental condition may become observable under another.

Therefore, the best way to solve an inverse problem is sometimes to improve the experiment rather than improve the optimizer.

Common Error: Assuming Every Forward Model Has a Unique Inverse

A forward function can map several parameter values to the same observation.

Always check uniqueness and identifiability before interpreting a fitted parameter value as uniquely determined.

Common Error: Ignoring the Observation Model

The mathematical state of a model is not always what the instrument measures.

The observation operator must represent the actual measurement process.

Common Error: Fitting Noise Exactly

Real observations contain uncertainty.

Forcing a highly flexible inverse model to reproduce every measured fluctuation can amplify noise and produce unstable parameter estimates.

Common Error: Confusing Numerical Convergence with Correctness

An optimizer can converge successfully to a parameter vector even when:

  • the model is wrong;
  • the parameters are not identifiable;
  • the solution is only a local optimum;
  • the data are insufficient.

Common Error: Reporting Only the Best-Fit Parameters

A complete inverse analysis should also report:

  • fit quality;
  • residual structure;
  • parameter uncertainty;
  • sensitivity;
  • identifiability;
  • dependence on assumptions.

A Reliable Forward-to-Inverse Workflow

  1. Define the physical or mathematical parameters.
  2. Implement the forward model.
  3. Define the observation operator.
  4. Specify measurement noise and uncertainty.
  5. Check parameter scaling and domains.
  6. Analyze sensitivity and identifiability.
  7. Choose a residual, likelihood, or posterior formulation.
  8. Fit or infer the parameters.
  9. Check multiple initial values or parameter regions when needed.
  10. Re-run the forward model at the estimated parameters.
  11. Inspect residuals and uncertainty.
  12. Validate using synthetic or independent data.

What to Remember

Forward and inverse models use the same mathematical system in opposite directions.

  • A forward model predicts observations from parameters or states.
  • An inverse problem infers hidden quantities from observations.
  • Real inverse problems usually involve noise and require estimation.
  • The observation operator connects the model state to what is actually measured.
  • Uniqueness depends on whether different parameter values can produce the same data.
  • Sensitivity determines how strongly parameters influence observations.
  • Weakly sensitive directions lead to large inverse uncertainty.
  • Underdetermined systems require additional structure or information.
  • Optimization, likelihood, Bayesian inference, and regularization are all inverse strategies.
  • The forward model is repeatedly evaluated inside most inverse algorithms.
  • Synthetic recovery tests are essential for validating inverse implementations.
  • Better experiments can improve an inverse problem more than a better optimizer.

The central principle is:

\[ \boxed{ \text{before solving an inverse problem, understand exactly how the forward model creates the data} }. \]
