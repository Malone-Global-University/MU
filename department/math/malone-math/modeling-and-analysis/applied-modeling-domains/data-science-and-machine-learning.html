Data Science and Machine Learning

Data science and machine learning build mathematical models from observations. Some models estimate relationships, some classify outcomes, some discover structure, and some make predictions or decisions. Their success depends not only on algorithms but also on data quality, feature design, loss functions, validation strategy, uncertainty, and the distinction between fitting observed patterns and learning relationships that generalize beyond the training data.

The Central Idea

A data-driven modeling workflow can be summarized as

\[ \boxed{ \text{data} \longrightarrow \text{representation} \longrightarrow \text{model} \longrightarrow \text{loss} \longrightarrow \text{training} \longrightarrow \text{validation} \longrightarrow \text{decision} }. \]

The model is only one part of the pipeline. Poor data, leakage, inappropriate objectives, or weak validation can invalidate an otherwise sophisticated algorithm.

Observations and Features

Suppose a dataset contains \(n\) observations and \(p\) measured features. A feature vector for observation \(i\) may be written

\[ \boxed{ \mathbf{x}_i = \begin{bmatrix} x_{i1}\\ x_{i2}\\ \vdots\\ x_{ip} \end{bmatrix} }. \]

The outcome or target is often denoted \(y_i\).

The Design Matrix

Collecting feature vectors into rows gives a design matrix

\[ \boxed{ X= \begin{bmatrix} x_{11}&x_{12}&\cdots&x_{1p}\\ x_{21}&x_{22}&\cdots&x_{2p}\\ \vdots&\vdots&\ddots&\vdots\\ x_{n1}&x_{n2}&\cdots&x_{np} \end{bmatrix} }. \]

Many machine-learning methods can be expressed as operations on \(X\), a target vector \(\mathbf{y}\), and model parameters.

Supervised Learning

In supervised learning, observations include both inputs and target values:

\[ \boxed{ (\mathbf{x}_i,y_i) }. \]

The objective is to learn a function

\[ \boxed{ \hat y=f(\mathbf{x};\theta) } \]

that predicts targets for new inputs.

Regression

Regression predicts a quantitative target. A linear regression model is

\[ \boxed{ \hat y = \beta_0 +\beta_1x_1 +\cdots +\beta_px_p }. \]

The coefficients describe how the fitted prediction changes as features change, holding the other modeled features fixed.

Residuals

A residual is the difference between observed and predicted outcome:

\[ \boxed{ e_i=y_i-\hat y_i }. \]

Residual patterns can reveal model misspecification, nonlinear structure, changing variance, outliers, or omitted variables.

Least Squares

Ordinary least squares chooses parameters to minimize the sum of squared residuals:

\[ \boxed{ J(\beta) = \sum_{i=1}^{n} (y_i-\hat y_i)^2 }. \]

Squaring emphasizes larger errors and creates a smooth optimization problem.

Matrix Form of Linear Regression

A linear model may be written

\[ \boxed{ \mathbf{y}=X\boldsymbol{\beta}+\boldsymbol{\varepsilon} }. \]

When \(X^TX\) is invertible, the least-squares solution is

\[ \boxed{ \hat{\boldsymbol{\beta}} = (X^TX)^{-1}X^T\mathbf{y} }. \]

In numerical practice, more stable matrix factorizations are generally preferred to forming the inverse explicitly.

Nonlinear Regression

Regression models need not be linear in the inputs. A model may include powers, interactions, splines, kernels, trees, neural networks, or other nonlinear structures.

Greater flexibility can improve fit but also increases the risk of overfitting.

Classification

Classification predicts a discrete category. In binary classification,

\[ y\in\{0,1\}. \]

A model may output either a class label or an estimated probability

\[ \boxed{ \hat p=P(Y=1\mid\mathbf{x}) }. \]

Logistic Regression

Logistic regression maps a linear score to a probability:

\[ z=\beta_0+\boldsymbol{\beta}^T\mathbf{x} \] \[ \boxed{ \hat p = \frac{1}{1+e^{-z}} }. \]

The logistic function constrains the model output to the interval \((0,1)\).

Odds and Log-Odds

If \(p\) is an event probability, the odds are

\[ \boxed{ \frac{p}{1-p} }. \]

The log-odds are

\[ \boxed{ \log\left(\frac{p}{1-p}\right) }. \]

Logistic regression models the log-odds as a linear function of the features.

Decision Thresholds

A probability model becomes a class decision only after a threshold is chosen:

\[ \hat y= \begin{cases} 1,&\hat p\ge t,\\ 0,&\hat p The threshold \(t\) should reflect the relative costs of false positives and false negatives.

Confusion Matrix

Binary classification outcomes can be organized into

  • true positives;
  • false positives;
  • true negatives;
  • false negatives.

Different performance metrics summarize different combinations of these counts.

Accuracy

Accuracy is

\[ \boxed{ \text{accuracy} = \frac{TP+TN}{TP+TN+FP+FN} }. \]

Accuracy can be misleading when classes are highly imbalanced.

Precision and Recall

Precision is

\[ \boxed{ \text{precision} = \frac{TP}{TP+FP} }. \]

Recall is

\[ \boxed{ \text{recall} = \frac{TP}{TP+FN} }. \]

Precision emphasizes reliability of positive predictions, while recall emphasizes finding positive cases.

F1 Score

The F1 score is the harmonic mean of precision and recall:

\[ \boxed{ F_1 = 2\frac{PR}{P+R} }. \]

It is useful when both false positives and false negatives matter.

Probability Calibration

A classifier can rank cases well while producing poor probability estimates. A calibrated model should satisfy, approximately,

\[ \boxed{ \text{among cases assigned probability }p, \text{ about fraction }p\text{ should occur} }. \]

Calibration is especially important when probabilities support decisions.

Unsupervised Learning

Unsupervised learning uses data without target labels and seeks structure in the feature space.

Common tasks include clustering, dimensional reduction, density estimation, and anomaly detection.

Clustering

Clustering groups observations according to a similarity or distance rule.

A clustering result is not automatically a discovery of natural or causal categories. It depends on representation, scaling, distance, and algorithm.

K-Means Clustering

K-means assigns observations to \(K\) cluster centers and minimizes within-cluster squared distance:

\[ \boxed{ J = \sum_{i=1}^{n} \left\| \mathbf{x}_i-\boldsymbol{\mu}_{c_i} \right\|^2 }. \]

Here \(c_i\) is the cluster assigned to observation \(i\).

Distance Matters

Euclidean distance between vectors is

\[ \boxed{ d(\mathbf{x},\mathbf{y}) = \sqrt{ \sum_{j=1}^{p} (x_j-y_j)^2 } }. \]

Features measured on larger numerical scales can dominate this distance unless the representation is standardized appropriately.

Feature Scaling

A standardized feature is

\[ \boxed{ z=\frac{x-\mu}{\sigma} }. \]

Standardization gives the feature mean \(0\) and standard deviation \(1\) on the dataset used to estimate \(\mu\) and \(\sigma\).

Training-Time Transformations

Scaling, imputation, feature selection, and other learned preprocessing steps must be estimated using training data only.

Applying information from validation or test data during preprocessing creates leakage.

Dimensional Reduction

High-dimensional data can contain redundant or correlated directions. Dimensional-reduction methods seek lower-dimensional representations that preserve selected structure.

Principal Component Analysis

Principal component analysis, or PCA, finds orthogonal directions of maximum variance in centered data.

If \(\Sigma\) is a covariance matrix, principal directions satisfy

\[ \boxed{ \Sigma\mathbf{v} = \lambda\mathbf{v} }. \]

Eigenvectors with larger eigenvalues capture more variance.

Explained Variance

If PCA eigenvalues are

\[ \lambda_1\ge\lambda_2\ge\cdots\ge\lambda_p, \]

the fraction of total variance explained by component \(j\) is

\[ \boxed{ \frac{\lambda_j} {\sum_{k=1}^{p}\lambda_k} }. \]

Train, Validation, and Test Sets

A common workflow separates data into

  • training data for fitting parameters;
  • validation data for model and hyperparameter choices;
  • test data for final evaluation.

The test set should remain untouched until model development is complete.

Generalization

Generalization is the ability to perform well on new data drawn from the intended deployment environment.

Low training error alone does not demonstrate generalization.

Overfitting

Overfitting occurs when a model learns noise or idiosyncratic structure in the training data that does not transfer to new data.

A common symptom is very low training error combined with substantially worse validation error.

Underfitting

Underfitting occurs when a model is too simple or insufficiently trained to capture important structure.

Both training and validation error may remain high.

Bias-Variance Tradeoff

Flexible models can reduce approximation bias but may become more sensitive to sampling variation. Simpler models may be more stable but less expressive.

Model complexity should be matched to data quantity, noise, and the prediction task.

Cross-Validation

In \(K\)-fold cross-validation, data are divided into \(K\) parts. Each part is used once for validation while the remaining \(K-1\) parts are used for training.

The average validation score estimates out-of-sample performance more efficiently than a single split in many settings.

Time-Series Validation

Random train-test splitting is inappropriate when future observations must be predicted from past information.

Time-series validation preserves temporal order:

\[ \boxed{ \text{train on past} \longrightarrow \text{validate on later data} }. \]

Data Leakage

Leakage occurs when information unavailable at prediction time enters model training or feature construction.

Leakage can produce unrealistically strong validation results that collapse in deployment.

Loss Functions

Training requires an objective. A generic empirical risk is

\[ \boxed{ J(\theta) = \frac{1}{n} \sum_{i=1}^{n} L(y_i,f(\mathbf{x}_i;\theta)) }. \]

The loss function determines which kinds of errors the training process penalizes.

Mean Squared Error

For regression,

\[ \boxed{ MSE = \frac{1}{n} \sum_{i=1}^{n} (y_i-\hat y_i)^2 }. \]

Mean Absolute Error

Another regression loss is

\[ \boxed{ MAE = \frac{1}{n} \sum_{i=1}^{n} |y_i-\hat y_i| }. \]

MAE gives large residuals less leverage than squared error.

Cross-Entropy Loss

For binary probabilistic classification,

\[ \boxed{ L = -\left[ y\ln\hat p +(1-y)\ln(1-\hat p) \right] }. \]

Confident incorrect probabilities are penalized strongly.

Regularization

Regularization penalizes model complexity. A general objective is

\[ \boxed{ J_{\text{reg}}(\theta) = J(\theta)+\lambda\Omega(\theta) }. \]

The parameter \(\lambda\) controls the tradeoff between fit and penalty.

L2 Regularization

Ridge-type regularization uses

\[ \boxed{ \Omega(\boldsymbol{\beta}) = \sum_j\beta_j^2 }. \]

It discourages large coefficients and can stabilize models with correlated features.

L1 Regularization

Lasso-type regularization uses

\[ \boxed{ \Omega(\boldsymbol{\beta}) = \sum_j|\beta_j| }. \]

L1 penalties can drive some coefficients exactly to zero and therefore perform a form of feature selection.

Optimization

Training many models requires numerical optimization:

\[ \boxed{ \theta^* = \arg\min_{\theta}J(\theta) }. \]

For differentiable objectives, gradients provide local information about how the loss changes with parameters.

Gradient Descent

Gradient descent updates parameters by

\[ \boxed{ \theta_{k+1} = \theta_k - \eta\nabla J(\theta_k) }. \]

The learning rate \(\eta\) controls step size.

Learning Rate

If the learning rate is too small, training may be unnecessarily slow. If it is too large, the algorithm may oscillate or diverge.

Learning-rate selection is therefore part of implementation, not merely a software setting.

Stochastic Gradient Methods

Large datasets often estimate the gradient from a subset, or mini-batch, of the training data.

This reduces computation per update and introduces gradient noise that can be useful in large-scale optimization.

Decision Trees

Decision trees recursively partition feature space into regions and assign a prediction within each region.

Trees are flexible and interpretable locally but can overfit when grown without constraint.

Ensemble Models

Ensembles combine predictions from multiple models:

\[ \boxed{ \hat y = \sum_{m=1}^{M}w_m\hat y_m }. \]

Averaging can reduce variance, while sequential ensembles can focus later models on errors made by earlier ones.

Random Forests

Random forests combine many decision trees trained on resampled data with randomized feature selection.

Their diversity reduces the variance associated with a single tree.

Boosting

Boosting builds models sequentially so later learners focus on errors not yet captured adequately.

The resulting model can be highly predictive but requires careful regularization and validation.

Nearest-Neighbor Methods

A nearest-neighbor model predicts using observations located near a query point in feature space.

Performance depends heavily on the distance metric, feature scaling, and local data density.

Kernel Methods

Kernel methods compare observations through a similarity function

\[ \boxed{ K(\mathbf{x},\mathbf{z}) }. \]

They can represent nonlinear relationships without constructing every nonlinear feature explicitly.

Neural Networks

A neural network composes linear transformations with nonlinear activation functions. A single layer may be written

\[ \boxed{ \mathbf{h} = \phi(W\mathbf{x}+\mathbf{b}) }. \]

Multiple layers create flexible function approximators.

Parameters in Neural Networks

Weights and biases are estimated by minimizing a training loss, usually with gradient-based optimization.

Large neural networks can contain millions or billions of parameters, making data quality, regularization, evaluation, and computational design especially important.

Representation Learning

Traditional models often depend on manually designed features. Deep learning can learn intermediate representations jointly with the prediction task.

This is especially useful for images, audio, text, and other high-dimensional structured data.

Classification versus Ranking

Some applications care less about the final class threshold and more about ordering observations by likelihood or priority.

Ranking quality and probability calibration are distinct performance goals.

ROC Curves

A receiver operating characteristic curve compares true-positive and false-positive rates across classification thresholds.

It measures ranking behavior across thresholds rather than performance at one operational cutoff.

Precision-Recall Curves

Precision-recall curves are often more informative than ROC curves when positive cases are rare and the operational focus is on positive predictions.

Imbalanced Classes

If only \(1\%\) of cases are positive, a model that always predicts the negative class achieves \(99\%\) accuracy while being useless for detecting positives.

Metrics must match the actual task.

Missing Data

Missing values can arise from sensor failure, survey nonresponse, incomplete records, or data-integration problems.

The consequences depend on why the data are missing, not merely on the fraction missing.

Imputation

Imputation replaces missing values using a rule or predictive model.

Imputation must be fitted using training information only, and uncertainty introduced by missingness should not be ignored when it materially affects the decision.

Outliers

Extreme observations may represent errors, rare valid cases, regime changes, or the most important events in the dataset.

Removing them automatically can destroy information about tail behavior.

Feature Engineering

Feature engineering constructs informative model inputs from raw data.

Examples include

  • ratios and rates;
  • lags and rolling averages;
  • interaction terms;
  • log transformations;
  • cyclical encodings;
  • domain-specific physical or operational quantities.

Feature Selection

Feature selection removes inputs that add noise, instability, cost, or complexity without sufficient predictive value.

Selection should occur within the training and validation process to avoid optimistic evaluation.

Correlation Does Not Establish Causation

Predictive models learn statistical relationships. A feature can be highly predictive because it is a cause, an effect, a proxy, or simply correlated with an unobserved common factor.

Causal interpretation requires additional design or assumptions.

Causal Modeling

Causal analysis asks how outcomes would change under interventions.

The relevant quantity may be a contrast such as

\[ \boxed{ E[Y(1)-Y(0)] }. \]

This is conceptually different from predicting \(Y\) from observed features.

Distribution Shift

A model may fail when deployment data differ from training data.

Changes can occur in

  • feature distributions;
  • outcome prevalence;
  • relationships between features and targets;
  • measurement systems;
  • behavior or policy.

Concept Drift

Concept drift occurs when the relationship between inputs and outcomes changes over time.

Models used in dynamic environments may require monitoring, retraining, or explicit time-varying structure.

Monitoring

Production models should be monitored for

  • input drift;
  • missingness changes;
  • prediction drift;
  • performance decay;
  • calibration changes;
  • latency or system failures.

Uncertainty in Prediction

A point prediction gives one number. Decision-making often requires a range or probability distribution.

A prediction interval may be written

\[ \boxed{ [L(\mathbf{x}),U(\mathbf{x})] }. \]

Its interpretation depends on the statistical method used to construct it.

Aleatoric and Epistemic Uncertainty

Aleatoric uncertainty refers to irreducible variability in the data-generating process. Epistemic uncertainty refers to uncertainty in the model or parameters that may shrink with better information.

The distinction is useful when deciding whether more data can materially improve performance.

Probabilistic Models

Probabilistic models represent a conditional distribution

\[ \boxed{ p(y\mid\mathbf{x},\theta) }. \]

This framework supports uncertainty quantification, likelihood-based training, and principled comparison with observations.

Maximum Likelihood

Maximum-likelihood estimation chooses parameters that maximize the probability of the observed data:

\[ \boxed{ \hat\theta = \arg\max_{\theta} \prod_{i=1}^{n} p(y_i\mid\mathbf{x}_i,\theta) }. \]

Equivalently, one often minimizes negative log-likelihood.

Bayesian Learning

Bayesian inference combines a prior distribution with the likelihood:

\[ \boxed{ p(\theta\mid D) \propto p(D\mid\theta)p(\theta) }. \]

Predictions then average over parameter uncertainty rather than relying only on one fitted parameter value.

Mechanistic and Data-Driven Models

A mechanistic model encodes known relationships such as conservation, geometry, or physical law. A data-driven model learns relationships primarily from observations.

Neither approach is universally superior.

Hybrid Models

Hybrid models combine mechanistic structure with learned components:

\[ \boxed{ \text{known structure} + \text{learned residual or closure} }. \]

This can improve data efficiency and preserve constraints while still capturing unresolved behavior.

Physics-Informed Learning

Physical equations can enter training through architecture, constraints, or penalty terms.

A generic loss might be

\[ \boxed{ J = J_{\text{data}} + \lambda J_{\text{physics}} }. \]

The physical term penalizes violation of known relationships.

Interpretability

Interpretability concerns how readily model structure or predictions can be understood.

Linear coefficients, small trees, feature effects, local explanations, and sensitivity measures provide different kinds of interpretability.

Interpretability Is Model-Dependent

A coefficient in a linear regression, a split in a decision tree, and an attribution score from a complex model do not carry the same meaning.

Explanations should be interpreted according to the underlying model and assumptions.

Fairness and Group Performance

Aggregate accuracy can hide large performance differences across subgroups.

When decisions affect people, evaluation may need to compare error rates, calibration, coverage, or other metrics across relevant groups.

Objective Functions Encode Priorities

The loss function, class weights, threshold, and optimization target determine which errors are treated as costly.

These choices are part of model governance because they translate operational priorities into mathematics.

Data Quality

Model performance is constrained by the quality of the underlying data. Important questions include

  • Are measurements accurate?
  • Are labels reliable?
  • Is sampling representative?
  • Are timestamps aligned?
  • Are units consistent?
  • Are duplicated or impossible records present?

Sampling Bias

If the training sample differs systematically from the target population, model performance estimates can be misleading.

More data do not automatically correct biased sampling.

Label Noise

Classification labels may contain mistakes, ambiguity, or inconsistent human judgment.

Label quality can become the limiting factor even when feature data are abundant.

Reproducibility

A reproducible machine-learning workflow records

  • data version;
  • feature transformations;
  • training split;
  • random seeds where relevant;
  • model configuration;
  • software environment;
  • evaluation metrics;
  • final artifacts.

Computational Cost

Model quality is not the only deployment criterion. Training time, inference latency, memory, energy use, and hardware requirements may matter.

A slightly less accurate model may be operationally superior if it is far cheaper, faster, or easier to maintain.

Model Compression

Large models can sometimes be approximated by smaller models through pruning, quantization, distillation, or low-rank approximation.

Compression introduces a tradeoff among size, speed, accuracy, and robustness.

Example: Linear Prediction

Suppose

\[ \hat y=5+2x_1-3x_2. \]

For

\[ x_1=4,\qquad x_2=1, \]

the prediction is

\[ \hat y =5+2(4)-3(1) \] \[ \boxed{\hat y=10}. \]

Example: Logistic Probability

Suppose a logistic model produces score

\[ z=1.2. \]

Then

\[ \hat p = \frac{1}{1+e^{-1.2}} \] \[ \boxed{\hat p\approx0.769}. \]

Example: Mean Squared Error

Suppose observed values are

\[ 3,\quad5,\quad7 \]

and predictions are

\[ 2,\quad5,\quad9. \]

The residuals are

\[ 1,\quad0,\quad-2. \]

Therefore,

\[ MSE = \frac{1^2+0^2+(-2)^2}{3} \] \[ \boxed{MSE=\frac{5}{3}\approx1.67}. \]

Example: Standardization

Suppose a feature value is \(x=70\), the training mean is \(\mu=50\), and the training standard deviation is \(\sigma=10\). Then

\[ z=\frac{70-50}{10} \] \[ \boxed{z=2}. \]

Example: Precision and Recall

Suppose

\[ TP=40,\qquad FP=10,\qquad FN=20. \]

Precision is

\[ \frac{40}{40+10} =\boxed{0.80}. \]

Recall is

\[ \frac{40}{40+20} =\boxed{\frac{2}{3}\approx0.667}. \]

Verification

Verification asks whether the data pipeline, transformations, mathematics, and software implement the intended model correctly.

Useful checks include

  • shape and dimension checks;
  • unit and scaling checks;
  • reproducing small analytical examples;
  • confirming split logic;
  • testing metric calculations;
  • checking gradient or optimization behavior;
  • verifying preprocessing is applied consistently.

Validation

Validation asks whether the model performs adequately on data representative of its intended deployment setting.

A model can be implemented perfectly and still fail because the data are unrepresentative, the target is poorly defined, the environment has shifted, or the evaluation metric does not match the operational goal.

Common Error: Training on the Test Set

Repeatedly checking the test set and adjusting the model in response turns the test set into a validation set.

Final performance will then be optimistically biased.

Common Error: Leakage through Preprocessing

Computing means, standard deviations, feature selections, or imputations using the full dataset leaks information from validation or test data into training.

Common Error: Optimizing One Metric Blindly

A high accuracy score can hide poor calibration, weak minority-class recall, unacceptable false positives, or poor tail performance.

Metrics should reflect the actual operating decision.

Common Error: Assuming More Complexity Is Better

A more complex model can fit more patterns but can also become less stable, harder to validate, more expensive to operate, and more vulnerable to overfitting.

Common Error: Treating Correlation as Causation

Predictive association does not establish how an intervention would change an outcome.

Causal claims require additional assumptions or study design.

Common Error: Ignoring Distribution Shift

Excellent historical performance does not guarantee future performance if the deployment population, measurement process, policy environment, or behavior changes.

Common Error: Ignoring Uncertainty

Point predictions can be misleading when several actions have similar expected outcomes but very different uncertainty or downside profiles.

Decision systems should use calibrated probabilities or intervals when uncertainty materially affects the choice.

A Reliable Modeling Procedure

  1. Define the prediction, inference, or decision objective.
  2. Identify the target population, target variable, and available features.
  3. Audit data quality, sampling, missingness, units, and label reliability.
  4. Separate training, validation, and test information before learned preprocessing.
  5. Choose a baseline model and evaluation metric matched to the decision.
  6. Train models using an appropriate loss function and regularization strategy.
  7. Evaluate generalization with cross-validation or time-aware validation as appropriate.
  8. Check calibration, subgroup performance, uncertainty, and failure cases.
  9. Compare against simpler and mechanistic alternatives where available.
  10. Monitor deployment data for drift, performance decay, and changing assumptions.

What to Remember

  • data science models depend on both mathematical algorithms and the quality of the surrounding data pipeline;
  • regression predicts quantitative outcomes, while classification predicts categories or probabilities;
  • clustering and dimensional reduction seek structure without target labels;
  • loss functions and regularization define what the training process rewards and penalizes;
  • training performance does not establish generalization;
  • validation design must match the deployment setting, especially for time-dependent data;
  • data leakage can make weak models appear excellent;
  • prediction, causal inference, calibration, ranking, and decision-making are different objectives;
  • distribution shift and concept drift can invalidate models after deployment;
  • verification, validation, uncertainty analysis, monitoring, and reproducibility are essential parts of a production-quality modeling system.
