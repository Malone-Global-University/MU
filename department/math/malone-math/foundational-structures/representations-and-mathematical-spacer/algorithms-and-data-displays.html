Algorithms and Data Displays

Some mathematics is best represented as a process, while other mathematics is best represented as organized data. Algorithms make procedures explicit; data displays make patterns, comparisons, distributions, and relationships visible.

Representing What We Do and What We Observe

A formula such as

\[ f(x)=2x+3 \]

represents a rule compactly.

But sometimes the most useful representation is not a single formula. We may need to describe a sequence of steps:

  1. Take the input.
  2. Multiply it by \(2\).
  3. Add \(3\).
  4. Return the result.

That is an algorithmic representation.

Likewise, if we collect many observations, a raw list may be difficult to interpret. A table, graph, or frequency display can reveal the structure hidden in the data.

\[ \boxed{ \text{algorithm} = \text{representation of a process} } \] \[ \boxed{ \text{data display} = \text{representation of organized observations} } \]

What Is an Algorithm?

An algorithm is a finite, well-defined procedure for carrying out a task or solving a class of problems.

An algorithm should make clear:

  • what information is supplied,
  • what steps are performed,
  • in what order the steps occur,
  • and what result is produced.

Example: Average of Three Numbers

Suppose the inputs are \(a\), \(b\), and \(c\).

  1. Add the three numbers.
  2. Divide the sum by \(3\).
  3. Return the quotient.

Symbolically, the same procedure is summarized by

\[ \frac{a+b+c}{3}. \]

The formula is compact; the algorithm makes the procedure explicit.

Ways to Represent an Algorithm

Algorithms can be expressed in several forms.

Natural Language

Explain the steps in ordinary words.

Numbered Steps

Organize a procedure into a fixed sequence.

Pseudocode

Use programming-like notation without depending on a specific language.

Flowchart

Show actions and decisions with a branching diagram.

Formula

Compress a simple deterministic procedure into symbolic form.

Pseudocode Example

INPUT x
y ← 2x
y ← y + 3
OUTPUT y

This represents the same rule as

\[ f(x)=2x+3. \]

Different representations emphasize different aspects of the process.

Inputs, Steps, and Outputs

An algorithm can often be viewed as a pipeline:

\[ \boxed{ \text{input} \longrightarrow \text{procedure} \longrightarrow \text{output} } \]

For example, consider the procedure:

  1. Input a radius \(r\).
  2. Square the radius.
  3. Multiply by \(\pi\).
  4. Output the area.

This procedure corresponds to

\[ A(r)=\pi r^2. \]

The algorithmic view emphasizes how the result is produced.

The functional view emphasizes the mapping from input to output.

Algorithms and Functions

Many deterministic algorithms can be modeled as functions.

If the same valid input always produces exactly one output, then the algorithm behaves functionally:

\[ x\mapsto f(x). \]

But not every algorithm is naturally represented by a simple formula.

An algorithm may include:

  • many steps,
  • repetition,
  • conditional branches,
  • data structures,
  • or comparisons.

The function and algorithm viewpoints are therefore related but not identical.

Iteration and Repetition

Some procedures repeat the same step several times.

For example, to calculate

\[ 2^5, \]

we could begin with \(1\) and multiply by \(2\) five times:

\[ 1\to2\to4\to8\to16\to32. \]

This is an iterative representation of exponentiation.

Sequence Connection

Repeated algorithms often generate sequences.

For example,

\[ a_0=1, \] \[ a_{n+1}=2a_n \]

produces

\[ 1,2,4,8,16,32,\ldots \]

So a recursive sequence can also be interpreted as an algorithm: take the current term, apply a rule, and generate the next term.

Decision Steps

Algorithms can change behavior depending on a condition.

For example:

  1. Input a real number \(x\).
  2. If \(x\geq0\), output \(x\).
  3. If \(x<0\), output \(-x\).

This algorithm computes absolute value.

Symbolically,

\[ |x|= \begin{cases} x,&x\geq0,\\ -x,&x<0. \end{cases} \]

The piecewise formula and the decision algorithm represent the same process in different forms.

From Raw Data to Displays

Suppose the observed values are

\[ 2,3,3,4,4,4,5,5,6,8. \]

This raw list contains the information, but some features are difficult to see immediately.

A data display reorganizes the values so we can inspect:

  • frequency,
  • trend,
  • distribution,
  • comparison,
  • or association.

The display should be chosen according to the question we want to answer.

Frequency Tables

A frequency table records how often each value or category occurs.

Value Frequency
\(2\)\(1\)
\(3\)\(2\)
\(4\)\(3\)
\(5\)\(2\)
\(6\)\(1\)
\(8\)\(1\)

The table immediately shows that \(4\) is the most frequent value.

Frequency tables are especially useful when repeated observations need to be summarized without losing the counts.

Bar Charts

A bar chart compares quantities across discrete categories.

Line Graphs

A line graph is especially useful for ordered change, such as measurements over time.

The connecting segments do not necessarily mean that every intermediate value was observed. They often serve as a visual guide to ordered change.

Scatter Plots

A scatter plot displays paired numerical observations

\[ (x,y). \]

It is useful for studying association between two quantitative variables.

A scatter plot shows association, not automatically causation.

Choosing a Data Display

The form of the data and the question should guide the display.

Goal Useful Display
Compare categories Bar chart
Show change over ordered time Line graph
Count repeated values Frequency table
Study two numerical variables together Scatter plot
Preserve exact observations Table or list
Show a process Algorithm, pseudocode, or flowchart

A representation is useful only when it makes the relevant structure easier to see.

How Displays Can Mislead

A data display is a representation, and representation choices can affect how the viewer interprets the data.

Truncated Axes

Beginning an axis far above zero can make small differences look very large.

Unequal Intervals

Uneven spacing can distort apparent rates of change.

Missing Data

Leaving out inconvenient observations can create a false visual pattern.

Inappropriate Connections

Connecting unordered categories with a line may suggest a progression that does not exist.

Overloaded Graphics

Too many labels, dimensions, or decorative effects can hide rather than clarify the mathematical information.

Good mathematical graphics should make the structure more honest and more readable, not merely more dramatic.

Practical Applications

Software

Programs implement algorithms: inputs are processed through explicit rules, loops, comparisons, and data structures to produce outputs.

Spreadsheets

A spreadsheet combines tabular data with algorithms embedded in formulas and cell references.

Business

Dashboards use charts and tables to summarize revenue, costs, customers, inventory, and performance over time.

Science

Experimental procedures are algorithms in practical form, while collected measurements are organized into tables and graphs for analysis.

Mathematics

Long division, the Euclidean algorithm, row reduction, Newton's method, and many numerical procedures are algorithmic representations of mathematical reasoning.

Worked Examples

Example 1: Turn a Formula into an Algorithm

Given

\[ f(x)=3x-5, \]

write a step-by-step algorithm.

  1. Input \(x\).
  2. Multiply \(x\) by \(3\).
  3. Subtract \(5\).
  4. Output the result.

Example 2: Turn an Algorithm into a Formula

Algorithm:

  1. Input \(x\).
  2. Square it.
  3. Add \(4\).

The equivalent formula is

\[ \boxed{f(x)=x^2+4}. \]

Example 3: Build a Frequency Table

Data:

\[ 1,1,2,2,2,4,5,5. \]
Value Frequency
\(1\)\(2\)
\(2\)\(3\)
\(4\)\(1\)
\(5\)\(2\)

Example 4: Choose a Display

Suppose a company wants to compare sales across six product categories.

A bar chart is a natural choice because the categories are discrete and the main question is comparison.

Example 5: Ordered Change

Suppose monthly revenue is recorded for twelve consecutive months.

A line graph is useful because month order matters and the goal is to see change over time.

Example 6: Two Numerical Variables

Suppose we measure study time and exam score for each student.

Each student contributes an ordered pair

\[ (\text{study time},\text{exam score}). \]

A scatter plot is appropriate because we want to examine the relationship between two numerical variables.

Common Errors

1. Treating an Algorithm as Just a Formula

Some algorithms contain decisions, loops, and data manipulations that cannot be captured conveniently by one elementary formula.

2. Leaving Steps Ambiguous

A useful algorithm should specify enough detail that the procedure can be carried out consistently.

3. Using a Line Graph for Unordered Categories

Connecting unrelated categories suggests order or continuity that may not exist.

4. Ignoring Axis Scale

A graph's visual impression depends heavily on scale.

5. Assuming Association Implies Causation

A scatter plot may reveal a relationship without proving that one variable causes the other.

6. Hiding Exact Data When Exactness Matters

Charts summarize visually, but a table may be better when precise values are important.

The Deeper Idea

Algorithms and data displays represent two complementary sides of mathematics.

Algorithms represent process:

\[ \text{what steps transform the input?} \]

Data displays represent structure in observations:

\[ \text{what pattern appears in the values?} \]

Together they connect symbolic mathematics to computation and empirical information.

\[ \boxed{ \text{rules} \longrightarrow \text{procedures} \longrightarrow \text{outputs} \longrightarrow \text{organized data} } \]

This bridge becomes increasingly important in numerical mathematics, statistics, computer science, modeling, optimization, and scientific analysis.

Summary

  • An algorithm is a finite, well-defined procedure for carrying out a task.
  • Algorithms can be represented with prose, numbered steps, pseudocode, flowcharts, or formulas.
  • Many deterministic algorithms can be viewed as functions from inputs to outputs.
  • Iteration repeats a process and often generates sequences.
  • Conditional steps let an algorithm branch according to a logical test.
  • Data displays organize observations so structure becomes easier to see.
  • Frequency tables summarize repeated values or categories.
  • Bar charts compare discrete categories.
  • Line graphs emphasize ordered change or trends.
  • Scatter plots display relationships between paired numerical variables.
  • The choice of representation should match the structure of the data and the question being asked.
  • Poor scale, omitted data, or inappropriate visual forms can mislead.
  • Algorithms and data displays connect mathematics with computation, measurement, and applied analysis.

A mathematical representation can show not only what an object is, but what to do with it and what patterns emerge from many observations. Algorithms make procedures visible; data displays make organized information visible.
