Definition, Purpose, and Scholarly Scope

A recurrence relation specifies a quantity in terms of its values on smaller or earlier inputs. In algorithm analysis, a cost recurrence describes the execution time, number of operations, memory consumption, or another resource required by a recursive computation. It has two essential parts: base conditions, which specify the cost of sufficiently small inputs, and recursive cases, which express the cost of the current case as smaller costs plus the work performed outside those calls.

A mathematical recurrence is not itself an algorithm. The formula T(n) = 2T(n/2) + Θ(n) abstracts away implementation details that may matter in practice: how data are partitioned, whether buffers are allocated, and whether operations assumed constant-time really are. Its strength is that it makes the growth of work explicit and permits mathematical bounds under stated assumptions.

It develops recurrence construction, expansion, substitution, recursion-tree accounting, the standard master method, unequal subproblems, implementation-sensitive resource models, and proof obligations. The companion Recursion Trees and Divide and Conquer entry treats tree-level accounting as its central technique; this article treats it as one method among several for understanding and solving recurrences.

The Cost Model: What Does T(n) Count?

Before deriving a recurrence, identify the input-size parameter n, the operation counted, and the machine or mathematical model. n may be the number of array elements, the length of a string, the number of nodes in a tree, or the bit length of an integer; these are not interchangeable. A comparison-based algorithm may count key comparisons, while a real implementation also performs indexing, allocation, branching, and data movement. The choice should match the question being answered.

In a conventional unit-cost RAM model, operations on fixed-width words are frequently treated as constant-time. If an algorithm manipulates integers of unbounded precision, multiplication and addition costs depend on operand length. Likewise, appending to a growable array may have amortized constant cost rather than guaranteed constant cost per operation. Recurrence equations are only as reliable as these nonrecursive-cost assumptions.

The common notation T(n) usually describes worst-case or appropriately specified input-size cost, not an undefined blend of best, average, and worst cases. Distinguish W(n) for work, D(n) for maximum call depth, and S(n) for storage when multiple resources are under discussion. State whether output storage is included in the space bound; otherwise, two apparently contradictory descriptions may both be valid under different conventions.

From Recursive Source Code to a Recurrence

Writing a correct recurrence starts by following the actual control flow rather than recognizing the word recursive. Every invocation pays for the work it performs directly and for each recursive call it actually makes. For a single branch, this often has the form T(n) = T(g(n)) + f(n); for several branches, T(n) = T(n₁) + … + T(nₖ) + f(n). Here f(n) counts the operations outside recursive descendants, including partitioning and combining results when relevant.

  1. Define size and domain: establish what an input of size n means and what values are legal.
  2. Enumerate base cases: specify the cost when recursion stops, often T(0) = Θ(1) or T(1) = Θ(1).
  3. Count recursive calls: identify how many children are reached and their sizes, including branches that may not execute.
  4. Count local work: include comparisons, data copies, loops, partitioning, and result assembly performed by the caller.
  5. Specify the kind of bound: decide whether a line is an exact operation count, an upper bound, or an asymptotically tight relation.
  6. Solve and interpret: derive growth, state assumptions, and compare with stack-depth and memory recurrences separately.

This procedure prevents a common category error: using the number of recursive calls as a surrogate for total execution cost. One call may spend Θ(n) time copying data; another may spend Θ(1) time updating indices. The resulting recurrences can have dramatically different solutions even if the call graph has the same shape.

Base Conditions, Thresholds, and Legal Domains

A recurrence is incompletely specified without the conditions that stop it. For a recursive search, the problem may become empty at n = 0; for a divide-and-conquer routine, a leaf may contain one element at n = 1; for a production implementation, any input with n ≤ 32 may be handled by a direct kernel. All three conventions are legitimate if they match the algorithm. A bounded base range normally changes only constant factors in a standard asymptotic analysis, but it can change an exact count.

For example, T(0) = 1 and T(n) = T(n - 1) + 1 for positive integers give the exact solution T(n) = n + 1. Saying only that T(n) = T(n - 1) + 1 leaves an unspecified additive constant. Similarly, substituting n = 0 into a recurrence that contains T(⌊n/2⌋) may produce the circular expression T(0) = T(0) + c unless the base case is checked first.

Floor and ceiling operators matter to termination: ⌊n/2⌋ < n for positive n, but ⌈n/2⌉ = n at n = 1. A recurrence using ⌈n/2⌉ therefore needs a base threshold that stops before this equality can create a nondecreasing call. State these boundaries, even when the analysis subsequently simplifies the algebra by considering powers of two.

Exact Counts, Inequalities, and Asymptotic Recurrences

An exact recurrence can count a specified primitive operation: C(n) = C(n - 1) + 1, C(0) = 0, counts exactly n steps. Asymptotic notation instead groups functions by their growth. A recurrence written T(n) = T(n - 1) + Θ(1) means that the nonrecursive work is bounded above and below by positive constants for sufficiently large inputs, subject to the model. This is enough to conclude T(n) = Θ(n) given a bounded positive base cost.

When a program only guarantees an upper bound f(n) = O(n), it is generally invalid to replace that with f(n) = Θ(n). For example, T(n) ≤ T(n - 1) + cn yields an O(n²) upper bound but does not by itself establish a quadratic lower bound. Likewise, an expected-case recurrence cannot be read as a worst-case identity without justifying the distribution of inputs and the conditioning of subproblems.

Throughout this article, expressions of the form T(n) = aT(n/b) + Θ(f(n)) describe a family of nonnegative cost functions for which sufficiently regular local costs have the indicated asymptotic order. Wherever a method requires more precise hypotheses—such as nonnegativity or a regularity condition—those assumptions are identified explicitly.

Worked Derivation I: Linear Recursion in Factorial

The factorial procedure reaches the base case after decrementing n by one at each call. Assuming a fixed-cost multiplication and comparison, the nonrecursive work in a nonbase call is Θ(1). The running-time recurrence is therefore T(0) = Θ(1) and T(n) = T(n - 1) + Θ(1) for integers n ≥ 1.

def factorial(n: int) -> int:
    if n < 0:
        raise ValueError("n must be nonnegative")
    if n <= 1:
        return 1
    return n * factorial(n - 1)

assert factorial(5) == 120

Unroll the recurrence: T(n) = T(n - 1) + c, then = T(n - 2) + 2c, and after n steps = T(0) + nc. Hence the unit-cost running time is Θ(n). With ordinary eager evaluation and no relevant tail-call elimination, the maximum number of outstanding invocations is also Θ(n), but call depth is a separate measure from work.

There is an important model caveat. Computing the exact integer n! produces an output with Θ(n log n) bits, and the multiplications operate on increasingly large integers. The recurrence above is a unit-cost abstraction, not a proof that a real arbitrary-precision implementation performs only a linear number of bit operations. A bit-complexity analysis must charge for the changing operand lengths.

Worked Derivation II: Binary Search and Halving

Binary search discards approximately half of a sorted interval after each comparison. A recursive implementation that passes index boundaries, rather than copying a slice, does constant work per nonbase invocation. For a worst-case unsuccessful search, a suitable relation is T(0) = Θ(1) and T(n) = T(⌊n/2⌋) + Θ(1) for sufficiently large n; details of the exact subinterval length depend on the chosen half-open or closed interval convention.

def binary_search(values: list[int], target: int, lo=0, hi=None) -> int:
    if hi is None:
        hi = len(values)
    if lo >= hi:
        return -1
    mid = lo + (hi - lo) // 2
    if values[mid] == target:
        return mid
    if target < values[mid]:
        return binary_search(values, target, lo, mid)
    return binary_search(values, target, mid + 1, hi)

assert binary_search([1, 4, 7, 9, 12], 9) == 3
assert binary_search([1, 4, 7, 9, 12], 2) == -1

After k unsuccessful halving steps, the remaining interval has size at most approximately n/2ᵏ. The recursion ends after k = Θ(log₂ n) steps. Therefore the worst-case time is Θ(log n); its call depth is also Θ(log n) in the conventional implementation. The best case is Θ(1) if the target is at the first midpoint.

Replacing the index-bound call with binary_search(values[:mid], target) changes the local work: a Python slice constructs a new list in time proportional to its length. This yields a recurrence closer to T(n) = T(n/2) + Θ(n) along the relevant path and gives Θ(n) time, despite halving the search interval. That difference is precisely why a recurrence must be derived from actual operations.

Worked Derivation III: Merge Sort

Merge sort sorts two approximately equal halves, then combines the sorted results with a linear-time merge. For a sequence of length n ≥ 2, the running-time recurrence is generally T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + Θ(n), with constant cost for arrays of length zero or one. On powers of two this simplifies to T(n) = 2T(n/2) + Θ(n).

def merge_sort(items: list[int]) -> list[int]:
    if len(items) <= 1:
        return items.copy()
    mid = len(items) // 2
    left = merge_sort(items[:mid])
    right = merge_sort(items[mid:])
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i]); i += 1
        else:
            result.append(right[j]); j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

assert merge_sort([7, 2, 9, 1, 4]) == [1, 2, 4, 7, 9]

For each level of the balanced recursion tree, the total number of elements processed by merges is Θ(n). There are Θ(log n) levels before singleton subarrays are reached, producing Θ(n log n) time. This implementation also copies slices and builds result lists; those costs are of linear order per tree level and therefore do not change its Θ(n log n) running-time class.

The time recurrence does not imply Θ(n log n) simultaneous memory usage. At a given moment, outstanding merge data, live lists, and call frames have a separate storage profile. A standard merge sort using an auxiliary merge buffer typically needs Θ(n) extra storage plus Θ(log n) frames; exact live allocations depend on the version. The next article in this unit specializes in the geometry and accounting of such recursion trees.

Worked Derivation IV: Naive Fibonacci and Branch Duplication

The familiar two-branch recursive Fibonacci function returns immediately at n = 0 or n = 1, but otherwise evaluates both fib(n - 1) and fib(n - 2). Under fixed-cost arithmetic, its execution cost satisfies T(n) = T(n - 1) + T(n - 2) + Θ(1). This is a linear recurrence with constant coefficients in the mathematical sense, even though the algorithm takes exponential time.

def fibonacci_plain(n: int) -> int:
    if n < 0:
        raise ValueError("n must be nonnegative")
    if n < 2:
        return n
    return fibonacci_plain(n - 1) + fibonacci_plain(n - 2)

assert fibonacci_plain(10) == 55

The recursion tree contains many repeated subproblems. For example, fib(5) is evaluated once as part of fib(6), then again inside a different descendant of fib(7). When counting calls exactly with C(0) = C(1) = 1, the relation is C(n) = 1 + C(n - 1) + C(n - 2), whose solution is C(n) = 2Fₙ₊₁ - 1, where Fₖ denotes the standard Fibonacci numbers. Thus C(n) = Θ(φⁿ) with φ = (1 + √5)/2.

The maximum recursion depth is only Θ(n). Total calls and maximum concurrent calls are different quantities. The asymptotic time is exponential because the algorithm recomputes states, not because every recursive algorithm must branch exponentially.

Memoization Changes the State Graph and the Recurrence

Memoization changes the work performed by the Fibonacci algorithm. Each distinct input k is computed at most once and the result is saved for later uses. Although the function's source code still includes two recursive calls, a reused cached state does not expand a second recursive subtree. The raw recurrence T(n) = T(n - 1) + T(n - 2) + Θ(1) therefore no longer models its total execution cost.

from functools import lru_cache

@lru_cache(maxsize=None)
def fibonacci_memo(n: int) -> int:
    if n < 0:
        raise ValueError("n must be nonnegative")
    if n < 2:
        return n
    return fibonacci_memo(n - 1) + fibonacci_memo(n - 2)

assert fibonacci_memo(10) == 55

With constant-time expected cache lookup and unit-cost arithmetic, there are n + 1 possible input states from zero through n. The total work is Θ(n) for a fresh cache, while the stored table and the deepest active recursive chain use Θ(n) space. A clearer analysis counts distinct computed states times work per state instead of pretending every edge in the source-level call graph expands a fresh subtree.

For exact large Fibonacci integers, bit-level arithmetic costs grow with output length and invalidate the simplistic constant-time-arithmetic claim. The important conceptual point remains: memoization alters the evaluated dependency graph, so the complexity model must reflect caching.

Expansion Method: Repeated Substitution

Expansion, also called repeated substitution or unrolling, replaces a recurrence's unknown lower term with its own defining expression. The objective is to expose a finite sum whose number of terms can be counted. For T(n) = T(n - 1) + n and T(0) = c, repeated replacement gives T(n) = c + 1 + 2 + … + n = c + n(n + 1)/2, hence T(n) = Θ(n²).

For T(n) = T(n/2) + 1 on powers of two, let n = 2ᵏ. Then T(2ᵏ) = T(2ᵏ⁻¹) + 1, and k substitutions reach T(1). The exact solution for unit cost one and base cost c is T(2ᵏ) = c + k = c + log₂ n.

Unrolling is especially suitable for one-child recurrences whose argument decreases by a fixed amount or a constant factor. For multiply branching calls, simple expansion quickly creates many terms; a recursion tree organizes those terms by depth. Both procedures make the same algebra visible in different forms.

For one recursive child of size n/2, the costs across successive levels form a sequence f(n), f(n/2), f(n/4), …. A constant cost at each level gives Θ(log n) total because there are logarithmically many levels. A cost proportional to the current input size gives n + n/2 + n/4 + … = Θ(n). A cost Θ(log n) per level gives a decreasing arithmetic sequence and Θ((log n)²) total.

Recursion Trees: Level Cost and Height

A recursion tree represents one subproblem as a node and each directly invoked recursive subproblem as a child. If T(n) = aT(n/b) + f(n) with integral a ≥ 1 and b > 1, then level i contains aⁱ subproblems, each of size n/bⁱ when sizes divide evenly. Its total local work is aⁱ f(n/bⁱ). The leaf level lies at depth h = log_b n for powers of b, and the number of leaves is aʰ = n^(log_b a).

The sum of internal-level work and leaf costs is the total sequential work. If f(n) = c nᵈ, then level i costs c nᵈ (a/bᵈ)ⁱ. This is a geometric series. The ratio a/bᵈ explains three regimes: decreasing level costs (root-dominated), constant level costs (all levels contribute), and increasing level costs (leaves dominate). That observation is the intuition behind the standard master theorem.

A recursion tree is an accounting tool, not necessarily an exact trace of stack residency or a parallel execution schedule. Many children shown on one level run at different times. Use separate notions for total work, peak storage, and critical-path length.

The Standard Master Theorem: Domain and Setup

The classical master method solves broad families of balanced divide-and-conquer recurrences of the form T(n) = aT(n/b) + f(n), with a ≥ 1, b > 1 constants, an appropriate bounded base region, and asymptotically nonnegative f(n). It compares the current-level work f(n) with the leaf-growth benchmark nᵖ, where p = log_b a.

For introductory derivations, assume n is an exact power of b; then each division is exact. Published versions of the theorem can account for suitable floor and ceiling effects under stated conditions. This convenient form does not automatically apply to arbitrary variable branching factors, unequal-sized children, negative local costs, or highly irregular functions.

Determine p, compare f(n) to nᵖ, and verify the hypotheses of the relevant case. When the local work is close to the benchmark by nonpolynomial factors such as log log n or 1/log n, the simplest three-case statement may not decide the answer. A proof by direct expansion, substitution, or a more general theorem may be needed.

Master Theorem Case 1: Leaf-Dominated Work

Case 1 applies when f(n) = O(n^(p - ε)) for some constant ε > 0. The nonrecursive work is polynomially smaller than nᵖ, so expanding the recursion tree produces increasing total costs toward its leaves. The solution is T(n) = Θ(nᵖ), subject to the theorem's usual base and nonnegativity assumptions.

Consider T(n) = 3T(n/2) + Θ(n). Here p = log₂ 3 ≈ 1.585. Since n = O(n^(1.585 - ε)) for, say, ε = 0.5, case 1 applies. Therefore T(n) = Θ(n^(log₂ 3)). The result is neither quadratic nor merely linear; the number of leaves grows more quickly than the cost assigned to the root.

A gap of only a logarithmic factor is not the polynomial gap required here. For example, f(n) = nᵖ/log n is smaller than nᵖ, but not by a fixed power of n. Treat such a boundary carefully instead of classifying it by whichever side looks numerically larger for small inputs.

Master Theorem Case 2: Balanced Work Across Levels

In the standard balanced case, f(n) = Θ(nᵖ). Each level of the recursion tree contributes Θ(nᵖ) local work. With Θ(log n) levels, the total is T(n) = Θ(nᵖ log n).

For T(n) = 2T(n/2) + Θ(n), p = log₂ 2 = 1 and f(n) matches nᵖ. The result is Θ(n log n), as derived directly for merge sort. Another example is T(n) = 4T(n/2) + Θ(n²), which gives Θ(n² log n).

A common extension covers f(n) = Θ(nᵖ logᵏ n) for fixed k ≥ 0, giving T(n) = Θ(nᵖ log^(k+1) n) under the appropriate hypotheses. The familiar k = 0 version is a subset. This extension should not be applied mechanically to negative k; the boundary at k = -1 leads to a log log n factor and is better derived directly when teaching the elementary method.

Master Theorem Case 3: Root-Dominated Work and Regularity

Case 3 applies when f(n) = Ω(n^(p + ε)) for some fixed ε > 0 and a regularity condition holds: for some constant c < 1 and all sufficiently large applicable n, a f(n/b) ≤ c f(n). Under these conditions, the local work at the root dominates the sum and T(n) = Θ(f(n)).

For T(n) = 2T(n/2) + Θ(n²), use the representative local cost f(n) = n². With p = 1, the polynomial gap exists, and 2 f(n/2) = 2(n/2)² = n²/2; choose c = 1/2. Thus T(n) = Θ(n²). The recursion still branches, but most of its total charged work occurs near the root.

Not every nonnegative function that appears larger than nᵖ behaves smoothly when evaluated at n/b. The regularity check rules out some oscillating or pathological local-cost functions for which naive root-dominance reasoning fails. It is a condition to verify, not a decorative sentence to omit.

When the Master Theorem Does Not Apply

It is a mistake to force every recurrence into aT(n/b) + f(n). The master theorem is a specialized result, not a universal algorithm for recurrence solving. If one child has size n - 1, there is no fixed b > 1 that makes n - 1 = n/b for all large n. If the children have sizes n/3 and 2n/3, their shrinkage factors differ. If the number of children depends on n, the constant-a hypothesis fails.

Even with fixed equal splits, a local cost such as n/log n lies in a gap of the basic master theorem, and an oscillatory cost may fail case 3 regularity. For these cases, use an expansion, recursion-tree sum, substitution proof, a suitable integral comparison, characteristic-equation analysis, or the more general Akra–Bazzi framework when its assumptions hold.

Unequal Splits: One-Third and Two-Thirds

Suppose a recursive algorithm splits an input of size n into portions approximately n/3 and 2n/3 and performs Θ(n) work to partition or combine. Its recurrence is T(n) = T(⌊n/3⌋) + T(⌈2n/3⌉) + Θ(n) for sufficiently large n, with a base case that ensures smaller subproblems; exact rounding can be adjusted to the particular implementation.

The tree is not perfectly balanced, but its total subproblem size at a level remains near n while both children exist. The shortest root-to-leaf paths have length proportional to log₃ n; the longest have length proportional to log_(3/2) n. Both depths are Θ(log n). The first constant fraction of those levels contains almost all of the original mass, giving a Ω(n log n) lower bound, while the O(log n) maximum depth and O(n) cost per level give an upper bound. Hence T(n) = Θ(n log n).

The elementary master theorem cannot be cited because there is no common n/b argument for both children. The result comes from a distinct proof. As a practical interpretation, consistently imbalanced but proportionally bounded splits may retain n log n behavior, whereas a degenerate n - 1 versus 0 split can be quadratic when local work is linear.

Quicksort: Best, Worst, and Expected Recurrences

Quicksort partitions around a pivot, and the subproblem sizes depend on the pivot's rank. If the pivot yields two nearly equal portions on every call, the recurrence resembles T(n) = 2T(n/2) + Θ(n) and gives Θ(n log n). If the pivot always has rank zero or n - 1, the worst-case relation is T(n) = T(n - 1) + Θ(n), which solves to Θ(n²).

To analyze expected comparisons under uniformly random pivot ranks, define E(n) for the expectation over the algorithm's random choices and make the distribution explicit. A representative recurrence is E(n) = (1/n) Σₖ₌₀ⁿ⁻¹ (E(k) + E(n - 1 - k)) + Θ(n), with suitable base values. Linearity of expectation allows the sum; symmetry combines the two child sums. The solution is Θ(n log n) under the standard model.

The expected recurrence is not evidence that every run costs Θ(n log n), nor does the worst-case recurrence imply that every randomized run is quadratic. Where performance guarantees matter, distinguish randomized expected time, worst-case deterministic bounds, and high-probability bounds. The space analysis also depends on which partition is processed recursively and whether the implementation limits call depth.

Fibonacci as a Linear Difference Equation

Recurrences whose arguments differ by fixed integer offsets can sometimes be solved using characteristic equations. For the homogeneous Fibonacci recurrence F(n) = F(n - 1) + F(n - 2), try a solution of the form rⁿ. Dividing by r^(n - 2) yields r² = r + 1; its roots are φ = (1 + √5)/2 and ψ = (1 - √5)/2. The base values determine a linear combination of φⁿ and ψⁿ.

Because |ψ| < 1 and φ > 1, the Fibonacci numbers grow as Θ(φⁿ). For naive Fibonacci call counts, the recurrence has an extra +1; shifting the sequence by a constant produces a homogeneous recurrence, or the call-count identity C(n) = 2F(n + 1) - 1 can be proved directly by induction.

Characteristic equations are useful for fixed-offset linear recurrences but are not a replacement for the master theorem. A divide-and-conquer argument n/2 is not a fixed shift of n; the two problem families have different structures and often require different tools.

A Boundary Example: 2T(n/2) + n/log n

Consider positive powers of two n ≥ 4, with a constant base cost for smaller inputs, and let T(n) = 2T(n/2) + n/log₂ n. The leaf benchmark from the master setup is n. The local work n/log n is smaller than n but not by any constant polynomial factor, so the standard case 1 hypothesis fails. It is not equal to Θ(n), so the standard case 2 also fails.

Set n = 2ᵐ. At depth i, there are 2ⁱ nodes of size 2^(m-i). Their combined local cost is 2ⁱ · 2^(m-i)/(m-i) = n/(m-i) until the base region is reached. Summing over depths gives n Σⱼ₌₂ᵐ 1/j = Θ(n log m). Since m = log₂ n, the total is Θ(n log log n); the Θ(n) leaf contribution is lower order.

This example illustrates both the usefulness of a recursion tree and the danger of classifying a case by visual resemblance. A logarithmic factor in f(n) can move the recurrence into a boundary regime outside an elementary theorem while still allowing a clean direct solution.

Substitution Proofs: From a Guess to a Bound

The substitution method assumes a candidate bound and proves it by induction over input size. It turns an observed pattern into a justified theorem. Suppose the recurrence for powers of two is T(1) = d and T(n) = 2T(n/2) + cn, where c, d > 0. An exact candidate is T(n) = cn log₂ n + dn. Substitution gives 2[c(n/2) log₂(n/2) + d(n/2)] + cn = cn(log₂ n - 1) + dn + cn, which equals the candidate expression.

For an asymptotic upper bound, propose T(n) ≤ A n log₂ n + Bn with constants chosen to satisfy the base case and recurrence. A lower-bound proof can use the positive cn work on each internal level or an induction with a matching lower-bound candidate. Both directions are necessary to claim a Θ(n log n) bound from scratch.

A substitution proof must identify the domain where the inductive hypothesis applies and use a base case valid on that domain. It must also choose constants that satisfy all inequalities, not merely write O(n log n) as a guess. This distinction is especially important when the desired bound is tight.

Strengthening an Inductive Hypothesis

Some recurrence proofs fail because the guessed bound is too weak to absorb an additive term. Consider T(n) = 2T(n/2) + n. Guessing only T(n) ≤ Cn log₂ n and applying induction leads to T(n) ≤ Cn(log₂ n - 1) + n. For sufficiently large C the coefficient may be absorbed, but one still has to handle n = 1, where Cn log₂ n = 0 does not bound a positive base cost.

A stronger and more accurate hypothesis such as T(n) ≤ Cn log₂ n + Dn handles the base naturally. In other settings, subtracting a lower-order term, for example Cn² - Dn, creates the slack needed by induction. The goal is not to manipulate symbols until an inequality appears true; it is to formulate a statement stable under the recurrence's structure.

When floors or ceilings are present, induction often requires a bound valid for all smaller integer inputs, not just powers of two. A strong induction hypothesis is then natural. Any discontinuities or small exceptional values should be covered by a finite base region rather than silently ignored.

Changing Variables: Transforming Halving into a Shift

Substitution of variables can transform one recurrence family into another. For T(n) = T(n/2) + log₂ n on powers of two, set n = 2ᵐ and define U(m) = T(2ᵐ). The recurrence becomes U(m) = U(m - 1) + m, which is a simple sum. Hence U(m) = Θ(m²) and T(n) = Θ((log n)²).

For T(n) = 2T(n/2) + n, the same substitution gives U(m) = 2U(m - 1) + 2ᵐ. Divide through by 2ᵐ: with V(m) = U(m)/2ᵐ, the recurrence is V(m) = V(m - 1) + 1. Therefore V(m) = Θ(m) and T(n) = Θ(n log n). These changes make the relationship between exponential input scales and linear recurrence depth explicit.

A useful variable change should simplify either the recursive arguments or the changing coefficient. Keep track of the domain: defining U(m) this way initially covers only powers of two. An additional bounding argument or a theorem with floors and ceilings may be required to extend the result to all positive integers.

Floors, Ceilings, and Off-by-One Subproblems

Real programs operate on integer sizes. A typical partition creates children of sizes ⌊n/2⌋ and ⌈n/2⌉, not two abstract halves of fractional size. This distinction matters for exact counts and for termination. It also matters when one expression uses ⌈n/2⌉ at n = 1 and would invoke itself on an unchanged size unless guarded by the base case.

For ordinary nonnegative balanced divide-and-conquer costs with a bounded base threshold, replacing the two nearly equal integer sizes with n/2 often preserves Θ growth. But the justification is that the rounding perturbation is controlled for the recurrence class in question, not that floors and ceilings are algebraically identical to their arguments.

When preserving source-level precision, write the actual recurrence first. For merge sort, T(n) = T(⌊n/2⌋) + T(⌈n/2⌉) + Θ(n) accurately models both branches. For a binary search that excludes the midpoint, the larger of its two possible remaining intervals is at most ⌊n/2⌋ for common half-open conventions. Different choices of comparison order or interval definition can change the exact formula but not its logarithmic worst-case growth.

Tree-Structured Inputs: Size Versus Height

A binary-tree traversal that visits each node once performs one fixed amount of local work per visited node. Its cost can be specified on a tree X rather than only on an integer: T(X) = T(left(X)) + T(right(X)) + Θ(1), with constant cost for an empty tree. Summing one constant per node yields Θ(n) total time for a tree with n nodes, regardless of whether the tree is balanced.

The maximum call depth depends on height h, not solely on node count. A balanced tree has h = Θ(log n); a path-shaped tree has h = Θ(n). Both can require Θ(n) total work to visit all nodes. Thus the useful time formula is Θ(n), while the call-stack space is Θ(h) for a straightforward recursive depth-first traversal.

Writing T(n) = 2T(n/2) + 1 for every tree is wrong because child sizes need not be equal. It happens to describe a balanced shape with equal branch sizes, not the general traversal. When structure varies, preserve the actual sizes n_left and n_right or sum directly over tree nodes.

Graph Search: Cycles and Unique States

Graphs can contain cycles and multiple paths to the same vertex. A naive recurrence that expands every outgoing edge without tracking visited vertices may not terminate or may count the same work repeatedly. A correctly implemented depth-first search marks states at an appropriate point, ensuring that each vertex is processed once and each adjacency entry is examined at most a constant number of times. With adjacency lists, this gives Θ(V + E) time on a represented graph, where V is the vertex count and E the edge count.

That result is often more naturally proved by charging operations to vertices and edges than by writing a simple one-variable recurrence. A graph does not generally split into disjoint smaller graphs at each recursive call; recursive subcalls may encounter shared vertices. The state of the visited set determines which future work is possible.

Call depth can reach Θ(V) even though time is Θ(V + E), and an explicit DFS stack can replace the language call stack without removing the need to store pending vertices or traversal frames. The companion Recursive Depth-First Search article owns the full graph-search treatment.

Backtracking and Exponential Search Spaces

Backtracking explores combinations of choices and abandons partial assignments when a constraint fails. If each level has up to b branches and the maximum search depth is d, a full search tree may have 1 + b + b² + … + bᵈ = Θ(bᵈ) nodes when b > 1. But pruning can remove subtrees and materially change observed or provable bounds. A recurrence for one specific problem instance may therefore depend on the remaining candidate set and the constraints already satisfied, not just the number of undecided positions.

A common rough worst-case upper bound is T(d) ≤ bT(d - 1) + O(g(d)) when each state creates at most b children and spends at most g(d) direct work. It is an upper bound, not necessarily a tight equation. If a search can exit upon finding the first solution, best-case cost may be small even when the complete-search worst case is exponential.

Complexity analysis should distinguish the cost of exploring nodes from the size of the output. An algorithm enumerating all 2ⁿ subsets must spend at least proportional work to produce those outputs under any ordinary representation. Pruning may reduce exploration for some instances, but it cannot eliminate the cost of output actually requested.

Output-Sensitive Recurrences and Result Construction

The cost of assembling recursive results can dominate the cost of descending through calls. A recursion that constructs [x] + recursive_result in Python creates a fresh list and copies elements at each level. If the result grows from length one to length n, the total copied elements are 1 + 2 + … + n = Θ(n²), despite the existence of only n recursive calls.

By contrast, a routine that writes each output position once into a preallocated buffer may use Θ(n) total time for the same logical result, assuming constant-time indexed writes. Its recurrence can have Θ(1) local work per level because the assembly strategy has changed. A recurrence must describe the representation that is actually produced, not just the recursion shape.

An output-sensitive algorithm may be analyzed as O(input-dependent exploration + number of output items). For enumeration, report the cost per generated object and any fixed preprocessing overhead. For a generator, the total work to yield all outputs differs from latency to first result and peak auxiliary storage during streaming.

Amortized Analysis and Recurrences

Some algorithms invoke recursive subroutines while performing operations whose individual costs vary significantly over time. A growable array append, for instance, may occasionally reallocate and copy an entire buffer, but over many appends the total resizing overhead can be linear under a suitable geometric-growth policy. If a recursive routine appends one item at each of n levels, charging every append by the worst individual resizing cost would grossly overestimate the total.

An amortized bound distributes a sequence's total cost across its operations, by aggregate counting, a potential function, or the accounting method. If such an analysis proves that all n appends cost Θ(n) in total, the recursive algorithm may still be linear-time despite occasional expensive individual appends. The justification is the amortized proof, not simply replacing each append with Θ(1) worst-case work.

When the nonrecursive work depends on the evolving capacity of a shared structure or on a global cache, a simple recurrence in the scalar size n may hide the state that determines the true cost. One response is to add parameters to the recurrence; another is to combine a recurrence for structural calls with an independent aggregate or potential-function bound.

Separate Recurrences for Stack Depth and Space

Time recurrences sum costs across recursive descendants because all of them eventually execute in a sequential computation. Peak call-stack depth follows the longest active chain, so its recurrence often uses a maximum rather than a sum. If a routine recursively invokes two children one after another, and each frame occupies constant space, a representative depth relation is D(n) = 1 + max(D(n_left), D(n_right)) for nonbase inputs.

Auxiliary Buffers and Recursive Data Copies

Recursive calls may allocate objects whose lifetimes overlap. A straightforward top-down merge sort may create slices, sorted halves, and merged result arrays. Some temporaries are released before siblings run; others remain live until their parent combines results. An expression that adds every allocation made over all recursive calls measures cumulative bytes allocated, not necessarily peak live bytes.

For peak memory, track which child runs first and which parent's intermediate objects remain reachable. In a sequential routine with one persistent size-n merge buffer, auxiliary storage can be Θ(n) even though the algorithm performs Θ(n log n) work. A routine that retains every intermediate level may have a different peak bound. Destruction, garbage collection, reference lifetimes, and data-sharing policy affect the concrete result.

State clearly whether auxiliary space excludes the mandatory input and output representations. If an algorithm must return a list of n values, its total space is at least Ω(n) in that representation, even if it uses O(1) additional working variables besides the result itself.

Sequential Work and Parallel Span Are Different

For an algorithm that can execute independent recursive children concurrently, work counts all operations while span (critical-path length) counts the longest chain of dependent operations. If two equal recursive children are independent, a representative work recurrence is W(n) = 2W(n/2) + M(n), but the span may be P(n) = P(n/2) + Q(n), where M is total local work and Q its serial depth.

If a merge step is sequential and takes Θ(n) time, then even with parallel recursive sorts the span relation is P(n) = P(n/2) + Θ(n) = Θ(n). The work remains Θ(n log n). A genuinely parallel merge algorithm can have a different Q(n), and the span bound must be derived from that algorithm rather than borrowed from sequential merging.

The common lower bounds for runtime on p processing units include W(n)/p from total work and P(n) from dependencies, abstracting away overhead. A large branching recursion tree by itself does not guarantee efficient parallelism: memory bandwidth, communication, task overhead, imbalance, and sequential combine stages may limit speedup.

Bit Complexity and Numeric Operations

A numeric recurrence may count arithmetic operations while ignoring the size of the numbers on which they operate. Recursive factorial performs n multiplications, but the final result has about Θ(n log n) bits. Operations on such integers require time beyond a constant per multiplication in a bit-level model. An analysis concerned with actual large-integer workloads must specify the multiplication algorithm and operand lengths along the call chain.

A similar issue occurs with the classic recursive exponentiation-by-squaring algorithm. It reduces the exponent roughly by half each time and therefore uses O(log e) recursive levels to compute a power with exponent e. If the result's bit length grows with e, the cost of each multiplication also grows. Thus the number of multiplications and the total bit operations are distinct complexity statements.

For fixed-width integers, overflow may alter the mathematical problem; for arbitrary-precision integers, memory and operation cost grow with the value. A sound recurrence description states whether arithmetic is unit-cost, word-cost, or bit-cost and makes no claims beyond that model.

Expected, Worst-Case, and Distributional Recurrences

A worst-case recurrence must bound the most expensive permitted input or branch at each size, but the individual worst children may require careful justification: they cannot always be selected independently if input constraints couple them. A best-case recurrence describes favorable inputs or branches and may have different base conditions or local work. An expected recurrence averages cost over a precisely stated probability distribution and must account for conditional subproblem distributions.

Randomized quicksort provides a standard model where the pivot rank is uniform. For other randomized divide-and-conquer routines, a distribution over split sizes may differ or may depend on the history of earlier decisions. The law of total expectation produces a weighted sum of conditional expected costs, not an unweighted average unless the alternatives are equally likely.

Be wary of replacing a random subproblem size X with its mean inside an unknown nonlinear cost function: E[T(X)] does not generally equal T(E[X]). Doing so may appear to simplify the recurrence, but it changes the mathematics unless additional properties establish equality or an appropriate bound.

Akra–Bazzi: A Framework for Unequal Subproblems

Some divide-and-conquer recurrences have several fixed but unequal shrinkage factors: T(x) = Σᵢ aᵢ T(bᵢ x + hᵢ(x)) + g(x). Under appropriate positivity, regularity, and perturbation assumptions, the Akra–Bazzi theorem can solve such relations. Its key exponent p is determined by Σᵢ aᵢ bᵢᵖ = 1, with each shrink factor 0 < bᵢ < 1. A common continuous form is T(x) = Θ(xᵖ (1 + ∫₁ˣ g(u)/u^(p+1) du)), given the theorem's stated hypotheses.

For T(n) = T(n/3) + T(2n/3) + Θ(n), the equation for the exponent is (1/3)ᵖ + (2/3)ᵖ = 1, giving p = 1. The integral of u/u² = 1/u from one to n contributes Θ(log n). Hence T(n) = Θ(n log n), consistent with the direct recursion-tree argument.

Akra–Bazzi is not a license to ignore its assumptions. Irregular local work, unsupported integer rounding, variable coefficients, or perturbations outside the theorem's scope require separate reasoning. It is best viewed as an advanced tool that generalizes selected master-theorem analyses, not as a replacement for understanding how the original algorithm generates its subproblems.

Comparing and Proving Bounds: O, Ω, and Θ

Big-O notation provides an asymptotic upper bound: T(n) = O(g(n)) means that, eventually, T(n) is at most a fixed multiple of g(n). Big-Omega, Ω(g(n)), provides a lower bound. Big-Theta, Θ(g(n)), requires both upper and lower bounds. Describing an algorithm as O(n²) does not exclude a faster Θ(n log n) bound; it is simply less informative.

For T(n) = 2T(n/2) + Θ(n), the recursion-tree proof provides both directions if each level has work bounded above and below by constant multiples of n. For a relation with O(n) rather than Θ(n) local work, the same construction only proves an upper bound unless the rest of the recurrence supplies a separate lower bound.

Every asymptotic statement is tied to an asymptotic variable. In graph algorithms, a bound such as O(V + E) involves two quantities and cannot be replaced with a single-size expression without assumptions about graph density. For memoization, the number of states and transitions may be a more informative parameter pair than raw input length.

Computational Experiments as a Check, Not a Proof

Instrumentation can reveal whether a theoretical model matches implementation behavior on selected workloads. For the recursive routines studied here, count calls, comparisons, allocation volume, recursion depth, and wall-clock time separately. Vary input size and shape, record whether the workload is worst case or random, and repeat measurements in a controlled environment to reduce noise.

Worked Scenario I: Counting a File-Index Tree

A document-management service traverses a rooted folder tree and computes aggregate file counts. Every folder is visited once and each immediate child is examined. The natural cost equation on a folder node v is T(v) = Σ T(child) + Θ(degree(v) + 1), where each child is considered once. Summing over all nodes and edges in the folder tree yields Θ(V) work, where V counts folders and files or just folders depending on the chosen representation.

For stack planning, the relevant variable is the deepest nesting height h, not the total file count. A folder structure with many sibling folders may have millions of entries but modest recursive depth; a single nested chain may have much less total work and a dangerous stack depth. The service should therefore monitor both input count and nesting limits, and may use an explicit stack if user-controlled depth is unbounded.

Decision: adopt the structural per-node recurrence for work, the height relation for call depth, and a separate accounting of any output manifest retained in memory.

Worked Scenario II: Sorting Records for a Report

An analytics service sorts millions of transaction records by timestamp. A merge-sort model makes two recursive calls on roughly equal partitions and pays Θ(n) to merge them; this yields Θ(n log n) comparison and movement work in the ordinary model. If records have variable-length keys, each key comparison may not be constant time. If the algorithm copies full record objects rather than references, the bytes moved also depend on record size.

To build a capacity plan, specify separate metrics: number of key comparisons, bytes copied, peak auxiliary storage, and time spent in I/O. The recurrence in n captures the first two only under appropriate assumptions. External sorting, where data exceed memory, introduces block transfers and disk access costs that require an I/O-aware model.

Decision: retain the n log n structural analysis for comparisons, but avoid claiming that wall-clock runtime or total memory is fully characterized by a single scalar recurrence.

Worked Scenario III: Nested Document Parsing

A parser reads a nested markup document and recursively processes embedded expressions. If every token is consumed once by a deterministic parser without repeated backtracking, the total parsing work may be Θ(n) even though the source code contains deeply nested recursive functions. If the grammar and parsing strategy can revisit previously examined substrings, the recurrence may include repeated subproblems and a larger cost.

In a deeply nested input, stack depth may approach the nesting depth, which can be as large as the number of tokens. A service that accepts untrusted documents must distinguish linear total work from stack-safety requirements. Some parsers impose a maximum nesting level; others use explicit stacks or iterative parsing algorithms to preserve a controlled memory policy.

Decision: derive time from actual token processing and backtracking behavior, and separately bound the maximum active parser context. A binary-split master theorem is not justified merely because the grammar is recursively defined.

Worked Scenario IV: Search with Repeated Subproblems

A planning engine evaluates alternative action sequences. Many branches reach the same state characterized by remaining budget, current position, and time period. A pure search-tree recurrence may charge separately for every path reaching that state and predict exponential exploration. Memoization changes the unit of work from path occurrence to distinct state; complexity then depends on the size of the state space and the number of transitions explored per state.

Suppose there are N reachable states and each has at most d outgoing candidate actions. Under constant-cost transition processing and cache operations, total work is O(Nd), plus any cost of storing or reconstructing decisions. This is often much smaller than a full branching tree of depth k, but can still be exponential in the original input length if N itself grows exponentially.

Decision: do not preserve the original naive recurrence after memoization. Establish a state definition, prove cache-key correctness, and analyze the resulting state-transition graph.

Worked Scenario V: Randomized Partitioning

A search-and-sort library selects pivots randomly to reduce sensitivity to adversarial input order. Its expected cost is obtained by averaging over random pivot positions; its worst-case cost remains quadratic for an implementation that can repeatedly choose an extreme pivot. The operational plan must not substitute an expected bound for a guaranteed time budget.

For ordinary batch workloads, randomized expected Θ(n log n) work may be acceptable. For a real-time processing deadline, designers may prefer an algorithm with a deterministic worst-case bound, an introspective sort that switches strategies after excessive partition depth, or an explicit resource cutoff. Each choice changes the actual control flow and therefore the relevant recurrence.

Decision: declare whether the requirement concerns expectation, a specified percentile, or a hard upper bound, then choose the recurrence and mitigation accordingly.

Worked Scenario VI: Parallel Divide-and-Conquer Analytics

An analytics pipeline divides a dataset into independent partitions, computes summaries, and combines partial results. Its sequential work may fit W(n) = 2W(n/2) + Θ(n), giving Θ(n log n) work if each merge scans all data at every level. However, launching the two recursive branches concurrently only reduces the child portion of the critical path; if the combine stage remains sequential Θ(n), the span is still Θ(n).

The scheduler also incurs task-creation costs, communication delays, and memory traffic. For small partitions, sequential processing may outperform parallel task spawning. Some systems therefore impose a grain-size threshold and process small subproblems directly. That changes constants and possibly observed performance but normally preserves the high-level work bound when the threshold is fixed.

Decision: calculate both work and span, document the serial combine stage, and benchmark the implementation across realistic processor counts and data layouts. A branching recurrence alone does not establish parallel scalability.

A recurrence analysis should be auditable from the algorithm's source-level behavior to the claimed complexity class. Frequent Misconceptions and Corrective Explanations

  1. “One recursive call means logarithmic time.” False: a one-child recurrence may decrement by one and need linear depth, or perform linear work at each of logarithmically many levels.
  2. “Two recursive calls mean exponential time.” False: balanced merge sort makes two calls but has Θ(n log n) time; naive Fibonacci is exponential because it repeatedly recomputes overlapping states.
  3. “The number of calls is the whole cost.” False: slicing, copying, partitioning, arithmetic precision, and output assembly may dominate.
  4. “The Master theorem solves every divide-and-conquer algorithm.” False: unequal child sizes and irregular local costs can violate the elementary form.
  5. “A case-3 polynomial gap is sufficient.” False: the standard third case also requires the regularity condition.
  6. “Floors and ceilings never matter.” False: they affect exact counts and can affect termination; asymptotic equivalence requires an applicable argument.
  7. “Time and stack space satisfy the same recurrence.” False: total work sums sequential branches, while maximum active depth follows a longest path.
  8. “Memoization keeps the original naive recurrence.” False: cache hits avoid expanding already evaluated states, so state-graph accounting is needed.
  9. “Average equals the cost at the average split.” False in general: E[T(X)] ≠ T(E[X]) for nonlinear T.
  10. “One empirical ratio proves an asymptotic bound.” False: measurement is useful for model validation, but a bound concerns all sufficiently large inputs in a specified class.
  11. “O(n²) means an algorithm is exactly quadratic.” False: Big-O is an upper bound; a tight class requires matching lower analysis.
  12. “A recursive implementation necessarily allocates all its tree nodes simultaneously.” False: a sequential depth-first runtime often retains only one active path plus explicitly retained data.

The corrective habit is to draw the call structure, count the actual local work, declare the cost measure, and separate the question of how many operations execute overall from how many frames or objects are live at once.

Suggested Study Pathways

Foundational sequence: begin with Recursive Definitions and Base Cases and Recursive Call Stacks, then work through the factorial and binary-search derivations here. Practice choosing exact base cases and explaining why a count of calls differs from the cost of local operations.

Mathematical analysis sequence: read Recursion and Mathematical Induction, then this entry's expansion and substitution proofs, followed by Recursion Trees and Divide and Conquer. Prove the merge-sort bound independently before applying the master theorem.

Implementation and performance sequence: compare Tail Recursion and Accumulators with Recursion Versus Iteration. Then derive both time and depth bounds for a tree walk, and study Recursion Limits and Stack-Safe Design to translate the analysis into resource safeguards.

Overlapping-subproblem sequence: start with the naive Fibonacci recurrence, explain why it is exponential, and study Memoization and Top-Down Dynamic Programming to understand why caching changes the work graph. Continue to state-space accounting for graph search and backtracking.

Advanced sequence: prove the unequal one-third/two-thirds split by a recursion tree or Akra–Bazzi; analyze n/log n boundary behavior; and compare sequential work and parallel span. The objective is to know when a familiar theorem cannot be applied, not only to memorize its final cases.

Review Questions and Model Answers

  1. Q1. Why does factorial have a linear unit-cost recurrence? A: One recursive child reduces n by one and each invocation performs constant local work; expansion gives n charged levels.
  2. Q2. What is the worst-case recurrence for index-based recursive binary search? A: T(n) = T(⌊n/2⌋) + Θ(1), with an empty or singleton base depending on the implementation; it solves to Θ(log n).
  3. Q3. Why is merge sort not quadratic despite two recursive calls? A: Its subproblems each have half the input size, and each depth processes a total of Θ(n) elements across Θ(log n) levels.
  4. Q4. Solve T(n) = T(n - 1) + n with constant base cost. A: Sum all local charges: Σᵢ₌₁ⁿ i = n(n + 1)/2, giving Θ(n²).
  5. Q5. Solve T(n) = 2T(n/2) + 1. A: The benchmark exponent is log₂ 2 = 1; the leaves dominate and the solution is Θ(n).
  6. Q6. Solve T(n) = 4T(n/2) + n². A: The benchmark is n², equal to local work; the result is Θ(n² log n).
  7. Q7. What must be checked in master-theorem case 3? A: The local work is polynomially above n^(log_b a) and satisfies a f(n/b) ≤ c f(n) for some fixed c < 1 eventually.
  8. Q8. Why does T(n) = T(n/3) + T(2n/3) + n require different reasoning? A: Child shrink factors differ, so the elementary equal-size master formula is inapplicable; direct levels or Akra–Bazzi yield Θ(n log n).
  9. Q9. What changes when Fibonacci is memoized? A: Calls to an already computed input become cache lookups, so total unit-cost work scales with distinct states and transitions rather than all naive call-tree occurrences.
  10. Q10. Does Θ(n log n) sequential time imply the same stack usage? A: No. Balanced merge sort ordinarily has Θ(log n) active call depth and often Θ(n) auxiliary merging storage.
  11. Q11. What is the solution of T(n) = T(n/2) + log₂ n on powers of two? A: Setting n = 2ᵐ gives a sum 1 + 2 + ⋯ + m, so Θ((log n)²).
  12. Q12. What distinguishes an exact count from a Big-O claim? A: An exact recurrence identifies the counted operation and constants; Big-O bounds growth from above without asserting exact work.
  13. Q13. Why can slicing change the binary-search time bound? A: Copying a half-array costs Θ(n) at that level; repeated halving then sums to Θ(n), unlike constant-cost index changes.
  14. Q14. What is wrong with replacing E[T(X)] by T(E[X])? A: In general the cost function is nonlinear, so evaluating it at the expected size does not reproduce the expected cost.
  15. Q15. Which additional metric is necessary for parallel recursion? A: Critical-path span, because reducing concurrent children does not remove serial combine-stage dependencies.
  16. Q16. Why can a time recurrence be valid while a memory claim is false? A: Time sums all child computations, whereas peak memory depends on live-object lifetimes, deepest frames, and retained buffers.

Independent practice: derive tight bounds for T(n) = 3T(n/3) + n, T(n) = T(n/2) + n², and T(n) = 2T(n/2) + n². Confirm, respectively, Θ(n log n), Θ(n²), and Θ(n²). For each, identify the dominant levels and state the recurrence's base conditions.

Glossary of Essential Terms

  • Recurrence relation: an equation expressing a quantity using values at smaller or earlier inputs.
  • Cost recurrence: a recurrence whose dependent quantity measures algorithmic work or another resource.
  • Base condition: the initial cost assigned to terminating cases.
  • Nonrecursive work: local computation performed outside recursive subcalls.
  • Input-size parameter: the measurable dimension used to characterize a problem instance.
  • Worst-case complexity: an upper characterization of cost over the most expensive allowed cases of a given size.
  • Expected complexity: cost averaged over a specified distribution or random choices.
  • Asymptotic upper bound (O): eventual domination by a constant multiple of a comparison function.
  • Asymptotic lower bound (Ω): eventual lower domination by a constant multiple.
  • Tight asymptotic bound (Θ): simultaneous upper and lower asymptotic bounds of the same order.
  • Unrolling: repeated substitution that converts recursive equations into explicit sums.
  • Substitution method: proving a candidate bound with induction.
  • Recursion tree: a tree representing recursive invocations and the local cost at each node.
  • Level cost: the total nonrecursive work across the nodes at a fixed recursion depth.
  • Branching factor: the number of recursive child invocations generated by a node.
  • Subproblem size: the input measure associated with a recursive child.
  • Master theorem: a theorem for certain fixed-ratio, equal-sized divide-and-conquer recurrences.
  • Leaf benchmark: the term n^(log_b a) associated with the number of leaves in a master recurrence.
  • Regularity condition: a requirement controlling the shrinkage of local work down the recursion tree in master case 3.
  • Polynomial gap: separation by a positive constant power of n rather than only logarithmic factors.
  • Characteristic equation: a polynomial equation whose roots help solve fixed-offset linear recurrences.
  • Akra–Bazzi theorem: a generalization for suitable recurrences with multiple unequal size ratios.
  • Memoization: caching computed subproblem answers to avoid repeating computation.
  • State graph: the set of distinct states and transitions explored by an algorithm.
  • Amortized cost: average cost per operation established by a bound on an entire sequence, not by a random expectation.
  • Call depth: number of simultaneously active nested invocations along an execution path.
  • Auxiliary space: working storage beyond the specified input and, under common conventions, output.
  • Work: total amount of computation in a parallel algorithm.
  • Span: longest dependency chain or critical-path computation in a parallel algorithm.
  • Unit-cost model: a model assigning constant cost to specified primitive operations.
  • Bit-complexity model: a model charging arithmetic costs according to operand representation and length.
  • Floor and ceiling: integer-rounding operations applied to real-valued size expressions.
  • Output-sensitive bound: a running-time bound expressed partly in terms of produced output size.
