Collection Overview

This directory is the specialist companion to the Recursion overview in the Computational Foundations division of the MGU Computer Science Encyclopedia. It separates the mathematical principle of self-reference from the concrete execution mechanisms of recursive programs and from the cost of algorithms that create recursive subproblems.

The parent identifies exactly 15 planned child articles. Their titles, filenames, and short descriptions are preserved here without creating a new parent page or replacing neighboring subjects. The directory groups the children into four study areas: foundations and proof, implementation and analysis, search and traversal, and advanced methods and safety.

At the conceptual level a successful recursive algorithm specifies a base case, a recursive reduction, and an argument that the reduction reaches a base case. In a program, these requirements connect to call-stack usage, control flow, time complexity, input constraints, and failure handling. The specialist articles address those dimensions in greater depth.

Publication convention: active links in this index point to designated future child destinations. They do not claim that those files exist or are live. For current comprehensive coverage, return to the Recursion parent article.

Recursive Definitions, Proofs, and Execution

Recursion is a method of defining or computing an object in terms of smaller instances of the same form. This group establishes base cases, the well-founded decrease toward termination, the connection to mathematical induction, and the execution mechanisms that make recursive procedures work.

  1. Recursive Definitions and Base Cases — Mathematical and programmatic formulation of terminating cases. (planned subarticle)
  2. Recursion and Mathematical Induction — Inductive correctness and structural proofs. (planned subarticle)
  3. Recursive Call Stacks — Activation records, stack depth, and unwinding. (planned subarticle)
  4. Structural and Generative Recursion — Data-driven and transformation-driven decompositions. (planned subarticle)

Implementation Choices and Complexity Analysis

Choosing a Recursive Technique

The presence of repeated function calls is not sufficient to identify an appropriate recursive design. Begin with the input structure, a termination argument, and the constraints of the runtime. The following table identifies the first subarticle to consult for a given problem; several subjects may be needed for one implementation.

These recommendations classify techniques rather than promising a universal fastest solution. An iterative breadth-first traversal may suit a shortest-path requirement better than recursive depth-first search, while a graph with millions of nodes may demand an explicit stack or streaming processing even when recursion is mathematically elegant.

Worked Comparison: Recursion, State, and Cost

Case A — a descending numerical recursion. Let factorial(n) return 1 when n = 0, and otherwise return n × factorial(n − 1) for nonnegative integers. Evaluating factorial(4) creates calls for inputs 4, 3, 2, 1, and 0; the results then return as 1, 1, 2, 6, and 24. There are five active calls at maximum depth, so stack use grows linearly with the input under the ordinary call-stack implementation. The key proof obligation is that each recursive step reduces the nonnegative input by one.

Case B — divide and conquer. A recursive merge-sort formulation splits an array into two roughly equal halves, sorts both halves, and merges the results. Its recurrence is typically T(n) = 2T(n/2) + Θ(n) for the simplified power-of-two case, giving Θ(n log n) time. The recursion depth is Θ(log n); separate merge storage can still require Θ(n) auxiliary space. The depth of recursion alone is therefore not the total memory cost.

Case C — overlapping subproblems. Naive recursive Fibonacci calculation branches into F(n − 1) and F(n − 2) and recomputes many values. With memoization, the routine evaluates each distinct input state at most once, yielding linear-time work under constant-cost arithmetic assumptions. The cache grows with the number of states, and for large numerical outputs the cost of big-integer arithmetic must also be considered.

Case D — a cyclic graph. A recursive depth-first search must mark discovered vertices or otherwise track visitation; without that discipline, cycles can produce repeated calls without progress. In a typical adjacency-list representation, a complete traversal visits every reachable vertex and scans each incident edge as appropriate, giving O(V + E) time. A path-shaped graph may still generate recursion depth proportional to the number of vertices, motivating explicit-stack designs in environments with limited call stacks.

Across all four cases, separate the logical definition, the termination measure, the time recurrence or work count, and the memory behavior. They are distinct questions and should be answered independently in a sound recursive design.

Suggested Study Pathways

Beginner foundations: Read Recursive Definitions and Base Cases first, followed by Recursive Call Stacks and Structural and Generative Recursion. Use simple list-processing or tree examples to identify the smaller instance in each call. Recursion and Mathematical Induction then formalizes the reasoning behind correctness and termination.

Algorithm analysis pathway: Continue from the foundational group to Recurrence Relations for Recursive Algorithms and Recursion Trees and Divide and Conquer. Study Recursive Binary Search to compare a single-branch logarithmic recurrence with merge sort’s multi-branch recurrence. Use Recursion Versus Iteration to compare algorithmic work with runtime overhead.

Data structures and search pathway: After the basics, study Recursive Tree Traversal, Recursive Depth-First Search, and Backtracking and Recursive Search. Make explicit whether the input is acyclic, whether each vertex can be revisited, and whether the objective is to find one solution or enumerate all results.

Programming language and compiler pathway: Pair Recursive Call Stacks with Tail Recursion and Accumulators, then study Recursive Descent Parsing. Finish with Recursion Limits and Stack-Safe Design. Compare what a language specification guarantees with optimizations that a particular compiler or runtime may provide.

Optimization pathway: Follow Recurrence Relations for Recursive Algorithms with Memoization and Top-Down Dynamic Programming. Identify overlapping states before adding a cache, distinguish a memoized recurrence from an unbounded cyclic dependency, and account for the memory cost of stored solutions.

These routes are recommended ways to read the planned collection, not a formal prerequisite scheme. Each future child should be comprehensible independently while pointing back to the parent overview for conceptual context.

Scope and Related Encyclopedia Topics

This collection treats recursion as a general mathematical and computational technique, not as a synonym for any specific algorithm. The child on recursive binary search is about the recursive formulation and its invariants; the broader subject of searching algorithms belongs in algorithm and data-structure references. Similarly, the child on recursive descent parsing examines recursion and grammars rather than replacing a comprehensive compiler article.

The sibling references below connect recursive ideas to established neighboring subjects. They are related topics, not additional children under the Recursion directory.

  • Discrete Mathematics — Inductive definitions, mathematical proof, functions, and recurrence relations.
  • Algorithm Analysis — Asymptotic bounds, running-time recurrences, correctness, and memory analysis.
  • Graph Theory — Trees, graph traversal, connectivity, and search algorithms.
  • Automata Theory — Formal languages, grammars, and machine models associated with parsing.
  • Complexity Theory — Resources and feasibility of computational problem families.
  • State Machines — State transitions, process descriptions, and control structure.
  • Linear Algebra for Computing — Recursive numerical decompositions and structured computational algorithms.
  • Probability and Statistics for Computing — Random branching, randomized search, and uncertainty in algorithm evaluation.
  • Processes and Threads — Execution contexts and concurrency distinct from recursive call structure.
  • Runtime Environments — Language and runtime mechanisms that determine call behavior.
  • Virtual Memory — Memory management and resource constraints in execution.
  • Information Retrieval — Search and indexing tasks that may use recursive traversal or partitioning.
  • Data Modeling — Hierarchical schemas and recursive relationships in data.

A recurring editorial boundary is the distinction between recursion and self-reference in definitions, recursion as a procedure-call implementation, and recursion as a complexity-generating subproblem structure. Future specialist articles should state which meaning is in use before introducing algorithmic or language-specific details.
