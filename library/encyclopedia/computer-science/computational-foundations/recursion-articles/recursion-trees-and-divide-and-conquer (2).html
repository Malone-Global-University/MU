Definition and Analytical Scope

A recursion tree is a conceptual representation of an algorithm’s recursive calls. Its root is the original problem; each child is a recursive subproblem; each node carries work performed locally, excluding the work delegated to descendants. Adding local work across all nodes yields the total cost under the chosen cost model. A divide-and-conquer algorithm intentionally decomposes one problem into smaller instances, solves them, and combines their answers. The tree is an analytical device, not necessarily a data structure allocated by the implementation.

This entry specializes in branching, subdivision, and level-by-level accounting: why balanced merge sort requires Θ(n log n) time, when skewed quicksort becomes quadratic, how depth differs from node count, and why memory analysis must include more than frame count. General recurrence-solving is treated in Recurrence Relations for Recursive Algorithms; complete sorting algorithms, data-structure implementations, and numerical analysis belong to their own specialist units.

A meaningful analysis states the input size, legal subproblem sizes, stopping rule, the combination or partition cost, whether the costs are worst-case or expected, and the operational meaning of “work.” Without these assumptions a familiar bound such as Θ(n log n) may describe a different algorithm from the one actually implemented.

Divide, Conquer, and Combine

The divide-and-conquer pattern comprises three logically distinct operations. Divide partitions an instance into strictly smaller instances. Conquer obtains a solution to each instance, often recursively. Combine constructs an answer for the original instance from the smaller answers. Some algorithms, such as binary search, discard one side and recurse only once; others, such as merge sort, retain both halves.

The word “balanced” refers to subproblem sizes, not necessarily equal output values or equal wall-clock time. Splitting an input of odd size n into ⌊n/2⌋ and ⌈n/2⌉ items is near balanced. A “two-way split” is not balanced merely because two recursive calls appear in source code: partitions of sizes 0 and n−1 are as skewed as possible.

The termination proof must give a well-founded measure that decreases in every child; size alone is suitable for finite arrays and many finite sets, but a recursive function that repeatedly receives an unchanged slice is not guaranteed to stop.

A Precise Cost Model

Let T(n) denote total work for an input of size n. If a call creates subproblems of sizes n₁,…,nₖ and performs local work f(n), then a common abstract model is T(n)=Σ T(nᵢ)+f(n), with explicitly stated base costs for sufficiently small inputs. The summation counts the work of child calls; f(n) counts division, partitioning, comparisons, merging, allocation, bookkeeping, or other operations performed outside those child calls.

The same source code can be assigned multiple cost models: primitive comparisons, arithmetic operations, bytes moved, cache misses, or span of a parallel computation. A constant-time comparison assumption may be reasonable for fixed-width keys but not for arbitrarily long strings. If slicing an array copies data, that copying must enter f(n), even when omitted from a simplified pseudocode treatment.

Worst-case functions require a bound that applies across valid inputs of the same size. Average-case or expected analyses require an input distribution or a randomized-choice model. A recursion tree for one particular input is a trace of that input, not by itself a worst-case theorem.

Trees of Calls Versus Trees of Work

A node in the call tree represents one invocation. A node in the work tree usually annotates that invocation with its own nonrecursive cost. This distinction prevents double-counting: a node labelled T(n) already includes descendants, whereas a node labelled f(n) counts only local operations. Summing T-values at every node would count descendants many times.

Each node may also carry its input size, level, partition ratio, result allocation, and memory lifetime. If two calls have the same logical state and are separately executed, they are separate call-tree nodes. Memoization can merge repeated computations into a shared dependency graph and changes the work accounting; the ordinary full recursion tree then overestimates the computation after cache hits.

The stack is another structure entirely: it records the chain of currently active calls, not every call ever executed. A large call tree can have a shallow maximum root-to-leaf path.

Level, Height, Width, and Leaf Count

The root is at level 0. The width of level i is its number of nodes, and its level cost is the sum of local costs of those nodes. Tree height is the longest number of edges from root to leaf; call depth is often measured in frames, so a one-node tree has height zero but one active frame. Clearly state the convention used when quoting depth.

For exactly a equal children per internal node and all leaves at depth h, there are aⁱ nodes at level i and aʰ leaves. The total number of nodes is (aʰ⁺¹−1)/(a−1) for a greater than 1, including the root. A balanced binary tree with n singleton leaves has Θ(n) nodes and Θ(log n) height; these are not contradictory measures.

A real recursion tree may be irregular, with variable branching and early leaf termination. Level-cost arguments still work by summing every node that actually exists at each level, but an equality such as 2ⁱ nodes must not be assumed without the required regularity.

General Balanced-Branching Accounting

Consider the recurrence T(n)=aT(n/b)+c n^d for fixed a≥1, b>1, constant c>0, and n a power of b. At depth i, the tree contains aⁱ nodes of size n/bⁱ. Ignoring base-case constants, each node costs c(n/bⁱ)^d, so total level cost is c n^d (a/b^d)^i. The number of levels before singleton problems is log_b n.

Write r=a/b^d. If r<1, the upper levels dominate the nonleaf sum; if r=1, each level contributes the same order and there are Θ(log n) levels; if r>1, the lowest levels dominate. The leaves number a^(log_b n)=n^(log_b a), which must be included when deriving a final bound.

This is a direct geometric-series argument for polynomial local work and uniform splits. It is not a complete statement of every master theorem: logarithmic factors, oscillatory costs, uneven subproblems, and missing regularity assumptions require separate reasoning.

The Root-Dominated Pattern

For T(n)=2T(n/2)+n², depth i contains 2ⁱ nodes; each does (n/2ⁱ)² work, giving a level total n²/2ⁱ. The level costs form n², n²/2, n²/4, and so on. Their sum is less than 2n² for nonnegative levels; the singleton leaves contribute Θ(n). Consequently total work is Θ(n²).

The recursion depth is Θ(log n), despite the quadratic total time. A superficial rule that every two-way recursion has Θ(n log n) time would be false here; combination or local work overwhelms the leaves. This pattern can occur when each call processes all pairs among its local items before descending.

The Equal-Per-Level Pattern

For T(n)=2T(n/2)+n, level i contains 2ⁱ subproblems of size n/2ⁱ. Each node incurs Θ(n/2ⁱ) local work, so every full internal level contributes Θ(n). At n=2^h, there are h=log₂ n internal levels and n base-case leaves. With constant base cost, the exact model T(1)=1; T(n)=2T(n/2)+n yields T(n)=n log₂ n+n.

Thus time is Θ(n log n), not Θ(n²) and not Θ(log n). The crucial fact is that each input item participates in Θ(log n) levels of processing when linear work is done once per level. Actual merge-sort implementations vary in constant factors and allocation strategies, but standard comparison-based merge sort is an exemplar of this level-cost pattern.

The Leaf-Dominated Pattern

For T(n)=4T(n/2)+n, level i incurs 4ⁱ·(n/2ⁱ)=n·2ⁱ local work. The sequence n,2n,4n,… grows toward the leaves. With h=log₂ n levels, the number of leaves is 4^h=n², so the total work is Θ(n²), assuming constant leaf work.

This result also demonstrates why “divide into halves” does not imply logarithmic processing. Four recursive subproblems on half-size inputs duplicate a great deal of work. In contrast, a binary search that retains only one half has T(n)=T(n/2)+Θ(1) and Θ(log n) time. Branch count is as important as shrink factor.

Merge Sort: Problem and Algorithm

Merge sort sorts a finite sequence by recursively sorting its left and right halves, then merging the two sorted results into one sorted output. The recurrence depends on the merge procedure: a conventional linear scan using a temporary buffer merges p and q items in O(p+q) comparisons and moves. Array slicing can add further O(n) copying per level but does not change the Θ(n log n) upper bound if performed in the same asymptotic amount.

Stability means items that compare equal retain their original relative order. It is achieved by taking the left element when keys compare equal. Stability is a property of the merge rule, not of the divide-and-conquer technique alone. A conventional two-way top-down merge sort uses a linear-size auxiliary buffer and a logarithmic-depth call stack for fixed-width elements under ordinary assumptions.

Worked Implementation: Stable Merge Sort

The example uses index ranges over one copied array and a reusable temporary buffer. It does not create a new list at every recursive call. The merge operation is linear in the range length; the recursive calls handle disjoint halves.

def stable_merge_sort(values):
    items = list(values)
    temp = [None] * len(items)

    def sort(lo, hi):                 # half-open interval [lo, hi)
        if hi - lo <= 1:
            return
        mid = lo + (hi - lo) // 2
        sort(lo, mid)
        sort(mid, hi)
        i, j = lo, mid
        for k in range(lo, hi):
            if j >= hi or (i < mid and items[i] <= items[j]):
                temp[k] = items[i]
                i += 1
            else:
                temp[k] = items[j]
                j += 1
        items[lo:hi] = temp[lo:hi]

    sort(0, len(items))
    return items

assert stable_merge_sort([8, 3, 7, 3, 2]) == [2, 3, 3, 7, 8]

The use of <= in the merge comparison selects the left element on a tie; the printed integer example alone does not prove stability for records with equal keys, but the comparator rule does preserve their relative sequence when comparisons reflect the intended keys. The function is illustrative rather than an alternative to production-tested library sorting. Its allocation is Θ(n) for the copied input and temporary array in addition to the call stack.

Merge Sort: Correctness by Induction

The induction measure is the interval length m=hi−lo. For m≤1, an interval is already sorted. Assume the recursive calls sort every shorter interval. Both child intervals have length strictly less than m and cover the original interval without overlap or omission. The merge loop always selects the smallest remaining front item of the two sorted intervals and appends it to the output prefix.

The merge invariant is: before each placement, the prefix already written is sorted and contains exactly the smallest processed elements from the two halves, in stable order when the left side wins ties. Each iteration increases that prefix by one element. When all m positions have been filled, the merged interval is sorted and contains precisely the original multiset. The induction closes, establishing correctness for every finite input.

The cost proof and correctness proof answer different questions. A recursion tree shows how many operations occur; it does not independently establish that the output is sorted or that every element appears exactly once.

Merge Sort: Unequal Halves and Small Inputs

For arbitrary n, the standard recurrence is T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+Θ(n) with constant cost for n≤1. Children are as equal as possible, and the depth is Θ(log n). A rigorous upper bound follows because every level processes at most n elements and there are O(log n) levels. A corresponding lower bound for a conventional full linear merge can be obtained from Θ(n) work over Θ(log n) sufficiently populated levels.

Do not quietly replace the recurrence with 2T(n/2) as an exact equality when n is odd. For asymptotic discussion it is often an acceptable simplification after noting rounding, but exact operation counts require the actual child sizes and the particular merge implementation. Empty and singleton arrays terminate without recursive subdivision.

Quicksort: Partitioning and Recursion Shape

Quicksort selects a pivot, rearranges the sequence around that pivot, and recursively sorts the subarrays on either side. A conventional partition procedure processes m items in Θ(m) local time. If the resulting subproblem sizes are k and m−1−k, the conditional recurrence is T(m)=T(k)+T(m−1−k)+Θ(m).

Unlike merge sort, the two child sizes depend on pivot selection and data arrangement. A best-case or highly balanced partition yields approximately two halves and Θ(n log n) work. Partitions of sizes zero and n−1 form a chain with Θ(n) levels; linear partition work accumulated along that chain yields Θ(n²). Random pivot selection gives expected Θ(n log n) comparisons under the usual uniform random pivot assumptions, but the worst-case remains quadratic.

Partition implementations also differ in treatment of duplicate keys. Three-way partitioning can dramatically reduce redundant work for arrays with many equal keys. These details affect both the recurrence and the validity of claims about a particular implementation.

Why Randomized Quicksort Has Expected n log n Work

A random pivot makes every rank equally likely within the current subarray under the standard model. One approach analyzes comparison indicators: two elements of ranks i<j are compared only if one of them is selected as the first pivot from the range of ranks i through j. That probability is 2/(j−i+1). Summing over every pair yields expected comparisons Θ(n log n).

A different route bounds the expected depth by observing that a nontrivial fraction of pivots split the current interval into pieces no larger than a fixed fraction, and such productive pivots occur with constant probability. Neither argument claims that every execution is balanced. Expected O(n log n) performance is compatible with rare Θ(n²) executions.

The random-pivot result depends on actual randomization, not on a fixed pivot rule that an adversarial input can exploit. Expected complexity is not a guarantee for every individual input or random seed.

Protecting Recursive Depth in Quicksort

A practical implementation can recurse on the smaller partition and process the larger partition iteratively. With each recursive call handling at most half the active range, the number of simultaneously active recursive frames is O(log n), even when the total number of partitions and total comparisons remain poor. This is a stack-management technique; it does not convert a quadratic worst-case time bound into O(n log n).

Introsort adds another safeguard: it begins with partition-based sorting and switches to a bounded-depth fallback, commonly heapsort, when recursion exceeds a threshold. A production implementation should also consider insertion sort for small partitions and special handling for equal keys. These are engineering choices; the recursion-tree analysis clarifies which resource each addresses.

Single-Branch Recursion Is a Different Tree

Binary search makes at most one recursive call after discarding a half-interval. Its recurrence is T(n)=T(⌊n/2⌋)+Θ(1) for the conventional cost model, so the call tree is a chain with Θ(log n) nodes. There are no two child branches to add.

The contrast with merge sort is instructive: both split the interval near the midpoint, but binary search ignores one half while merge sort must process both. Balanced splitting by itself does not determine cost. For a full treatment of sortedness, interval invariants, and boundary cases, see Recursive Binary Search.

A Four-Branch Example and the Geometry of Growth

An algorithm that recursively solves four half-size problems and performs Θ(n) local work follows T(n)=4T(n/2)+Θ(n). At level i, the total nonrecursive cost is Θ(n·2ⁱ), so the leaves dominate with Θ(n²) total work. This pattern occurs, for example, in some straightforward recursive formulations that expand combinations of subproblems without eliminating redundant work.

If the children overlap in their input regions, the number of distinct states may be much lower than the number of call-tree nodes. Memoization may then change the computational structure into a dependency graph. For spatial or matrix algorithms, the real task may include many subproblems but also specialized operations that alter f(n). One cannot transfer the four-branch result to an arbitrary block algorithm without examining its actual recurrence.

Unequal Subproblems: The One-Third–Two-Thirds Split

Consider T(n)=T(⌊n/3⌋)+T(⌈2n/3⌉)+Θ(n), adjusted at tiny n so every child is smaller. The splits are uneven but their sizes sum to n. At any given depth, subproblem ranges are disjoint and the sum of their sizes is at most n, so the total cost per level is O(n). The longest branch has O(log n) depth because it repeatedly shrinks by about 2/3, giving an O(n log n) upper bound.

For a matching lower bound in the idealized linear-local-work setting, use the fact that no leaf can occur before roughly log₃ n levels along any path when all children are at least near n/3, and that all work of a fully populated early level still accounts for the n original elements. Therefore Θ(n) work persists across Θ(log n) upper levels, yielding Ω(n log n). Under the stated regularity and constant-size leaves, the total is Θ(n log n).

The ordinary equal-size Master theorem does not directly apply to this form. Substitution, a weighted-level argument, or a more general recurrence theorem can establish the bound.

When Unequal-Split Logic Fails

Not every pair of subproblems partitions the original data. If a recurrence makes two overlapping calls each on 0.7n elements and does Θ(n) local work, the sum of child sizes exceeds n; the assertion that every level processes at most n elements fails. Repeated states and overlapping windows must be modeled, not silently treated as disjoint partitions.

Similarly, a call whose largest child has size n−1 is not a fixed-fraction shrink, and its height need not be logarithmic. Recurrences such as T(n)=T(n−1)+Θ(n) have a linear-depth chain and quadratic total work. State an actual upper bound on child size before invoking geometric-depth arguments.

The Master Theorem: Appropriate Use

The familiar Master theorem addresses many recurrences of the form T(n)=aT(n/b)+f(n) where a≥1 and b>1 are constants and suitable positivity and regularity hypotheses hold. It compares f(n) with the critical power n^(log_b a). For polynomial local work, the recursion-tree ratio reproduces its principal cases.

If f(n) is polynomially smaller than the critical term, leaves dominate. If f(n) matches the critical term, contributions across levels accumulate a logarithmic factor. If f(n) is polynomially larger and an appropriate regularity condition is satisfied, the root-side nonrecursive work dominates. No single three-case slogan handles arbitrary oscillatory functions, nonconstant branching factors, or genuinely unequal child sizes.

This article emphasizes why the theorem’s cases occur in the tree. Formal recurrence statements, exceptions, and alternative solution methods appear in Recurrence Relations for Recursive Algorithms.

Distinguishing Time, Depth, and Auxiliary Space

Total time counts the work of every executed node. Maximum recursion depth counts the length of the longest active path. Auxiliary space counts storage simultaneously alive, including stack frames, temporary arrays, partition buffers, result objects, and any copies of input data. A full recursion tree should not be mistaken for a pile of frames held at once during standard sequential execution.

For a balanced top-down merge sort, the total time is Θ(n log n), the recursive depth is Θ(log n), and a conventional linear auxiliary merge buffer contributes Θ(n) space. For a straightforward in-place quicksort, partition operations can use O(1) extra local storage, while active recursive frames use O(log n) for balanced splits but O(n) for skewed splits unless the code bounds recursion by processing the smaller side first.

An implementation that copies each slice before descending changes the memory-lifetime calculation. If recursive buffers are held while children run, peak live storage can accumulate; if a reusable buffer is shared or allocated once, it may not. Analyze allocation policy and lifetime rather than inferring space from the time recurrence.

Parallel Work and Span

When recursive subproblems are independent, they may be evaluated concurrently. Work is the sum of operations across all tasks; span (critical-path length) is the longest dependent chain of operations. For a balanced two-way split with Θ(n) sequential combine cost, work satisfies W(n)=2W(n/2)+Θ(n)=Θ(n log n), while span can satisfy S(n)=S(n/2)+Θ(n)=Θ(n) if the merge remains sequential.

Using a parallel merge can reduce the combine-span term, but requires a different algorithm and proof. A processor count by itself does not establish the span bound, and parallel runtime also includes scheduling, communication, synchronization, and memory effects. The recursion tree distinguishes potentially parallel branches from the mandatory order of operations along a path.

External Memory and Cache-Aware Interpretation

An algorithm with good comparison complexity may still perform poorly when data moves across cache and storage levels. Merge sort’s sequential merge phases can offer good locality, yet repeated allocation and copying increase memory traffic. Quicksort may be attractive for in-place partitioning, but its access pattern and pivot behavior influence cache utilization.

A recursion-tree model for I/O can assign cost to block transfers instead of arithmetic operations. Such a model needs block size, available memory, and assumptions about placement; it is not legitimate to equate the arithmetic recurrence with the number of disk reads. Similarly, divide-and-conquer matrix and geometric algorithms can profit from recursive locality, but the performance claim must be tied to the actual memory model.

How Base Cases and Cutoffs Affect the Tree

Stopping at a fixed threshold k rather than at size one changes tree height from roughly log_b n to log_b(n/k), and changes the number and size of leaves. If a small-instance algorithm runs in Θ(k²) time on each of approximately n/k leaves for a balanced binary partition, leaf work totals Θ(nk). For fixed k this is linear, but if k grows with n it can alter the asymptotic result.

Well-designed hybrids often use a small cutoff for better constant factors. The cutoff must ensure every child is smaller and that the fallback algorithm returns a valid result. Tuning k experimentally on one machine does not establish a universal optimum or invalidate a correctly derived large-input asymptotic bound.

Recursion Trees and Output Construction

Building output can dominate a recurrence that counts only logical recursion. Suppose a function recursively forms all permutations of n distinct items. The output itself contains n! sequences of length n, so writing the complete explicit result requires Ω(n·n!) work and storage of comparable order if the entire output is retained. A tree that counts only branch selection understates the work.

Likewise, concatenating immutable strings at each node can cause repeated copying; returning references or a generator changes allocation and output timing. Correct complexity analysis must count the representation and delivery of results, not just the number of branches. The recursion tree is a framework for accounting, not a substitute for choosing the correct unit of cost.

Work Sharing, Memoization, and Call DAGs

Naive Fibonacci recursion illustrates repeated subproblems: the call for F(n−2) appears directly and again under F(n−1). A full call tree contains many copies of the same argument. Memoization computes each state once, retains the result, and converts the execution dependencies into a directed acyclic graph for this case. The number of distinct states and dependency edges, not the expanded tree’s repeated copies, then governs work.

Caching imposes space and lookup costs, and a cache with eviction can reintroduce repeated work. More generally, dynamic programming is appropriate when repeated subproblems can be identified by a valid state key and their results can be reused safely. See Memoization and Top-Down Dynamic Programming for state formulation and correctness.

Recursion Trees Versus Structural Tree Traversal

When recursively traversing a binary tree stored as input, the recursion follows the input’s edges; it is not necessarily dividing a flat input into near-equal halves. A balanced input tree has Θ(log n) height, while a chain-shaped input tree has Θ(n) height. A full traversal visits n nodes in Θ(n) time in either case if each node is handled in Θ(1) time.

In a general branching tree, variable node degrees change width, but visiting each reachable node once still gives linear work in the number of nodes for the usual pointer-based traversal. Thus tree height affects stack use and latency to deep descendants, while total visits depend on the input size. This boundary is developed in Recursive Tree Traversal.

Recursion Trees Versus Graph Search

A graph may contain cycles and multiple paths to a vertex. Expanding neighbors recursively without marking visited vertices can revisit states indefinitely. Depth-first search with a visited set turns the state exploration into a traversal of reachable vertices and edges rather than the unlimited path-expansion tree.

A conventional adjacency-list DFS runs in O(V+E) time and O(V) auxiliary space including visited state and worst-case stack, assuming each vertex and edge is considered a bounded number of times. This is not the same recurrence as balanced divide and conquer; use Recursive Depth-First Search for cycle handling and traversal invariants.

Worked Scenario I: Sorting Eight Records

Suppose a department must sort eight records by a fixed-width key. Merge sort divides 8→4+4, then each 4→2+2, then each 2→1+1. There are three internal merge levels; at each, the sum of the lengths of merged intervals equals eight. If we model each merge by a cost exactly equal to its interval length and each leaf cost one, the total accounting is 8+8+8+8=32.

Actual comparisons may be fewer: merging two sorted lists of lengths p and q uses at most p+q−1 key comparisons, though movement and assignments add operations. The example distinguishes a cost-model tally from an exact language-level instruction count. The stable merge procedure can be selected if retaining original order among equal keys matters.

Worked Scenario II: A Pivot Rule Meets Presorted Data

An analyst chooses the final array element as quicksort’s pivot. On an already ascending array of distinct values, this pivot is the maximum, so each partition leaves an n−1 subproblem and an empty side. Linear partition work yields approximately n+(n−1)+···+2=Θ(n²) time and potentially Θ(n) call depth.

Switching to random pivots changes the expected behavior, not the theoretical worst case. Recurse-on-smaller-side-first can protect stack depth without eliminating worst-case quadratic partition work. A benchmark that reports only random arrays would not reveal the failure of the deterministic last-element rule on this input class.

Worked Scenario III: Document Processing by Halves

A documentation pipeline recursively divides a very large sequence of pages into halves, extracts independent metadata for each page, and combines two result lists in linear time. The model resembles T(n)=2T(n/2)+Θ(n) because the combine phase scans all returned records. The expected work is Θ(n log n) if full rescanning really occurs at each level.

If instead each leaf extracts one record and internal nodes combine two linked sequences in O(1) time while deferring flattening until the end, a different representation can change the nonrecursive cost and perhaps the total. The tree method forces an implementation-level question: does “combine” actually copy all items, or merely link existing results?

Worked Scenario IV: Recursively Processed Images

An image system divides each square region into four quadrants and performs a constant amount of metadata work at each region until single pixels are reached. If n measures the number of pixels and each quadrant contains n/4 pixels, the recurrence is T(n)=4T(n/4)+Θ(1)=Θ(n). If n instead measures the side length, the equivalent form is T(n)=4T(n/2)+Θ(1)=Θ(n²).

Both statements describe linear work in the number of pixels, but use different definitions of input size. This is a recurring source of apparent disagreement in divide-and-conquer analysis. Always say whether n denotes area, side length, number of objects, or bit length.

Worked Scenario V: A Weighted Unbalanced Partition

A data pipeline divides n records into approximately n/3 and 2n/3, processes both independently, and merges them with a single linear pass. The tree is asymmetrical, yet each level carries no more than n records in total. The largest path shrinks by a factor near 2/3 each step, yielding O(log n) height and O(n log n) aggregate work.

To justify a matching lower bound, assume the local processing is at least c·m on a node of m items and that the partition divides all m records between children until bounded-size leaves. For the first Θ(log n) levels, all records reside in active nonleaf subproblems, each counted exactly once, so the level contributes Ω(n). This explains why unequal is not synonymous with inefficient.

Worked Scenario VI: Parallel Aggregation

A service calculates an aggregate over independent chunks. Each call divides its input into two halves, both calls compute sums, and the parent combines the results in O(1) time. Sequential work is Θ(n) from W(n)=2W(n/2)+Θ(1). If subtasks execute concurrently without overhead and combining needs constant span, the critical path is Θ(log n).

On a finite worker pool, actual elapsed time cannot be lower than total work divided by the number of processors or lower than span, apart from model-specific constants. This idealized case is a basis for scheduling analysis, not a promise of logarithmic wall-clock runtime on a single processor.

Ten-Gate Design and Analysis Framework

GateQuestionEvidence to record
1. Define inputWhat exactly does n measure?Elements, pixels, key length, or other unit
2. Validate subdivisionDoes every child become smaller?Size inequalities and base-case threshold
3. Determine branchingHow many child calls execute?Actual calls, not merely potential branches
4. Measure local costWhat is done outside the calls?Partition, merge, copy, allocation, result construction
5. Sketch shapeBalanced, skewed, variable, overlapping?Sizes and widths at representative levels
6. Add level costsHow much work occurs across one depth?Summation formula, not a guessed diagram
7. Count leavesWhat is the base-case contribution?Number and cost of terminal calls
8. Derive boundWhich levels dominate and why?Geometric sum, induction, or suitable theorem
9. Separate resourcesWhat is time, depth, peak space, span?Independent bounds and memory lifetime
10. Validate scopeWhich assumptions change in production?Rounding, duplicates, randomness, caching, I/O

A completed analysis should end with a defensible claim that includes its assumptions, rather than a naked asymptotic expression. The framework also helps identify when experimentation is needed to estimate constants after the proof establishes a growth class.

Misconceptions and Corrections

  • “Two recursive calls mean quadratic time.” False: two half-size calls with constant local work cost Θ(n), whereas two half-size calls with linear local work cost Θ(n log n).
  • “A tree with n leaves needs n stack frames.” False: sequential depth-first execution holds one active root-to-leaf path, plus any separately live buffers.
  • “Every partition uses two equal halves.” False: quicksort’s children depend on the pivot; two calls can be almost entirely skewed.
  • “The Master theorem always applies.” False: hypotheses concerning the recurrence shape and local-cost regularity matter.
  • “Balanced recursion uses no extra memory.” False: merge sort may allocate an O(n) buffer in addition to O(log n) frames.
  • “Expected n log n prevents n² executions.” False: expectation is a distributional statement, not a per-run guarantee.
  • “An algorithm’s source recursion is the recursion tree.” False: a recursion tree is an analytical expansion; memoization and shared states can change execution shape.
  • “A faster asymptotic bound proves faster real-world execution at any n.” False: constants, memory traffic, and input distributions also matter.

Review Questions and Model Answers

  1. 1. What is a recursion tree? A tree of recursive invocations annotated with local work; the sum of local work plus base work yields total work.
  2. 2. For T(n)=2T(n/2)+n, why is each level linear? Level i contains 2ⁱ nodes of size n/2ⁱ, making 2ⁱ·(n/2ⁱ)=n local work.
  3. 3. What is the Θ-bound for T(n)=2T(n/2)+n²? Θ(n²), because level cost decreases geometrically away from the root.
  4. 4. How do merge sort and binary search differ? Both divide near a midpoint; merge sort processes both halves, binary search retains only one.
  5. 5. Why does a bad quicksort pivot matter? It yields n−1-sized recursive work on each level, Θ(n) depth and Θ(n²) total partition work.
  6. 6. Does Θ(log n) depth imply Θ(log n) space? Not if separately allocated live buffers or copied data add more space.
  7. 7. What makes a recurrence suitable for the standard Master theorem? A fixed branching factor, fixed equal-size shrink ratio, suitable base cases and a qualifying nonrecursive cost.
  8. 8. What does randomization guarantee for quicksort? Under standard assumptions it gives expected Θ(n log n) comparisons, not a per-execution worst-case guarantee.
  9. 9. Why is a balanced tree not the same as an input tree? A recursion tree is generated by calls, whereas a tree-shaped input may be arbitrarily skewed.
  10. 10. What changes when memoization is added? Repeated states may be computed only once; a dependency graph becomes more appropriate than the fully expanded call tree.
  11. 11. Why analyze leaf work? A large number of constant-cost leaves can dominate even if all upper levels do little work.
  12. 12. What is the span of balanced parallel aggregation with constant combine time? Θ(log n) in an ideal parallel-dependency model, while total work is Θ(n).
