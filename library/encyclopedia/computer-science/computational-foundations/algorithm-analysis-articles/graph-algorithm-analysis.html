Definition, Purpose, and Scope

Graph algorithm analysis studies how computational effort depends on a graph's number of vertices, edges, representation, topology, and optional edge weights. The same graph question can be inexpensive or prohibitive depending on whether the graph is sparse, dense, weighted, changing over time, held in main memory, or represented implicitly. A proof about O(V + E) traversal is meaningful only after defining which vertices and edges the algorithm actually inspects.

This is the eleventh Level 5 specialist article under the Algorithm Analysis unit index. It extends the Algorithm Analysis overview, focusing on comparing cost models and guarantees rather than replacing the Graph Theory overview or the Recursive Depth-First Search specialist article. Its mathematical demonstrations draw on established algorithms; the executable examples are deliberately small so the invariants and operation counts remain inspectable.

Before choosing an algorithm, state whether the graph is directed or undirected, whether parallel edges and self-loops are allowed, whether weights may be negative, which representation is available, whether the output is one vertex, a path, a full traversal tree, or every pair of distances, and whether the input is static or updated between queries.

Graph Size, Input Encoding, and Output Contracts

Write V = |Vertices| and E = |Edges| for a graph G = (Vertices, Edges). For a simple undirected graph E is at most V(V − 1)/2, and for a simple directed graph without self-loops E is at most V(V − 1). Multigraphs may contain parallel edges, so neither bound applies without that restriction. When an undirected adjacency list stores each edge under both endpoints, its total neighbor-entry count is 2E; a directed adjacency list stores E outgoing entries.

Distinguish an algorithm's input representation size from the mathematical counts V and E. A matrix uses Θ(V²) cells even when few edges are present. An explicit list of isolated vertices uses Θ(V) space. A graph described by a successor function can have exponentially many reachable states without ever storing them simultaneously; its cost must include successor generation and the number of states actually explored.

Outputs also impose lower bounds: reporting every vertex requires Ω(V) output work, enumerating every edge requires Ω(E), and materializing all V² pairwise distances requires Ω(V²) space or output time even if a special graph admits a faster test for a single pair. Cost models should charge for the output that the application actually requests.

Adjacency Lists, Matrices, and Edge Lists

An adjacency list stores the neighbors of each vertex and normally supports a full neighbor scan in time proportional to its degree. A standard dictionary-of-lists representation uses Θ(V + E) storage, counting undirected edges once mathematically and twice as neighbor entries. Testing whether a specific edge exists may require scanning a list, unless neighbors are indexed or stored in sets. An adjacency matrix supports O(1) indexed edge checks and Θ(V²) storage, but a full row scan takes Θ(V) regardless of degree.

A bare edge list uses Θ(V + E) storage when the vertex set is recorded separately and supports simple streaming over edges. Finding all outgoing edges from one vertex may require scanning the entire list without an auxiliary index. Adding indexes or sorting edges changes construction, memory, and update costs. Choose a representation by its complete workload, not by the speed of a single primitive.

Degree Sums and Why Traversal Is Linear in V Plus E

For a simple or multigraph represented by adjacency lists, traversing all outgoing adjacency entries of a directed graph performs exactly E neighbor examinations; an undirected graph usually performs 2E because each undirected edge is encountered from both endpoints. Adding one initialization step per vertex yields Θ(V + E) time for a complete graph traversal under constant-cost adjacency access and queue or stack operations.

It is incorrect to multiply V by E merely because the program contains a loop over vertices with a nested loop over their neighbors: each neighbor loop has a different bound. The relevant sum is ∑vdeg(v), which is E for out-degrees in a directed graph and 2E for degrees in an undirected graph. A full DFS that visits all components is Θ(V + E); a source-restricted traversal may instead be bounded by O(V + E), with an actual count reflecting the reachable subgraph.

For adjacency matrices, iterating through V potential neighbors for each of V visited vertices can cost Θ(V²). That difference is an implementation consequence, not a contradiction of the underlying graph theorem.

Sparse, Dense, and Implicit Graphs

Graphs with E = O(V) are often called sparse; simple graphs with E = Θ(V²) are dense. The distinction predicts when Θ(V²) matrix storage is comparable to the number of actual edges. It does not determine every runtime: a sparse network with enormous V can still exceed memory capacity, and a dense matrix may be faster for repeated edge-membership queries when locality and representation overhead dominate.

Implicit graphs are defined by a state-transition or neighbor-generation rule. A maze grid, puzzle state space, or program-control graph may be explored without first listing every state. If each expanded vertex requires cost c(v) to generate its neighbors, total traversal work is more precisely O(Vseen + Egenerated + ∑c(v)), with care not to double-count generation. Stop conditions, revisitation rules, and path length become essential; a syntactically small state description may encode a huge search space.

Breadth-First Search: Queue Invariant and Complexity

Breadth-first search (BFS) explores an unweighted graph from a source in nondecreasing number of edges. At the moment a vertex is first enqueued, BFS records its shortest unweighted distance and normally marks it discovered so it cannot be enqueued repeatedly. Because all edges have unit length, visiting successive queue layers cannot miss a shorter route. The output is usually a distance map, parent pointers, or the set of reachable vertices.

Each discovered vertex is enqueued and dequeued at most once; its outgoing adjacency entries are scanned once. For adjacency lists this gives O(V + E) time and O(V) auxiliary queue, distance, and parent storage, apart from graph storage. With a complete BFS forest, Θ(V + E) work is typical. BFS is not a weighted shortest-path algorithm in general; a five-edge path might be cheaper than a one-edge path if edge costs differ.

from collections import deque

def bfs_distances(graph, source):
    if source not in graph:
        raise KeyError('unknown source')
    distance = {source: 0}
    parent = {source: None}
    queue = deque([source])
    while queue:
        u = queue.popleft()
        for v in graph[u]:
            if v not in distance:
                distance[v] = distance[u] + 1
                parent[v] = u
                queue.append(v)
    return distance, parent

g = {'A': ['B', 'C'], 'B': ['A', 'D'],
     'C': ['A', 'D'], 'D': ['B', 'C'], 'E': []}
d, p = bfs_distances(g, 'A')
assert d == {'A': 0, 'B': 1, 'C': 1, 'D': 2}
assert 'E' not in d and p['A'] is None

Reconstructing Paths and Accounting for Output

A BFS parent map represents a shortest-path tree rooted at the source. Reconstruct one destination path by repeatedly following its parent until reaching the source, then reverse the collected sequence. If the path has k edges, reconstruction takes Θ(k + 1) time and additional space; the initial search remains O(V + E). Distances alone are sufficient if the output contract asks only for path lengths, reducing some output handling.

When numerous destinations are queried from one fixed source, paying one BFS preprocessing cost can be cheaper than running a new traversal for each query. But when sources change, edge weights appear, or the graph is updated, the preprocessing strategy must be reconsidered. Each different workload has a different total cost.

def restore_path(parent, target):
    if target not in parent:
        return None
    path = []
    while target is not None:
        path.append(target)
        target = parent[target]
    return path[::-1]

parent = {'s': None, 'a': 's', 'b': 'a', 'x': 's'}
assert restore_path(parent, 'b') == ['s', 'a', 'b']
assert restore_path(parent, 'missing') is None

Depth-First Search: Frames, Discovery, and Finishing

Depth-first search (DFS) follows one branch until it cannot continue, then backtracks to another. A visited set prevents infinite revisitation around cycles. Recursive implementations use call frames, while iterative ones use an explicit stack of pending vertices or frames. To reproduce the same exact discovery and finishing events, a stack implementation must preserve which neighbor iterator is active—not just push all neighbors at once.

Adjacency-list DFS takes O(V + E) time on a full forest and O(V) auxiliary visited and recursion-stack or explicit-stack storage under typical implementations. Recursion depth can reach Θ(V) on a path; an explicit frame stack avoids reliance on the language's recursion-depth limit but does not eliminate Θ(V) worst-case logical state. When a stack pushes duplicate undiscovered vertices, pending entries can grow with E; marking on push or using frames can bound the auxiliary structure differently.

def dfs_iterative(graph, source):
    seen = {source}
    order = [source]
    stack = [(source, iter(graph[source]))]
    while stack:
        u, it = stack[-1]
        try:
            v = next(it)
        except StopIteration:
            stack.pop()
            continue
        if v not in seen:
            seen.add(v)
            order.append(v)
            stack.append((v, iter(graph[v])))
    return order

graph = {0: [1, 2], 1: [3], 2: [3], 3: []}
assert dfs_iterative(graph, 0) == [0, 1, 3, 2]

DFS Forests and Disconnected Components

A DFS forest starts a traversal from each not-yet-visited vertex, producing one rooted search tree per run. In an undirected graph those trees correspond to connected components; in a directed graph a DFS tree is merely a reachability structure and should not be confused with a strongly connected component. A complete forest takes Θ(V + E) on adjacency lists, accounting for isolated vertices as well as stored edges.

Component analysis should distinguish weakly connected components (edge direction ignored) from strongly connected components (mutual reachability) in directed graphs. A surprising number of incorrect implementations apply undirected component logic unchanged to directed inputs. Document how self-loops and parallel edges are represented and whether they affect the intended result.

def undirected_components(graph):
    seen = set()
    groups = []
    for start in graph:
        if start in seen:
            continue
        seen.add(start)
        stack = [start]
        group = []
        while stack:
            u = stack.pop()
            group.append(u)
            for v in graph[u]:
                if v not in seen:
                    seen.add(v)
                    stack.append(v)
        groups.append(set(group))
    return groups

g = {0: [1], 1: [0], 2: [3], 3: [2], 4: []}
assert {frozenset(x) for x in undirected_components(g)} == {
    frozenset({0, 1}), frozenset({2, 3}), frozenset({4})}

Directed Acyclic Graphs and Topological Ordering

A topological order lists vertices of a directed acyclic graph (DAG) so every directed edge goes from an earlier vertex to a later one. DFS finishing times or Kahn's indegree-removal algorithm can construct such an order in O(V + E) time with adjacency lists. A cycle makes a complete topological order impossible, so a correct implementation must report failure rather than return a partial order as if it were valid.

Kahn's algorithm initializes each vertex's indegree, enqueues all zero-indegree vertices, repeatedly removes one, and decreases each outgoing neighbor's indegree. Each vertex enters the queue once and each edge is processed once. A heap may be used for deterministic lexicographically minimal ordering but adds a log V factor. A queue-based result is only one valid topological order, not necessarily a unique sequence.

from collections import deque

def topological_sort(graph):
    indegree = {u: 0 for u in graph}
    for u in graph:
        for v in graph[u]:
            indegree[v] += 1
    ready = deque(u for u, d in indegree.items() if d == 0)
    result = []
    while ready:
        u = ready.popleft()
        result.append(u)
        for v in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                ready.append(v)
    if len(result) != len(graph):
        raise ValueError('directed cycle detected')
    return result

g = {'parse': ['typecheck'], 'typecheck': ['compile'],
     'compile': [], 'docs': []}
order = topological_sort(g)
assert order.index('parse') < order.index('typecheck') < order.index('compile')
try:
    topological_sort({'a': ['b'], 'b': ['a']})
    assert False, 'cycle was not detected'
except ValueError:
    pass

Strongly Connected Components and Condensation

Within a strongly connected component (SCC), every vertex can reach every other vertex by directed paths. Kosaraju's two-pass DFS and Tarjan's single-pass low-link method both run in O(V + E) time using adjacency lists. Kosaraju first derives a finishing order, then searches the transpose graph in reversed finishing order; constructing the transpose also takes O(V + E) time and space. Tarjan's method tracks discovery indices, a stack, and low-link values.

Contract SCCs into single vertices to produce a condensation DAG. This is useful for dependency analysis and cycle diagnosis: if a component contains more than one vertex, or one vertex with a self-loop, it represents a directed cycle. A graph of SCCs is necessarily acyclic, because any cycle among components would make their vertices mutually reachable and merge those components.

def strongly_connected_components(graph):
    seen, order = set(), []
    def visit(u):
        seen.add(u)
        for v in graph[u]:
            if v not in seen:
                visit(v)
        order.append(u)
    for u in graph:
        if u not in seen:
            visit(u)
    transposed = {u: [] for u in graph}
    for u in graph:
        for v in graph[u]:
            transposed[v].append(u)
    seen.clear()
    result = []
    def collect(u, out):
        seen.add(u)
        out.add(u)
        for v in transposed[u]:
            if v not in seen:
                collect(v, out)
    for u in reversed(order):
        if u not in seen:
            comp = set()
            collect(u, comp)
            result.append(comp)
    return result

g = {0: [1], 1: [0, 2], 2: [3], 3: [2], 4: []}
assert {frozenset(s) for s in strongly_connected_components(g)} == {
    frozenset({0, 1}), frozenset({2, 3}), frozenset({4})}

Cycle Detection and Low-Link Applications

Cycle tests depend on edge direction. In an undirected graph, DFS finds a cycle if it encounters a visited neighbor other than the edge used to arrive at the current vertex, subject to special care for parallel edges. In directed graphs, a DFS edge to a currently active (gray) ancestor indicates a cycle; edges to previously completed vertices do not necessarily do so. Kahn's topological-sort procedure also detects a directed cycle by leaving some vertices unremoved.

Bridges and articulation points in undirected graphs can be identified by DFS discovery times and low-link values in O(V + E) time. Low-link reasoning asks whether a DFS subtree has a back edge to an earlier ancestor. In multigraphs, parent-edge identity rather than just parent-vertex identity is important; parallel edges can prevent an edge from being a bridge. These algorithms illustrate how a second piece of state in a linear traversal can answer more sophisticated structural questions.

Weighted Graphs and Relaxation as a Proof Operation

For weighted shortest paths, the algorithm maintains a provisional distance estimate d[v]. A relaxation of edge u→v with weight w checks whether d[u] + w is smaller than d[v], and updates the estimate and parent if so. The fundamental path-relaxation invariant is that finite estimates represent weights of some discovered source-to-vertex walks, hence are upper bounds on a well-defined shortest-path value when one exists.

Edge-weight restrictions determine valid algorithms. BFS is appropriate for unit costs; Dijkstra is correct for nonnegative weights; Bellman–Ford allows negative weights and identifies negative cycles reachable from the source. A negative cycle that can be reached and followed without limit makes shortest-walk costs unbounded below for vertices reachable from that cycle; an unreachable negative cycle does not invalidate distances from a different source.

Dijkstra: Heap Entries, Decrease-Key, and Cost Bounds

Dijkstra's algorithm repeatedly settles the unsettled vertex with minimum tentative distance and relaxes its outgoing edges. If every edge weight is nonnegative, any alternative path reaching a supposedly nearer unsettled vertex cannot improve a settled distance through still-nonnegative extensions. This establishes the greedy invariant. With negative edges, that reasoning fails and ordinary Dijkstra is not generally correct.

Using adjacency lists and a binary heap that permits duplicate candidate entries, there are O(E) successful relaxations and O(E) heap insertions, giving O((V + E) log(V + E)) for the straightforward lazy-heap model. Under standard assumptions and more specialized indexed priority queues, the familiar O((V + E) log V) bound applies; for simple graphs with E ≤ O(V²), these expressions are asymptotically comparable when V ≥ 2. A binary heap with explicit decrease-key can achieve O((V + E) log V), while theoretical Fibonacci-heap bounds improve certain decrease-key costs.

Heap operation counts and graph representation matter: an adjacency-matrix implementation with a linear minimum scan can instead require O(V²) time, which may be reasonable on dense graphs.

import heapq
from itertools import count

def dijkstra(graph, source):
    if source not in graph:
        raise KeyError('unknown source')
    for u, edges in graph.items():
        for v, weight in edges:
            if v not in graph:
                raise KeyError('unknown target')
            if weight < 0:
                raise ValueError('Dijkstra requires nonnegative weights')
    distance = {u: float('inf') for u in graph}
    distance[source] = 0
    parent = {source: None}
    serial = count()
    heap = [(0, next(serial), source)]
    while heap:
        du, _, u = heapq.heappop(heap)
        if du != distance[u]:
            continue
        for v, w in graph[u]:
            candidate = du + w
            if candidate < distance[v]:
                distance[v] = candidate
                parent[v] = u
                heapq.heappush(heap, (candidate, next(serial), v))
    return distance, parent

g = {'s': [('a', 5), ('b', 1)],
     'a': [('t', 1)], 'b': [('a', 1), ('t', 9)], 't': []}
d, p = dijkstra(g, 's')
assert d == {'s': 0, 'a': 2, 'b': 1, 't': 3}
assert p['t'] == 'a'
try:
    dijkstra({'s': [('t', -1)], 't': []}, 's')
    assert False
except ValueError:
    pass

Bellman–Ford: Negative Weights and Reachable Cycles

Bellman–Ford repeatedly relaxes the edge set. If no negative cycle reachable from the source disrupts the requested distances, a shortest path can be chosen simple and therefore uses at most V − 1 edges. After i full relaxation passes in a fixed edge-order interpretation, distances are no worse than the best paths of at most i edges under a synchronous proof model; an in-place pass can also propagate information farther. A Vth improvement after V − 1 passes indicates a reachable negative cycle under the standard assumptions.

With an edge list and V − 1 passes, the elementary running-time bound is O(VE + V), often abbreviated O(VE) for nontrivial connected graphs. Early stopping improves practice but not the general worst-case guarantee. The algorithm also uses O(V) working distances and predecessors besides the supplied edge collection.

def bellman_ford(vertices, edges, source):
    vertices = list(vertices)
    dist = {v: float('inf') for v in vertices}
    dist[source] = 0
    for _ in range(len(vertices) - 1):
        changed = False
        for u, v, w in edges:
            if dist[u] != float('inf') and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                changed = True
        if not changed:
            break
    for u, v, w in edges:
        if dist[u] != float('inf') and dist[u] + w < dist[v]:
            raise ValueError('negative cycle reachable from source')
    return dist

vertices = ['s', 'a', 'b', 'z']
edges = [('s', 'a', 4), ('s', 'b', 7), ('a', 'b', -3)]
assert bellman_ford(vertices, edges, 's') == {
    's': 0, 'a': 4, 'b': 1, 'z': float('inf')}
try:
    bellman_ford(['s', 'a'], [('s', 'a', -1), ('a', 's', -1)], 's')
    assert False
except ValueError:
    pass

Shortest Paths in DAGs and Negative Edge Weights

A weighted DAG can be processed in topological order. Initialize the source distance to zero and all others to infinity, then relax each outgoing edge when its starting vertex is processed. No vertex has a future incoming edge from a later vertex in a topological order, so every needed predecessor's distance has already been finalized. This yields O(V + E) time, even if individual edge weights are negative, because a DAG has no directed cycles.

This is an important counterexample to the simplistic rule that negative weights always require Bellman–Ford. What matters is the combination of structural restrictions and edge weights. Similarly, a 0–1 BFS uses a deque to obtain O(V + E) behavior when weights are restricted to zero and one; the algorithmic guarantees follow from the special cost domain, not from an arbitrary weighted graph.

from collections import deque

def dag_shortest_paths(graph, source):
    indegree = {v: 0 for v in graph}
    for u in graph:
        for v, w in graph[u]:
            indegree[v] += 1
    queue = deque(v for v in graph if indegree[v] == 0)
    order = []
    while queue:
        u = queue.popleft()
        order.append(u)
        for v, w in graph[u]:
            indegree[v] -= 1
            if indegree[v] == 0:
                queue.append(v)
    if len(order) != len(graph):
        raise ValueError('not a DAG')
    dist = {v: float('inf') for v in graph}
    dist[source] = 0
    for u in order:
        if dist[u] == float('inf'):
            continue
        for v, w in graph[u]:
            dist[v] = min(dist[v], dist[u] + w)
    return dist

g = {'s': [('a', 3), ('b', 7)],
     'a': [('b', -5)], 'b': [('t', 2)], 't': []}
assert dag_shortest_paths(g, 's')['t'] == 0

Zero–One BFS and Restricted Edge Costs

For directed or undirected graphs whose edge weights are exactly 0 or 1, a deque can replace a general priority queue. Relax a zero-weight edge by placing its destination at the front and a unit-weight edge by placing its destination at the back. When outdated entries are skipped or otherwise handled appropriately, the deque order maintains the relevant small-distance frontier and yields O(V + E) operations under a standard implementation.

Do not generalize this technique directly to arbitrary small nonnegative integers without accounting for bucket structures, weight range, and memory requirements. Dial-style bucket queues can exploit bounded integer weights under specified assumptions, but are distinct from plain 0–1 BFS. Negative edges violate the 0–1 BFS invariant.

from collections import deque

def zero_one_bfs(graph, source):
    distance = {v: float('inf') for v in graph}
    distance[source] = 0
    dq = deque([(source, 0)])
    while dq:
        u, snapshot = dq.popleft()
        if snapshot != distance[u]:
            continue
        for v, weight in graph[u]:
            if weight not in (0, 1):
                raise ValueError('weights must be 0 or 1')
            nd = snapshot + weight
            if nd < distance[v]:
                distance[v] = nd
                if weight == 0:
                    dq.appendleft((v, nd))
                else:
                    dq.append((v, nd))
    return distance

g = {'s': [('a', 1), ('b', 0)],
     'a': [('t', 1)], 'b': [('a', 0), ('t', 1)], 't': []}
assert zero_one_bfs(g, 's')['t'] == 1
assert zero_one_bfs(g, 's')['a'] == 0

All-Pairs Shortest Paths: Repeated Search versus Dynamic Programming

The all-pairs shortest-path problem computes a distance for each ordered pair of vertices. Repeated BFS solves unweighted graphs in O(V(V + E)); repeated Dijkstra handles nonnegative weighted graphs with the applicable priority-queue bound. Floyd–Warshall uses dynamic programming over permitted intermediate vertices and runs in Θ(V³) time with Θ(V²) matrix storage. Johnson's algorithm uses reweighting and repeated Dijkstra runs to exploit sparsity while allowing negative edges if no negative cycle exists.

The Floyd–Warshall recurrence is Dk[i,j] = min(Dk−1[i,j], Dk−1[i,k] + Dk−1[k,j]). Its correctness follows by partitioning shortest walks into those using intermediate vertex k and those not using it. Negative diagonal entries after the algorithm signal a negative cycle affecting shortest-walk definitions. Explicitly define unreachable pairs and distinguish a distance matrix from a complete set of output paths.

def floyd_warshall(vertices, edges):
    verts = list(vertices)
    d = {(u, v): (0 if u == v else float('inf'))
         for u in verts for v in verts}
    for u, v, w in edges:
        d[u, v] = min(d[u, v], w)
    for k in verts:
        for i in verts:
            for j in verts:
                d[i, j] = min(d[i, j], d[i, k] + d[k, j])
    if any(d[v, v] < 0 for v in verts):
        raise ValueError('negative cycle')
    return d

d = floyd_warshall(['a', 'b', 'c'],
                   [('a', 'b', 2), ('b', 'c', -1), ('a', 'c', 5)])
assert d['a', 'c'] == 1
assert d['c', 'a'] == float('inf')

Minimum Spanning Trees and the Cut Property

A minimum spanning tree (MST) of a connected undirected weighted graph connects all vertices with V − 1 edges of minimum total weight. A disconnected graph has a minimum spanning forest, one tree per component. MST is not a shortest-path tree: minimizing the sum of selected edge weights does not minimize the route from a chosen root to every destination. Negative edge weights are permitted in MST problems; the core cut and cycle properties do not require nonnegative weights.

Under the cut property, a minimum-weight edge crossing an appropriate cut is safe to include in some MST (and in every MST under suitable uniqueness assumptions). Kruskal sorts edges by weight and adds them when they connect different components. Prim grows one tree by repeatedly choosing the lightest outgoing crossing edge. Their proofs show the partial solution can be extended to an optimal spanning tree, often by an exchange argument.

Kruskal: Sorting Cost and Disjoint-Set Operations

Kruskal's algorithm sorts E undirected edges by nondecreasing weight, then calls find/union on endpoints while accepting edges that join different components. Sorting costs O(E log E) comparisons. With path compression plus union by rank or size, a sequence of disjoint-set operations costs almost linear time, typically expressed as O((V + E) α(V)) or a closely related inverse-Ackermann bound depending on precise parameters. The overall elementary graph bound is O(E log E + (V + E) α(V)).

Use a stable and deterministic tie policy only if the application needs reproducible output; equal-weight edges can yield multiple valid minimum spanning forests. A union–find does not reveal the final tree's path lengths, and it cannot by itself reconstruct shortest paths. Its purpose here is efficient cycle prevention.

def kruskal_forest(vertices, edges):
    parent = {v: v for v in vertices}
    size = {v: 1 for v in vertices}
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    def unite(a, b):
        ra, rb = find(a), find(b)
        if ra == rb:
            return False
        if size[ra] < size[rb]:
            ra, rb = rb, ra
        parent[rb] = ra
        size[ra] += size[rb]
        return True
    chosen = []
    for w, u, v in sorted(edges, key=lambda edge: edge[0]):
        if unite(u, v):
            chosen.append((w, u, v))
    return chosen

edges = [(1, 'a', 'b'), (4, 'a', 'c'),
         (2, 'b', 'c'), (3, 'b', 'd'), (1, 'c', 'd')]
forest = kruskal_forest(['a', 'b', 'c', 'd'], edges)
assert len(forest) == 3
assert sum(w for w, u, v in forest) == 4

Prim: Dense and Sparse Implementations

With an adjacency matrix and simple array-based minimum selection, Prim's algorithm runs in O(V²), often an attractive choice for sufficiently dense graphs. With adjacency lists and an indexed binary heap, a common implementation takes O((V + E) log V). A lazy heap that stores duplicate entries instead has O(E log E) heap work in a straightforward analysis, equivalent to O(E log V) for simple graphs with E = O(V²) and V at least 2. An indexed decrease-key heap and a lazy duplicate-entry heap have different operation counts and space overhead; state which one is being analyzed.

For disconnected graphs, restart Prim from another unvisited vertex to compute a minimum spanning forest; a single-source implementation otherwise covers just one component. Weight ties need not imply a unique spanning forest. Most importantly, a Prim key is the cheapest edge connecting a vertex into the growing tree, not a source-to-vertex path distance as in Dijkstra.

import heapq
from itertools import count

def prim_forest(graph):
    serial = count()
    seen = set()
    chosen = []
    for root in graph:
        if root in seen:
            continue
        seen.add(root)
        heap = [(w, next(serial), root, v) for v, w in graph[root]]
        heapq.heapify(heap)
        while heap:
            w, _, u, v = heapq.heappop(heap)
            if v in seen:
                continue
            seen.add(v)
            chosen.append((w, u, v))
            for x, w2 in graph[v]:
                if x not in seen:
                    heapq.heappush(heap, (w2, next(serial), v, x))
    return chosen

g = {'a': [('b', 1), ('c', 4)],
     'b': [('a', 1), ('c', 2), ('d', 3)],
     'c': [('a', 4), ('b', 2), ('d', 1)],
     'd': [('b', 3), ('c', 1)]}
forest = prim_forest(g)
assert len(forest) == 3
assert sum(w for w, u, v in forest) == 4

Graphs with Negative Weights, Zero Weights, and Overflow

Weights can represent distance, cost, risk, time, probability-derived scores, or capacities, but their algebraic interpretation must be explicit. A shortest-path algorithm assumes path costs are sums of edge weights; a bottleneck problem may instead minimize the maximum edge cost, making standard additive relaxation unsuitable. Zero-weight edges can generate multiple equal shortest walks; negative cycles can make a minimum unbounded below for certain source–target pairs.

In fixed-width integer languages, adding a large edge weight to a large provisional distance can overflow before a comparison. Floating-point representations introduce rounding and NaN behavior. A robust implementation separates unreachable infinity from finite values, checks the operation's numeric domain, and defines how ties and parallel edges are handled. “All weights are numeric” is not enough to establish correctness.

Graph Traversal versus Graph Search

A traversal describes a systematic visit order or reachability forest. A search has a specified goal and may terminate early. This difference can materially affect observed cost: BFS that stops when a nearby target is discovered explores much less than the full graph, although its worst-case remains O(V + E). The precise stopping condition matters—stopping upon first discovery is correct for unweighted BFS shortest distances, while Dijkstra's weighted target distance is safely finalized when the target is extracted with the minimum valid tentative label.

Depth-limited search, bidirectional BFS, and informed methods may reduce the explored state space on selected workloads, but they introduce extra assumptions and metadata. A graph can contain Θ(V²) edges even when a short solution path exists; shortest output length alone does not upper-bound search effort.

A* Search: Admissibility, Consistency, and Worst-Case Cost

A* orders frontier states by f(v) = g(v) + h(v), where g is the best known cost from the source and h is a heuristic estimate to the goal. An admissible heuristic never exceeds the true remaining shortest-path cost. A consistent heuristic additionally satisfies h(u) ≤ w(u,v) + h(v) for each directed edge, with h(goal) = 0. Consistency supports closed-set policies that settle states without reopening them under the standard assumptions; a merely admissible but inconsistent heuristic may require reopening when a better path appears.

Despite often reducing expansions, A* has no universal sublinear or polynomial-time improvement merely because a heuristic is used. With a zero heuristic and nonnegative edges it reduces to uniform-cost/Dijkstra-style ordering; with weak estimates it can expand most reachable states. Runtime analysis must count heuristic evaluation, priority-queue operations, and memory occupied by open and closed sets.

Bipartiteness, Two-Coloring, and Structural Tests

An undirected graph is bipartite precisely when its vertices can be split into two groups so every edge connects opposite groups; equivalently, it has no odd cycle. BFS or DFS can assign alternating colors and reject an edge whose endpoints receive the same color. With adjacency lists, full-component coverage is O(V + E) time and O(V) additional state.

This illustrates an important modeling principle: an algorithm that computes a property of the entire graph may need to restart from each isolated component. Testing only the component containing vertex 0 can incorrectly classify the whole input. A self-loop instantly violates bipartiteness because it would require one vertex to have both colors.

from collections import deque

def is_bipartite(graph):
    color = {}
    for start in graph:
        if start in color:
            continue
        color[start] = 0
        queue = deque([start])
        while queue:
            u = queue.popleft()
            for v in graph[u]:
                if v not in color:
                    color[v] = 1 - color[u]
                    queue.append(v)
                elif color[v] == color[u]:
                    return False
    return True

assert is_bipartite({0: [1], 1: [0], 2: []})
assert not is_bipartite({0: [1, 2], 1: [0, 2], 2: [0, 1]})

Network Flow and Residual-Graph Complexity

A flow network assigns capacities to directed edges and seeks a feasible flow of maximum value between a source and a sink. Residual edges represent the ability to reroute or undo portions of a provisional flow. A correct augmenting-path method must update both forward and reverse residual capacities. The max-flow/min-cut theorem links an optimal flow with a cut of equal total capacity.

The generic Ford–Fulkerson method using arbitrary augmenting paths does not have a strongly polynomial bound from V and E alone; for integral capacities, its running time can depend on the maximum flow value. Edmonds–Karp chooses shortest augmenting paths in the residual graph by BFS and runs in O(VE²) time for the standard adjacency-list framework. Dinic's algorithm and push–relabel methods offer other bounds and performance regimes. Avoid reducing a flow problem to an MST or shortest-path problem merely because all operate on graphs.

Graph Representation, Locality, and Memory Hierarchy

On modern hardware, graph algorithms often pay a substantial cost for pointer chasing, irregular neighbor access, and cache misses. A theoretically linear traversal on a sparse graph may have less predictable performance than a dense, contiguous matrix scan when the latter benefits from locality and vectorized operations. Compressed sparse row (CSR) storage packs neighbor arrays and vertex offsets contiguously, often improving scanning locality for mostly static graphs. Its update costs differ from pointer-based lists.

In external-memory analysis, the number of block transfers is a separate resource from RAM operations; a graph algorithm with good O(V + E) CPU work need not be optimal for I/O. Partitioning, edge ordering, compression, and streaming passes can change the operating envelope. These subjects are developed systematically in Cache and External-Memory Complexity; this article records the impact on graph algorithm comparison.

Parallel Graph Algorithms: Work and Span

Parallel algorithm analysis separates work, the total operations over all processors, from span, the length of the longest dependency chain. A parallel BFS can process many vertices in one frontier together, but the number of BFS levels constrains sequential dependencies. High-degree vertices can dominate load imbalance, and concurrent discovery of the same vertex requires coordination to avoid repeated work.

Parallel MST and shortest-path methods have additional synchronization and consistency concerns. Replacing O(V + E) sequential work with many worker threads does not guarantee proportional speedup; the number of processors, memory bandwidth, atomic contention, frontier size, and communication overhead matter. See Parallel Algorithm Analysis for formal speedup and scheduler bounds.

Dynamic Graphs and the Cost of Updating an Answer

For a dynamic graph, edges and vertices can be inserted or deleted between queries. Rebuilding an index, shortest-path tree, SCC decomposition, or spanning forest after each change may be correct but expensive. Dynamic algorithms trade preprocessing and maintenance work against query cost; results may be amortized, worst-case, exact, or approximate under carefully stated update models.

For example, a union–find structure efficiently maintains connected components under edge insertions, but cannot generally handle arbitrary edge deletions simply by undoing unions. This limitation arises because removing an edge can split a component and union–find retains no adequate historical connectivity information. A benchmark that evaluates only additions does not establish performance under mixed insertions and deletions.

Correctness Proofs: Invariants and Exchange Arguments

Graph algorithms use several recurring proof patterns. For BFS, show that first discovery gives the smallest edge count; for Dijkstra, show that nonnegative edges prevent improvement of settled labels; for Bellman–Ford, induct on the maximum number of edges in the represented shortest path; for MST methods, show that a cut-minimum safe edge can be exchanged into an optimal spanning tree; and for DFS low-link techniques, prove that the recorded ancestor reachability captures every relevant back edge.

Do not replace proof of an algorithm's central invariant with a few successful sample outputs. Tests can expose implementation mistakes, but they do not establish correctness on unbounded inputs. Conversely, a mathematically correct algorithm can still be wrong in a concrete program if its representation admits unhandled labels, overflow, negative edges, cycles, or duplicate states.

Worst-Case, Expected, and Output-Sensitive Costs

Worst-case bounds range over all admissible graphs of stated size. Expected bounds require a probability distribution, for example over randomized tie-breaking or a model of graph generation. Output-sensitive graph algorithms express cost in terms of how many paths, vertices, or edges are actually enumerated; listing all simple paths can be exponential even when reachability takes linear time. A graph with many overlapping routes is particularly capable of producing exponentially many solutions.

An O(V + E) BFS bound says little about the complexity of listing all shortest paths when the output is enormous. Similarly, a randomized algorithm may have good expected work yet poor tail latency on rare random choices. Use Worst-Case and Average-Case Analysis and Randomized Algorithm Analysis to qualify uncertainty honestly.

Graph Generation, Input Validation, and Invariant Checks

Before trusting a result, validate the representation's contract. Each edge endpoint must be part of the declared vertex set; undirected adjacency lists should either contain matching reverse entries or follow a documented encoding; parallel edges should be preserved or combined by an explicit rule; nonnegative-weight algorithms should reject disallowed negative weights; and vertex labels should be handled consistently by dictionaries or indexed arrays.

Testing should cover isolated vertices, disconnected graphs, self-loops, parallel edges, directed cycles, ties, unreachable destinations, zero-weight paths, negative edges, and empty graphs where meaningful. Differential testing against a second independent implementation can reveal mistakes that handpicked examples miss, but only if both implementations solve the same defined problem.

Worked Investigation 1: Sparse Road Network versus Dense Compatibility Graph

Assume one application represents a directed road network with 100,000 intersections and 300,000 road segments, while another represents pairwise compatibility among 4,000 devices where almost every pair may communicate. Both are graphs, yet their representations should differ. The road network has E/V = 3 and is sparse: a conventional adjacency list needs storage proportional to roughly 400,000 vertices and directed-edge entries, neglecting per-object overhead. A dense matrix over 100,000 vertices would have 10 billion cells, an impractical conceptual allocation for many deployments.

The device graph may admit up to about 16 million directed, non-self pairs, so a matrix of 16 million cells can be comparable in order to its edge information, particularly if bit-packed. A repeated arbitrary edge-membership workload can then benefit from O(1) matrix checks. But if the task is merely to visit actual neighbors of a few devices, an adjacency list may still be preferable.

Analytical decision: quantify V, E, degree distribution, update frequency, and query patterns before selecting storage. Do not use “graphs are O(V + E)” as if storage were independent of representation.

Worked Investigation 2: Unit-Hop Delivery versus Weighted Route Cost

A messaging system asks for the fewest network hops from node s to node t, while a freight system asks for the least total transportation expense. A BFS can solve the former in O(V + E) time on adjacency lists because every edge counts as one hop. In the second, an expensive direct route can be worse than a longer sequence of inexpensive routes; BFS's layer invariant no longer proves optimality.

If all expenses are nonnegative, Dijkstra is an appropriate single-source method. If rebates create negative edge costs but no relevant negative cycle, Bellman–Ford or a DAG method when the network is acyclic may be appropriate. A negative cycle reachable on the way to a destination invalidates a finite optimum in the unrestricted-walk model.

Analytical decision: first confirm that route composition is additive and identify the weight domain; only then compare algorithmic costs. A performance comparison between BFS and Dijkstra is meaningless if the two programs are solving different optimization contracts.

Worked Investigation 3: Build Dependencies and Hidden Cycles

Consider a build system with tasks scan → parse → compile → package plus independent documentation work. It needs a schedule in which every prerequisite precedes its dependent task. Kahn's topological sort scans all declared dependencies in O(V + E) time and returns a valid order. If an accidental dependency package → scan is introduced, no valid topological order exists; a correct implementation must identify that the output is incomplete rather than silently mark the build as schedulable.

For diagnostic purposes, an SCC algorithm can identify the mutually dependent task group. Contracting SCCs yields a DAG, helpful for showing the higher-level structure, but it does not make the original cycle executable. More detailed dependency-analysis features may report a specific cycle witness or a smallest feedback set, which are additional computational problems.

Analytical decision: use topological ordering for scheduling and SCCs for cyclic-group diagnosis. The fact that both use linear-time graph traversals does not make their result contracts interchangeable.

Worked Investigation 4: Choosing a Spanning Network, Not a Shortest-Route Network

A facilities team wants to connect ten buildings with fiber while minimizing the total installation length. This is an MST objective when each candidate undirected link has an installation cost and no additional engineering constraint changes feasibility. Kruskal or Prim finds a minimum spanning tree or forest, depending on connectivity. The result minimizes the sum of selected edge lengths, not the distance between every pair of buildings.

A second team wants fastest communication from a central control building to every destination. That is a shortest-path-tree objective, potentially calling for Dijkstra if the latency weights are nonnegative. An MST can contain long control-to-destination paths because it minimizes global selected-edge weight. Conversely, a shortest-path tree may require more total cable length than an MST.

Analytical decision: define the optimized quantity before benchmarking algorithms. When connectivity, redundancy, degree constraints, or multiple simultaneous networks are required, the elementary MST model may no longer capture the operational problem.

Worked Investigation 5: Many Distance Queries on One Static Graph

A route service has 20,000 vertices and 60,000 nonnegative weighted edges. It receives a few queries per day for varying source–destination pairs. Running Dijkstra on demand may be preferable to materializing 400 million ordered vertex-pair distances. If every source is queried repeatedly and memory permits, preprocessing per-source distances or a dedicated shortest-path index may become valuable.

For a dense graph with only a few hundred vertices, Floyd–Warshall's Θ(V³) preprocessing with Θ(V²) distance storage can make sense when many all-pairs queries follow. But its cost is paid even if users request only two paths. With updates, maintaining precomputed distances introduces invalidation and recomputation costs that a single static all-pairs formula omits.

Analytical decision: compare total lifecycle cost: preprocessing + (queries × query cost) + update maintenance + memory. This yields a defensible strategy rather than a rule based on the asymptotic complexity of a single query.

Worked Investigation 6: A Million-State Implicit Puzzle

A search problem generates up to a million possible states, but the program can compute neighbors of each state from a compact transformation rule. Materializing a full matrix would use around one trillion cells, despite the successor rule being short. A BFS from an initial state stores only discovered states and a frontier, and can stop at the first goal state when all transitions count equally.

If each state has up to four successors and only 8,000 states are reached before the goal, search work depends on those 8,000 states and roughly 32,000 generated successor events, plus the cost of constructing and hashing state descriptions. If a global visited set is omitted, cycles may make the search repeat work indefinitely. If a heuristic is introduced, A* may focus the frontier but its quality and evaluation expense must be measured.

Analytical decision: identify what the graph's vertices represent, count generated states rather than all theoretically possible states when analyzing a particular run, and separate worst-case bounds from observations of typical puzzle instances.

Worked Investigation 7: Edge Updates Break a Static Index Assumption

Suppose a communications graph is analyzed nightly and its SCC decomposition is cached. During the day, operators insert and remove links. A cached SCC result can become incorrect after either type of change: a newly inserted edge may merge components, while a deleted edge can split one. The complexity of a static SCC run does not describe the cost of keeping the cached result valid under such updates.

A conservative design reruns O(V + E) SCC analysis after each update, potentially O(U(V + E)) across U updates. A more sophisticated dynamic method may improve certain workloads but comes with stronger assumptions and engineering costs. If only insertions matter for undirected connectivity, union–find is promising, but SCC maintenance in a directed graph is a different problem.

Analytical decision: specify the allowed update operations, freshness guarantee, and query cadence. Treat “dynamic algorithm” as a separate cost model rather than assuming one static complexity can be reused.

Operation-Counting Exercise: Edge Scans in a BFS

The following demonstration exposes actual counts rather than timing noise. In a full BFS forest on an undirected triangle plus one isolated vertex, the three triangle edges occur in six adjacency entries. A correct exhaustive traversal examines six neighbor entries and initializes or visits four distinct vertices. The exact number of enqueue operations is four, not six, because each vertex is discovered only once.

For directed graphs, the same procedure examines one outgoing entry per stored directed edge. If a scan is restricted to a component, it need not examine edges lying entirely in unreachable components. Note also that object hashing and iteration overhead are real implementation costs even when the mathematical model treats them as constant.

from collections import deque

def full_bfs_counts(graph):
    seen = set()
    queue_actions = 0
    examined = 0
    for start in graph:
        if start in seen:
            continue
        seen.add(start)
        q = deque([start])
        queue_actions += 1
        while q:
            u = q.popleft()
            for v in graph[u]:
                examined += 1
                if v not in seen:
                    seen.add(v)
                    q.append(v)
                    queue_actions += 1
    return len(seen), queue_actions, examined

g = {0: [1, 2], 1: [0, 2], 2: [0, 1], 3: []}
assert full_bfs_counts(g) == (4, 4, 6)

Empirical Measurement and Graph Workload Design

Measured runtime must be interpreted alongside input size, graph family, representation, and instrumented work counts. Useful workload families include paths, stars, grids, random sparse graphs, preferential-attachment networks, dense graphs, directed acyclic graphs, and disconnected cases. These exercise different degree distributions, diameters, frontiers, and memory-access patterns. One synthetic random graph is rarely representative of every application.

When benchmarking in a managed runtime, separate graph construction from algorithm execution, consider warm-up and garbage collection, fix or record random seeds, repeat independent runs, and report distributions rather than only an isolated minimum. For priority-queue algorithms, record numbers of relaxations, pushes, pops, stale entries, and edge examinations. For memory, report peak auxiliary allocations rather than only nominal graph storage. These are complementary indicators, not substitutes for correctness.

Algorithmic Lower Bounds and Unavoidable Input Inspection

In the ordinary adjacency-list input model, identifying a property that can depend on every edge may require Ω(V + E) inspections in the worst case: an unseen final edge could affect reachability or the presence of a cycle. But no universal Ω(V + E) claim applies to every graph query. Testing whether a named edge exists in a matrix is O(1); reporting a fixed known vertex may take O(1); and a BFS may stop early for a nearby target.

Input-model lower bounds must define what the algorithm is allowed to inspect and which answers it must distinguish. Problems that output exponentially many simple paths may have correspondingly large unavoidable reporting costs. The Lower Bounds and Decision Trees article develops general adversary and information arguments; the present unit shows their graph-specific significance.

Review Questions and Worked Answers

The following review items emphasize precise models and proof responsibilities. Answers follow each question so readers can compare their reasoning against the stated assumptions.

  1. Q: Why is an adjacency-list BFS O(V + E)? A: Each discovered vertex is queued at most once and its outgoing neighbor entries are scanned once; the degree sum accounts for all examined edges.
  2. Q: Why can a matrix-based BFS be Θ(V²)? A: Enumerating neighbors may scan all V matrix cells in each of V visited rows.
  3. Q: Is E always at most V²? A: For simple directed graphs yes up to a constant factor, but multigraphs with parallel edges do not share that bound.
  4. Q: Why is DFS not an unweighted shortest-path algorithm? A: It follows a branch deeply and may first reach a vertex by a longer route.
  5. Q: What distinguishes an undirected connected component from a directed SCC? A: Mutual directed reachability is required for an SCC, not merely connectivity after ignoring directions.
  6. Q: When can a topological order exist? A: Exactly when the directed graph is acyclic.
  7. Q: What permits Dijkstra's greedy settlement proof? A: Nonnegative edge weights prevent an unsettled continuation from yielding a smaller settled distance.
  8. Q: Can DAG shortest paths handle negative weights? A: Yes; topological relaxation works because there is no directed cycle.
  9. Q: What does Bellman–Ford detect? A: A negative cycle reachable from the selected source, using a further improving relaxation after the V − 1 bound.
  10. Q: Why is a source-unreachable negative cycle irrelevant to that source's distances? A: No source path can exploit it to lower a reachable destination's walk cost.
  11. Q: What is the main distinction between an MST and a shortest-path tree? A: MST minimizes total selected edge weight; shortest-path tree preserves optimal source-to-vertex distances.
  12. Q: Why does Kruskal use union–find? A: To accept a light edge only when it joins two currently separate components and does not create a cycle.
  13. Q: How do equal-weight ties affect MST results? A: Multiple minimum spanning trees may exist, though the optimal total weight remains the same.
  14. Q: What is the difference between Prim's key and Dijkstra's key? A: Prim stores the cheapest connecting edge; Dijkstra stores the current total distance from the source.
  15. Q: What does Floyd–Warshall compute and cost? A: All-pairs shortest distances via intermediate-vertex dynamic programming, Θ(V³) time and Θ(V²) storage.
  16. Q: When is 0–1 BFS applicable? A: When every edge weight is either zero or one.
  17. Q: What makes an A* heuristic consistent? A: h(u) ≤ w(u,v) + h(v) for all edges, with h(goal)=0 under the standard formulation.
  18. Q: Can union–find handle arbitrary deletions? A: No; ordinary union–find maintains merges, not general component splits.
  19. Q: Why can reporting all simple paths cost exponentially much? A: Some graphs contain exponentially many qualifying paths, and the output alone can dominate runtime.
  20. Q: What is a BFS frontier? A: The current collection of discovered vertices awaiting or undergoing expansion; its size affects memory and parallelism.
  21. Q: Why should benchmarks disclose graph representation? A: Storage layout and neighbor-query costs can alter both asymptotic and empirical behavior.
  22. Q: Why is an implicit graph not automatically small? A: A concise successor rule can describe exponentially many reachable states.
  23. Q: What resource does parallel span measure? A: The length of a longest dependency chain, independent of total work.
  24. Q: Which cost components belong in a repeated-query index decision? A: Construction, maintenance, per-query work, memory, and output costs.
  25. Q: How should an algorithm report an unreachable destination? A: With a documented sentinel or absence rather than an invented finite path.
  26. Q: How should a directed cycle be distinguished from an already-completed DFS cross edge? A: Track active versus completed DFS vertices; an edge to an active ancestor indicates a cycle.
