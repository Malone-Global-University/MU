Definition, Purpose, and Scope

Loop and summation analysis translates the control flow of an iterative algorithm into a precise count of executed operations. Its central tool is a mathematical sum: the total work of a loop is the sum of the work performed in each iteration. Where an inner loop depends on an outer index, the number of operations is a dependent sum, not automatically the product of two independent loop lengths.

A meaningful analysis specifies the input size, admissible input family, measured operation, and cost model. Under a word-RAM model, assignments, comparisons, and fixed-width arithmetic on machine words are commonly charged constant time; this assumption can fail for huge integers, variable-length strings, disk transfers, and other data-dependent operations. The article distinguishes exact counts under declared conventions from asymptotic classes and empirical timings. It treats loop execution, not a general algorithm's recursive subproblem costs, which belong to companion articles.

Its mathematical toolkit supports future study of Amortized Analysis, Cache and External-Memory Complexity, and benchmarking.

A Systematic Method for Counting Loop Work

Analyze the algorithm before assigning a complexity label. Identify the size parameter n; state when the loop executes; identify the update rule for the controlling variables; count executions of the chosen primitive operation; then simplify an exact expression or bound it above and below. If one iteration costs c(i) and iteration indices belong to a set I(n), the loop's modeled work is T(n)=Σ_{i∈I(n)} c(i), plus separately accounted setup and termination work.

For the same program, different count conventions yield different constant terms. The loop body may execute n times, while its condition is evaluated n+1 times. A body containing a variable-time helper operation should be charged by the helper's own cost, not automatically by a unit. At the end, explain whether the result is an exact count, a worst-case upper bound, a tight asymptotic bound, or a workload-dependent expectation.

A useful proof supplies both an upper bound and a matching lower bound when asserting Θ, and verifies that the control variables make progress toward termination. A confident-looking O(n) statement without those assumptions is a summary, not a complete analysis.

Input Size, Primitive Operations, and Counting Conventions

Input length n is frequently the number of array elements, but graph algorithms may need two parameters V and E; matrix loops may require dimensions r, c, and k; numeric algorithms may use the bit length of an integer rather than its numerical magnitude. If a loop runs from 1 to the numeric value N, its Θ(N) iteration count is exponential in the encoded bit length b≈log₂N. Keeping those measures distinct prevents false claims of polynomial-time behavior.

In a simple instruction-count model, a single array element access is often constant time, whereas copying an array of length n is linear, comparing long strings can depend on the compared prefix, and growing a multi-precision integer can change arithmetic costs. Operations may also mutate shared state, creating dependencies across loop iterations. The chosen cost function must reflect those facts whenever they are material.

When presenting exact operation counts, label the measured operation—body executions, comparisons, additions, swaps, or bytes transferred. There is no implementation-independent exact runtime in seconds for a general loop construct.

Loop Initialization, Condition Checks, and Updates

Consider for i in range(n): work() with nonnegative integer n and a constant-time call to work. The body is entered exactly n times, and the iterator produces exactly n values. A textbook C-style loop for(i=0; i<n; ++i) performs one initialization, n successful tests, one unsuccessful terminating test, and n updates under ordinary execution. A Python for loop is implemented through iterator protocol operations, not the same explicit C test, so the count of particular language-level tests is not identical.

For a model T(n)=c₀+c₁(n+1)+c₂n+c₃n, fixed nonnegative coefficients yield Θ(n) as long as a positive-cost operation is performed each iteration. The exact expression matters in careful comparison counts and in arguments about short loops; the asymptotic simplification matters when input sizes become large.

def count_linear_body(n):
    assert n >= 0
    count = 0
    for _ in range(n):
        count += 1
    return count

assert all(count_linear_body(n) == n for n in range(101))
print('linear-body counts agree with n for n=0..100')

The Summation Operator and Index Conventions

The notation Σ_{i=a}^b f(i) means f(a)+f(a+1)+⋯+f(b) when the indices are integers and a≤b. When a>b, the conventional finite empty sum is zero. This convention makes formulas for empty loops and boundary cases concise. Summation indices are dummy variables; renaming an index without changing its range does not alter the sum.

For for i in range(a,b) with integer unit steps and b≥a, the count is b−a, because Python's upper endpoint is excluded. For inclusive mathematical indices i=a,…,b, the number of terms is b−a+1. Many off-by-one errors arise from switching these conventions without changing the formula.

Linearity permits Σ (α f(i)+βg(i))=αΣ f(i)+βΣ g(i) for fixed coefficients, and splitting an index interval into disjoint subintervals permits separate sums. Neither rule requires probabilistic assumptions. However, replacing a variable-time operation with a constant must still be justified by the computational model.

Constant and Arithmetic-Series Work

A loop that performs fixed work on each of n iterations has cost Σ_{i=1}^n c=cn, hence Θ(n) for positive constant c. If the cost on iteration i grows proportionally with i, the total becomes Σ_{i=1}^n i=n(n+1)/2, hence Θ(n²). The closed form follows by pairing the first and last terms: 1+n=n+1, 2+(n−1)=n+1, and so on, with the middle term handled consistently for odd n.

The sum of the first n nonnegative zero-based indices is Σ_{i=0}^{n−1}i=n(n−1)/2. These two versions differ by n and share the same quadratic growth rate. Be explicit about the chosen indexing before asserting an exact comparison count.

def triangular_direct(n):
    return sum(range(1, n + 1))

for n in range(100):
    assert triangular_direct(n) == n * (n + 1) // 2
print('arithmetic-series identity checked')

Square and Higher Power Sums

When an inner operation is repeated i² times for outer index i, the total is Σ_{i=1}^n i²=n(n+1)(2n+1)/6=Θ(n³). The next power satisfies Σ_{i=1}^n i³=[n(n+1)/2]²=Θ(n⁴). More generally, for any fixed real p>−1, Σ_{i=1}^n i^p=Θ(n^{p+1}). This comparison follows by bounding the sum with integrals or by grouping terms of comparable magnitude.

At p=−1, the harmonic sum grows logarithmically rather than as n⁰; for p<−1, the infinite series converges to a finite limit, and the partial sums remain bounded. Thus the common rule “add one to the exponent” has a domain restriction. Terms that change sign or do not remain monotone also require more care when applying simple integral comparisons.

def power_sums(n):
    return sum(i*i for i in range(1, n+1)), sum(i**3 for i in range(1, n+1))

for n in range(35):
    squares, cubes = power_sums(n)
    assert squares == n*(n+1)*(2*n+1)//6
    assert cubes == (n*(n+1)//2)**2
print('square and cube identities checked')

Geometric Series and Repeated Doubling

A geometric sequence multiplies each term by a fixed ratio r. For r≠1, Σ_{i=0}^{k−1}r^i=(r^k−1)/(r−1); when r=1, the sum is k. For r>1, the last few terms dominate, so the finite total is Θ(r^k). For 0<r<1, the infinite sum approaches 1/(1−r), which bounds every finite prefix.

Repeated doubling often produces a logarithmic number of iterations, but the total cost is logarithmic only if each iteration's work is bounded by a constant. A loop performing i operations at values i=1,2,4,… incurs 1+2+4+⋯, whose cost is linear in the final threshold instead. Distinguish the number of loop entries from the operations performed inside those entries.

Loop Counters That Double or Halve

For positive threshold n, the loop i=1; while i<n: i*=2 executes ⌈log₂n⌉ times when n≥1 (and zero times at n=1). The sequence before each body is 1,2,4,…, and the smallest k with 2^k≥n determines termination. For i=n; while i>0: i//=2 with positive integer n, the body executes ⌊log₂n⌋+1 times, accounting for the final iteration when the counter is one.

Those formulas describe the number of executed bodies, not the number of machine instructions; Python's arbitrary-precision multiplication and division have operand-size costs that a fixed-word model suppresses. In code using fixed-width signed integers, repeated doubling can overflow, which may break the termination argument. Always state the legal range and use a safe update strategy where appropriate.

def doubling_steps(n):
    assert n >= 1
    i = 1
    count = 0
    while i < n:
        i *= 2
        count += 1
    return count

def halving_steps(n):
    assert n >= 1
    count = 0
    while n > 0:
        n //= 2
        count += 1
    return count

for n in range(1, 10000):
    assert doubling_steps(n) == (n - 1).bit_length()
    assert halving_steps(n) == n.bit_length()
print('doubling and halving counts checked for n=1..9999')

Harmonic Series and Logarithmic Accumulation

The harmonic number H_n=1+1/2+⋯+1/n satisfies ln(n+1)≤H_n≤1+ln n for positive integer n; therefore H_n=Θ(log n). The inequalities follow by comparing each rectangle of height 1/i with the decreasing curve 1/x. More precisely, H_n=ln n+γ+o(1), where γ is the Euler–Mascheroni constant, though that refinement is unnecessary for most complexity proofs.

A harmonic expression appears when iteration counts or expected costs contain terms proportional to 1/i. For instance, the number of multiples of each i in 1,…,n is ⌊n/i⌋, and summing those counts yields Θ(n log n). It is incorrect to replace a reciprocal sum by Θ(n) just because it has n terms: the terms decrease.

The Divisor-Enumeration Nested Loop

Consider an outer variable d=1,…,n and an inner loop visiting d,2d,3d,… up to n. The inner body executes ⌊n/d⌋ times, so the exact number of visits is S(n)=Σ_{d=1}^n⌊n/d⌋. Since n/d−1<⌊n/d⌋≤n/d, summing shows nH_n−n<S(n)≤nH_n, yielding Θ(n log n).

This example is especially instructive because both loops are written with for-style syntax and the inner loop has a variable step. Multiplying n by the maximum inner count n gives a valid but loose O(n²) bound; it misses the sharp Θ(n log n) total. The sum captures the useful fact that large steps contribute fewer visits.

def multiples_visits(n):
    total = 0
    for divisor in range(1, n + 1):
        for multiple in range(divisor, n + 1, divisor):
            total += 1
    return total

for n in range(1, 60):
    assert multiples_visits(n) == sum(n // d for d in range(1, n+1))
print('harmonic nested-loop counts checked')

Telescoping Sums and Difference of Consecutive Terms

A telescoping sum contains cancellations between adjacent terms. If f(i)=g(i+1)−g(i), then Σ_{i=a}^b f(i)=g(b+1)−g(a). For example, Σ_{i=1}^n 1/[i(i+1)]=Σ(1/i−1/(i+1))=1−1/(n+1). Although there are n terms, the numerical value remains bounded.

The value of a sum is not always the work required to evaluate it naively. A loop that adds those fractions one at a time still performs n additions, regardless of the sum's constant limiting value. Telescoping is valuable for algebraically simplifying costs when those costs themselves are differences (such as changes in a potential), but an equality between sum values cannot justify removing operations from an unmodified implementation.

from fractions import Fraction

def telescoping_sum(n):
    return sum((Fraction(1, i*(i+1)) for i in range(1, n+1)), Fraction(0, 1))

for n in range(0, 45):
    assert telescoping_sum(n) == 1 - Fraction(1, n+1)
print('telescoping identity checked exactly')

Integral Bounds When Closed Forms Are Unavailable

When f(x) is nonnegative and nondecreasing, the rectangle comparison gives ∫_0^n f(x)dx≤Σ_{i=1}^n f(i)≤∫_1^{n+1}f(x)dx under ordinary continuity conditions. For nonnegative decreasing f, the inequality direction and index placement must be adjusted; for f(x)=1/x, the harmonic bounds above are obtained by integrating from one.

Integrals estimate sums without demanding an unwieldy exact formula. For f(x)=x^p and fixed p>−1, integration gives growth proportional to n^{p+1}. Integral methods are asymptotic tools, not replacements for precise end conditions when an exact iteration count is required. If f changes sign, is highly oscillatory, or depends on other parameters, a straightforward area argument may not be valid.

Bounding by Grouping and Dyadic Intervals

An alternative to integration is to partition indices into blocks [1,2),[2,4),[4,8),…. Each block has a predictable number of terms. For a decreasing reciprocal sum, block [2^j,2^{j+1}) contains 2^j terms, each roughly 1/2^j, so a block contributes bounded constant work and there are Θ(log n) blocks. For sums of increasing powers, the last block often dominates.

Grouping is useful when a summand has floors, ceilings, or discrete jumps that make an exact antiderivative irrelevant. It also reveals hidden logarithms: a counter that changes multiplicatively crosses only logarithmically many scale bands. To establish a tight bound, show both how many blocks exist and how much each block contributes, with constants independent of n.

Independent Nested Loops and Product Counts

If the outer loop executes n times and each outer iteration runs an independent inner loop exactly m times, the body runs nm times. For square bounds m=n, the cost is n² and the growth is Θ(n²). The analysis depends on independence: reinitialization of the inner counter and the absence of early exits or shared progress.

For a rectangular matrix with r rows and c columns, visiting all elements costs Θ(rc); calling it Θ(n²) is sensible only after an additional relation such as r=c=n. Multiple size parameters are often more informative than artificially combining dimensions into one variable.

def rectangular_visits(rows, cols):
    count = 0
    for _ in range(rows):
        for _ in range(cols):
            count += 1
    return count

for r in range(12):
    for c in range(12):
        assert rectangular_visits(r,c) == r*c
print('rectangular iteration counts verified')

Triangular Nested Loops with Dependent Bounds

Consider an outer loop over i=0,…,n−1 and an inner loop over j=0,…,i−1. Its exact body count is Σ_{i=0}^{n−1}i=n(n−1)/2, not n². If the inner range is 0,…,i inclusive, the count becomes n(n+1)/2. Both are Θ(n²), but the distinct constants matter for pair enumeration and exact comparison accounting.

An important structural interpretation is that the first loop visits each unordered pair of distinct indices exactly once. The full rectangular double loop visits ordered pairs, including or excluding the diagonal depending on the bounds. In applications such as duplicate detection or pairwise distance computation, selecting the triangular loop prevents redundant work without changing the asymptotic order.

def pair_count(n):
    count=0
    for i in range(n):
        for j in range(i):
            count += 1
    return count

for n in range(101):
    assert pair_count(n) == n * (n-1) // 2
print('dependent triangular-loop count verified')

Triangular Loops with a Shrinking Inner Range

An inner loop over j=i,…,n−1 performs n−i iterations on outer pass i. Summing for i=0,…,n−1 yields n+(n−1)+⋯+1=n(n+1)/2. If the inner loop starts at i+1, the diagonal is excluded and the result is n(n−1)/2.

This pattern occurs in pairwise comparisons, suffix aggregation, and elementary sorting implementations. It also illustrates why two syntactically nested loops do not necessarily do the same amount of work on every outer pass. A direct per-pass table—n,n−1,…,1—is often the fastest route to the correct sum.

A Cubic Loop with a Quadratically Growing Inner Workload

Suppose a triply nested computation has outer index i=1,…,n, middle index j=1,…,i, and a constant-time innermost operation repeated i times. For fixed i, middle and inner loops together execute i² operations, so the total is Σ_{i=1}^n i²=Θ(n³). The correct calculation groups all work depending on a chosen outer iteration before summing across the outer range.

By contrast, if the innermost loop runs j times, the per-i work is Σ_{j=1}^i j=i(i+1)/2 and the total is still cubic, but with a different exact expression. Deriving the nested sums is superior to a blanket “three loops imply cubic” rule, because logarithmic bounds, shared counters, and breaks can invalidate such a rule.

Order of Summation and Counting the Same Work Twice

For a finite nonnegative count over a triangular index region 1≤j≤i≤n, one can sum rows Σ_{i=1}^n Σ_{j=1}^i 1 or columns Σ_{j=1}^n Σ_{i=j}^n 1. Both give n(n+1)/2 because they count the same pairs. Reordering summation can simplify a nested loop whose inner bound depends on the outer variable.

This equivalence is a mathematical fact about a finite set of operations. Reordering execution in actual software may nevertheless alter results if operations have side effects, mutate state, depend on floating-point evaluation order, or must preserve an invariant. Use the swapped summation to count work, not as blanket permission to swap actual loops.

Logarithmic Outer Loop, Linear Inner Loop

If i doubles from one until it reaches n, and each outer iteration visits all n array elements, the total body work is n⌈log₂n⌉=Θ(n log n) for n≥2. Each inner pass is genuinely length n, so the product rule applies even though the outer loop is logarithmic.

Changing the inner work from a full length-n scan to a length-i scan changes the sum to 1+2+4+⋯, yielding Θ(n) for large n. These two programs can have nearly identical syntactic structures and yet different complexity classes. Analysis must follow the actual index range on each pass.

def nested_log_patterns(n):
    assert n >= 1
    full = growing = 0
    i = 1
    while i < n:
        for _ in range(n):
            full += 1
        for _ in range(i):
            growing += 1
        i *= 2
    return full, growing

for n in range(1,65):
    outer=(n-1).bit_length()
    full, growing = nested_log_patterns(n)
    assert full == n * outer
    assert growing == 2**outer - 1
print('logarithmic-outer-loop patterns verified')

Doubly Nested Loops with a Shared Monotone Pointer

Nested loop syntax can conceal a linear total. Consider a two-pointer scan where the outer index advances i through an array and the inner while advances a pointer j, but j is never reset. Across the entire procedure j can increase at most n times, even though the inner loop appears inside an outer loop that runs n times. Thus the total number of pointer increments is at most 2n, and the work is O(n) if all other operations are constant time.

That is an aggregate argument, not a per-iteration constant bound. A single outer iteration may advance the inner pointer many positions. The linear upper bound comes from the global progress invariant 0≤j≤n and strictly increasing updates. If the inner pointer is reset each outer pass, the same reasoning fails and quadratic work may return. The broader method of accounting for costly occasional operations is developed in Amortized Analysis.

def shared_pointer_visits(a):
    # For a sorted nondecreasing array, count all advances of a shared pointer.
    n=len(a)
    j=0
    advances=0
    for i in range(n):
        while j < n and a[j] <= a[i]:
            j += 1
            advances += 1
    return advances

for n in range(50):
    values = list(range(n))
    assert shared_pointer_visits(values) == n
print('shared-pointer aggregate bound verified')

Two Pointers Advancing from Opposite Ends

A classic interval scan initializes left=0 and right=n−1, then moves at least one endpoint inward on each iteration until the endpoints meet. The potential right−left decreases by at least one on every iteration; hence there can be at most n−1 comparisons for n≥1, up to the exact stopping convention. The loop is linear even though two indices move and each movement may depend on data values.

The proof requires that the implementation never moves an endpoint outward or leaves both unchanged. If the body performs a nonconstant operation—for example, rebuilding a list every iteration—the iteration-count bound is not the total-cost bound. This pattern appears in sorted pair-sum searches, partitioning, and interval maintenance.

def two_pointer_steps(values, target):
    left, right = 0, len(values) - 1
    steps = 0
    while left < right:
        steps += 1
        s=values[left]+values[right]
        if s == target:
            return steps
        if s < target:
            left += 1
        else:
            right -= 1
    return steps

for n in range(60):
    assert two_pointer_steps(list(range(n)), -1) <= max(0,n-1)
print('opposite-end monotone scan verified')

Variable Additive Steps and Square-Root Bounds

A loop such as i=0; k=1; while i<n: i+=k; k+=1 advances i through the triangular numbers 1,3,6,10,…. After t iterations, i=t(t+1)/2. The smallest t reaching a threshold n satisfies t(t+1)/2≥n; therefore the iteration count grows as Θ(√n) for n≥2. Merely noticing that the counter increases does not reveal the speed of that increase.

This result is different from incrementing by a fixed stride k, which needs about n/k iterations for a positive constant k. If the stride itself grows multiplicatively, the count can become logarithmic. A reliable technique is to derive the counter value after t steps and solve the stopping inequality for t.

def growing_stride_steps(n):
    assert n >= 0
    i, step, count = 0, 1, 0
    while i < n:
        i += step
        step += 1
        count += 1
    return count

for n in range(0, 500):
    t=growing_stride_steps(n)
    assert t*(t+1)//2 >= n
    assert t==0 or (t-1)*t//2 < n
print('growing-stride threshold identities checked')

Growth by Multiplication and Subtraction

Updates like i*=2 are often simple, but hybrid updates require care. For i=max(0,i−k) with positive fixed k, an initial value n takes ⌈n/k⌉ body executions to reach zero. For i//=2, the bit length decreases by about one per step and the count is logarithmic. For i=i−max(1,⌊√i⌋), decrement size grows with the current value, and more sophisticated bounding can show a square-root scale for large n.

For every such loop identify a nonnegative integer ranking function that strictly decreases toward the exit condition. To obtain a tight asymptotic bound, determine how much the rank can change per iteration, not just that it changes. Progress proves termination; quantitative progress establishes the complexity class.

Nested Loops with Multiplicative Inner Bounds

Consider an outer index i=1,…,n and an inner loop that doubles j while j≤i. The inner loop performs ⌊log₂i⌋+1 iterations for positive i; therefore total work is Σ_{i=1}^n (⌊log₂i⌋+1)=Θ(n log n). A simple upper bound uses at most 1+log₂n inner iterations on every outer pass. For a matching lower bound, at least n/2 outer values have i≥n/2, each requiring Ω(log n) inner work for sufficiently large n.

Note that Σ log i = log(n!), which grows like n log n; it does not grow like (log n)². The logarithm's argument changes each pass, but there are n passes. This is a frequent source of analytical mistakes.

def log_inner_visits(n):
    total=0
    for i in range(1,n+1):
        j=1
        while j <= i:
            total += 1
            j*=2
    return total

for n in range(1,150):
    assert log_inner_visits(n) == sum(i.bit_length() for i in range(1,n+1))
print('dependent logarithmic inner counts verified')

Nested Loops over Divisors and Factor Pairs

A number-theoretic loop may test candidate divisors only up to ⌊√n⌋, because every nontrivial factorization n=ab contains a factor no greater than the square root. If the loop checks a constant-time divisibility condition on ⌊√n⌋−1 candidates, its worst-case number of tests is Θ(√n) for numbers without a smaller divisor, provided the number itself is the magnitude parameter.

If instead the input is an arbitrary-precision integer encoded using b bits, then n can be as large as about 2^b, and √n is exponential in b. Moreover, multi-precision remainder operations are not constant-time in b. This example shows why parameter selection can change a complexity claim's practical meaning.

Condition-Dependent Early Exit

A linear search stops when it finds its target. With n elements, an unsuccessful search needs n element comparisons, a successful search at zero-based position k needs k+1, and the best successful case needs one comparison when n≥1. Thus the worst-case comparisons are Θ(n), while the best successful case is Θ(1).

It is incorrect to assign a single exact loop count to a break-controlled search without stating the input. A distribution-weighted mean requires probabilities for targets and positions; the separate Worst-Case and Average-Case Analysis article develops that inference. In this article, the loop-level lesson is to represent the exit time as a function of the input rather than silently assume the longest path always occurs.

def linear_search_comparisons(items,target):
    comparisons=0
    for i,value in enumerate(items):
        comparisons+=1
        if value==target:
            return i,comparisons
    return -1,comparisons

items=list(range(20))
assert linear_search_comparisons(items,0)==(0,1)
assert linear_search_comparisons(items,19)==(19,20)
assert linear_search_comparisons(items,100)==(-1,20)
print('linear-search case counts verified')

Nested Loops with an Early Return

A nested search that compares every distinct pair until it finds a duplicate has a worst-case count of n(n−1)/2 pair comparisons when no duplicate is found, but it may return after the very first comparison for a favorable input. A nested-loop upper bound based on the full triangular domain remains correct; claiming the same exact count for every execution does not.

Proof of a Θ(n²) worst-case bound requires a family of admissible inputs on which the loop runs essentially the entire domain—for example, an all-distinct sequence under the pairwise duplicate-checking strategy. Whether such inputs exist may depend on the key universe; if n exceeds the number of possible distinct keys, the assumed witness may be impossible. A complete worst-case argument therefore also states the problem's value domain.

Data-Dependent Inner Costs

The total cost of a nested loop is not always the number of inner iterations. Suppose an inner body compares two strings of length at most L lexicographically, or copies a progressively larger buffer. A comparison can inspect up to Θ(L) character positions, while copying a prefix of length i can cost Θ(i). Then a loop with n bodies may incur up to Θ(nL) comparisons or a triangular Θ(n²) total from growing prefix copies.

A useful model assigns a cost c(i,x) to the operation actually executed on iteration i with input x. The running-time function is T(x)=Σ_i c(i,x) over iterations executed on x. Simplify the formula only after documenting bounds on the costly operation, rather than classifying loops by indentation depth.

String Concatenation and Growing Intermediate Data

Repeatedly constructing a new immutable string s=s+piece can copy the accumulated prefix on each pass. If piece has fixed positive length and each concatenation copies all existing content, cumulative copying is proportional to 1+2+⋯+n=Θ(n²) bytes. Appending pieces to a buffer and joining once is usually a more predictable linear-total-copy strategy when the runtime supports efficient buffered construction.

But the exact costs are language- and implementation-dependent. An interpreter may optimize certain concatenation cases, small-string representations may change constants, and variable-size pieces can yield a different total. A mathematical model should describe the copying behavior it assumes. For an independent proof of the buffered approach, count the total bytes accumulated and copied, not simply the number of append calls.

Repeated List Slicing in a Loop

Taking a fresh slice of an array or list can copy or allocate elements depending on the language and data structure. For example, in Python a slice such as items[:i] constructs a new list of i references under ordinary semantics. Performing this for i=1,…,n copies n(n+1)/2 references in total, a quadratic amount of work and allocation traffic despite only one visible loop.

This case cautions against treating every expression inside a loop as O(1). A string, list, matrix, or library operation may hide another loop in an implementation. When the exact cost is not documented, use a stated model and profile the behavior rather than making a universal claim about every language or runtime.

def slice_reference_copies(n):
    values=list(range(n))
    count=0
    for i in range(1,n+1):
        prefix=values[:i]
        count += len(prefix)
    return count

for n in range(60):
    assert slice_reference_copies(n)==n*(n+1)//2
print('prefix-slicing reference copies verified')

Repeated Prefix Sums: Quadratic Work versus Linear Precomputation

If every prefix sum Σ_{j=0}^{i}a[j] is recomputed from scratch for i=0,…,n−1, then the total additions are on the order of Σ_{i=1}^n i=Θ(n²) under a constant-time arithmetic model. Instead maintain a cumulative total after each new element; this gives all prefix sums in Θ(n) time with Θ(n) output storage.

The improvement follows from an invariant: after processing the first i elements, the running total equals their sum. No earlier element needs to be revisited. This is a general technique for reducing nested recomputation, but it is not automatically beneficial when the operator lacks associativity, overflow semantics differ, or exact floating-point summation order matters.

def prefix_sums_quadratic(values):
    result=[]
    additions=0
    for i in range(len(values)):
        s=0
        for j in range(i+1):
            s+=values[j]
            additions+=1
        result.append(s)
    return result,additions

def prefix_sums_linear(values):
    result=[]
    running=0
    for v in values:
        running+=v
        result.append(running)
    return result

for n in range(50):
    a=list(range(n))
    baseline,count=prefix_sums_quadratic(a)
    assert baseline==prefix_sums_linear(a)
    assert count==n*(n+1)//2
print('quadratic and linear prefix-sum results agree')

Difference Between Iteration Count and Result Magnitude

A program may compute the integer 2^n in n simple multiplications, yet the resulting number has n+1 bits and does not fit in a fixed-size word once n grows. Under arbitrary-precision arithmetic, the time and memory to store or multiply such values depend on their bit lengths. Conversely, a simple arithmetic formula can calculate a large summation value without performing one addition per summand, though materializing all individual outputs still requires work proportional to the output size.

Separate three quantities: the number of iterations, the total cost of operations inside them, and the magnitude or representation size of the result. They may grow at different rates. Loop counts alone establish total running time only when individual operations remain uniformly bounded under the chosen model.

Loop Invariants for Functional Correctness

A loop invariant is a statement about program state that holds before the first iteration, is preserved by every iteration, and can be combined with termination to establish the result. For summing array values, the invariant after i iterations might be: total=Σ_{j=0}^{i−1}a[j]. Initialization gives the empty sum zero; adding a[i] preserves the claim; at i=n the stored value is the complete sum.

Correctness and runtime are related but different arguments. The invariant explains what the loop computes; a ranking function such as n−i explains why it terminates; a count of n additions explains its modeled work. An algorithm analysis is strongest when all three are explicit rather than treating termination and correctness as consequences of the same complexity formula.

Ranking Functions and Proofs of Termination

For an ordinary loop while condition: body, a natural-number-valued rank R proves termination if the loop cannot execute with negative rank and every body execution decreases R strictly while the condition holds. For i+=1 up to a fixed n, use R=n−i. For an interval whose endpoints move inward, use R=max(0,right−left) under the correct exit condition. A rank may be multidimensional, with lexicographic order, for more complex loops.

Strict descent alone does not yield a tight work bound in arbitrary domains: a rank defined over nonnegative integers gives at most the initial rank many iterations if the rank drops by at least one, but a real-valued rank that decreases by an unspecified positive amount can admit infinitely many steps. The proof must identify a well-founded set and, for quantitative complexity, enough progress to bound the step count.

Summation Proofs by Mathematical Induction

Induction supplies exact formulas needed for loop counts. To prove Σ_{i=1}^n i=n(n+1)/2, verify n=1. Suppose the formula holds at n. Then Σ_{i=1}^{n+1}i=n(n+1)/2+(n+1)=(n+1)(n+2)/2, completing the step. Similar inductive arguments establish the geometric-series and square-sum identities.

Correctness of a program that accumulates terms can be proved by induction on its number of completed iterations, using the running total as the inductive object. The algebraic identity describes the answer, whereas the program invariant describes the computed state. Both are useful: a wrong loop bound may satisfy a valid arithmetic identity for the wrong range of terms.

Upper and Lower Bounds from Per-Iteration Costs

If a loop executes exactly m(n) times and each execution costs between positive constants c and C, then c m(n)≤T(n)≤C m(n), so T(n)=Θ(m(n)). If some iterations have zero cost or variable cost depending on state, the lower bound must be reconsidered. For a nested summation, bound each cost function and sum the resulting inequalities.

A simple upper bound can be useful but not tight. Replacing every inner-loop length by its maximum n gives O(n²) for the divisor-enumeration loop, while a harmonic argument proves Θ(n log n). To claim Θ, either derive an exact sum or supply matching upper and lower estimates. A proof of O alone cannot establish a tight class.

Big-O, Big-Omega, and Big-Theta in Loop Analysis

f(n)∈O(g(n)) asserts an eventual upper bound by a constant multiple of g; f(n)∈Ω(g(n)) asserts an eventual lower bound; and f(n)∈Θ(g(n)) asserts both. For nonnegative cost functions, the triangular count n(n−1)/2 is Θ(n²) for sufficiently large n, but at n=0 or n=1 it equals zero. Asymptotic definitions deliberately permit a threshold beyond which the bounds apply.

Writing O(n²) for a linear loop is technically an upper bound, but it obscures useful information. Prefer the tightest familiar bound justified by the proof, and state the measured operation. See Asymptotic Notation for quantifier-level formal definitions and distinctions among tight, loose, and little-o/little-ω comparisons.

Worst-Case, Best-Case, and Expected Loop Counts

Define C(x) as the count of a chosen operation for admissible input x. For an input-size class I_n, the worst-case cost is the maximum over I_n, while the best case is the minimum. The expected count requires a probability distribution D_n over inputs and is E_{X∼D_n}[C(X)]. A random-pivot algorithm introduces a second probability source from its internal choices; it must be distinguished from the input distribution.

For a loop with early termination, these case measures can differ dramatically. Some loops always execute a deterministic number of iterations independent of values; others terminate when data satisfy a condition. Exact loop syntax does not fix their average without workload assumptions. The analysis should state whether it has proven a uniform bound, calculated an expected value, or sampled finite observed runs.

Nested Loops over Two Independent Input Dimensions

Programs that combine two collections commonly need two size parameters. Comparing every item in an n-element set with every item in an m-element set entails nm pair checks. Reporting Θ(n²) would require an assumption such as m=Θ(n); if m stays constant, the same operation is linear in n.

When an outer loop operates on rows of unequal lengths r₁,…,rₙ, the total element visits are Σ rᵢ, not necessarily n·max rᵢ as a tight bound. This ragged-array analysis generalizes to adjacency lists, variable-length records, and hierarchical datasets, where the true work is proportional to the total represented data rather than the area of a hypothetical rectangular array.

Graph Adjacency Lists: Summing Degrees

An adjacency-list traversal that iterates once over each vertex and then once over all of its outgoing adjacency entries performs Σ_{v∈V}deg⁺(v)=E edge-entry visits in a directed graph. Including vertex setup work yields Θ(V+E) for such a scan under constant-time adjacency access. In an undirected graph with each edge stored at both endpoints, Σ_v deg(v)=2E, still giving Θ(V+E).

The sum is more precise than V·V simply because a loop is nested: an adjacency list for a sparse graph contains far fewer than V² neighbor entries. The proof requires an accounting convention for edges, directedness, and representation. An adjacency matrix, by contrast, can require scanning V² cells to inspect all possible neighbors, even when few edges exist.

def edge_entry_count(adjacency):
    examined=0
    for neighbors in adjacency:
        for _ in neighbors:
            examined += 1
    return examined

# A directed graph with five vertices and six represented arcs.
adj=[[1,2],[2,3],[4],[],[1]]
assert edge_entry_count(adj)==6
assert edge_entry_count(adj)==sum(map(len,adj))
print('adjacency-list entry count verified')

Matrix Traversal and Cache-Aware Resource Models

Visiting every cell in an r×c matrix entails rc logical visits. The measured cost of a visit, however, may depend on storage order and memory hierarchy. Traversing a row-major matrix row by row often has better spatial locality than a column-first scan, even when both execute exactly rc visits. If cache lines, page faults, or disk I/O dominate, the word-operation count alone does not predict elapsed time.

This boundary motivates the separate Cache and External-Memory Complexity unit. Loop and summation analysis establishes the number of logical operations; a memory-traffic model charges for accessing blocks and may find meaningful differences between the same iteration counts in different orders.

Unrolled, Vectorized, and Parallel Loops

Loop unrolling groups multiple logical iterations into one block, often reducing branch overhead while retaining an operation count proportional to n for a full scan. Vectorization may perform several element operations in one hardware instruction, but vector width and masking conditions matter; the logical work is not necessarily equal to the number of machine instructions. Parallel loops distribute work across processors and may reduce elapsed span without reducing total work.

For a parallel reduction of n values, the total number of additions remains approximately n−1, while an ideal balanced addition tree has dependency depth Θ(log n). Work, critical-path span, memory traffic, and wall-clock duration are distinct metrics. See Parallel Algorithm Analysis for formal work–span frameworks.

Space Complexity of Iterative Algorithms

Loop count by itself says little about auxiliary space. A loop that maintains two integer counters and a running sum uses O(1) auxiliary words under a fixed-word representation, even if it executes billions of times. A loop appending one result on every pass can allocate Θ(n) output storage. A nested loop can reuse a constant-size temporary buffer; conversely, a single loop can allocate a fresh Θ(i)-sized object on each pass and retain all objects, reaching Θ(n²) storage.

Specify whether output space counts and whether earlier temporary values remain live. The peak simultaneously live memory can be less than the cumulative amount allocated. Large integer counters also require more than one machine word in languages with arbitrary-precision integers, which is relevant to bit-complexity analysis.

Exact Counts versus Wall-Clock Benchmark Results

Counting loop bodies is a mathematical and implementation-specific exercise. Timing a program reports a noisy observation affected by processor frequency, interpreter dispatch, compiler optimization, memory hierarchy, background load, warm-up, input distributions, and measurement overhead. An exact count of 10,000 comparisons does not imply a universal number of microseconds. Likewise, two programs with identical asymptotic growth can have substantially different timing curves over finite inputs.

Useful benchmarking compares like workloads, records environment and sizes, repeats trials, checks correctness, and measures the resource that matters. It should not replace a mathematical proof of an upper or tight bound. See Algorithm Benchmarking and Profiling for experimental design and interpretation.

Worked Investigation I: Duplicate-Pair Detection

Problem: Given n keys, compare each key with all earlier keys and stop at the first match. Work model: one constant-time equality comparison per pair. In the no-duplicate case the complete triangular region executes, giving Σ_{i=1}^{n−1}i=n(n−1)/2 comparisons. The best case can return on the first pair comparison for n≥2. A bound on all executions is O(n²); a worst-case tight bound of Θ(n²) follows when arbitrarily long all-distinct valid inputs exist.

Alternative: a hash set can reduce expected operations to linear under an appropriate expected constant-time hashing model, but its worst-case behavior and extra memory depend on the hashing implementation and threat model. The loop-count derivation and data-structure guarantee are separate analytical claims. Avoid reporting either as an unconditional “best algorithm” result.

Worked Investigation II: All Multiples from One to n

Problem: For every positive d≤n, visit its multiples up to n. Calculation: each d contributes ⌊n/d⌋ visits, so the total is Σ_{d=1}^n⌊n/d⌋. Bounding floors between n/d−1 and n/d reduces the estimate to the harmonic series, yielding Θ(n log n). The upper-bound shortcut n² is valid but needlessly loose.

Engineering consequence: the distribution of inner-loop steps explains the result. Small divisors visit many multiples; large divisors visit only a few. If the inner operation itself is expensive or values require multi-precision arithmetic, that separate per-visit cost must be added to the sum.

Worked Investigation III: Two-Pointer Interval Search

Problem: Search for a target pair in a sorted array by moving endpoints inward. Termination: the interval width decreases with every unsuccessful iteration, so the algorithm cannot execute more than n−1 unsuccessful pair comparisons with initial endpoints 0 and n−1. Cost: if each arithmetic comparison and pointer update costs O(1), total work is O(n) with O(1) auxiliary words.

Correctness condition: the input must satisfy the ordering assumption and the update rule must preserve any potential solution. The linear runtime proof alone does not establish that moving one endpoint is logically sound. An unsorted input can invalidate correctness while leaving the same low iteration count.

Worked Investigation IV: Matrix Sweep and Memory Locality

Problem: Sum every element of an r×c matrix. A conventional nested traversal performs exactly rc element visits and rc additions under a fixed-word model. Swapping loop order does not change that sum. However, if the physical storage is row-major, traversing contiguous rows typically uses cache lines more efficiently than stepping between distant rows.

Decision: classify the logical arithmetic as Θ(rc), then separately benchmark cache misses or memory transfers if performance is sensitive to layout. If the actual representation is sparse, analyzing only stored entries may produce a bound in terms of nonzero count rather than the full logical matrix area.

Worked Investigation V: Prefix-Recomputation Refactor

Problem: Generate the sums of every prefix in an array. Recomputing each prefix from scratch adds 1+2+⋯+n=n(n+1)/2 values. A cumulative algorithm maintains the invariant that the running total equals the sum of items seen so far, performs one addition per element, and emits the current total. With constant-time arithmetic, the running-time bound improves from Θ(n²) to Θ(n).

Trade-off: generating n outputs requires Θ(n) result storage if they are retained, but a streaming interface can emit them one at a time with constant extra working space. On floating-point data, accumulating left-to-right and recomputing prefixes can have different rounding behavior; numeric guarantees need a separate analysis.

Worked Investigation VI: Multi-Parameter Data Traversal

Problem: For each of V graph vertices, inspect only represented outgoing edges. The outer loop has V passes and the inner loop has deg⁺(v) passes for vertex v. The total is V+Σ_v deg⁺(v)=V+E. A graph with V=10,000 and E=20,000 therefore has a linear number of setup-plus-edge visits in V+E, not 100 million potential adjacency cells.

Boundary: the conclusion assumes each adjacency entry is available at constant cost and is inspected once. If adjacency lists are repeatedly copied, filtered, or sorted, add those costs separately. Changing from adjacency lists to a dense matrix also changes the natural loop domain.

A Practical Analysis and Design Checklist

Before publishing a runtime bound, identify the actual size parameter (including multiple dimensions), the input preconditions, the precise loop ranges, whether index variables are reset or shared, the number of inner iterations on each outer pass, and any data-dependent exit conditions. Next examine the body: identify copies, allocations, library calls, big-integer operations, and memory accesses whose costs may not be constant.

Translate the execution pattern into a summation or a global progress argument. Evaluate exact arithmetic or geometric sums where possible; otherwise use logarithmic grouping, integrals, upper/lower comparisons, or aggregate charging. State whether the result is an exact operation count, O, Ω, Θ, worst-case, or expected under a named distribution. Finish by checking empty inputs, singleton inputs, and transition thresholds, then compare a few instrumented counts to the prediction without confusing these checks with a proof.

When a loop analysis becomes unwieldy, ask whether the implementation can be simplified: carry state forward, avoid repeated copying, use a monotone pointer, precompute reusable results, or select a data representation suited to the required operations. Those transformations should be justified by correctness arguments as well as complexity claims.

Review Questions and Worked Answers

These questions are designed to test exact counting, asymptotic interpretation, and the reasoning needed for unusual loop structures. Every answer assumes the stated loop body costs constant time unless the question says otherwise.

  1. Question: How many times does for i in range(n) enter its body for n≥0? Answer: exactly n.
  2. Question: What is Σ_{i=0}^{n−1} i? Answer: n(n−1)/2.
  3. Question: What is Σ_{i=1}^n i²? Answer: n(n+1)(2n+1)/6=Θ(n³).
  4. Question: If each of n outer passes scans m elements, how many visits occur? Answer: nm; keep both dimensions when independent.
  5. Question: How many times does a positive integer halve until reaching zero? Answer: ⌊log₂n⌋+1.
  6. Question: Why is Σ_{i=1}^n 1/i not linear? Answer: it grows as Θ(log n) because later terms diminish.
  7. Question: How many distinct pairs of n indices exist? Answer: n(n−1)/2.
  8. Question: Why is a doubles-counter outer loop with a full n-item scan Θ(n log n)? Answer: logarithmically many full linear scans.
  9. Question: Why can an outer doubling loop with an inner scan of length i be linear? Answer: its cost is a geometric sum 1+2+4+⋯=Θ(n).
  10. Question: What is Σ_{d=1}^n⌊n/d⌋ asymptotically? Answer: Θ(n log n).
  11. Question: What is the cost of walking every adjacency entry in a directed adjacency-list graph? Answer: Θ(V+E) including vertex setup.
  12. Question: Can two nested loops be O(n)? Answer: yes, if a shared pointer advances at most n times globally.
  13. Question: What makes a termination proof different from an operation count? Answer: the former establishes progress to an exit, while the latter quantifies work.
  14. Question: Why might one visible loop cost quadratic time? Answer: a length-i slice or copy inside each pass creates Σi hidden work.
  15. Question: How many steps reach threshold n when step sizes are 1,2,3,…? Answer: the least t with t(t+1)/2≥n, namely Θ(√n).
  16. Question: If a search breaks after its first match, is its iteration count always n? Answer: no; it depends on the matching position or an unsuccessful search.
  17. Question: Does algebraic telescoping imply a naive loop computes the sum in constant time? Answer: no; the loop may still evaluate every summand.
  18. Question: How can you prove a tight Θ bound after obtaining O? Answer: find a matching Ω lower bound under the same assumptions.
  19. Question: Does Θ(n) logical work imply the same cache behavior under all iteration orders? Answer: no; memory locality and transfer counts can differ.
  20. Question: Why is a loop to numeric magnitude N not necessarily polynomial in the encoded input size? Answer: N can be exponential in its bit length.
  21. Question: What does it mean for two loops to share state? Answer: updates in one iteration persist to later iterations, so the inner work is not reset.
  22. Question: When can integral comparison estimate a sum? Answer: when the nonnegative summand has suitable monotonicity and regularity over its range.
  23. Question: What must be specified before calling a loop’s expected cost average-case? Answer: the distribution over admissible inputs, and any internal randomness.
  24. Question: Why can the cost of repeated string concatenation vary by language? Answer: allocation, mutability, and runtime optimization can change the amount of copying.

Extension exercise: Analyze a loop that for each i=1,…,n visits j=1,2,4,…≤i. A complete solution should establish Σ_{i=1}^n(⌊log₂i⌋+1) visits, bound that sum from above and below, and conclude Θ(n log n). Then change the outer loop to double i as well and show how that changes the count to Θ((log n)²) for sufficiently large n.
