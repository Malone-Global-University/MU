Definition, Purpose, and Scope

A recursion tree is an analytical representation of how a recursive algorithm expands into smaller instances and where it spends work. Each node stands for a subproblem; edges stand for recursive calls; the node’s assigned toll records work that occurs outside the descendant calls. Summing the tolls over every level, including the leaves, converts a recurrence relation into a total-cost bound. It is a mathematical accounting tool, not necessarily a picture of the implementation’s simultaneously resident stack frames.

The Master Theorem packages the common conclusions for recurrences of the form T(n)=aT(n/b)+f(n). Its cases compare the work at leaves with the work done by internal nodes. The theorem is efficient because it summarizes an entire tree with a small set of hypotheses; using it responsibly requires checking those hypotheses before selecting a case.

This is specialist article 5 of the Algorithm Analysis unit and extends the Algorithm Analysis overview. It follows Recurrence Relations in Algorithm Analysis, which develops recurrence construction and substitution, and complements the Recursion unit’s divide-and-conquer article. Here the primary responsibility is level accounting, theorem cases, exceptional recurrences, and proof checks.

Why Recursion Trees Are More Than Drawings

A rough branching diagram can suggest whether a procedure grows quickly, but it is not a proof until the sizes and costs are specified. A complete tree analysis establishes how many nodes exist at each depth, what size each node receives, the cost of one node at that size, the number of levels, and the contribution from terminal cases. In an unbalanced tree, these quantities may differ along branches and cannot be compressed into a single uniform level count without justification.

The same recursion tree can answer several questions. The sum of costs across all nodes models serial work; the longest path models depth; and different forms of allocation determine peak memory. A tree that has a million total nodes may still need only logarithmically many active stack frames under a depth-first implementation. Conversely, a procedure that allocates a new full-size array at every level may use much more memory than the number of active frames would suggest.

Use the tree to explain the source of a bound, and use induction or a formal theorem to verify the claimed bound. A sketch with plausible labels but no treatment of leaves, rounding, or abnormal inputs should be described as intuition rather than a complete asymptotic argument.

Begin with the Resource and Input Model

An algorithm analysis must state whether T(n) counts comparisons, primitive word operations, data moves, cache transfers, or elapsed time in an idealized machine. These counts can differ. For example, divide-and-conquer sorting may perform Θ(n log n) comparisons and move Θ(n log n) elements under a simple array model, but cache behavior and real execution times depend on memory layout and implementation constants.

The standard balanced-tree derivation temporarily assumes a positive power-of-b input size, a base-case cost bounded above and below by positive constants, fixed integer a≥1, fixed real reduction factor b>1, and nonnegative toll f(n). Floor and ceiling choices are handled later; they are not an excuse to drop a child or to assume the same work for every possible partition.

Calling a mathematical cost T(n) does not make it a running-time measurement. If arithmetic on long integers, substring copies, or input parsing has cost growing with its argument, incorporate that cost into f(n) before drawing the tree.

The Standard Divide-and-Conquer Recurrence

The model T(n)=aT(n/b)+f(n), with T(1)=Θ(1), has a recursive calls on subproblems of size n/b and f(n) units of nonrecursive work. For an actual integer input, the program may use ⌊n/b⌋ or ⌈n/b⌉; the clean formula is an idealization whose extension to nearby sizes should be justified.

Consider merge sort. Two half-size calls sort the input pieces, and a linear-time merge combines the results, so the idealized recurrence is T(n)=2T(n/2)+Θ(n). A binary search makes just one recursive call on half the data and performs a constant number of comparisons, leading to T(n)=T(n/2)+Θ(1). Changing either the number of children or the toll changes the growth of the tree.

The nonrecursive toll must include everything paid by the invocation: partitioning, copying, memory allocation, arithmetic, and result combination. The tree cannot fix an incorrectly modeled recurrence.

Count Nodes and Subproblem Sizes by Level

At depth j of the idealized a-ary recursion tree, there are a^j nodes, each handling an input of size n/b^j. The cost of one nonleaf node is f(n/b^j), so the total toll for level j is L(j)=a^j f(n/b^j). This is the central identity from which all common cases follow.

The formula requires fixed branching and equal-sized subproblems. For adaptive recursion, a level can contain inputs of many sizes; in that situation, its actual total is a sum over the nodes that exist, not automatically a^j f(n/b^j). Parent and child sizes must be recorded from the real algorithm.

Levels are indexed here starting from the root as level zero. For power-of-b inputs, the last level occurs at h=log_b n. There are h+1 levels if both the root and leaf level are counted.

Tree Height, Leaf Count, and the Critical Exponent

Solving n/b^h=1 gives h=log_b n. The number of leaves is a^h=a^(log_b n)=n^(log_b a), using the identity a^(log_b n)=n^(log_b a). Define p=log_b a. The quantity n^p measures the total constant-cost leaf contribution in the idealized tree and forms the threshold against which f(n) is compared.

For example, 3T(n/2) has roughly n^(log₂3) leaves, with log₂3≈1.585. The leaf count alone does not include work spent partitioning or combining at internal nodes. The theorem’s central insight is that one of three broad patterns arises: internal work decreases toward leaves, stays comparable across levels, or increases toward leaves.

The expression log_b a is a mathematical exponent, not a runtime call count. If a=1, then p=0 and there is exactly one leaf; a single chain still has logarithmically many levels when the argument shrinks by a fixed factor.

Sum Internal Tolls and Leaf Costs Separately

The idealized total is T(n)=Σ[j=0 to h−1] a^j f(n/b^j) + Θ(a^h). The first term counts nonrecursive work at internal nodes and the second accounts for leaf work; the base-case costs cannot simply disappear when f(1) was defined only for nonterminal calls.

This expression is especially useful when the theorem does not apply. An exact level formula lets us compare the sequence of level tolls with familiar sums: geometric series, arithmetic series, harmonic sums, or integrals. It can also show when the cost is concentrated at the root, at all levels collectively, or near the leaves.

For f(n)=Θ(n^q), the level toll becomes L(j)=Θ(n^q(a/b^q)^j). The ratio r=a/b^q is the decisive quantity. If r<1, costs decrease with depth; if r=1, each level contributes the same order; if r>1, costs increase toward leaves.

These patterns are the intuitive core of the standard three-case theorem for polynomial tolls. More generally, a logarithmic factor can make costs drift slowly between levels, and an irregular toll may fail the assumptions of the closed-form theorem. The ratio argument is direct only for a sufficiently uniform toll function.

For a geometric series, the finite total is 1+r+⋯+r^(h−1)=(r^h−1)/(r−1) when r≠1. With r=1, the sum equals h. These identities explain the three regimes; they do not require measuring the algorithm with a stopwatch.

Worked Tree: Merge Sort and Equal-Level Work

Merge sort has T(n)=2T(n/2)+cn for powers of two under a linear merge model. At level j, 2^j subproblems each merge roughly n/2^j elements, so the level cost is 2^j·c(n/2^j)=cn. There are log₂n internal levels, yielding cn log₂n internal operations plus Θ(n) leaf work.

The resulting bound is Θ(n log n). Importantly, this is not because one individual call loops logarithmically many times. Each element participates in a sequence of merges at successive levels, and the aggregate amount of work stays linear per level.

A comparison-specific recurrence can be tighter than the generic work recurrence. Depending on the input, merging two sorted runs uses a bounded number of comparisons, while element copying can have its own accounting. The model chosen for c n should match the operation actually counted.

import math

def merge_tree_levels(n):
    assert n >= 1 and n & (n-1) == 0
    levels=[]
    size=n
    nodes=1
    while size>1:
        levels.append(nodes*size)
        nodes*=2
        size//=2
    return levels,nodes

for n in (2,4,8,16,32):
    costs,leaves=merge_tree_levels(n)
    assert costs==[n]*int(math.log2(n))
    assert leaves==n
print('Each internal level performs n units of modeled work')

Worked Tree: Leaf-Dominated Branching

Consider T(n)=4T(n/2)+cn. Depth j contains 4^j nodes of size n/2^j, so the level toll equals cn·2^j. Its contributions double at each deeper level. With h=log₂n, the last internal level is on the order of n² and there are 4^h=n² constant-cost leaves.

The complete geometric sum is cn(1+2+⋯+2^(h−1))=cn(2^h−1)=c(n²−n). Adding Θ(n²) leaves yields T(n)=Θ(n²). Multiplying the root toll n by tree height would give the wrong answer: the number of nodes grows faster than the shrinkage of the toll.

This example is a reminder to calculate the whole level toll, not just the cost of one call. A large fanout can overwhelm a decreasing per-node input size.

Worked Tree: Root-Dominated Combination Work

For T(n)=2T(n/2)+cn², the level toll is 2^j·c(n/2^j)²=cn²/2^j. Work halves with each descent, so the sum of all internal levels is less than 2cn². There are only n leaves with constant base cost, which does not change the dominant quadratic term.

Consequently T(n)=Θ(n²). In this case, the top-level combine operation already costs as much as the total asymptotic work. Recursion does not improve or worsen the growth order beyond that expensive toll.

The same observation applies to expensive input copying, pairwise comparisons, or all-pairs combination steps performed outside recursive calls. Even when the recursive branching looks efficient, a quadratic toll at each root can be decisive.

Worked Tree: One Branch with Constant Toll

In a binary search recurrence T(n)=T(n/2)+c, there is one node at each depth and each active level costs a constant. The recursion reaches its base case after log₂n reductions on power-of-two inputs, so the total is c log₂n+Θ(1)=Θ(log n). Here a=1 and p=log₂1=0.

Binary search is a useful diagnostic because the tree degenerates to a chain. If a student mechanically counts two child branches because the search interval has two possible halves, the recurrence becomes incorrect: each actual step chooses one half, rather than recursively exploring both halves. The recurrence must represent executed calls, not hypothetical branches.

If a program obtains a copy of the half-list on each call, however, the local cost can become proportional to the active interval size. The resulting recurrence T(n)=T(n/2)+Θ(n) instead sums a decreasing geometric series and gives Θ(n) time even though depth remains logarithmic.

Worked Tree: Noninteger Polynomial Exponents

For T(n)=3T(n/2)+cn, the critical exponent is p=log₂3≈1.585. A level contains 3^j nodes of size n/2^j, so the toll grows by factor 3/2 each level. This makes the leaf contribution dominant, producing Θ(n^(log₂3)).

Do not round the exponent 1.585 up to 2 and then report Θ(n²). It is true that this cost is O(n²), but the rounded exponent discards a meaningful tighter bound. Exact expressions such as n^(log₂3) are preferable until numerical approximation becomes useful for interpretation.

The example illustrates a general analytical advantage of recursion trees: growth exponents that seem mysterious when looking at source code often arise directly from multiplying the number of subproblems through repeated levels.

The Master Theorem: Formal Statement

For a recurrence T(n)=aT(n/b)+f(n) over sufficiently large n, assume fixed a≥1, fixed b>1, nonnegative and suitably regular toll f(n), and constant-size base cases. Define p=log_b a. The standard three-case Master Theorem classifies costs by whether f(n) grows polynomially slower than, comparably to, or polynomially faster than n^p.

Case 1: if f(n)=O(n^(p−ε)) for a constant ε>0, then T(n)=Θ(n^p). Case 2: if f(n)=Θ(n^p), then T(n)=Θ(n^p log n). Case 3: if f(n)=Ω(n^(p+ε)) for some ε>0 and the regularity condition a f(n/b)≤c f(n) holds eventually for some constant c<1, then T(n)=Θ(f(n)).

These are three sufficient sets of conditions, not an exhaustive list of every possible toll function. When none fits, do not choose the nearest case by intuition. Inspect the recursion tree, derive a bound by another method, or invoke a properly stated extension.

Check the Theorem’s Preconditions First

Before comparing exponents, verify the recurrence actually has a equal-sized recursive subproblems of size approximately n/b. Both a and b must be constants independent of n in the standard statement. A quicksort recurrence with split sizes k and n−k−1, a tree that branches differently at every depth, or a procedure that produces one child of size n−1 cannot be substituted directly without additional reasoning.

Check the base case and whether f(n) really is the total nonrecursive cost. Check that the positive lower-bound assumptions implicit in a tight Θ statement hold. Oscillatory, discontinuous, or non-monotonic toll functions can be problematic for particular theorem variants. Also distinguish a recurrence describing at most some cost from an exact equality; an upper recurrence alone does not prove a matching lower bound.

Introductory proofs commonly assume n is a power of b to display the tree cleanly. Standard formulations handle routine floors or ceilings under appropriate hypotheses, but that simplification does not validate arbitrary input-size rounding or expensive padding.

The Critical Exponent p = log_b a

The first numerical calculation is p=log_b a=ln(a)/ln(b). This exponent is derived from the number of leaves, not the cost of the combining procedure. For a=8 and b=2, p=3; for a=7 and b=2, p≈2.807; for a=2 and b=4, p=1/2. Fractional exponents are normal and should remain exact when possible.

After computing p, express f(n) in comparable terms. A polynomial n^q has an immediate exponent comparison, but n^p log n is larger than n^p without being polynomially larger. Similarly, n^p/log n is smaller without being polynomially smaller. Both require care beyond the basic statement.

If p=0, remember that n^p=1. The boundary case T(n)=T(n/2)+Θ(1) therefore belongs to Case 2 and has logarithmic total work, even though the tree contains only one leaf.

import math

def critical_exponent(a, b):
    assert a>=1 and b>1
    return math.log(a)/math.log(b)

for a,b in [(1,2),(2,2),(3,2),(4,2),(7,2),(2,4)]:
    print(a,b,round(critical_exponent(a,b),5))
assert math.isclose(critical_exponent(2,4),0.5)

Case 1: Leaf-Dominated Recursion

When f(n)=O(n^(p−ε)) for a fixed ε>0, the local work is polynomially smaller than the leaf baseline. The recursion tree is deep enough and branches sufficiently fast that the total cost accumulates near the leaves. The result is Θ(n^p), not Θ(f(n) log n).

For example, T(n)=8T(n/2)+n² has p=3 and f(n)=n²=O(n^(3−1)). Thus T(n)=Θ(n³). The level toll is n²(8/4)^j=n²·2^j; at depth approximately log₂n, that scale reaches n³.

Case 1 does not apply merely because f(n)=o(n^p). The gap must be polynomial in the standard theorem. For instance, n^p/log n is o(n^p) but is not O(n^(p−ε)) for any fixed positive ε. A separate summation is needed.

Case 2: Comparable Work at Many Levels

If f(n)=Θ(n^p), the level toll is a^j(n/b^j)^p=n^p(a/b^p)^j=n^p, since b^p=a. Every internal level contributes the same asymptotic work and there are Θ(log n) such levels. Consequently T(n)=Θ(n^p log n).

Merge sort, 2T(n/2)+Θ(n), is the standard example with p=1. Binary search, T(n/2)+Θ(1), is another example with p=0. By the same reasoning, 4T(n/2)+Θ(n²) yields Θ(n² log n).

Some textbooks give an extended Case 2 for f(n)=Θ(n^p log^k n) with k≥0, leading to Θ(n^p log^(k+1)n). That extension is useful but should be identified separately from the basic f(n)=Θ(n^p) case.

Case 3: Root-Dominated Recursion and Regularity

When f(n) exceeds n^p by a fixed polynomial factor, nonrecursive work is a candidate to dominate the entire recurrence. Case 3 requires f(n)=Ω(n^(p+ε)) for some ε>0 and a regularity condition: there must exist constants c<1 and n₀ such that a f(n/b)≤c f(n) for all n≥n₀ in the relevant domain.

This inequality ensures that the combined cost one level below the root is at most a fixed fraction of the root toll. Applying it repeatedly gives a decreasing geometric total: f(n)(1+c+c²+⋯)=O(f(n)). The root alone contributes Ω(f(n)), yielding T(n)=Θ(f(n)).

For T(n)=2T(n/2)+n², take a=2, b=2, p=1, and f(n)=n². Then 2f(n/2)/f(n)=2(n/2)²/n²=1/2. Any c strictly between 1/2 and 1 satisfies the condition, so the result is Θ(n²).

How to Verify the Regularity Inequality

A practical check is to simplify the ratio R(n)=a f(n/b)/f(n) wherever f(n)>0. If R(n) is eventually at most some constant c<1, regularity holds. For a polynomial f(n)=n^q, R(n)=a/b^q. When q>p, we have b^q>a, so the ratio is below one. Nonnegative polylogarithmic modifiers commonly preserve the limit, but this needs to be shown for the specific function.

Example: T(n)=3T(n/2)+n² log n has p=log₂3<2 and a polynomial gap. The ratio tends toward 3/4 because log(n/2)/log n→1. Choose a fixed c between 3/4 and one for sufficiently large n; Case 3 gives Θ(n² log n).

Do not write “regularity is automatic” merely because the toll is nonnegative, increasing, or exceeds the critical exponent. The theorem demands a uniform contraction. Some deliberately irregular functions violate this and require a separate analysis.

A Reusable Master-Theorem Classification Procedure

The following workflow is suitable for handwritten solutions, code review, or an algorithm-design document. It begins with an eligibility check, and it explicitly stops rather than forcing an invalid conclusion.

1. Derive the recurrence from executed operations. 2. Identify the fixed a, b, and f; confirm base cases and nonnegative toll. 3. Compute p=log_b a. 4. Compare f(n) to n^p using precise O, Θ, and Ω claims. 5. For Case 1 or 3, exhibit a positive ε; for Case 3, also prove regularity. 6. If Case 2 applies, count the logarithmic number of levels. 7. State the final bound under the assumptions. 8. When none fits, analyze the level sum directly or choose an appropriate other theorem.

This method intentionally treats inapplicability as a legitimate result. A recurrence may be solvable even when the basic Master Theorem does not apply. Recognizing that distinction is a sign of accurate analysis, not failure.

Given T(n) = a T(n/b) + f(n):
    Verify fixed a >= 1, fixed b > 1, base case, toll, and actual child sizes.
    Let p = log_b(a).
    If f(n) = O(n^(p-epsilon)) for some epsilon > 0:
        conclude Theta(n^p).
    Else if f(n) = Theta(n^p):
        conclude Theta(n^p log n).
    Else if f(n) = Omega(n^(p+epsilon)) for epsilon > 0
            and a f(n/b) <= c f(n) eventually for some c < 1:
        conclude Theta(f(n)).
    Else:
        use a recursion tree, substitution, or a valid extension.

Extended Case 2: Logarithmic Toll Factors

An extension worth deriving directly is T(n)=aT(n/b)+Θ(n^p log^k n) for a fixed k≥0, where p=log_b a. At depth j, the level toll is proportional to n^p(log(n/b^j))^k. Reindexing from the leaves yields a sum of powers 0^k+1^k+⋯+h^k, which is Θ(h^(k+1)) for fixed k≥0. Therefore the total is Θ(n^p log^(k+1)n).

For T(n)=2T(n/2)+n log n, the nonrecursive toll at level j is n(log₂n−j), and summing the arithmetic sequence over Θ(log n) levels gives Θ(n log²n). For T(n)=4T(n/2)+n² log²n, the analogous sum yields Θ(n² log³n).

The logarithmic extension is mathematically different from the basic equal-level Case 2, which assumes a toll within constant factors of n^p. When reporting a result, state which version of the theorem or which level-summation proof was used.

Boundary Toll: n^p Divided by a Logarithm

The recurrence T(n)=2T(n/2)+n/log₂n, with a suitable constant-size base case, illustrates a gap in the basic three-case theorem. Here p=1; the toll is asymptotically below n, but not below by a fixed polynomial factor. It is not Θ(n), and the root-dominant case is irrelevant. Thus none of the three basic conditions applies.

At level j there are 2^j subproblems, so the combined toll is n/(log₂n−j). Writing h=log₂n and summing over j=0,...,h−1 gives n Σ[k=1 to h]1/k=n H_h=Θ(n log h)=Θ(n log log n). Leaf cost adds Θ(n), which is smaller.

This example shows why the difference between a logarithmic and a polynomial gap is important. A careless use of Case 1 would return Θ(n) and miss a growing log log n factor.

Boundary Toll: n^p Divided by log² n

Now consider T(n)=2T(n/2)+n/(log₂n)² for powers of two above the base threshold. The level toll is n/(h−j)². Summing over internal levels gives n Σ[k=1 to h]1/k², which stays between constant multiples of n, because the series Σ 1/k² converges.

Adding the Θ(n) leaves yields T(n)=Θ(n). This recurrence also falls outside the basic Master Theorem, but it has a different result from the n/log n example. In fact, for n^p/log^q n at the critical exponent, the outcome depends on whether q<1, q=1, or q>1.

These borderline calculations are best presented through the actual level sum. They demonstrate the value of understanding the recursion-tree proof rather than memorizing three labels.

Generalized Logarithmic Tolls at the Critical Exponent

For T(n)=aT(n/b)+Θ(n^p log^k n) with p=log_b a and fixed real k, power-of-b tree accounting gives Θ(n^p Σ[t=1 to Θ(log n)]t^k) plus Θ(n^p) leaves. The series has three regimes: for k>−1, it is Θ((log n)^(k+1)); for k=−1, it is Θ(log log n); for k<−1, it remains Θ(1).

The corresponding answers are Θ(n^p log^(k+1)n), Θ(n^p log log n), and Θ(n^p). This direct derivation supports negative logarithmic exponents as well as the familiar nonnegative extension. It requires appropriate treatment of the final constant-sized subproblems so that logarithms of one are not used as denominators.

Do not attribute all three results to a classroom statement of the “Master Theorem” unless the version being cited includes such an extension. The recursion-tree summation is the transparent justification in this article.

Merge Sort: A Full Recursion-Tree Proof

Let n=2^h and suppose each merge costs between c₁n and c₂n elementary operations for the selected work measure, with positive constants. Each of the 2^j nodes at level j has size n/2^j. Therefore that level costs between c₁n and c₂n for each j<h. Summing h internal levels yields lower and upper bounds proportional to n log₂n.

The n leaves each contribute constant base cost, so the leaf total is Θ(n). Consequently T(n)=Θ(n log n). This establishes both sides of the Θ claim instead of relying on the phrase “logarithmic levels.”

If the merge implementation uses additional temporary arrays, its peak live storage is a separate question. A merge step might allocate an array of size proportional to the current input; maximum simultaneously live storage depends on allocation and release behavior, not on the total work recurrence alone.

Karatsuba Multiplication: Fewer Leaves

Karatsuba’s divide-and-conquer multiplication replaces four half-size multiplications with three, plus additions, subtractions, and shifts. In an idealized arithmetic model where that auxiliary work is Θ(n) for n-digit inputs, the recurrence is T(n)=3T(n/2)+Θ(n). The critical exponent is p=log₂3≈1.585; the toll is polynomially smaller, so Case 1 gives Θ(n^(log₂3)).

The reduction from four children to three changes the number of leaves from about n² to about n^1.585. That is the source of Karatsuba’s asymptotic improvement over schoolbook multiplication under comparable arithmetic models.

The analysis should not assume that every addition of arbitrarily large integers is constant time. The digits or bits in each operand matter. At practical sizes, implementation overhead and specialized multiplication libraries can determine the fastest method, but they do not invalidate the mathematical bound.

Strassen Multiplication: Comparing Toll and Leaves

The idealized Strassen matrix multiplication recurrence is T(n)=7T(n/2)+Θ(n²), where each recursive multiplication handles submatrices with half the side length and auxiliary matrix additions use quadratic arithmetic work. The critical exponent is p=log₂7≈2.807; since 2<p by a polynomial gap, Case 1 yields Θ(n^(log₂7)).

The result is not Θ(n² log n) simply because each level performs some matrix addition. There are seven descendants per node, and their combined work increases toward the leaves more rapidly than the size reduction diminishes the local toll.

Memory traffic, numerical stability, matrix shape, allocation policy, and crossover thresholds are separate engineering considerations. A proof of arithmetic-operation complexity does not automatically imply that the implementation is fastest or best for every matrix size.

Exponentiation by Squaring: Branch Count Matters

Exponentiation by squaring can compute x^n with one recursive call on approximately n/2 and a constant number of extra multiplications. When a multiplication is charged as a constant-cost operation, its recurrence is T(n)=T(⌊n/2⌋)+Θ(1)=Θ(log n). A mistaken implementation that recomputes the half-power twice can instead obey T(n)=2T(⌊n/2⌋)+Θ(1)=Θ(n) under the same arithmetic-cost model.

Both programs may produce exactly the same mathematical answer. The difference arises entirely from how many recursive calls are made. Store the half-power once and square it, rather than invoking the same costly recursive function twice.

When results have unbounded bit length, the multiplication itself grows more expensive as n increases. The number of multiplications is still logarithmic, but bit-operation complexity requires the multiplication algorithm and operand sizes to be included.

def power_efficient(x, n, counter):
    assert n>=0
    counter[0]+=1
    if n==0: return 1
    half=power_efficient(x,n//2,counter)
    return half*half*(x if n%2 else 1)

def power_redundant(x,n,counter):
    assert n>=0
    counter[0]+=1
    if n==0: return 1
    left=power_redundant(x,n//2,counter)
    right=power_redundant(x,n//2,counter)
    return left*right*(x if n%2 else 1)

Integer Rounding and Uneven Terminal Levels

Real algorithms rarely receive only powers of two. A merge sort may invoke subproblems of sizes ⌊n/2⌋ and ⌈n/2⌉, which are not identical except for even n. With appropriate monotonicity and bounded-toll assumptions, comparing such a tree to nearby power-of-two instances often preserves the same Θ(n log n) conclusion.

A responsible proof can use upper and lower recurrences, or show that levels still contain total size n until the final few uneven levels. It should not replace all child sizes with n/2 as an exact identity for odd n. Rounding can matter greatly if a recursive size fails to decrease, if the algorithm keeps a large odd remainder, or if padding performs extra work.

One approach to a monotone cost function is to bracket n between consecutive powers of b, but that argument needs both monotonicity and sufficiently regular growth. Where those properties are missing, solve the actual floor/ceiling recurrence rather than assuming a familiar answer.

Quicksort: A Recursion Tree That Changes Shape

Quicksort partitions around a pivot. If the pivot ends in position k, the recursive work is on sizes k and n−k−1, giving the shape-dependent recurrence T(n)=T(k)+T(n−k−1)+Θ(n) for a standard linear partition implementation. Balanced partitions produce approximately 2T(n/2)+Θ(n)=Θ(n log n) work; repeatedly selecting an extreme pivot produces T(n−1)+Θ(n)=Θ(n²).

Because the split sizes depend on the input or randomized pivot choices, this is not a single fixed aT(n/b) equation covering all executions. Expected comparison analysis can instead average over pivot ranks, yielding a sum over subproblem sizes. The Master Theorem cannot be applied to that expectation without first deriving and justifying a different recurrence with the required form.

Tree shape explains why pivot selection, duplicated keys, and partition strategy matter. Three-way partitioning may avoid pathological behavior on many equal keys, but correctness and performance still depend on its concrete implementation.

Unequal Fixed Fractions and Akra–Bazzi

Consider T(n)=T(n/3)+T(2n/3)+Θ(n). The two descendants have different sizes, so the simple equal-size Master Theorem is not an exact fit. A recursion-tree argument observes that the sum of subproblem sizes at each complete level is n, while the tree height is Θ(log n) for these fixed fractions. With proper handling of uneven bottom levels, the total is Θ(n log n).

General recurrences of the form T(x)=Σᵢ aᵢ T(bᵢx+hᵢ(x))+g(x) can in some settings be analyzed using the Akra–Bazzi theorem. Its characteristic exponent p solves Σᵢ aᵢ bᵢ^p=1; the resulting bound involves an integral containing g(u)/u^(p+1). The precise regularity and perturbation conditions matter and are not reproduced by simply replacing different fractions with their average.

For the recurrence above, (1/3)^1+(2/3)^1=1 gives p=1, and a linear toll leads to a logarithmic multiplier. The example is a bridge between recursion-tree reasoning and generalized theorems, not permission to invoke an unnamed extension without verifying its conditions.

Subtract-One Recursion Is Not Divide-and-Conquer

The recurrence T(n)=T(n−1)+n does not have a fixed fractional shrinkage n/b. Its tree is a chain of lengths n,n−1,...,1, and summation gives T(n)=Θ(1+2+⋯+n)=Θ(n²). By contrast, T(n)=T(n/2)+n has a geometrically decreasing chain and yields Θ(n).

Both recurrences contain one recursive call and a linear toll. The difference lies in the shrinkage rate. A branching factor alone does not determine complexity; the trajectory of subproblem sizes is equally important.

For T(n)=T(n−1)+Θ(1), the result is Θ(n), while for T(n)=T(n−1)+Θ(n²), the sum of squares yields Θ(n³). These are ordinary summation problems, not cases of the basic Master Theorem.

Changing Variables for Nonstandard Reductions

Some recurrences look unlike the Master form because the natural size parameter changes nonlinearly. Consider T(n)=T(√n)+Θ(1) for n>2. Repeated square roots reduce log n by half each step. With m=log₂n and S(m)=T(2^m), the recurrence becomes S(m)=S(m/2)+Θ(1), giving S(m)=Θ(log m) and therefore T(n)=Θ(log log n).

If an algorithm repeatedly replaces an input value N with its square root, the number of steps is doubly logarithmic in N, but that does not automatically mean the algorithm is doubly logarithmic in the number of input bits. The encoding and cost of finding a square root must also be specified.

A valid change of variables should be explicitly reversible, preserve the relevant domain, and transform both recursive arguments and tolls. Guessing an exponent without transforming the recurrence can create a correct-looking answer for the wrong reason.

Variable Branching Factors and Recursion Fanout

The recurrence T(n)=nT(n/2)+1 has a branching factor that changes with n, so the standard Master Theorem does not apply. At the root it creates n children; deeper levels have smaller but still size-dependent fanout. A useful analysis must multiply the fanouts along a path and consider where the recursion stops, rather than substituting a=n into a formula that requires constant a.

Similarly, a backtracking algorithm may have up to n choices at the root, then n−1 at the next level, producing factorially many paths. The structure may be more naturally analyzed using products, combinations, state pruning, and distinct reachable configurations than by an equal-size divide-and-conquer recurrence.

Fixed-branching recursion trees are one important family, not a universal picture of every recursive algorithm.

Oscillating or Irregular Toll Functions

Case 3’s regularity requirement guards against unexpectedly expensive lower levels. A toll can be nonnegative and asymptotically large while fluctuating so sharply between input scales that a f(n/b) is not bounded by any fixed fraction of f(n). On such inputs, a root-dominance argument can fail even though the toll appears large on many sizes.

For example, choose an irregular function that alternates between a large power and a much smaller positive value on successive powers of two. If f(2^k) is large for even k but tiny for odd k, some parent levels may be much cheaper than their descendants. One cannot assume a decreasing geometric series from a graph that oscillates.

Such examples are less common in ordinary programs than polynomial or polylogarithmic tolls, but they clarify the theorem’s logic. To apply Case 3, establish the contraction inequality on the actual domain, not only an average trend.

Recursion Trees Versus Runtime Call Stacks

A recursion tree counts the total sequence of calls that would be made by a recursive algorithm. A call stack records only the active chain waiting for returns at one moment. If 2T(n/2)+Θ(n) describes a depth-first implementation, the tree has Θ(n) leaves and Θ(n) total nodes, while maximum call depth is only Θ(log n).

Time complexity and stack space therefore answer different questions. A balanced binary recursion can do Θ(n log n) time and require only Θ(log n) activation records, excluding extra arrays or output storage. A deeply unbalanced recursion may have Θ(n) active frames even if the tree contains only Θ(n) total calls.

When a recursive function allocates an auxiliary array that remains live while descendants run, peak memory may exceed stack-frame space. Analyze allocations and lifetimes explicitly rather than inferring memory directly from tree width.

Time, Auxiliary Space, and Peak Live Allocation

For a recursive algorithm, define W(n) as total work, D(n) as maximum stack depth, and S(n) as additional simultaneously live memory. These can satisfy different recurrences. A divide-and-conquer routine might have W(n)=2W(n/2)+Θ(n) but D(n)=D(n/2)+1. It is incorrect to apply the work recurrence mechanically to stack depth, because only one branch’s frames may be live at a time.

Peak allocation depends on execution order. If a fresh buffer of size Θ(n) is held during one recursive descent, a space recurrence S(n)=S(n/2)+Θ(n) yields Θ(n) additional live storage for that path. If child calls return and release their buffers before the next call begins, the total memory need not be the sum of both children’s peaks.

Always distinguish cumulative allocation from peak residency. An algorithm may allocate Θ(n log n) bytes over its entire execution and still have only Θ(n) bytes live simultaneously.

Parallel Work and Span from the Same Tree

When independent child calls execute in parallel, work counts all modeled operations and span (critical-path length) counts the longest dependency chain. For a balanced two-branch recurrence with a sequential combine step of cost Θ(n), work may satisfy W(n)=2W(n/2)+Θ(n)=Θ(n log n), while span satisfies S(n)=S(n/2)+Θ(n)=Θ(n).

If the combine operation can itself be parallelized, its span changes and the total span recurrence must reflect the parallel algorithm actually used. The recursion tree alone does not guarantee speedup: task spawning, synchronization, data movement, and finite processor counts impose additional costs.

A useful upper bound on parallel speedup is constrained by the ratio W(n)/S(n), sometimes called available parallelism. This value is a property of the algorithm’s work-dependency structure; it is not a direct measurement of how fast a particular multicore machine will run the code.

A Complete Instrumented Recursion-Tree Example

Instrumenting a recurrence can support intuition when done carefully. The following pure counting routine does one modeled unit of toll per element at each internal node, calls two half-sized descendants, and counts the constant-cost leaves. It avoids building temporary arrays; its purpose is to reproduce a chosen recurrence, not to benchmark a real merge sort.

For n=2^h, the predicted count is n h+n if the internal toll is exactly n and each leaf costs one. This provides a concrete correctness target for the instrumentation and makes the level accounting visible.

Execution for small inputs can corroborate the formula, but finite tests do not by themselves prove the Θ(n log n) result. The proof comes from the complete symbolic tree.

def counted_balanced_work(n):
    assert n>=1 and n & (n-1)==0
    if n==1: return 1
    return n + counted_balanced_work(n//2) + counted_balanced_work(n//2)

for h in range(1,9):
    n=2**h
    assert counted_balanced_work(n)==n*h+n
print('Observed exact counts match n log2(n)+n')

Generate and Check the Level-Cost Series

Explicit level calculations are often the simplest way to check a proposed asymptotic pattern. The code below computes theoretical level tolls for a synthetic recurrence with polynomial toll f(n)=n^q, assuming powers of b. It reports internal levels only, then separately counts leaves. The values are an algebraic model, not an execution profile.

For a=2, b=2, and q=1, the toll should stay constant at n. For q=2, the toll should halve each level; for q=0, it should double. Testing those ratios is a useful diagnostic for the chosen formula.

When numeric sizes become large, floating-point overflow and rounding can obscure comparisons. Exact symbolic reasoning is preferred for formal asymptotic claims.

def polynomial_level_tolls(n,a,b,q):
    assert n>=1 and a>=1 and b>=2 and q>=0
    out=[];nodes=1;size=n
    while size>1:
        out.append(nodes*(size**q))
        nodes*=a
        size//=b
    return out,nodes

assert polynomial_level_tolls(16,2,2,1)==([16,16,16,16],16)
assert polynomial_level_tolls(16,2,2,2)==([256,128,64,32],16)
assert polynomial_level_tolls(16,2,2,0)==([1,2,4,8],16)
print('Balanced, root-dominated, and leaf-dominated patterns confirmed')

Substitution Proof After the Tree Suggests a Bound

A recursion tree frequently suggests a tight asymptotic result; mathematical induction can verify it. For example, to show T(n)=O(n log₂n) for T(n)=2T(n/2)+cn, suppose for smaller powers of two that T(m)≤C m log₂m for a sufficiently large positive C. Then T(n)≤2C(n/2)log₂(n/2)+cn=Cn(log₂n−1)+cn≤Cn log₂n if C≥c.

The induction has to handle its base case; n log₂n vanishes at n=1. One can start the bound at n≥2, adjust the proposed expression to Cn(1+log₂n), or treat the terminal cost separately. A lower bound follows by charging positive linear work on each internal level under the assumed model.

For more complicated recurrences, adding a lower-order term to an inductive hypothesis can provide the slack needed to absorb tolls. If the algebra fails at the last step, the attempted bound has not been proved regardless of how convincing the tree sketch appears.

Testing the Claimed Asymptotic Bound

One useful classroom experiment is to compare exact model counts with a predicted growth function at increasing powers of two. If T(n)=Θ(g(n)), ratios such as T(n)/g(n) should eventually remain within positive constant bounds, although finite samples cannot prove that they always will. Exact operation counts are more reproducible than wall-clock timings for this purpose.

In practical benchmarking, compiler optimization, runtime warm-up, allocation, caching, input distributions, and timer resolution can dominate small inputs. A recursion-tree proof describes an abstract cost model; a benchmark observes a specific implementation and machine. Both are valuable, but they answer distinct questions.

Use instrumentation to detect missing terms. For example, if a recurrence predicts linear merge cost but a Python implementation repeatedly slices arrays and copies data, record allocation and copying counts as well as comparisons. An apparent contradiction may reveal that the selected cost model omitted actual work.

Worked Investigation 1: Why Two Leaves Are Not Two Calls

An algorithm chooses either the left or the right half of a sorted array after one comparison. One might be tempted to draw two branches because two candidate halves exist, but only one branch is executed on each call. The correct recurrence for comparisons is T(n)=T(⌊n/2⌋)+Θ(1), not 2T(n/2)+Θ(1).

Applying Case 2 with a=1, b=2, and p=0 gives Θ(log n) comparisons in the worst case. A tree containing two children would analyze an exhaustive search of both halves, which is a different algorithm.

Transfer lesson: derive tree edges from actual recursive calls. An algorithm’s possible choices are not the same as its complete set of executed descendants.

Worked Investigation 2: A Quadratic Toll Changes the Answer

A divide-and-conquer program makes two half-size calls and then performs a nested pairwise comparison over all n elements, costing Θ(n²) outside recursion. The recurrence is T(n)=2T(n/2)+Θ(n²).

Since p=1 and f(n)=Θ(n²), Case 3 applies with regularity ratio 1/2. The correct bound is Θ(n²). Claiming Θ(n log n) because the program divides into halves would ignore the expensive combine operation.

Transfer lesson: distinguish decomposition pattern from the toll. A favorable recursion depth does not compensate for a large amount of local work unless the level sum shows it.

Worked Investigation 3: A Missing Polynomial Gap

An analyst is given T(n)=2T(n/2)+n/log₂n and proposes Case 1 because the toll is smaller than n. The claim is invalid: n/log n is not O(n^(1−ε)) for any constant positive ε.

The level sum is harmonic and leads to Θ(n log log n) as shown above. By changing the denominator to (log n)², the same recurrence instead yields Θ(n). Neither result follows from a nearest-case guess.

Transfer lesson: compare growth using the exact quantifiers in the theorem, not just a visual ranking of functions.

Worked Investigation 4: Unequal Recursion and Wrong Theorem

A data-partitioning routine splits the input into one-third and two-thirds portions, then scans all n elements before returning. Its recurrence is T(n)=T(n/3)+T(2n/3)+Θ(n). Because the child sizes differ, do not substitute a=2 and b=2 directly into the basic Master Theorem.

A balanced-size conservation argument, with properly bounded height and terminal contributions, gives Θ(n log n). Alternatively one may use an appropriate generalized recurrence theorem with its full preconditions.

Transfer lesson: a correct final answer does not validate an incorrect intermediate theorem application. State a proof method matching the actual recurrence.

Worked Investigation 5: Memory Bound Is Not Work Bound

A standard recursive merge-sort analysis gives Θ(n log n) operations, but a version that reuses a single auxiliary buffer of size n may require only Θ(n) extra array space and Θ(log n) activation records. Another implementation using fresh slices or retaining all intermediate arrays can have different allocation characteristics.

If an engineer concludes that peak memory must be Θ(n log n) because the work recurrence has that solution, the accounting mixes incompatible resources. Model the maximum simultaneously retained storage according to the actual lifetime of buffers.

Transfer lesson: derive one recurrence for each resource that matters: total operations, stack depth, peak live storage, and, if relevant, traffic between memory levels.

Worked Investigation 6: Parallel Branches and Sequential Combine

Imagine a divide-and-conquer procedure that recursively solves both halves in parallel but performs a linear sequential merge after they finish. Its work recurrence is W(n)=2W(n/2)+Θ(n)=Θ(n log n); its span recurrence is S(n)=S(n/2)+Θ(n)=Θ(n).

A tempting but false analysis might write S(n)=2S(n/2)+Θ(n), which sums both child spans even though those children are intended to run concurrently. Another false analysis might claim Θ(log n) span by counting only the recursion depth and ignoring the linear merge along the critical path.

Transfer lesson: a tree can support different cost measures, but each measure requires the appropriate combination rule.

Numerical Check: Harmonic Versus Convergent Level Sums

Two recurrences at the critical polynomial exponent can have very different logarithmic outcomes. For 2T(n/2)+n/log₂n, each level contributes n/k after reindexing, and the multiplier Σ1/k grows without bound. For 2T(n/2)+n/(log₂n)², the multiplier Σ1/k² converges. The numerical experiment below compares the two finite multipliers as tree height increases.

Neither set of figures proves the asymptotic bound. The harmonic-series theorem and the comparison test do that. The purpose of the experiment is to reveal the distinct trend in a form readers can reproduce and connect to the level cost expression.

The code deliberately operates on h=log₂n rather than generating a massive recursion tree. Analytical formulas are usually more economical than constructing all nodes merely to count work.

def critical_level_multiplier(height, power):
    assert height>=1
    return sum(1/(k**power) for k in range(1,height+1))

for h in (4,8,16,32,64,128):
    slow=critical_level_multiplier(h,1)
    bounded=critical_level_multiplier(h,2)
    assert slow>=bounded
    assert bounded<2
    print(h,round(slow,3),round(bounded,3))

Numerical Check: Quicksort Partition Shapes

Two implementations can share the same partitioning cost model and have radically different trees. In a simple comparison-counting model where a partition of size n costs n−1 comparisons, a repeatedly extreme pivot gives C(n)=C(n−1)+(n−1)=n(n−1)/2. A perfectly balanced pivot instead produces two nearly equal descendants and the familiar Θ(n log n) total.

The code below counts comparisons in idealized partition shapes; it does not manipulate array elements, benchmark a complete quicksort, or claim that the pivot can always be chosen at zero cost. The comparison illustrates how the recurrence tree depends on partition quality.

Uniform random pivot selection leads to a separate expected-comparison calculation and does not guarantee balanced splits in each individual run.

def skewed_quicksort_comparisons(n):
    if n<=1: return 0
    return (n-1)+skewed_quicksort_comparisons(n-1)

def balanced_quicksort_comparisons(n):
    if n<=1: return 0
    left=(n-1)//2
    right=n-1-left
    return n-1+balanced_quicksort_comparisons(left)+balanced_quicksort_comparisons(right)

for n in (7,15,31,63):
    skew=skewed_quicksort_comparisons(n)
    balanced=balanced_quicksort_comparisons(n)
    assert skew==n*(n-1)//2
    assert balanced<skew
    print(n,balanced,skew)

Numerical Check: Regularity Ratios for Polynomial Tolls

For f(n)=n^q, the case-three contraction ratio is R=a f(n/b)/f(n)=a/b^q. This is independent of n, which makes the regularity check particularly transparent. With a=2 and b=2, a quadratic toll has ratio 1/2; a linear toll has ratio 1; a constant toll has ratio 2.

Only the quadratic toll is root-dominated among these three under this branching pattern. The linear toll is the equal-level boundary, while constant toll is leaf-dominated. The code checks those particular ratios, but the proof that Case 3 applies must still state its other conditions, including the polynomial gap.

This illustrates why regularity is a quantitative requirement rather than the informal observation that f “gets bigger.”

def polynomial_child_ratio(a,b,q):
    assert a>=1 and b>1
    return a/(b**q)

assert polynomial_child_ratio(2,2,2)==0.5
assert polynomial_child_ratio(2,2,1)==1.0
assert polynomial_child_ratio(2,2,0)==2.0
assert polynomial_child_ratio(3,2,2)==0.75
print('Ratios reflect child-level contractions or expansions')

Numerical Check: Work and Call Depth Are Different

Consider a full binary recursion with a linear toll at each nonterminal node. Define the work as the sum of all local operations, but define call depth as the maximum number of nested invocations. Under a depth-first implementation these measures combine child results differently: work adds the two subtrees, whereas depth takes the maximum child depth and adds one.

The following routine returns both metrics as a pair, making the difference explicit. For power-of-two sizes, the work is n log₂n+n in this synthetic model, while the maximum depth is log₂n+1. Neither value automatically gives auxiliary heap-space usage or the cost of allocating output arrays.

In parallel algorithms the same distinction motivates separate recurrences for work and span.

def work_and_depth(n):
    assert n>=1 and n & (n-1)==0
    if n==1: return 1,1
    lw,ld=work_and_depth(n//2)
    rw,rd=work_and_depth(n//2)
    return n+lw+rw,1+max(ld,rd)

for h in range(1,8):
    n=2**h
    work,depth=work_and_depth(n)
    assert work==n*h+n
    assert depth==h+1
print('Work and depth grow at different rates')

Numerical Check: Fixed Unequal Fractions

The recurrence T(n)=T(⌊n/3⌋)+T(n−⌊n/3⌋)+n for sufficiently large n has two unequal children whose sizes sum to n. Both shrink by a constant factor asymptotically, but the exact tree is not the balanced equal-size Master form. A level-by-level argument or a generalized recurrence theorem establishes Θ(n log n) total work.

This simulation uses a constant-cost leaf and exact integer child sizes. The observed counts are compatible with the theoretical scale but do not replace a proof, especially at small inputs where rounding matters. Readers should compare it with the earlier equal-size examples and note the different depths along distinct branches.

The example illustrates a useful boundary: a recurrence can have a familiar final asymptotic result without satisfying the hypotheses of the standard three-case theorem.

import math

def unequal_split_work(n):
    assert n>=1
    if n==1: return 1
    left=max(1,n//3)
    right=n-left
    return n+unequal_split_work(left)+unequal_split_work(right)

for n in (9,27,81,243):
    work=unequal_split_work(n)
    assert n<=work<=n*(1+math.ceil(math.log(n,1.5)))
    print(n,work)

  1. What does one node in a recursion tree represent? A particular subproblem invocation, labeled with its input size and the work done locally outside descendant calls.
  2. What is the level-j toll for T(n)=aT(n/b)+f(n)? Under equal-size fixed branching, a^j f(n/b^j).
  3. Why is the number of leaves n^(log_b a)? The height is log_b n and each level multiplies the node count by a, so a^(log_b n)=n^(log_b a).
  4. Which term must be included besides the sum of internal tolls? The total cost of terminal leaves, Θ(n^(log_b a)) for constant-cost leaves.
  5. What causes a root-dominated tree with f(n)=Θ(n^q)? The ratio a/b^q is below one; level work decreases geometrically.
  6. What causes a leaf-dominated tree with f(n)=Θ(n^q)? The ratio a/b^q exceeds one; level work grows toward the leaves.
  7. What is the standard Case 1 conclusion? When f(n)=O(n^(p−ε)) for some ε>0, T(n)=Θ(n^p), with p=log_b a.
  8. What is the standard Case 2 conclusion? When f(n)=Θ(n^p), T(n)=Θ(n^p log n).
  9. What extra condition accompanies standard Case 3? Eventually a f(n/b)≤c f(n) for a fixed c<1, in addition to a polynomial gap above n^p.
  10. Solve T(n)=2T(n/2)+n. p=1 and f(n)=Θ(n), giving Θ(n log n).
  11. Solve T(n)=4T(n/2)+n. p=2 and f(n) is polynomially smaller, giving Θ(n²).
  12. Solve T(n)=2T(n/2)+n². p=1, regularity ratio 1/2, giving Θ(n²).
  13. Solve T(n)=T(n/2)+1. p=0, standard Case 2, giving Θ(log n).
  14. Why not use Case 1 for f(n)=n/log n when p=1? The toll lacks a fixed polynomial gap below n; n/log n is not O(n^(1−ε)) for any ε>0.
  15. Solve T(n)=2T(n/2)+n/log₂n for powers of two. The level sum is n times the harmonic series, giving Θ(n log log n).
  16. Solve T(n)=2T(n/2)+n/(log₂n)². The level sum uses a convergent inverse-square series, giving Θ(n).
  17. Solve T(n)=2T(n/2)+n log n. Extended Case 2 or an arithmetic level sum gives Θ(n log²n).
  18. Why is worst-case quicksort not an equal-size Master recurrence? Its partition sizes vary with pivot positions and may become n−1 and zero.
  19. What theorem can help with fixed but unequal subproblem fractions? The Akra–Bazzi theorem under its required technical hypotheses; tree arguments may also work.
  20. What is the cost of T(n)=T(n−1)+n? A sum of n+(n−1)+⋯+1 gives Θ(n²).
  21. Why does T(n)=T(√n)+1 have Θ(log log n) calls? Under m=log n, the recurrence becomes S(m)=S(m/2)+1.
  22. Why does recursion-tree width not equal stack usage? A depth-first execution retains a chain of active calls, not every node in the full expansion tree.
  23. How does work differ from span? Work sums operations over all branches; span counts the longest dependency chain under parallel execution.
  24. How should a numerical comparison validate an asymptotic claim? Use exact operation counts to check predicted patterns, but retain a symbolic proof for the asymptotic guarantee.
