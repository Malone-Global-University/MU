Division Overview and Taxonomy

Networking Systems is a division of the MGU Computer Science Encyclopedia. It covers how hosts identify and reach one another, how networks carry traffic, and how connected services are designed, operated, and evaluated.

A summary article introduces a subject at the division level. Its companion unit directory connects that summary to specialist articles. Standalone specialists can be read directly or in the context of their owning unit. The directory below identifies existing entry points and the planned home for each unit.

Networking Foundations and Protocols

Computer Networking

Network design concepts, scope, physical and logical topology, and communication between hosts. Start here to separate reachability, capacity, service availability, and application behavior.

Specialist coverage priorities. Ethernet and local-area networks; campus and WAN design; network performance measurement.

Network Protocols

Layered communication rules, message formats, interoperability, and the Internet protocol suite. Use this unit to trace encapsulation and separate delivery, transport, and application semantics.

Specialist coverage priorities. IPv4 and IPv6 addressing and subnetting; TCP and UDP; QUIC; ICMP and neighbor discovery.

Forwarding, Routing, and Internet Infrastructure

Routing and Switching

Forwarding across switched and routed networks, segmentation, path selection, and convergence. Use this unit when investigating a path across VLANs, routing domains, or policy boundaries.

Specialist coverage priorities. Ethernet switching and MAC learning; VLANs and trunks; loop prevention; inter-VLAN routing; routing convergence.

Routers

Router platforms, interfaces, forwarding engines, route installation, and operational diagnostics. Use this unit to understand how routing policy becomes installed forwarding state on a device.

Specialist coverage priorities. Router architecture and forwarding engines; interfaces and adjacencies; RIB and FIB; longest prefix match; route redistribution and router operations.

The router unit owns platform implementation and diagnostics. Routing and Switching owns network-wide packet paths and policy. Treat BGP peering policy in Internet Infrastructure and router-specific BGP deployment here.

Internet Infrastructure

Autonomous networks, interconnection, Internet exchange points, naming, and global service delivery. Use this unit when a service depends on multiple operators, public resolution, or regional delivery.

Specialist coverage priorities. Autonomous systems, transit and peering; Internet exchange points; backbone and submarine networks; CDNs and anycast.

Wireless, Distributed, and Private Connectivity

Wireless Communication

Radio propagation, modulation, spectrum, antennas, and network access over shared media. Use this unit to separate radio coverage, airtime contention, roaming, and upstream congestion.

Specialist coverage priorities. Wi-Fi architecture and roaming; cellular access; wireless site surveys and spectrum planning.

Wireless Communication owns the radio and link fundamentals. Wireless Networks specializes in WLAN and other access architectures, operational behavior, and performance.

Distributed Networking

Peer discovery, overlays, federation, decentralized topology, and network resilience under churn. Use this unit when network participation and peer reachability drive the design.

Specialist coverage priorities. Overlay routing; peer discovery and bootstrap; federated network architecture; peer reachability and churn.

Virtual Private Networks

Protected connectivity, tunnels, remote and site-to-site access, and operational failure modes. Use this unit to examine route selection, identity, tunnel boundaries, and encapsulation overhead.

Specialist coverage priorities. Remote access and site-to-site design; IPsec and WireGuard concepts; tunnel routing and MTU diagnostics.

Cloud Platforms and Services

Cloud Computing

Cloud service models and the compute, networking, storage, and operations systems behind them. Use this unit when resource placement, managed-service boundaries, or cloud connectivity shape design.

Specialist coverage priorities. Use the existing unit index to prioritize coverage gaps after the division-wide directory pass.

The Cloud Computing unit directory is available now. Start with service models, then choose infrastructure, application design, operations, or migration.

Illustrative Networking Scenarios

An office can reach local devices but a shared service is unreachable

Use Routing and Switching to follow the path across VLANs. Compare endpoint addressing and gateway selection, then check whether forwarding and return routes exist. The result narrows the fault to a host, a segment boundary, or the service path.

Some users see the old service after a migration

Use Internet Infrastructure and DNS to inspect the record returned by authoritative servers and compare it with recursive answers and remaining cache lifetimes. Test the old and new service addresses separately to distinguish name-resolution delay from service reachability.

Wireless calls break up during a shift change

Use Wireless Communication and Wireless Networks to compare airtime use, retransmissions, and roam timing with wired-side latency. Capacity and contention can deteriorate even when clients still show a strong signal.

A VPN carries small requests but stalls on large transfers

Use Virtual Private Networks and Network Protocols to compare effective tunnel MTU, packet sizes, and path-MTU behavior. Confirm whether the failing transfer exceeds the effective path before changing tunnel or host settings.

A peer network loses reachability during participant turnover

Use Distributed Networking to measure bootstrap success and overlay connectivity during churn. Check whether peers depend on the same rendezvous point or whether alternate paths can sustain the expected participation level.

A cloud application becomes slow for one region

Use Cloud Computing and Internet Infrastructure to separate DNS and edge latency from inter-region service calls. Compare regional measurements with traces across the application dependency path before changing resource placement.

Network Design and Evaluation Framework

  1. Identify endpoints, service dependencies, traffic flows, and participating administrative domains.
  2. Map physical and logical topology, trust boundaries, overlays, and return paths.
  3. Specify delivery and performance targets, including latency, loss, availability, and recovery.
  4. Choose protocols and connectivity models against interoperability and operational requirements.
  5. Record the evidence needed at each layer and collect a baseline under typical load.
  6. Test representative failures, including a lost path, failed dependency, or location outage.
  7. Compare operational complexity and lifecycle costs before choosing a deployment design.
  8. Assign ownership for monitoring, incident response, changes, and periodic verification.
