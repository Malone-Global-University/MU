Collection Overview

The Computer Networking unit belongs to the Networking Systems division of the Computer Science volume of the MGU Encyclopedia. It supplements the Computer Networking parent overview, which introduces communication over networks, common devices and links, network scales, performance, reliability, and the contemporary role of connected computing.

A computer network is a system of hosts, communication media, forwarding devices, addressing and naming functions, and operating policies that together permit digital information exchange. A single successful connection does not establish that the full path, application service, or security policy is working. Conversely, one failed application does not prove that the underlying link or internet connection is down. Networking analysis therefore moves from the observed symptom to the specific boundary and evidence relevant to it.

This Level 4 unit index defines 20 planned Level 5 specialist subarticles in four instructional groups. Their filenames are a newly established editorial plan: the existing parent overview did not prescribe child slugs, and the prior local file tree explicitly reserved this Unit for later planning. The articles below provide broad foundational knowledge without duplicating advanced specialist coverage of Network Protocols, TCP/IP Protocol Suite, Routing and Switching, Domain Name System, or Wireless Networks.

Publication distinction: Every specialist article link below is intentionally active as an authoritative planned destination. This does not mean that a linked HTML file has already been authored or published. This deliverable creates the directory index and establishes its 20-item production plan, not the 20 child articles.

Networking Foundations and Packet Communication

The networking foundations and packet communication group contains 5 complementary specialist treatments. Readers should distinguish a component, its configured state, its observed behavior, and the operational boundary responsible for it; the deeper sibling Units remain authoritative for narrowly specialized protocols.

1. Network Endpoints and Interface Roles

Primary scope: An endpoint is any network-attached participant that generates, receives, or processes traffic. This article distinguishes host interfaces, virtual interfaces, device identifiers, hardware addresses, IP addresses, and service endpoints without treating each identifier as interchangeable. It explains how a laptop, printer, virtual machine, phone, and server participate in networks at different boundaries.

Practical emphasis: Identify the physical or virtual interface involved in a communication problem; determine whether the failure concerns link attachment, host configuration, address assignment, or a specific application. The specialist discussion also covers multi-homed hosts, interface selection, loopback, and the meaning of a directly attached network.

Illustrative investigation: An instructor traces a student laptop connecting to an internal file share and identifies its Wi-Fi adapter, assigned IP address, default gateway, and application endpoint.

Planned file: network-endpoints-and-interface-roles.html. This article addresses the distinct foundational scope above rather than replacing the specialist Units that treat related protocol or architectural details.

2. Network Links, Media, and Transceivers

Primary scope: This article introduces the way adjacent devices exchange signals using copper, fiber, or radio. It distinguishes link rate from useful application throughput, presents common cable and optic characteristics, and explains why attenuation, interference, connector damage, duplex mismatch, or signal quality can impair transmission.

Practical emphasis: Use link LEDs, interface status, media specifications, negotiated speed, error counters, and measured loss to investigate physical-layer symptoms. The treatment stays focused on network links; detailed antenna systems and wireless modulation remain under Wireless Communication.

Illustrative investigation: A laboratory switch shows an active port, yet a damaged copper run causes high frame-error counts and unstable throughput.

Planned file: network-links-media-and-transceivers.html. This article addresses the distinct foundational scope above rather than replacing the specialist Units that treat related protocol or architectural details.

3. Network Data Units and Encapsulation

Primary scope: This article traces a message as it is represented at successive boundaries: application data, transport-layer segments or datagrams, network-layer packets, and link-layer frames. It distinguishes encapsulation from encryption and explains why each layer may add addressing, control information, or integrity checks.

Practical emphasis: Learn to interpret frame headers, IP packets, TCP segments, and UDP datagrams in packet-capture summaries; calculate overhead conceptually without assuming a fixed number of bytes for every protocol. The child article introduces MTU, fragmentation concerns, and reassembly as topics for deeper treatment in the TCP/IP Protocol Suite unit.

Illustrative investigation: A 1,500-byte Ethernet MTU does not imply that a single TCP segment can carry 1,500 bytes of application data.

Planned file: network-data-units-and-encapsulation.html. This article addresses the distinct foundational scope above rather than replacing the specialist Units that treat related protocol or architectural details.

4. Network Layering and OSI–TCP/IP Models

Primary scope: This article compares the OSI reference model and the practical Internet protocol architecture. It shows how physical and data-link functions differ from IP forwarding, transport exchange, and application protocols while acknowledging that implementations often blur boundaries.

Practical emphasis: Apply a layering model to classify evidence from a failed application exchange. Explain that a device can perform functions at several layers; a wireless access point, router, firewall, and load balancer are distinguished by what they do rather than by a single permanent layer label.

Illustrative investigation: A web page fails after DNS succeeds: the investigator must distinguish transport connectivity from a TLS or HTTP error rather than declaring a generic network outage.

Planned file: network-layering-and-osi-tcp-ip-models.html. This article addresses the distinct foundational scope above rather than replacing the specialist Units that treat related protocol or architectural details.

5. Network Identifiers and Addressing Fundamentals

Primary scope: This article identifies common types of network names and addresses and their scopes. It compares interface identifiers, link-layer addresses, IP addresses, subnet prefixes, transport ports, and human-readable domain names while highlighting the role of routing domains and local-link reachability.

Practical emphasis: Introduce IPv4 and IPv6 address notation, private versus public reachability, and the idea of an address prefix. Detailed allocation, protocol packet structure, routing policy, and DNS delegation are handled by the corresponding specialist sibling units.

Illustrative investigation: A printer is reachable by IP but not by name: link and IP connectivity may be healthy while name resolution is impaired.

Planned file: network-identifiers-and-addressing-fundamentals.html. This article addresses the distinct foundational scope above rather than replacing the specialist Units that treat related protocol or architectural details.

Worked Networking Scenarios

The following are constructed learning cases, not observations of Malone Global University infrastructure. Each illustrates the difference between a symptom, the evidence available, and a reasoned next check.

Scenario 1 — A newly installed workstation cannot access the learning portal

A desktop appears physically connected but cannot open the internal portal. The first checks are interface status and the actual host configuration: assigned addresses, prefix, default route, and DNS server. If the link is active and a local gateway responds, investigate name resolution and then transport or application errors. Do not interpret a single successful ICMP test as proof of web-service health.

Related specialists: Network Endpoints and Interface Roles, Host Network Configuration and DHCP, Name Resolution and Connectivity Basics, Network Troubleshooting from Link to Service.

Scenario 2 — A campus adds hundreds of student devices for an examination

The network team must estimate concurrent users, required application throughput, RF coverage, access point capacity, DHCP scope size, uplink capacity, authentication demand, and support staffing. Rather than assuming a faster internet circuit alone solves the problem, designers document the entire service path and conduct tests at representative peak demand.

Related specialists: Wired and Wireless Network Access Methods, Network Performance Metrics and Measurement, Network Design Requirements and Capacity Planning, Network Monitoring, Baselines, and Alerts.

Scenario 3 — A real-time lecture suffers delay despite a fast speed test

An instructor experiences unstable audio during cloud uploads. The useful measures are variation in latency, packet loss, queue occupancy, and path congestion under the same simultaneous workload. A nominal high link rate does not exclude bufferbloat or contention; traffic priority can adjust scheduling but cannot manufacture additional capacity.

Related specialists: Network Performance Metrics and Measurement, Network Queues, Congestion, and Traffic Priority, Network Monitoring, Baselines, and Alerts, Network Operations, Change, and Security Hygiene.

Scenario 4 — A remote building loses access after a fiber cut

A building connects through two circuits but both share one conduit. An excavation disables both, revealing correlated failure. Resilience planning must document physical diversity, alternative routing, power, DNS dependency, gateway behavior, application access, and realistic failover testing rather than simply counting installed links.

Related specialists: LAN, WAN, and Campus Network Scopes, Network Availability and Redundancy Basics, Network Design Requirements and Capacity Planning, Network Topology Inventory and Documentation.

Scenario 5 — Guests can reach a sensitive internal management service

Guest devices and staff devices have separate SSID labels but no effective inter-network filtering. The investigator verifies broadcast domains, IP reachability, the applicable firewall or ACL policy, and authorized service flows. The remediation targets the actual policy boundary and tests both permitted and denied traffic.

Related specialists: Network Segmentation and Trust Boundaries, Home and Small-Office Network Design, Network Troubleshooting from Link to Service, Network Operations, Change, and Security Hygiene.

Standards and Reference Foundations

The following external specifications support the conceptual boundaries used throughout the directory and provide starting points for child article references. An individual specialist manuscript should confirm the current status, updates, and errata of the specific standard it relies upon, rather than assuming every historic RFC remains the latest authority.

  • RFC 1122 — Requirements for Internet Hosts — Communication Layers — Host behavior and the Internet protocol architecture; some individual protocol requirements have been superseded.
  • RFC 8200 — Internet Protocol, Version 6 (IPv6) Specification — IPv6 packet structure and core delivery architecture.
  • RFC 9293 — Transmission Control Protocol (TCP) — Consolidated TCP functional specification.
  • RFC 768 — User Datagram Protocol — Foundational UDP datagram semantics.
  • RFC 2131 — Dynamic Host Configuration Protocol — DHCP for IPv4 and automatic host configuration.
  • RFC 4861 — Neighbor Discovery for IP version 6 (IPv6) — IPv6 link-local neighbor and router discovery.
  • RFC 1918 — Address Allocation for Private Internets — Private IPv4 address ranges.
  • RFC 4632 — Classless Inter-domain Routing (CIDR) — CIDR address aggregation and routing principles.
  • RFC 6349 — Framework for TCP Throughput Testing — Application-minded test framework and throughput interpretation.
  • RFC 9110 — HTTP Semantics — What application success means above network and transport reachability.
  • IEEE 802.3 Ethernet Working Group — Ethernet standards and physical/link-layer development.
  • IEEE 802.11 Wireless LAN Working Group — Wireless LAN standards and their scope.
  • IETF RFC Editor — Primary source for Internet protocol RFC publications and status.
