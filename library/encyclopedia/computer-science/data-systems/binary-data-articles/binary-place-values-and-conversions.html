Definition and Scope

Binary Place Values and Number Conversion is a Level 5 specialist topic of the Binary Data unit. It develops how positional base-two notation represents integers and fractions. It belongs within the Binary Data specialist directory rather than as a separate Level 4 summary article.

Positional Representation in Base Two

Binary notation represents nonnegative integers using powers of two instead of powers of ten. Each digit position contributes either zero or its associated power. Counting from the rightmost position at exponent zero, the weights are 1, 2, 4, 8, 16, 32, 64 and so on. The binary sequence 101101 therefore represents 1×32 + 0×16 + 1×8 + 1×4 + 0×2 + 1×1 = 45 in decimal notation.

The notation 101101₂ explicitly distinguishes a base-two numeral from the decimal numeral 101101. The binary representation is the same mathematical value expressed through a different numeral system; converting the numeral alone does not encrypt, compress or change the information content of that value. Leading zeroes do not change an unsigned integer's numerical value, but they may matter when the data is an eight-bit field, fixed-width register or serialized format.

Binary to Decimal Conversion

To convert a nonnegative binary integer to decimal, multiply each bit by its positional weight and add the contributions. For 11001010₂, the set positions represent 128, 64, 8 and 2, giving 202₁₀. A useful alternative evaluates digits from left to right: start at zero, repeatedly double the current value and add the next bit. Reading 1011, the successive totals are 1, 2, 5 and 11.

The left-to-right method works because appending a binary digit b to a numeral representing n yields 2n+b. This makes conversion easy to implement without separately constructing a table of powers. It also generalizes to other bases using the recurrence base×current+digit.

Decimal to Binary Conversion

For a nonnegative integer, repeatedly divide by two and record the remainders. Each remainder determines the next least significant bit; read the collected remainders in reverse order. For decimal 45, the steps are 45÷2=22 remainder 1, 22÷2=11 remainder 0, 11÷2=5 remainder 1, 5÷2=2 remainder 1, 2÷2=1 remainder 0, and 1÷2=0 remainder 1. Reversing gives 101101₂.

An equivalent method repeatedly subtracts the largest power of two not exceeding the remaining value. For 45, subtract 32 (remaining 13), subtract 8 (remaining 5), subtract 4 (remaining 1), and subtract 1. The set positions correspond to weights 32, 8, 4 and 1. Either method can be checked by converting the result back to decimal.

For zero, the standard representation is simply 0, not an empty sequence. Negative integers require a separate sign or signed encoding convention; the unsigned conversion algorithm alone does not determine a two's-complement bit pattern.

Fixed Width and Unsigned Ranges

With n unsigned bits, there are 2^n distinct bit patterns and the values range from zero through 2^n−1. Thus eight unsigned bits represent values 0–255. A fixed-width field cannot represent values beyond its range without a declared overflow behavior, wider representation or multiprecision encoding. A mathematical integer has no inherent eight-bit limit; the limit comes from a chosen data format or machine operation.

Overflow behavior depends on language, instruction and data type. Some arithmetic environments wrap unsigned results modulo 2^n, some raise errors, and some use arbitrary-precision integers. A four-bit unsigned field calculating 15+1 cannot store decimal 16 in four bits. A hardware or software system must define whether the result wraps to zero, saturates, traps or expands its width.

The distinction between value and representation is critical when moving data between formats. A decimal string 255 contains three text characters, while an eight-bit unsigned binary field can represent the same numerical value in one byte. Neither representation is inherently more accurate for integers within the stated range; they have different encoding and interoperability properties.

Binary Fractions and Fixed-Point Interpretation

Binary fractional positions to the right of the radix point have weights 1/2, 1/4, 1/8, and so on. Thus 0.101₂ represents 1/2 + 0/4 + 1/8 = 0.625₁₀. A binary fraction can be converted by summing positional weights, while decimal-to-binary fractional conversion repeatedly multiplies the remaining fractional part by two and records the resulting integer parts.

Not every finite decimal fraction has a finite binary representation. The decimal value 0.1 repeats in binary, just as 1/3 repeats in decimal. This fact helps explain why finite binary floating-point formats can represent some decimal values only approximately. The article on numeric data types and floating-point representation treats rounding and exponent formats in greater detail.

Fixed-point formats assign an agreed number of fractional bit positions to an integer-like bit field. For example, interpreting the eight-bit unsigned pattern 00101000 with four fractional bits gives 40/16=2.5. Without the scaling rule, the same pattern is simply unsigned 40. The bits do not reveal which interpretation is intended.

Worked Conversion and Validation Exercise

Convert decimal 173 into eight-bit unsigned binary. Select the largest weight 128, leaving 45. Select 32, leaving 13; select 8, leaving 5; select 4, leaving 1; and select 1. The eight positions from 128 to 1 become 10101101₂. Checking by addition: 128+32+8+4+1=173. Grouping into two four-bit nibbles gives 1010 1101, which corresponds to hexadecimal AD.

To check a second value, convert 01111111₂ using the positional sum 64+32+16+8+4+2+1=127. The leading zero signals an eight-bit field but contributes nothing to its unsigned numerical value. If these bits are interpreted as an eight-bit signed two's-complement integer, 01111111 is still +127; 11111111 instead represents −1 under that separate convention, despite being 255 unsigned.

Conversion problems should explicitly state base, width and signedness. A bare pattern like 10000000 is ambiguous as a value without an interpretation rule.

Common Mistakes and Practical Use

Frequent errors include counting positional weights from one instead of zero, reading division remainders in the original rather than reverse order, assuming eight bits automatically means a signed number, and treating the printed base-two numeral as a different mathematical quantity from its decimal counterpart. Another problem is ignoring widths when parsing external data and accidentally truncating values.

Use conversion as a diagnostic technique when reading protocol diagrams, file-format field maps, flags, permission masks and debugging displays. When working with real files or network streams, always consult the specification for byte order, signedness and field length; a correct base conversion cannot repair a wrong interpretation of the source bytes.
