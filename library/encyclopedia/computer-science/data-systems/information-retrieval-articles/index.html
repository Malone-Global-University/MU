Collection Overview

The Information Retrieval unit belongs to the Data Systems division of the MGU Computer Science volume. It extends the established Information Retrieval overview with specialized treatments of indexing, lexical ranking, neural search, evaluation, and retrieval-supported generation. A retrieval system translates an information need into a query, discovers relevant candidates, applies filtering and ranking, and presents evidence for a user's judgment.

Information retrieval differs from database querying because results frequently have graded or uncertain relevance and may be ordered by a score rather than satisfying exact relational predicates alone. It differs from data science because retrieving information is not the same as deriving a valid statistical or scholarly inference from it. The unit includes traditional search models as well as embedding-based and retrieval-augmented systems, while retaining clear distinctions among the operations they perform.

This Level 4 unit index uses the 15 named Level 5 child articles already specified in the existing Information Retrieval overview, not a newly invented competing outline. Active links denote the intended canonical child locations. The four topical groups below are editorial groupings only; they do not introduce another directory layer.

Worked Retrieval Scenarios

Scenario 1: Search a scholarly encyclopedia

A reader enters “Meiji land tax reform.” Text analysis preserves the historical name while normalizing suitable inflections. An inverted index returns articles and passages containing the necessary terms. BM25 provides a lexical candidate ranking; dense retrieval may surface alternative wording, and a reranker may improve ordering. A published-article and authorization filter must be applied before results are shown. The reader receives source titles, excerpts, publication dates and link destinations so claims can be checked directly.

Scenario 2: Search a technical error catalog

A user enters a precise error identifier such as ERR-1042. Semantic embedding similarity alone is an unsafe primary retrieval strategy because nearby vectors do not guarantee exact character matches. A field-specific analyzer and exact identifier field provide reliable matching; other descriptive text may be searched with BM25. Evaluation should include exact-match test cases, false positives and time-to-first-result, not only generic relevance ranking.

Scenario 3: Search a multilingual image archive

Records contain Spanish, English and Japanese captions, while some images have no reliable text descriptions. A metadata index handles dates, rights and creator fields; cross-lingual retrieval finds equivalent concepts; image embeddings can help discover visually related items. Scores from the three methods need controlled fusion and task-specific relevance judgments. Lack of an image caption should not silently become lack of discoverability.

Scenario 4: Retrieval-augmented answers

A system retrieves several passages about a documented institutional policy before producing a draft answer. It must apply source permissions, carry stable passage references and distinguish quotation from inference. Success requires both relevant retrieval and faithful answer composition: a high-scoring passage is not proof that an unsupported model-generated statement is true. Test those two stages separately.

Design and Investigation Framework

  1. Define the information need: exact lookup, exploratory research, known-item navigation, multilingual discovery or evidence-backed question answering.
  2. Inspect corpus characteristics: document lengths, field structure, languages, quality, duplicate rates, update frequency and permissions.
  3. Establish an interpretable baseline: measure Boolean matching and BM25 before introducing opaque semantic rankers.
  4. Choose analyzers and index structures: align query-time and document-time tokenization; reserve exact fields for identifiers and required filters.
  5. Specify candidate and ranking stages: define first-stage candidate budgets, rank-fusion rules, reranking capacity and fallbacks.
  6. Construct a judgment set: collect queries, representative user intents and documented relevance labels; include difficult negative cases.
  7. Measure quality and operations: report recall at candidate depth, ranked quality, response latency, index freshness, resource consumption and permission leakage risks.
  8. Manage changes: version analyzers, embeddings, indexes, source deletions and evaluation suites so apparent gains are reproducible.

Suggested Study Pathways

Search foundations: Text Analysis and Tokenization → Inverted Indexes and Postings Lists → Boolean and Phrase Retrieval → TF–IDF and Vector Space Retrieval → BM25 and Probabilistic Ranking. Work through a three-document example by hand before tuning complex ranking systems.

Quality and ranking: BM25 → Query Expansion and Relevance Feedback → Learning to Rank → Retrieval Evaluation and Metrics. Use measured judgments to decide whether each added component genuinely helps.

Semantic production path: Dense Passage Retrieval → Approximate Nearest Neighbor Indexes → Hybrid Search and Rank Fusion → Neural Reranking and Late Interaction → Retrieval-Augmented Generation. Preserve a strong exact-term route for identifiers, rare names and formal terminology.

Large collections and inclusive access: Web Crawling and Search Indexing → Multilingual and Multimodal Retrieval → Retrieval Evaluation and Metrics. Treat content rights, access control and multilingual fairness as system requirements, not optional ranker features.
