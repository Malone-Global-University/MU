Website Architecture

Digital platform structure, system integration, content routing, and website discovery.

Collection Overview

Website Architecture is the systems-design and information-architecture collection within MGU Public Records. It documents the structure of the MGU digital platform, the relationships among academic departments and Library holdings, shared technical components, navigational routes, and architectural decisions affecting discoverability and maintenance.

This collection answers how the digital platform is organized, how its parts interact, and how content is located through the website. Its publications may describe existing architecture, planned changes, compatibility requirements, or documented limitations; their publication status must distinguish proposals from adopted standards.

Substantive publications are issued as PDF whitepapers and technical documents only. This HTML page provides navigation. Software source, deployed web pages, active databases, and operational scripts remain in their appropriate systems.

Architectural Coverage

  • Platform structure: academic departments, MGU Library collections, common infrastructure, and relationships among institutional content systems.
  • Information architecture: URL hierarchy, parent–child page relationships, content routing, indexes, breadcrumbs, and consistent navigational patterns.
  • Shared components: structural responsibilities and integration of headers, footers, navigation scripts, reusable stylesheets, and page-level component dependencies.
  • Discovery and retrieval: site search, navigation-driven discovery, cross-references, integration with catalog metadata, and the relationship between search interfaces and indexed holdings.
  • Architectural evolution: proposed structural changes, interoperability considerations, migration constraints, backward compatibility, and documented design decisions.

Proposed Initial Architecture Series

WA-001 through WA-005 remain proposed for future development and have no active PDF download links. WA-006 is listed above as the completed technical report prepared for filing.

  1. WA-001 — MGU Digital Platform Architecture and Systems Overview. Maps the principal website domains, major functional collections, academic interfaces, shared components, and system dependencies at an institutional level.
  2. WA-002 — MGU Department–Library Content Ownership and Routing Architecture. Defines the structural relationship between teaching departments, tutorials, Reference, Encyclopedia collections, and other Library destinations, emphasizing canonical content ownership and cross-linking rather than duplication.
  3. WA-003 — MGU URL Hierarchy, Navigation, and Information Architecture Standard. Documents routing conventions, directory indexes, parent–child relationships, breadcrumbs, navigational link practices, and changes requiring redirects or compatibility treatment.
  4. WA-004 — MGU Shared Components and Website Integration Architecture. Explains architectural interactions among shared headers, footers, CSS, JavaScript, page shells, and reusable component dependencies. Visual styling specifications remain in Templates and Style Guides.
  5. WA-005 — MGU Digital Discovery, Search, and Cross-Reference Architecture. Describes the proposed website-facing discovery architecture, including retrieval pathways, cross-document links, catalog search interfaces, and integration with the Library's classification and metadata systems.

Architecture, Cataloging, and Implementation

The Library Catalog Codex is a separate Library Reference collection. It defines the classification, metadata, catalog records, and intellectual relationships used to describe MGU's holdings. Website Architecture addresses how such records may be surfaced, searched, and navigated through the web platform; it does not replace the Catalog Codex.

Architecture reports may include diagrams, interface specifications, system inventories, and migration plans, but they are not a substitute for executable code or operational procedures. Actual build scripts and release engineering documentation belong in Build, Automation, and Deployment.

Filing Boundaries

Website Architecture documents structural design and system integration. Templates and Style Guides documents approved page formats, component appearance, and document presentation rules. Build, Automation, and Deployment documents the processes that generate, test, and deploy the platform.

University-wide decisions about investing in a new platform capability belong in Institutional Planning; adopted directives may be recorded in Institutional Decisions and Directives. Verification of a particular implementation belongs in Quality Assurance and Audits.
