Cheat Sheets

Fast, task-oriented references for commands, syntax, shortcuts, and frequently repeated technical work.

Overview

The Cheat Sheets collection provides compact references that students and project builders can consult while working. Its purpose is speed and precision: a reader should be able to locate a command, syntax pattern, shortcut, or concise procedure without searching through an entire lesson or manual.

Cheat sheets are supporting materials, not substitutes for conceptual instruction. They complement the more detailed Software Reference collection and the step-by-step procedures in Setup Guides.

Quick-Reference Areas

Entries are classified by the tasks they support. These headings establish the collection's coverage without presenting unpublished documents as available downloads.

  • Terminal and Operating System Commands. PowerShell, Windows utilities, Bash, shell navigation, file operations, and basic diagnostics.
  • Programming Language Syntax. Core expressions, control flow, functions, data structures, and common idioms.
  • HTML, CSS, and JavaScript. Element patterns, selectors, browser APIs, and frequently used web-development syntax.
  • Version Control. Everyday Git commands, repository inspection, branch operations, and safe recovery procedures.
  • Database Queries. Common SQL clauses, joins, aggregation patterns, and client-specific shortcuts.
  • Editor and IDE Shortcuts. Navigation, search, refactoring, terminal access, and debugging key combinations.
  • Networking and Troubleshooting. Diagnostic command families, protocol references, and configuration lookups.
  • Data Formats and File Operations. JSON, CSV, Markdown, regular expressions, and routine transformation patterns.

Cheat Sheet Publication Standard

Every cheat sheet should clearly identify its subject, intended platform, applicable version or shell, and date of review. Commands must be readable, copyable, and paired with brief explanations where ambiguity could cause mistakes.

  • Keep related commands and patterns together under descriptive headings.
  • Show placeholders and required arguments consistently; distinguish examples from literal input.
  • Label potentially destructive, privileged, or irreversible operations clearly.
  • Differentiate Windows PowerShell, PowerShell, Command Prompt, and Unix-like shells when syntax differs.
  • Prefer stable terminology and cite the software's official documentation for version-dependent behavior.
  • Link back to the fuller software reference and relevant teaching material where available.

Practical Use

First confirm that a reference matches your operating system, program version, and command environment. Read any cautions before executing a command. Adapt example paths, filenames, credentials, and parameters to your own project rather than copying them without review.

When a quick reference does not explain a prerequisite or a workflow decision, consult the corresponding Software Reference or Setup Guide. For a complete explanation and exercises, use the relevant department lesson.
