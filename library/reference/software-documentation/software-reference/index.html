Software Reference

Technical reference materials for understanding software, platforms, capabilities, compatibility, and everyday operation.

Overview

The Software Reference collection provides organized information about the software and technical platforms encountered in MGU coursework, research, and student projects. It is designed for consultation: readers use it to identify a tool, understand its principal functions, distinguish versions and platforms, and locate authoritative technical information.

Unlike a lesson, a software reference entry is not a sequential teaching unit. Unlike a setup guide, it does not primarily walk the reader through installation. Each entry serves as a durable point of reference that can support many lessons and projects across departments.

Reference Areas

The following subject areas guide the organization of this collection. They describe reference coverage, not a claim that individual documents have already been published.

  • Operating Systems and Shells. Windows, Linux, macOS, command environments, file systems, permissions, and system administration concepts.
  • Editors and Development Environments. Source-code editors, integrated development environments, debugging interfaces, terminals, and related extensions.
  • Programming Languages and Runtimes. Language implementations, interpreters, compilers, package managers, runtimes, and supported tooling.
  • Web and Internet Software. Browsers, developer tools, HTTP clients, web servers, and web-development frameworks.
  • Version Control and Collaboration. Source-control systems, repositories, branching models, and collaborative workflows.
  • Data and Database Systems. Relational databases, query tools, data formats, database clients, and analytical environments.
  • Infrastructure and Virtualization. Virtual machines, containers, cloud consoles, networking utilities, and deployment systems.
  • Productivity and Accessibility. Office software, document tools, assistive technologies, and widely used cross-disciplinary applications.

What a Software Reference Entry Contains

A complete entry should identify the software by its official product name, developer or maintainer, and purpose. Where relevant, it should also record:

  • Supported operating systems and important compatibility considerations.
  • Major functions, supported file types, interfaces, and common use cases.
  • Licensing or access requirements, with clearly identified limitations.
  • Version-sensitive features and the date on which technical details were checked.
  • Links to the official documentation, release information, and relevant MGU lessons.
  • Cross-references to a setup guide or cheat sheet when one is available.

Technical claims that change with software releases should be dated and sourced. Where documentation applies only to a specific operating system, version, or edition, that scope should be stated explicitly.

How to Use This Collection

Start by identifying the software or technical environment required for a task. Consult its reference entry to learn what the software does and which version or platform is relevant. Use the associated setup guide when preparing an environment, then keep a cheat sheet nearby for commands and repetitive operations.

For guided instruction and assessments, return to the appropriate MGU department lesson. Reference material supports instruction; it does not replace it.
