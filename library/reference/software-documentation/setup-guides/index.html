Setup Guides

Practical setup and configuration guidance for reliable software environments and project workspaces.

Overview

The Setup Guides collection documents how to prepare working software environments for learning and project development. It addresses the practical sequence from checking prerequisites through installation, configuration, validation, and basic troubleshooting.

These guides support students using different devices and operating systems. Instructions should specify the environment they apply to rather than implying that one procedure works across all platforms. Detailed product information belongs in Software Reference; frequently repeated commands and shortcuts belong in Cheat Sheets.

Setup and Configuration Areas

The collection organizes installation and environment preparation by workflow. These headings define where guides belong; they do not imply that every topic already has a published guide.

  • Computer and Operating System Preparation. Required updates, storage, permissions, accounts, and platform prerequisites.
  • Code Editors and Development Environments. Installing editors, selecting extensions, configuring terminals, and testing preview workflows.
  • Programming Languages and Runtimes. Installing interpreters, compilers, SDKs, environment managers, and development dependencies.
  • Version Control and Repository Access. Installing source-control tools, configuring local identity, and connecting to permitted repositories.
  • Web Development Workspaces. Browser developer tools, local development environments, runtime configuration, and testing workflows.
  • Databases and Data Tools. Local databases, clients, connection settings, development datasets, and verification queries.
  • Virtualization and Containers. System requirements, isolated workspaces, images, and environment validation.
  • Diagnostics and Recovery. Common installation failures, configuration conflicts, and safe rollback procedures.

Required Elements of a Setup Guide

A complete MGU setup guide should be reproducible by a student following it on a supported system. To achieve that, every guide should contain:

  1. Purpose and expected result: what the prepared environment should be able to do.
  2. Supported platforms: operating systems, versions, hardware requirements, and permissions.
  3. Prerequisites: required software, storage, accounts, backups, and dependencies.
  4. Installation source: an official or otherwise clearly justified distribution channel.
  5. Numbered configuration steps: exact actions and commands with platform-specific alternatives.
  6. Verification test: a short observable check confirming that the installation works.
  7. Troubleshooting and recovery: common failures, diagnostic checks, and removal or rollback guidance where applicable.
  8. Maintenance note: version scope, review date, and the source documentation used.

Reliable Setup Practices

Use trusted distribution sources, verify that instructions match your operating system, and avoid granting administrative privileges unless an installation requires them. Preserve existing work before changing shared settings, system paths, or storage partitions. Never publish real passwords, access tokens, private keys, or other credentials as part of a setup example.

After completing a guide, run its verification check before proceeding to the associated lesson or project. If a later activity requires a different version or environment, consult the relevant software reference and the guide's compatibility notes before changing a functioning installation.
