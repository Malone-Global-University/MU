# MGU Technical Report
## Development, Architecture, and Operation of `backup-mgu.ps1`

**Report Date:** November 21, 2026  
**Backup Execution Date:** November 20, 2026  
**Project:** MGU Website Infrastructure and Modernization  
**Operational Status:** Initial backup successfully executed

### 1. Executive Summary

The `backup-mgu.ps1` utility was developed to establish a comprehensive, dated working-file backup of the Malone Global University website project before major architectural modernization.

Historically, MGU's monthly backup procedures concentrated on selected high-priority directories, particularly the Department and Library systems. The November 20, 2026 backup was designed to preserve the broader project in its existing operational state before changes involving website templates, JavaScript infrastructure, and potentially backend application logic.

The script uses Microsoft Robocopy, orchestrated through Windows PowerShell, to perform recursive file copying with controlled exclusions, preservation of file metadata, and operational logging.

### 2. Development History

Development proceeded through three principal requirements.

**Initial implementation:** Establish recursive copying from `C:\MGU` to `D:\2026-11-20\MGU`, excluding the entire `C:\MGU\desk` directory.

**Safety implementation:** Introduce a non-destructive preview mode to evaluate the intended backup operation before executing file transfers.

**Reporting enhancement:** Implement CSV inventory generation after determining that the volume of project files exceeded practical review through PowerShell's console history.

These requirements produced a consolidated PowerShell script capable of scanning, reporting, and copying a large project directory through a single operational interface.

The implementation requires no external PowerShell modules or third-party backup applications.

### 4. Functional Architecture

The script operates in two modes.

**Preview mode** conducts a recursive source-directory inventory, excluding the designated working directory and reparse points from the CSV scan. It generates a CSV containing each eligible file's relative path, full source path, intended backup path, size, and modification timestamp.

A separate Robocopy dry-run operation records the proposed file-copy actions without transferring project files.

**Copy mode** invokes Robocopy to reproduce the source directory hierarchy at the destination, including eligible files and empty subdirectories.

The copy operation preserves file data, attributes, and timestamps. It employs eight concurrent copying threads and limits unsuccessful file-copy attempts to two retries with two-second intervals.

The script uses `/E`, `/XJ`, `/MT:8`, `/COPY:DAT`, `/DCOPY:DAT`, and `/XD`, among other Robocopy parameters.

It deliberately excludes `/MIR` and `/PURGE`, preventing automatic deletion of destination-only files.

### 5. Reporting and Audit Outputs

The script generates three principal reporting artifacts:

- `MGU-backup-preview.csv` — sortable inventory of eligible source files.
- `MGU-backup-preview.log` — Robocopy dry-run report.
- `MGU-backup.log` — actual backup execution log.

The CSV inventory is produced independently of Robocopy's copy decisions. Therefore, it describes the eligible source collection rather than only files requiring transfer.

The execution log documents Robocopy's activity and provides the principal record for reviewing completion statistics and copy errors.

### 6. Safeguards and Limitations

Several safeguards were implemented to reduce operational risk.

The script validates the existence of the source directory, availability of the destination drive, and presence of Robocopy before processing.

Source files are copied rather than moved. The excluded working directory is omitted from the backup operation. Destination-only files are not automatically deleted.

Robocopy exit codes of eight or greater trigger an error.

The script does not, however, provide cryptographic integrity verification, automatic restoration, transactional snapshot consistency, or complete preservation of NTFS security metadata.

It also does not automatically capture databases, external services, or configuration files located outside the designated source directory.

### 7. Operational Execution

On November 20, 2026, the script was executed for the initial backup of the MGU project to the designated destination.

The operator confirmed successful execution.

The backup was intended to preserve the project before undertaking significant changes to its website architecture and underlying application systems.

The reported successful run constitutes completion of the file-copy operation. Independent inspection of the destination contents, Robocopy statistics, and recovery readiness remains a separate verification activity.

### 8. Institutional Significance

The November 20, 2026 backup establishes a defined historical reference point for MGU's development operations.

Its significance extends beyond routine data protection. It provides a documented baseline against which subsequent changes to webpage templates, navigation components, directory structures, and backend systems can be evaluated.

Preserving this baseline separately from future backups supports configuration management, troubleshooting, historical reconstruction, and potential recovery.

### 9. Maintenance Recommendation

The destination `D:\2026-11-20\MGU` should be retained unchanged after acceptance as the pre-modernization baseline.

Future backup operations should use separately dated destinations rather than repeatedly updating this historical reference.

The associated execution log should be preserved as part of MGU's engineering records.

### 10. Conclusion

The development and successful execution of `backup-mgu.ps1` represent a completed infrastructure-preparation milestone for MGU.

The utility establishes a repeatable, reviewable backup workflow that improves on selective manual directory copying while retaining safeguards against destructive synchronization.

The November 20, 2026 backup provides the project-file foundation for proceeding with the next phase of website modernization, subject to final verification of the copied files and identification of any backend dependencies requiring separate protection.

**Final Status:** Development complete. Initial backup successfully executed. Post-backup recovery verification recommended.
