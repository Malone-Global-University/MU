# WORKFLOW NOTE

## Title
MGU File Audit System v2.0 — Initial Deployment, PowerShell Compatibility Corrections, Baseline Inventory, and Automated Scheduling

## Date
2026-11-14

## Area
Malone Global University (MGU) — Project File Management, Historical Auditing, PowerShell Automation, and Administrative Infrastructure

**Project Root:** `C:\MGU`

**Audit System:** `C:\MGU-Audit`

**Application:** `C:\MGU-Audit\app\mgu-audit.ps1`

**Environment:** Windows PowerShell 5.1

## Problem
The MGU project had accumulated tens of thousands of files across its academic departments, encyclopedias, and supporting directories without a centralized mechanism for auditing file creation and modification activity.

The existing filesystem allowed individual file timestamps to be inspected, but there was no consolidated system for producing historical reports across the entire project root.

The initial deployment of MGU File Audit System v2.0 encountered two operational problems:

1. **PowerShell execution restrictions:** Windows PowerShell refused to execute `mgu-audit.ps1` because the script was not digitally signed.
2. **Snapshot index variable collision:** Following successful baseline creation, the `Status` and `Report` operations failed with the error `Cannot bind argument to parameter 'LiteralPath' because it is an empty array.`

These errors initially prevented the audit system from operating as a complete, reusable reporting platform.

## Intended Goal
Establish a permanent MGU file-auditing system capable of:

- Recursively inventorying the entire `C:\MGU` project directory.
- Recording file paths, creation timestamps, modification timestamps, file sizes, and SHA-256 hashes.
- Preserving existing historical audit reports.
- Generating CSV reports for user-selected start and end dates.
- Comparing successive inventories to identify additions, modifications, and removals.
- Retaining snapshot records outside the audited project directory.
- Performing automatic daily snapshots through Windows Task Scheduler.
- Supporting future department-level and publication-development analytics.

The correct operational state required a successful baseline inventory, functioning status and reporting commands, preserved historical records, and a registered daily scheduled task.

## Root Cause

### 1. PowerShell execution policy
The system's execution policy restricted unsigned PowerShell scripts. The audit script was not digitally signed, preventing its execution through the normal invocation method.

This was an execution-policy restriction rather than a demonstrated defect in the file inventory operation.

### 2. Case-insensitive PowerShell variable collision
The audit script used `$Index` to store the path to the snapshot index CSV while also using `$index` to store an array of imported snapshot records.

Windows PowerShell treats variable names as case-insensitive.

Consequently, assignments such as:

`$index = @()`

overwrote the variable containing the snapshot index file path.

Subsequent operations attempted to pass the empty array into a `LiteralPath` parameter, producing the binding error.

The initial attempt to wrap CSV-reading results in array expressions did not address this underlying naming conflict.

### 3. Initial absence of historical snapshot comparisons
Before deployment, MGU had no permanent sequence of SHA-256 inventory snapshots.

Historical filesystem timestamps were available, but complete records of past additions, deletions, and intermediate modifications could not be reconstructed retrospectively from those timestamps alone.

## Steps Taken

1. **Created initial historical audit reports.** Executed separate PowerShell audits covering existing historical creation timestamps and file activity during November 1–14, 2026. Produced two CSV files for review.

2. **Reviewed and reconciled the reports.** Established that the November 1–14 activity report contained 4,703 qualifying files. Distinguished creation timestamps from modification timestamps and identified limitations in retrospective filesystem auditing.

3. **Prepared MGU File Audit System v2.0.** Established the audit application under `C:\MGU-Audit\app`, with separate directories for legacy reports, snapshots, and generated reports.

4. **Resolved execution-policy restrictions.** Applied a temporary execution-policy override for the active PowerShell session:

   `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`

   This permitted execution without permanently changing the system-wide policy.

5. **Imported historical records.** Executed the application with `-Action Import`, successfully archiving both original CSV reports under `C:\MGU-Audit\legacy`.

6. **Generated the initial SHA-256 baseline.** Executed `-Action Snapshot`, recursively inventorying 47,005 files with zero reported scanning errors. The resulting baseline was saved as:

   `C:\MGU-Audit\snapshots\20261114-191607-5038775.csv`

7. **Identified reporting failures.** Attempted `-Action Report` and `-Action Status`, both of which encountered the empty-array `LiteralPath` error. An initial array-handling patch did not resolve the issue.

8. **Inspected the actual PowerShell script and snapshot index.** Used `Select-String`, `Get-Content`, and `Get-ChildItem` to examine the relevant code and confirm that the snapshot index and baseline CSV existed.

9. **Corrected the variable collision.** Created a backup of the application script and replaced the uppercase `$Index` references with the distinct variable name `$SnapshotIndexPath`. Ten references were changed, separating the filesystem path variable from the lowercase `$index` record collection.

10. **Verified application status.** Re-executed `-Action Status`. The application successfully reported one baseline snapshot containing 47,005 files, zero scanning errors, and the correct project root.

11. **Verified date-range reporting.** Re-executed the November 1–14 timestamp report. The application returned exactly 4,703 matching files and generated:

    `C:\MGU-Audit\reports\timestamps-20261114-213328-7955154.csv`

12. **Registered automatic daily auditing.** Executed:

    `& "C:\MGU-Audit\app\mgu-audit.ps1" -Action Schedule -ScheduleTime "23:30"`

    Windows Task Scheduler confirmed the task `MGU File Audit v2 Daily` was registered in the `Ready` state, with its next execution scheduled for November 14, 2026, at 11:30 PM.

13. **Tested observed-event reporting.** Generated a report for November 15–21, 2026, using `-Basis Observed`. The command completed successfully and reported zero observed events, consistent with the future reporting window and absence of a second snapshot at that time.

## Key Change
Separated the snapshot index filepath variable from the snapshot record collection, correcting a PowerShell case-insensitive naming collision that prevented the `Status` and `Report` operations from functioning.

## Rules Going Forward

1. **Maintain unique variable names regardless of capitalization.** PowerShell variables are case-insensitive. Distinct concepts must use distinct identifiers.

2. **Preserve the original baseline.** Do not overwrite or delete the November 14 snapshot. Future audits should create additional timestamped inventory files.

3. **Keep audit infrastructure outside the MGU project root.** Audit databases, reports, and logs must remain under `C:\MGU-Audit` or another separate administrative location.

4. **Back up scripts before modifying them.** Maintain recoverable versions of application code before applying patches.

5. **Use SHA-256 comparisons for substantive content-change detection.** Do not rely exclusively on Windows `CreationTime` or `LastWriteTime` to determine whether a document was authored or substantively revised.

6. **Distinguish timestamps from observed events.** Filesystem timestamps represent recorded metadata. Observed events represent differences detected between completed snapshots, not necessarily the exact times when the underlying changes occurred.

7. **Avoid unnecessary full-project rescans.** Generate timestamp reports from saved inventories whenever possible. Reserve SHA-256 rescanning for planned snapshots and verification needs.

8. **Validate scheduled executions.** A scheduled task in the `Ready` state is not proof that an unattended execution has succeeded.

9. **Preserve legacy audit records.** Existing reports must remain available for historical reference and reconciliation.

10. **Monitor scanning errors and incomplete inventories.** A zero-error baseline is established, but every subsequent snapshot should be independently checked for failures or unexpected file-count changes.

11. **Protect audit history.** Retain the snapshot index, individual snapshot CSVs, and observed-event records. Back up the audit database separately to reduce the risk of losing historical evidence.

12. **Validate revisions against PowerShell 5.1.** All future application changes must remain compatible with the installed Windows PowerShell environment unless an explicit migration is approved.
