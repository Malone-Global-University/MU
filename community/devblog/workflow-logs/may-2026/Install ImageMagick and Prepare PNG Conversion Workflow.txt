WORKFLOW NOTE

Title
Install ImageMagick and Prepare PNG Conversion Workflow

Date
2026-05-21

Area
Image processing / Infographic asset conversion / PowerShell tooling

Problem
ImageMagick was installed with winget, but PowerShell could not recognize the `magick` command afterward. The user then needed a reliable way to convert PNG files located in `C:\MGU\desk\infographics\og`.

Intended Goal
ImageMagick should be available from PowerShell so PNG infographic assets can be batch converted into web-ready image formats, especially JPG files for OG/social preview use.

Root Cause
The ImageMagick installer completed successfully, but the `magick.exe` command was not available in the active PowerShell session. This was likely because the system PATH had not refreshed yet, or the ImageMagick install directory was not added to PATH.

Steps Taken

1. Installed ImageMagick using winget with the package ID `ImageMagick.ImageMagick`.

2. Tested the installation using:

```powershell
magick -version
```

3. Identified that PowerShell returned `magick : The term 'magick' is not recognized`, meaning the command was not currently reachable through PATH.

4. Provided a method to locate the installed ImageMagick folder:

```powershell
Get-ChildItem "C:\Program Files" -Directory | Where-Object Name -like "ImageMagick*"
```

5. Provided a direct full-path test command for `magick.exe`:

```powershell
& "C:\Program Files\ImageMagick-7.1.2-Q16-HDRI\magick.exe" -version
```

6. Provided a user PATH update method so future PowerShell sessions can recognize `magick` directly.

7. Created a batch conversion command for PNG files in:

```powershell
C:\MGU\desk\infographics\og
```

8. Provided two conversion options: converting PNG files into JPG files in the same folder, and converting them into a separate output folder.

9. Recommended a web-friendly conversion command using `-strip -quality 85` to remove metadata and reduce file size.

Key Change
The workflow moved from a single failed `magick` command to a repeatable ImageMagick verification and batch-conversion process.

Outcome
The user now has a clear PowerShell workflow for verifying ImageMagick, fixing PATH issues if needed, and converting all PNG files in the infographic OG folder into JPG files.

Validation
Installation was confirmed by winget’s successful install message. The remaining issue was isolated to command discovery in PowerShell, not a failed installation. The provided validation command is:

```powershell
magick -version
```

or, if PATH is still not working:

```powershell
& "C:\Program Files\ImageMagick-7.1.2-Q16-HDRI\magick.exe" -version
```

Rules Going Forward
For ImageMagick on Windows, always confirm the install with `magick -version` after opening a new PowerShell session.

If `magick` is not recognized, check the install folder under `C:\Program Files` and test `magick.exe` by full path before reinstalling.

For batch conversions, use `Get-ChildItem` with a specific source folder and output folder instead of manually converting files one at a time.

For web/social preview images, prefer stripped metadata and controlled quality settings:

```powershell
magick input.png -strip -quality 85 output.jpg
```

Notes
The recommended conversion folder was:

```powershell
C:\MGU\desk\infographics\og
```

A safer long-term approach is to write converted JPG files into a separate folder, such as:

```powershell
C:\MGU\desk\infographics\jpg
```

This preserves the original PNG files while creating optimized JPG copies for use on the site.
