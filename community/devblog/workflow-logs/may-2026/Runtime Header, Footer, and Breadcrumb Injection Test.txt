WORKFLOW NOTE

Title
Runtime Header, Footer, and Breadcrumb Injection Test

Date
2026-05-21

Area
MGU shared HTML components, header/footer injection, breadcrumb system

Problem
The site needed a simple way to load a shared `header.html` and `footer.html` at runtime without duplicating the same markup across many static pages.

Intended Goal
Use the simplest possible JavaScript `fetch()` method to inject shared HTML components while preserving page-specific metadata such as uploaded and updated dates.

Root Cause
Static HTML pages duplicated global header/footer markup, making future navigation or footer changes harder to maintain across the site.

Steps Taken

1. Created a test page served locally with `python -m http.server 8000`.
2. Added `<div id="header-placeholder"></div>` and loaded `/component/header.html` using `fetch()`.
3. Added `<div id="footer-placeholder"></div>` and loaded `/component/footer.html` using `fetch()`.
4. Confirmed the header, footer, and theme toggle worked.
5. Identified that duplicate `header-placeholder` IDs should be removed.
6. Discussed keeping upload/update dates outside the shared footer unless using page-level data attributes.
7. Reviewed a simple filepath-based dynamic breadcrumb script.

Key Change
The site can now use lightweight runtime HTML includes for shared header and footer components.

Outcome
Header and footer injection now works successfully on the test page, reducing the need to manually duplicate global layout markup.

Validation
Confirmed locally through `python -m http.server 8000`; the header loaded, the footer loaded, and the theme toggle functioned.

Rules Going Forward
Use one unique placeholder ID per injected component. Keep global footer content in `footer.html`; keep page-specific dates on the page unless using explicit metadata logic. Use root-relative paths like `/component/header.html`.

Notes
This lightweight fetch-based method is better for the current MGU static-site workflow than heavier JavaScript-generated component templates. Dynamic breadcrumbs can be added later using the URL filepath.
