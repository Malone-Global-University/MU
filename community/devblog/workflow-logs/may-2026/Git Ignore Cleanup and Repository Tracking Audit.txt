WORKFLOW NOTE

Title
Git Ignore Cleanup and Repository Tracking Audit

Date
2026-05-21

Area
Repository management, Git tracking rules, encyclopedia build pipeline

Problem
The repository was tracking unnecessary local and system-generated files including `desktop.ini` metadata files and local encyclopedia pipeline assets. The `.gitignore` structure had redundant entries and there was uncertainty about how Git handled tracked vs ignored files. There was also concern about messy commit history and whether repository history could be reset or rewritten.

Intended Goal
Ensure that local-only generator files, Windows metadata files, and encyclopedia pipeline artifacts are excluded from version control while preserving legitimate project source files. Establish a cleaner and more maintainable Git tracking structure and clarify options for repository history cleanup.

Root Cause
The repository evolved organically during rapid development and experimentation. Local generator systems, temporary build assets, and Windows Explorer metadata were created alongside production content before `.gitignore` rules and repository boundaries were fully defined. Some Git behaviors regarding tracked files versus ignored files were also not yet fully established in workflow conventions.

Steps Taken

1. Reviewed existing `.gitignore` structure and identified redundant entries such as duplicated `software/` and `desk/` rules.
2. Clarified Git ignore behavior for files versus folders, including trailing slash semantics and recursive directory ignores.
3. Added encyclopedia pipeline exclusions for:

   * `library/encyclopedia/content/`
   * `library/encyclopedia/build-*.js`
   * `library/encyclopedia/renderPage.js`
   * `library/encyclopedia/search.js`
4. Established that `library/encyclopedia/content/` is a local-only JSON production pipeline directory and should remain fully ignored.
5. Investigated Git tracking state using:

   * `git ls-files`
   * `git status`
   * `git ls-tree`
6. Diagnosed `git rm --cached` failure as a sign that the ignored encyclopedia content directory was never committed or already excluded from tracking.
7. Explained repository inventory commands for viewing:

   * tracked files
   * working directory files
   * remote repository contents
8. Reviewed the purpose and behavior of the `git-auto.sh` automation script and confirmed it should normally remain version controlled as a reusable workflow utility.
9. Identified `desktop.ini` files as Windows Explorer metadata files unintentionally entering version control.
10. Added repository-wide ignore guidance for:

    * `desktop.ini`
    * `Thumbs.db`
11. Generated cleanup commands to remove tracked `desktop.ini` files recursively using:

    * `git rm --cached`
    * `git ls-files | findstr desktop.ini`
12. Discussed Git history rewrite strategies including:

    * interactive rebase
    * orphan branch reset
    * full `.git` reinitialization
    * forced remote replacement

Key Change
The repository was reclassified into clear boundaries between production source content and local-only build pipeline artifacts, with corresponding Git ignore rules and cleanup procedures established.

Outcome
The repository structure is now cleaner and easier to reason about. Local encyclopedia generator assets and Windows metadata files can be excluded from version control permanently. Git inspection and cleanup commands are now standardized, and repository history reset options are understood for future cleanup if desired.

Validation
Validation was performed through:

* `.gitignore` rule inspection
* `git ls-files` tracking checks
* `git status` verification
* failed `git rm --cached` checks confirming some files were never tracked
* path-specific Git inspection commands
* recursive metadata cleanup command review

Rules Going Forward

* Treat local generators, temporary pipeline JSON, and machine-specific tooling as ignored assets unless intentionally shared.
* Ignore all Windows metadata files globally (`desktop.ini`, `Thumbs.db`).
* Keep reusable workflow utilities such as repository automation scripts under version control.
* Separate source content from generated outputs structurally whenever possible.
* Audit `.gitignore` regularly as the repository architecture evolves.
* Use repository resets or orphan branches when historical commits become structurally misleading or unusable.

Notes
The encyclopedia system now has a clearer distinction between:

* production-facing HTML/content
* local generation infrastructure
* temporary build outputs
* repository-managed source assets

Future improvements may include:

* dedicated `/tools/` or `/scripts/` directory for automation utilities
* dedicated `/generated/` or `/cache/` structure for pipeline outputs
* layered Git ignore architecture (global, local, repo-specific)
* repository commit discipline separating content updates from infrastructure changes
