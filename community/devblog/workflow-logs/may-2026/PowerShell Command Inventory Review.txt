WORKFLOW NOTE

Title
PowerShell Command Inventory Review

Date
2026-05-21

Area
PowerShell Reference / Windows Command Environment

Problem
The total number of available PowerShell commands was unclear because PowerShell does not have one fixed command count. The available command set changes based on installed modules, loaded functions, aliases, and external applications available in the system path.

Intended Goal
Determine how many PowerShell-recognized commands were available in the current system session and identify which modules were contributing the largest command groups.

Root Cause
PowerShell command availability is dynamic. It includes cmdlets, functions, aliases, scripts, and applications, so the command count depends on the current machine, installed Windows features, imported modules, and session state rather than a single universal PowerShell number.

Steps Taken

1. Explained that PowerShell command counts vary by machine and that `Get-Command` is the correct tool for counting the local command environment.
2. Ran and interpreted a command-type breakdown showing 1,042 functions, 964 cmdlets, and 107 aliases, for a total of 2,113 PowerShell-recognized commands.
3. Grouped available commands by source module using `Get-Command | Group-Object Source | Sort-Object Count -Descending`.
4. Reviewed the major command sources, including Hyper-V, Storage, Microsoft.PowerShell.Utility, NetSecurity, Microsoft.PowerShell.Management, NetAdapter, DISM, Appx, SMB, DNS, BitLocker, Defender, and other Windows administration modules.
5. Compared the full command-source list against a cleaner cmdlet/function-only source list to separate aliases from primary usable PowerShell commands.
6. Identified that a blank Source group existed, meaning some commands were not tied to a normal module source and should be inspected separately if needed.

Key Change
The session shifted from asking “how many PowerShell commands exist?” to producing a local command inventory showing that this system currently exposes about 2,113 PowerShell-recognized commands.

Outcome
The PowerShell environment is now better understood as a large Windows administration command surface, with especially large command groups from Hyper-V, Storage, networking, security, and core Microsoft.PowerShell modules.

Validation
The result was confirmed by grouping `Get-Command` output by `CommandType` and then by `Source`, showing consistent totals and revealing the largest contributing modules.

Rules Going Forward
Use `Get-Command | Measure-Object` for total local command count.
Use `Get-Command | Group-Object CommandType` to separate cmdlets, functions, aliases, and applications.
Use `Get-Command -CommandType Cmdlet,Function | Group-Object Source` to identify which modules provide the main usable command set.
Investigate blank Source entries separately before assuming they are errors.

Notes
This system has a strong administrative PowerShell footprint, especially for Hyper-V, storage, networking, security, and Windows management. A future PowerShell reference table could be organized by module/source rather than alphabetically only, because grouping by source makes the command universe easier to understand.
