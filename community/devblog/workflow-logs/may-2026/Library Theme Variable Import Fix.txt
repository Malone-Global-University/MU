WORKFLOW NOTE

Title
Library Theme Variable Import Fix

Date
2026-05-21

Area
MGU Library CSS theme system, hero section, root variables, imported stylesheet stack

Problem
The Library page was showing the intended red hero styling, but links, section headings, borders, and the header school name were still using the old blue theme. The hero text also changed correctly only when its CSS was placed inline, while the imported hero stylesheet appeared not to apply reliably.

Intended Goal
The Library page should use the red Library theme consistently while keeping hero text light-colored at all times, independent of light and dark mode.

Root Cause
The wrong root variable file was being imported. Because global colors were controlled through CSS variables such as `--accent`, `--card`, `--text`, and `--bg`, the page continued inheriting the old blue palette even after some hero styling was corrected.

Steps Taken

1. Identified that hero text was changing because it inherited `color: var(--text)` from the body theme system.
2. Locked hero text color directly with `.hero`, `.hero h1`, and `.hero p` using a fixed light color.
3. Checked the visible blue styling and traced it to `var(--accent)` still being supplied by the wrong root variable import.
4. Confirmed that the issue was not browser cache, but an incorrect CSS variable source file.
5. Corrected the imported root variables so the Library page receives the intended red palette.

Key Change
The Library page now imports the correct root variable file, allowing the red theme variables to cascade through links, headings, borders, cards, and navigation styling.

Outcome
The Library page now visually matches the intended red Library theme, while the hero section keeps its light text color consistently.

Validation
The page was visually checked in the browser: the hero background and text displayed correctly, and the remaining blue styling was traced to the wrong imported variable file rather than the hero CSS itself.

Rules Going Forward
Theme files must be verified before debugging individual component styles. If links, headings, borders, and brand text all show the wrong color, check the active root variables first.

Notes
Inline CSS worked because it bypassed the variable cascade. Imported CSS failed only because the wrong variable source was feeding the page.
