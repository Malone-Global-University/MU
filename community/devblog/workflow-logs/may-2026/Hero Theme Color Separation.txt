WORKFLOW NOTE

Title
Hero Theme Color Separation

Date
2026-05-05

Area
Site-wide CSS, hero sections, MGU page identity themes

Problem
MGU pages were using similar hero styling across main pages, departments, library pages, community pages, and news pages. This made different areas of the site feel too visually similar and made it harder to distinguish Departments from the Library and Community sections.

Intended Goal
Keep the same basic hero structure across the site while using different hero color themes to identify major site areas.

Root Cause
The hero styling was centralized, but the visual identity was not separated by page area. The same or similar gradient colors were being reused across sections that serve different purposes.

Steps Taken

1. Reviewed the existing `.hero` CSS structure.
2. Identified that `color: #dbefff;` controls the inherited hero text color for both the heading and paragraph.
3. Confirmed that `.hero h1` and `.hero p` do not need their own color unless a theme-specific override is wanted.
4. Assigned distinct hero gradient directions by area: blue for Departments and main pages, red for Library, green for Community, and purple for News.
5. Chose a revised Department blue gradient that reads more true blue and less teal/green.
6. Kept the same hero spacing, alignment, font sizing, and text-shadow behavior to avoid a radical redesign.
7. Preserved the existing transition behavior on `.hero h1` and `.hero p` for future theme or mode changes.

Key Change
The site keeps one shared hero structure while changing only the color identity by section.

Outcome
MGU pages can now feel visually distinct without requiring separate layouts or major template changes. Departments remain blue and academic, Library pages can become red and reference-oriented, Community pages can become green, and News pages can use purple.

Validation
The CSS inheritance was checked: `.hero` sets the text color, and the child heading and paragraph inherit it correctly. The override rules only control typography and transition behavior, not the base color.

Rules Going Forward
Use shared hero layout CSS for all major site areas. Only override background gradients and optional text color by theme. Avoid redesigning the page structure just to create section identity.

Notes
A future improvement would be to organize these into small area-based CSS files such as `department.css`, `library.css`, `community.css`, and `news.css`, or to use body classes such as `theme-department`, `theme-library`, `theme-community`, and `theme-news`.
