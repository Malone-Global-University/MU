WORKFLOW NOTE

Title
Refactor Encyclopedia Pipeline Around JSON Source of Truth

Date
2026-05-21

Area
MGU Library Encyclopedia static site generator

Problem
The encyclopedia build system still had legacy HTML-as-database behavior. Markdown was converted to HTML, then HTML was re-read to build indexes and search data. Folder roles such as `volumes` and `categories` were unclear, and malformed frontmatter caused pages to fall back to `uncategorized`, lose tags, and render raw markdown/frontmatter.

Intended Goal
Create a cleaner backendless SSG pipeline where Markdown is private source content, JSON is the structured source of truth, and HTML, index pages, and search data are generated from JSON rather than scraped from HTML.

Root Cause
The older system mixed generation, indexing, search, and presentation responsibilities. HTML was acting as both output and data source. Frontmatter parsing also failed when copied markdown contained HTML entities like `&#x20;`, which made YAML invalid.

Steps Taken

1. Identified roles of existing scripts: `build-encyclopedia.js`, `build-index.js`, `build-search-index.js`, `search.js`, and `search.json`.
2. Removed obsolete `build-encyclopedia-v2.js`.
3. Redesigned the pipeline as `markdown → content/*.json → HTML/index/search`.
4. Created a full-schema `build-content.js` plan using metadata, SEO, OpenGraph, Twitter, breadcrumbs, related links, output paths, source info, and timestamps.
5. Refactored `build-html.js` around a cleaner renderer model using JSON fields instead of parsing HTML.
6. Diagnosed timestamp formatting issues and raw ISO output.
7. Diagnosed frontmatter parsing failure caused by HTML-encoded spaces (`&#x20;`) inside YAML.
8. Confirmed `gray-matter` is installed at the root project level and does not need a second package.json in `/library/encyclopedia`.
9. Planned updated JSON-driven `build-index.js` and `build-search-index.js`.

Key Change
The encyclopedia pipeline was re-centered around structured JSON as the source of truth instead of generated HTML.

Outcome
The architecture is now clearer and more scalable: Markdown is private authoring input, JSON is the canonical content model, HTML is presentation output, index pages are navigation output, and `search.json` is search output.

Validation
Confirmed `gray-matter@4.0.3` is installed and loadable from the root `C:\MGU` package environment. Pipeline output showed that when frontmatter is malformed, fields correctly fall back to defaults, proving the issue was invalid YAML rather than missing dependencies.

Rules Going Forward
Do not scrape generated HTML for metadata. Do not place HTML entities like `&#x20;` inside markdown frontmatter. Author Markdown in a plain text editor. Keep one root `package.json` unless the encyclopedia becomes an independent package. JSON should remain the source of truth for HTML, index, and search generation.

Notes
Next useful upgrades are a strict frontmatter validator, tag index pages, subdomain folder routing, and auto-related articles based on shared domain and tags.
