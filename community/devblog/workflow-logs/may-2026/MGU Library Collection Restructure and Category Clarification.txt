WORKFLOW NOTE

Title
MGU Library Collection Restructure and Category Clarification

Date
2026-05-21

Area
MGU Library architecture, collection taxonomy, homepage organization, and reference system structure

Problem
The library structure contained overlapping conceptual categories, especially between encyclopedia, wiki, guides, and reference materials. The original “Wiki” concept implied collaborative editing and rapid public revision, which conflicted with the actual controlled and curated nature of the MGU system. There was also uncertainty regarding where reference content should live, how departments related to the library, and how instructional material should be separated from explanatory material.

Intended Goal
Create a scalable and internally consistent library structure where instructional departments remain separate from supporting library materials. The library should function as a centralized reference system with clearly defined collections that do not overlap in purpose. Collection names and descriptions should accurately reflect their actual roles within the MGU ecosystem.

Root Cause
The earlier architecture evolved from multiple independent concepts developed over time:

* “Wiki” originally served as a placeholder for quick explanations and navigational material.
* “Reference” lacked a sharply defined role and risked becoming miscellaneous storage.
* The relationship between department lessons and library reference materials was not initially formalized.
* Some categories were inherited from generic knowledge-system ideas rather than the actual educational workflow of MGU.

Steps Taken

1. Clarified the distinction between instructional departments and the library reference system.
2. Established that departments contain lessons and curriculum progression, while the library contains supporting explanatory and lookup materials.
3. Confirmed that library content should live directly inside department-named folders for predictable linking and simplified lesson references.
4. Evaluated the “Wiki” category and determined that its original purpose substantially overlapped with encyclopedia content.
5. Explored alternative replacements such as “Pathways,” “Indexes,” and “Knowledge Maps.”
6. Determined that “Pathways” would only be useful if MGU implemented curated study-roadmap navigation pages.
7. Concluded that the existing department and lesson structure already fulfills most navigational progression needs.
8. Pressure-tested the “Reference” collection and defined it specifically as a quick-lookup repository for structured factual material rather than explanatory articles.
9. Refined the conceptual role of each remaining collection:

   * Dictionary = definitions
   * Encyclopedia = explanatory articles
   * Guides = procedural instruction
   * Reference = structured lookup
   * Malonicus Rex Educare = authored doctrine/framework
10. Reviewed the current library homepage structure and confirmed that the overall architecture is now significantly cleaner and more scalable than earlier iterations.

Key Change
The most important correction was redefining the MGU library as a centralized reference support system for department lessons rather than as a standalone generalized wiki-style knowledge platform.

Outcome
The library structure became substantially more coherent, scalable, and internally consistent. Overlapping roles between collections were reduced, the “Wiki” category was identified as unnecessary in its current form, and the “Reference” collection received a sharply defined functional purpose. The relationship between departments and the library is now clearly separated into:

* Departments = instruction and curriculum
* Library = reference and support material

Validation
Validation was performed through conceptual stress-testing of multiple example content types:

* Definitions
* Explanatory articles
* Tutorials
* Lookup tables
* Foundational legal documents
* Department lesson references

The revised structure successfully provided predictable placement rules without requiring duplicate systems or ambiguous storage locations.

Rules Going Forward

* Department folders contain lessons and instructional progression only.
* Library folders contain supporting reference materials only.
* Library content should live in department-named folders for predictable linking and discoverability.
* “Reference” must remain limited to quick-lookup factual materials and structured data.
* “Encyclopedia” should contain explanatory and contextual material only.
* “Guides” should remain procedural and step-oriented.
* Avoid introducing categories that do not have a sharply defined and unique purpose.
* Do not create parallel systems that duplicate navigation or explanation functions already handled elsewhere.

Notes
The “Wiki” concept has likely outlived its usefulness within the current MGU architecture unless repurposed into a true curated navigation or study-roadmap layer in the future. The present system is strongest when kept simple and centered around:

* Dictionary
* Encyclopedia
* Guides
* Reference
* Malonicus Rex Educare

The current architecture now resembles a mature educational reference ecosystem rather than an experimental generalized knowledge repository.
