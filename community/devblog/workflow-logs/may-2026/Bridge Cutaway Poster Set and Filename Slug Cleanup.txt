WORKFLOW NOTE

Title
Bridge Cutaway Poster Set and Filename Slug Cleanup

Date
2026-05-21

Area
MGU “How Systems Work” / Engineering Cutaway Infographic Series

Problem
The bridge image set was first generated in a simpler cutaway style, but the delivered filenames were inconsistent and not ideal for long-term organization. Some files used underscores, some had extra descriptive wording, and one ZIP link was first shown as plain `/mnt/data/...` text instead of a clickable sandbox download link. As the infographic library grows into hundreds of files, unclear filenames would make later sorting, labeling, and uploading difficult.

Intended Goal
Create a consistent bridge poster set matching the cleaner “How a Foundation Works” and “How a Gas Line System Works” style, then name the files with predictable lowercase hyphenated slugs such as `how-a-beam-bridge-works.png`, `how-a-suspension-bridge-works.png`, and similar. The correct state is a folder or ZIP where each image can be identified immediately from its filename.

Root Cause
The image generation tool produced files with automatic names that did not always match the requested naming convention. The first ZIP was packaged from the available generated filenames, but the generated filenames themselves were not fully standardized. The workflow needed a deliberate slugging step after generation instead of relying on auto-generated names.

Steps Taken

1. Generated a “How a Bridge Works” poster in a simplified cutaway style based on the uploaded foundation reference image, emphasizing a large central diagram, clear labels, key functions, material notes, load-path explanation, and signs of problems.

2. Generated the first bridge type set: Beam Bridge, Truss Bridge, Arch Bridge, Cantilever Bridge, Suspension Bridge, Cable-Stayed Bridge, and Tied-Arch Bridge.

3. Packaged the first seven bridge images into a folder named `7 Main Types of BridgesI` and created a ZIP file named `7_Main_Types_of_BridgesI.zip`.

4. Corrected the download delivery by providing a clickable sandbox link instead of plain `/mnt/data/...` text.

5. Reviewed the user’s preferred visual direction using the uploaded “How a Gas Line System Works” and “How a House Is Framed” examples.

6. Remade the full bridge set in the cleaner MGU Engineering Reference format with navy headers, numbered content panels, flow-path structure, central bridge cutaway, load-path sidebar, and concise explanatory blocks.

7. Identified the need for a future slug convention so every generated image can be saved with predictable lowercase hyphenated filenames.

Key Change
The bridge series should use lowercase hyphenated slug filenames as a required post-generation step, not rely on automatic image-generation filenames.

Outcome
The bridge poster set now matches the cleaner engineering reference style more closely and is easier to organize conceptually. The user also clarified that future image sets need slugs because hundreds of files in one folder will become difficult to label manually.

Validation
The generated bridge images visually followed the uploaded reference style: large central cutaway, strong title treatment, clear explanatory side panels, bottom flow sections, and MGU Engineering Reference footer. The ZIP file was created and confirmed in the sandbox, and the clickable download format was corrected after the initial plain-text path issue.

Rules Going Forward
Use lowercase hyphenated slugs for all infographic filenames.

Preferred pattern:
`how-a-[system]-works.png`

Examples:
`how-a-beam-bridge-works.png`
`how-a-truss-bridge-works.png`
`how-an-arch-bridge-works.png`
`how-a-cantilever-bridge-works.png`
`how-a-suspension-bridge-works.png`
`how-a-cable-stayed-bridge-works.png`
`how-a-tied-arch-bridge-works.png`

Avoid underscores, generic auto-generated names, and vague titles such as `understanding_the_tied_arch_bridge_design.png`.

When packaging image batches, create a folder with a clear category name and place slugged files inside it before zipping.

Always provide clickable sandbox links for generated ZIPs or files.

Notes
A slug manifest would help future batches. For each set, keep a simple mapping like:

Display Title → Filename Slug → Category Folder

Example:

Beam Bridge → `how-a-beam-bridge-works.png` → `bridges/`
Truss Bridge → `how-a-truss-bridge-works.png` → `bridges/`
Arch Bridge → `how-an-arch-bridge-works.png` → `bridges/`

This will prevent confusion later when hundreds of MGU infographic images are stored in the same asset library.
