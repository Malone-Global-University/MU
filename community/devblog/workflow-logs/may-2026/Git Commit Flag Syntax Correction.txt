WORKFLOW NOTE

Title
Git Commit Flag Syntax Correction

Date
2026-05-21

Area
Git version control workflow / PowerShell terminal usage

Problem
A Git commit command failed because the commit message flag was entered incorrectly as `--m"Renamed art homes to index "` instead of using the proper `-m` syntax with spacing. Git interpreted the entire string as an invalid option and returned the command usage help screen instead of creating the commit.

Intended Goal
Allow the Git commit command to execute successfully with a valid commit message attached to the repository snapshot.

Root Cause
The commit flag and the commit message were concatenated into a single malformed argument. Git command-line flags require separation between the option and its value.

Steps Taken

1. Reviewed the Git error output and identified the malformed option parsing issue.
2. Corrected the command syntax to use `-m "message"` format.
3. Provided both the short-form and long-form valid Git commit command examples for future reference.

Key Change
The malformed `--m"..."` argument was corrected to the valid `-m "..."` Git commit syntax.

Outcome
The Git workflow issue was resolved and the correct command structure was clarified, allowing commits to be created properly from PowerShell.

Validation
Validation was performed by comparing the failed command structure against standard Git commit syntax and confirming that the corrected command matches accepted Git CLI usage patterns.

Rules Going Forward

* Always separate Git flags from their values with spaces.
* Use `git commit -m "message"` as the standard commit pattern.
* Review terminal commands carefully before execution when using quoted arguments.
* Treat Git usage output screens as indicators of malformed syntax rather than repository corruption.

Notes
The correction was minor and did not indicate any issue with the repository itself. The failure occurred entirely at the command parsing stage before Git attempted to create a commit.
