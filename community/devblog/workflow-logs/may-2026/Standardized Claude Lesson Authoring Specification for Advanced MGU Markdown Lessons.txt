WORKFLOW NOTE

Title
Standardized Claude Lesson Authoring Specification for Advanced MGU Markdown Lessons

Date
2026-05-21

Area
MGU curriculum production pipeline; Markdown lesson authoring standards; Claude.ai prompt engineering; reusable lesson template system

Problem
The existing 21-section reusable lesson structure successfully enforced lesson organization, but it did not fully enforce the advanced institutional tone, analytical density, practitioner-oriented reasoning, and operational specificity seen in stronger lessons such as Lesson 9.3: Debt Issuance and Bond Offerings. High-quality outputs were being achieved only after iterative feedback and revision comments added manually during generation sessions. The template described structural expectations but did not sufficiently constrain prose style, paragraph behavior, instructional depth, or prohibited low-quality patterns. As a result, first-draft lesson quality could drift toward generic textbook prose in new Claude.ai chats.

Intended Goal
Create a production-ready reusable Claude.ai authoring specification capable of generating advanced professional-grade Markdown lessons in a single prompt without requiring iterative feedback. The specification should reliably reproduce the tone, density, structure, operational rigor, and practitioner-training style demonstrated in Lesson 9.3 while remaining compatible with the updated YAML-based Markdown-to-JSON lesson pipeline.

Root Cause
The original lesson template focused primarily on section architecture and token placeholders rather than generation behavior. Structural guidance alone was insufficient to constrain large language model prose quality. Critical stylistic controls—global tone requirements, paragraph standards, anti-pattern prohibitions, operational reasoning expectations, and formatting constraints—existed only implicitly through revision feedback rather than explicitly in the reusable template itself.

Steps Taken

1. Evaluated the differences in tone, analytical rigor, operational depth, and institutional specificity across multiple advanced MGU lessons, including the IPO lesson, government bond markets lesson, complex product operations lesson, and Debt Issuance and Bond Offerings lesson.

2. Identified recurring characteristics of high-quality lessons:

   * practitioner-oriented institutional voice
   * operational consequence analysis
   * systems-level reasoning
   * mechanism-focused explanation
   * analytical comparisons
   * compressed but dense paragraphs
   * explicit competent vs incompetent operational distinctions

3. Revised the reusable 21-section lesson architecture to better align with advanced institutional instructional design rather than generic textbook formatting.

4. Added a new “Global Writing Standard” layer to define:

   * advanced professional tone
   * analytical expectations
   * operational reasoning requirements
   * institutional specificity requirements
   * anti-simplification constraints

5. Added “Prohibited Output Patterns” to explicitly prevent:

   * generic textbook prose
   * dictionary-style definitions
   * filler language
   * repeated concepts
   * motivational/marketing phrasing
   * shallow explanation patterns

6. Added “Paragraph Quality Standards” to define how paragraphs should behave structurally and analytically rather than only specifying paragraph count.

7. Added explicit Markdown output formatting rules:

   * YAML frontmatter requirements
   * heading hierarchy conventions
   * markdown-only output enforcement
   * subsection formatting consistency

8. Standardized YAML schema for compatibility with the updated `auto-lesson.js` pipeline:

   * lesson_number
   * unit_number
   * track_slug
   * track_name
   * title
   * description

9. Reframed the lesson specification as a three-layer generation system:

   * formatting specification
   * structural lesson architecture
   * prose and analytical behavior specification

10. Produced a finalized “MGU Professional Lesson Authoring Spec” intended for direct reuse in fresh Claude.ai chats without additional coaching.

Key Change
The lesson template evolved from a structural outline into a full instructional-generation specification that explicitly controls prose behavior, analytical rigor, institutional tone, and operational depth.

Outcome
The MGU lesson generation workflow is now substantially more deterministic and scalable. Claude.ai can be prompted with a single reusable specification and lesson topic request while maintaining much closer alignment to the quality level established by Lesson 9.3. The updated specification better enforces:

* institutional practitioner tone
* advanced curriculum depth
* operational systems reasoning
* dense analytical writing
* high-quality Markdown structure
* YAML pipeline compatibility

Validation
Validation was performed by:

* comparing the revised specification against the structure and tone of Lesson 9.3
* analyzing prior lesson quality inconsistencies
* confirming that the updated YAML schema matches the revised Markdown pipeline requirements
* verifying that section behavior now reflects the actual prose characteristics of stronger lessons
* confirming that markdown heading conventions align with the updated auto-generated section parsing logic

Rules Going Forward

* All future advanced MGU lesson generation prompts should begin with the full authoring specification rather than only the 21-section structure.
* Tone and analytical standards must be defined globally, not embedded only in revision feedback.
* Structural instructions alone are insufficient for maintaining consistent institutional-quality prose.
* YAML frontmatter must remain standardized for compatibility with `auto-lesson.js`.
* Lesson prompts should specify professional/practitioner orientation explicitly.
* Core Concepts and Key Terms must remain distinct in instructional purpose.
* Avoid allowing Claude to revert to generalized textbook language through underspecified prompts.

Notes
Potential future improvements include:

* creating a compressed low-token version of the specification
* creating track-specific style overlays for different disciplines
* adding exemplar paragraph snippets for stronger style calibration
* building automated lesson QA scripts to detect weak prose patterns
* further separating conceptual frameworks from glossary terminology in Section 7
* adding optional difficulty-tier modifiers for undergraduate vs advanced professional tracks
