WORKFLOW NOTE

Title
MGU Newspaper Section Folder and Index Completion

Date
2026-05-22

Area
`C:\MGU\news` newspaper folder structure, section directories, subsection directories, and section `index.html` files

Problem
The MGU newspaper folder system had major top-level news sections in place, but several subsection folders under `politics` and `science` did not yet have their own `index.html` landing pages. This left parts of The Malone Panther newspaper structure incomplete, especially for deeper section navigation.

Intended Goal
Every news section and subsection folder under `C:\MGU\news` should exist and contain an `index.html` file so each folder can function as a valid newspaper landing page. The structure should support future article placement, section navigation, and sitemap development.

Root Cause
The newspaper directory had been partially built. Top-level folders and some subsection folders already existed, but the deeper `politics` and `science` subsections had been created without matching index pages. The first script provided was written in PowerShell syntax, but it was accidentally saved or run as Python, causing a syntax error.

Steps Taken

1. Reviewed the existing `C:\MGU\news` directory listing and tree structure to identify the current newspaper sections and subsections.

2. Confirmed the existing top-level newspaper folders: `africa`, `campus`, `culture`, `diaspora`, `digest`, `economy`, `features`, `forums`, `heritage`, `investigative-reports`, `mgu-report`, `north-america`, `perspectives`, `politics`, `science`, `us`, `wellness`, and `world`.

3. Confirmed existing subsection folders under `forums`, `perspectives`, `politics`, and `science`.

4. Created a repeatable PowerShell script, `news.ps1`, to create missing folders and generate starter `index.html` pages without overwriting existing index files.

5. Included section metadata, readable section titles, descriptions, header/footer injection, breadcrumb placeholder, hero block, article-list placeholder, and basic section notes in the generated index template.

6. Diagnosed the `SyntaxError: unterminated string literal` error that occurred when the PowerShell script was run as `python news.py`.

7. Explained that the `@" ... "@` syntax is valid PowerShell here-string syntax, not Python syntax.

8. Provided the correct PowerShell execution command:

```powershell
powershell -ExecutionPolicy Bypass -File .\news.ps1
```

9. Also provided a Python equivalent as an alternative in case the workflow needed to remain Python-based.

10. Ran the PowerShell script successfully from `C:\MGU\news`.

11. Confirmed that existing folders were preserved and existing `index.html` files were skipped.

12. Created missing index files for the following `politics` subsections:


16. Confirmed that the verification command returned no results, meaning every folder under `C:\MGU\news` now has an `index.html`.

Key Change
A repeatable section-index generation workflow was created and run so every MGU newspaper folder now has a valid `index.html` landing page.

Outcome
The Malone Panther newspaper folder skeleton is now complete at the current section level. All top-level and nested section folders under `C:\MGU\news` contain index pages. Existing article files remained in place, including campus articles, politics articles, editorials, and the science article under `science/physics-chemistry-and-math`.

Validation
Validation was completed in two ways. First, `tree /F` showed every folder and its files, confirming the new index pages were present. Second, this command returned no missing folders:

```powershell
Get-ChildItem "C:\MGU\news" -Directory -Recurse | Where-Object {
    !(Test-Path (Join-Path $_.FullName "index.html"))
} | Select-Object FullName
```

Because the command returned nothing, all folders passed the index-file check.

Rules Going Forward
Every newspaper section folder should have an `index.html` file before articles are added beneath it.

Scripts using PowerShell syntax should be saved as `.ps1` and run with PowerShell, not Python.

Index-generation scripts should skip existing index files by default to prevent accidental overwrites.

Parent section indexes should eventually link to child subsection indexes so users can navigate from broad sections like `Politics`, `Science`, `Perspectives`, and `Forums` into their deeper categories.

Notes
The next useful follow-up is to update parent index pages such as `politics/index.html`, `science/index.html`, `perspectives/index.html`, and `forums/index.html` so they list and link to their child sections. This will make the folder structure visible to readers, not just complete on disk.
