WORKFLOW NOTE

Title
Multi-Theme CSS Palette Standardization

Date
2026-05-21

Area
Global CSS theme system, hero banner gradients, root variable color palettes

Problem
The site originally relied on a single primary color identity and a partially mixed set of theme values. Hero gradients and accent variables were not fully organized into parallel color families, making it harder to maintain consistent branding variations across separate CSS files for different site sections or theme variants.

Intended Goal
Create a clean, parallel system of matching color palettes for blue, green, purple, and red themes so each theme maintains the same structural relationships between light accents, dark accents, hover states, and hero gradients while preserving visual consistency across the MGU interface.

Root Cause
The original CSS evolved incrementally from a mostly blue/purple-oriented design system. New color variants were added manually instead of being designed as synchronized palette families with equivalent tonal balance and matching gradient structures.

Steps Taken

1. Converted the original blue accent palette into a matching red palette while preserving the same variable naming structure and contrast relationships.

2. Created a coordinated green palette using equivalent brightness and saturation levels for:

   * `--accent-light`
   * `--accent-dark`
   * `--accent-hover-light`
   * `--accent-hover-dark`

3. Added a standardized purple palette aligned to the same visual intensity and hover behavior as the other themes.

4. Designed separate hero gradient systems for blue, green, purple, and red themes using:

   * brighter pastel-oriented light mode gradients
   * darker atmospheric gradients for dark mode

5. Preserved existing root variable architecture so theme files can be swapped modularly without changing component CSS.

Key Change
The color system was transformed from isolated theme values into a structured family of interchangeable palette variants with matching tonal behavior and hero gradient logic.

Outcome
The site now has a cleaner multi-theme architecture with coordinated blue, green, purple, and red branding variants. Hero sections maintain consistent visual depth across themes, while hover colors and accent states remain balanced and predictable.

Validation
Visual inspection confirmed:

* gradients transition smoothly in both light and dark themes
* hover colors remain readable and distinct
* dark hero gradients preserve contrast with light hero text
* palette families feel visually related rather than randomly selected

Rules Going Forward

* Maintain identical variable naming across all theme files.
* Keep tonal relationships consistent between theme variants.
* Use matching brightness hierarchy for hover states and accents.
* Preserve light hero gradients as brighter atmospheric variants and dark hero gradients as deeper cinematic variants.
* Avoid introducing isolated colors that do not belong to a coordinated palette family.

Notes
The new structure supports future expansion into additional departmental themes such as teal, gold, orange, or monochrome variants. The palette architecture also aligns well with the MGU area-based branding system already used across department, library, community, and news sections.
