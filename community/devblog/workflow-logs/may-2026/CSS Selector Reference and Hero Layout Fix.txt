WORKFLOW NOTE

Title
CSS Selector Reference and Hero Layout Fix

Date
2026-05-21

Area
MGU Library reference tables; Malone Panther page CSS

Problem
The Malone Panther hero changed from the correct vertical layout into an incorrect horizontal layout. The hero paragraph appeared beside the `<h1>` instead of underneath it. The CSS reference material also needed clearer tables for selector types, specificity, cascade, and responsive table formatting.

Intended Goal
Restore the hero so the heading and paragraphs stack vertically, and create reusable HTML reference-table sections for the MGU Library tables area.

Root Cause
A broad CSS selector applied flexbox to all `<section>` elements:

```css
.bottom-nav,
section {
  display: flex;
}
```

Because `.hero` is also a `<section>`, it inherited the flex layout and began arranging its direct children side-by-side.

Steps Taken

1. Identified that the global `section` selector inside the bottom navigation block was overreaching and affecting the hero.
2. Removed `section` from the `.bottom-nav, section` selector group and from the related mobile selector group.
3. Confirmed that only `.bottom-nav` and `.bottom-nav .btn` should receive the flex and responsive button rules.
4. Reviewed CSS selector categories: element/type, class, ID, universal, attribute, descendant, child, sibling, pseudo-class, pseudo-element, grouped, compound, and complex selectors.
5. Drafted HTML reference tables for CSS selector types, specificity weights, specificity examples, and cascade/inheritance concepts.
6. Added `class="reference-table"` to the tables for reusable styling.
7. Recommended a `.table-wrapper` pattern using `overflow-x: auto` and `min-width` so wide reference tables remain readable on mobile.

Key Change
The most important correction was removing the global `section` selector from the bottom navigation flex block so ordinary page sections no longer inherit navigation layout behavior.

Outcome
The hero layout can return to its intended vertical structure, with the paragraph text beneath the `<h1>`. The CSS reference material is now better organized for the MGU Library tables section and includes reusable table styling.

Validation
The issue was validated by matching the visible symptom to the CSS rule: applying `display: flex` to all `<section>` elements explains why the hero’s heading and paragraphs appeared beside one another. Removing `section` from the selector confines the flex layout to the bottom navigation only.

Rules Going Forward
Avoid applying layout rules like `display: flex`, `display: grid`, `flex-direction`, or button sizing to broad element selectors such as `section` unless every section on the site is intended to share that layout. Use specific class selectors for components such as `.bottom-nav`, `.hero`, `.directory-page`, and `.reference-table`.

Notes
The CSS reference set now has a useful foundation: selector types, specificity, cascade/inheritance, and responsive table handling. A future companion table could cover the CSS box model, display types, positioning, or flexbox/grid properties.
