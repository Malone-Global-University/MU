WORKFLOW NOTE

Title
Mobile Header Hamburger Toggle Fix

Date
2026-05-21

Area
MGU site header / mobile navigation

Problem
The hamburger menu opened the navigation, but the icon animation was buggy. After opening, the toggle did not clearly change into an X state.

Intended Goal
The mobile menu button should visually switch from a hamburger icon to an X when the menu is open, then return to the hamburger when closed.

Root Cause
The menu state and the icon state were not being controlled together. The navigation could open, but the button itself was not reliably receiving an active class for the CSS animation.

Steps Taken

1. Identified that the hamburger button needs its own `.active` state.
2. Recommended building the icon from three internal `<span>` bars.
3. Added CSS transforms so the first and third bars rotate into an X while the middle bar fades out.
4. Updated the JavaScript toggle so the button class, menu class, and `aria-expanded` value change together.

Key Change
The hamburger button now receives an `.active` class at the same time the mobile navigation opens.

Outcome
The toggle behavior becomes predictable: closed state shows a hamburger, open state shows an X.

Validation
Visual inspection should confirm that tapping the button opens the menu, changes the icon to an X, and tapping again closes the menu and restores the hamburger.

Rules Going Forward
Keep menu visibility state and button icon state synchronized in the same JavaScript click handler.

Notes
Use real span bars for animated hamburger icons instead of relying on a single text character or symbol.
