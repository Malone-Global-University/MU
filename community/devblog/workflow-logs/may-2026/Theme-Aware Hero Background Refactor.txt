WORKFLOW NOTE

Title
Theme-Aware Hero Background Refactor

Date
2026-05-21

Area
CSS theme system, hero banner styling, catalog page stylesheet organization

Problem
The hero banner background was hardcoded to a single gradient and did not change when switching between light and dark themes. The CSS structure also became disorganized after partial edits, duplicate `.hero` blocks, misplaced variables, and improperly nested sections inside a media query. One declaration additionally used invalid syntax (`color: --var(--accent);`).

Intended Goal
Create a clean theme-aware hero system where the hero background automatically changes with light/dark mode using CSS variables, while also reorganizing the stylesheet into a maintainable structure with properly grouped sections.

Root Cause
The hero background was defined directly inside the `.hero` selector instead of being controlled through theme variables. Additional edits introduced duplicated rules and variable declarations outside the `:root` block, causing structural inconsistency and potential parsing/layout issues.

Steps Taken

1. Added dedicated hero background variables:

   * `--hero-bg-light`
   * `--hero-bg-dark`
   * `--hero-bg`

2. Connected theme switching logic to the hero system by assigning:

   * `.light { --hero-bg: var(--hero-bg-light); }`
   * `.dark { --hero-bg: var(--hero-bg-dark); }`

3. Updated the `.hero` selector to use:

   * `background: var(--hero-bg);`

4. Removed duplicate and conflicting `.hero` sections.

5. Corrected invalid CSS syntax:

   * Changed `color: --var(--accent);`
   * To `color: var(--accent);`

6. Moved misplaced variable declarations out of the media query block and back into `:root`.

7. Reordered the stylesheet into logical sections:

   * Root Variables
   * Light Mode
   * Dark Mode
   * Hero
   * Catalog Page
   * Course Links
   * Buttons
   * Mobile Media Query

8. Cleaned spacing, indentation, and comment hierarchy for readability and long-term maintenance.

Key Change
The hero banner background is now fully theme-controlled through CSS variables instead of hardcoded gradients.

Outcome
The hero section now visually switches between light and dark gradients automatically when the theme changes. The stylesheet became significantly cleaner, easier to maintain, and structurally safer for future modularization or expansion.

Validation
Confirmed that:

* Light mode displays the light hero gradient.
* Dark mode displays the dark hero gradient.
* No variables remain outside valid selector scopes.
* Media query braces close correctly.
* Hero styles are no longer duplicated.
* Theme switching updates the hero background immediately without affecting layout.

Rules Going Forward

* Theme-sensitive colors and gradients should always use CSS variables.
* Do not place variable declarations outside `:root`, `.light`, or `.dark`.
* Never place major component blocks inside media queries accidentally.
* Keep stylesheet sections grouped logically and consistently labeled.
* Avoid duplicate component selectors unless intentionally overriding behavior.

Notes
This refactor establishes a scalable pattern for future theme-aware areas such as cards, navigation bars, sidebars, footer gradients, and department-specific hero themes.
