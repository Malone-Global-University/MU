WORKFLOW NOTE

Title
MGU Computer Science Department Structural Overhaul and Software Documentation Consolidation

Date
2026-11-16

Area
Malone Global University — Computer Science Department and Central Library

Primary directories:
- /department/computer-science/
- /department/computer-science/developer-tools/
- /department/computer-science/degree-programs/
- /library/reference/software-documentation/

Affected systems: Department navigation, instructional organization, shared HTML templates, dynamic JavaScript components, technical reference tables, metadata, and resource classification.

Problem
The Computer Science Department had accumulated structural inconsistencies and outdated HTML from earlier development phases.

Specific problems included:

1. Department-level links pointing to missing or relocated directories.
2. Specialization Tracks appearing as a separate department division despite belonging with structured academic programs.
3. Software reference materials distributed across departmental resource folders instead of the centralized MGU Library.
4. Functional developer utilities grouped with documentation rather than recognized as a separate operational division.
5. Older HTML reference tables lacking standard MGU headers, navigation, breadcrumbs, footers, and dynamic component loaders.
6. Obsolete metadata identifying Library reference pages as Computer Science Department resources.
7. Encoding corruption (mojibake) in at least one reference file.
8. Inconsistent styling between older technical tables and current MGU presentation standards.
9. Deeper departmental pages containing outdated navigation structures and incomplete instructional material.

Several initially suspected missing pages were ultimately recognized as remnants of an earlier organizational transition rather than necessarily unfinished work.

Intended Goal
Establish a consistent Computer Science Department architecture that separates instructional content, functional development tools, centralized reference documentation, and structured academic pathways.

The desired system should:

- Use current MGU HTML templates and dynamically loaded shared components.
- Keep instructional lessons and modules within the department.
- Maintain finished student development utilities in Developer Tools.
- Centralize reusable technical documentation within the Library.
- Organize specializations alongside prospective degree and certificate programs.
- Eliminate obsolete links, metadata, and encoding defects.
- Support progressive development of complete lessons without duplicating resources.

Root Cause
The inconsistencies originated from incremental website development and subsequent changes to MGU's institutional content architecture.

Earlier departmental structures combined instructional resources, software documentation, developer utilities, and academic pathways.

As MGU expanded, these categories acquired distinct responsibilities. However, older directories, navigation links, metadata, and HTML templates were not uniformly updated.

Some reference files retained metadata dating to May 5, 2026, reflecting their original Computer Science classification.

The primary problem was therefore architectural evolution without complete reconciliation of legacy content and templates, rather than isolated HTML errors.

Steps Taken

1. Reviewed the Computer Science homepage and its immediate navigation hierarchy to identify working pages, obsolete links, missing directories, and outdated content.

2. Determined that Specialization Tracks are curated learning pathways rather than an independent instructional division.

3. Removed the obsolete Specialization Tracks link from the Computer Science homepage. Retained specialization planning within the Degree Programs structure.

4. Relocated Developer Tools from:

   C:\MGU\department\computer-science\resources\developer-tools\

   to:

   C:\MGU\department\computer-science\developer-tools\

5. Preserved the existing functional developer utilities, including the MGU browser-based HTML editor used to preview pages with the university's shared CSS and JavaScript infrastructure.

6. Relocated departmental reference materials into the centralized Library directory:

   C:\MGU\library\reference\software-documentation\

7. Standardized the collection name to Software Documentation, encompassing software references, setup guides, and cheat sheets.

8. Created three category landing pages for the centralized Software Documentation collection:
   - software-reference/index.html
   - cheat-sheets/index.html
   - setup-guides/index.html

9. Moved html-color-reference-table.html and html-tag-reference-table.html from Developer Tools into the Library.

10. Modernized technical reference pages that previously lacked the standard MGU page structure.

11. Added dynamic JavaScript-loaded breadcrumbs, top navigation, bottom navigation, and other required shared template components to the affected reference tables.

12. Corrected obsolete Computer Science metadata to identify the appropriate Library location and classification.

13. Removed identified mojibake from an affected reference file.

14. Applied standardized MGU styling to the following files:
   - powershell-command-reference-table.html
   - programming-&-tech-skills.html
   - html-tag-reference-table.html
   - css-cascade-reference.html
   - css-selector-types.html

15. Identified html-color-reference-table.html as a remaining styling exception because of its extensive custom CSS.

16. Established the next development objective: producing complete Computer Science lessons using current MGU HTML templates, beginning with foundational coursework.

Key Change
Separated Computer Science instructional content, finished developer utilities, centralized software documentation, and structured academic programs into distinct, maintainable areas of the MGU website.

Outcome
The Computer Science Department's major structural modernization work is substantially complete.

Specific improvements include:

- A cleaner department homepage without redundant specialization navigation.
- Developer Tools established as a dedicated top-level department resource.
- Software documentation consolidated into the Library for institution-wide reuse.
- Three new Software Documentation category pages prepared.
- Technical reference tables brought into closer alignment with MGU's standard HTML component system.
- Obsolete departmental metadata corrected.
- Identified encoding corruption removed.
- Five technical reference pages visually standardized.
- Clearer separation between lessons, supporting utilities, documentation, and prospective academic programs.

The department is now positioned to prioritize instructional content production rather than continued structural reorganization.

Validation
Validation during the session consisted of manual inspection, page rendering, and review of the affected website structure.

- Confirmed that the Computer Science homepage and major second-level navigation pages were functioning during preliminary inspection.
- Identified and corrected obsolete or misplaced navigation links during the reorganization.
- Used the MGU Code Editor workflow to demonstrate rendering of HTML with centrally hosted CSS and JavaScript components.
- Reviewed the resulting standardized reference-table presentation.
- Confirmed removal of identified mojibake and correction of obsolete metadata during manual editing.
- Identified the HTML Color Reference Table as the remaining known styling exception.

Validation limitation: A comprehensive automated regression audit of every departmental lesson, link, and nested directory was not performed. The three new Software Documentation category pages were generated and structurally checked, but live deployment verification was not established in this session.

Rules Going Forward

1. Departments own instruction. Lessons, exercises, assessments, and instructional modules remain within their appropriate academic departments.

2. The Library owns reusable documentation. Software references, technical guides, cheat sheets, and other cross-departmental reference resources belong in centralized Library collections.

3. Developer Tools contain functional utilities. Publish working tools that help students complete projects. Expand the collection according to demonstrated instructional needs.

4. Programs organize existing coursework. Specialization tracks, certificate pathways, and prospective degree programs are structured navigation layers, not independent lesson repositories.

5. Avoid duplication. Reference centralized Library materials from departmental pages instead of maintaining separate copies.

6. Use current MGU templates. New and reconstructed HTML pages must use the established shared stylesheets, dynamic JavaScript component loaders, breadcrumbs, navigation, and footer.

7. Use consistent metadata. Page titles, descriptions, organizational references, and update information must reflect the page's current institutional location.

8. Preserve UTF-8 encoding. Inspect newly edited content for mojibake and malformed characters.

9. Use canonical directory navigation. Prefer clean directory URLs ending in / rather than hardcoded /index links.

10. Build complete lessons. Instructional pages must contain substantive explanations, practical examples, exercises, and appropriate assessments rather than placeholder descriptions.

11. Do not prematurely advertise credentials. Prospective academic pathways must remain clearly identified as developmental until their curriculum, institutional requirements, and authorization issues are resolved.

12. Preserve functional content. Do not overwrite existing operational utilities or substantive reference materials merely to modernize their presentation.

Notes
The overhaul revealed that several apparently missing departmental pages were likely intentionally abandoned or relocated during earlier planning.

This reinforces the importance of distinguishing obsolete architecture from genuine content gaps.

The MGU browser-based Code Editor remains a valuable development utility because it enables rapid HTML previewing against the university's existing CSS and JavaScript resources without a dedicated local server.
