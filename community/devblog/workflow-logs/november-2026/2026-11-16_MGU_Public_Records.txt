WORKFLOW NOTE

Title
MGU Public Records — Institutional Architecture Restructuring, Documentation Classification, and Category Index Development

Date
2026-11-16

Area
Malone Global University — MGU Public Records

Primary directory: C:\MGU\library\reference\mgu-docs\

Public URL: https://maloneuniversity.org/library/reference/mgu-docs/

Affected systems: Institutional documentation, website navigation, departmental planning, engineering documentation, production records, publication standards, and Library reference organization.

Problem

The existing MGU Internal Documentation repository had grown without a sufficiently defined institutional classification system.

The original index contained only two organizational divisions and ten categories. Several category names were ambiguous, some directories had been renamed without corresponding navigation updates, and most folders lacked functional index pages.

Previously produced institutional whitepapers, software engineering documents, weekly production reports, and curriculum materials had accumulated without consistent filing boundaries.

The repository also lacked a clear publication policy distinguishing formal institutional documents from ordinary HTML instructional pages.

Specific deficiencies included:

- An outdated two-division navigation structure.
- Missing institutional documentation categories.
- Inconsistent directory names and index links.
- Limited differentiation between institutional planning and department planning.
- No formal distinction between production records and quality-assurance audits.
- Software engineering whitepapers grouped under an insufficiently defined release-notes category.
- Historical weekly production records stored outside a permanent institutional records structure.
- No established separation between Library cataloging infrastructure and institutional documentation.
- Incomplete category-level navigation and document discovery.

Intended Goal

Establish MGU Public Records as a permanent, publicly accessible institutional documentation repository.

The correct system should:

1. Organize institutional documentation into three clearly defined divisions.
2. Maintain fourteen primary categories with distinct institutional responsibilities.
3. Publish substantive institutional documents exclusively as PDFs.
4. Use HTML only for category navigation, collection descriptions, and document indexes.
5. Preserve formal executive, scholarly, and technical language within institutional publications.
6. Provide permanent locations for planning reports, standards, whitepapers, audits, and engineering documentation.
7. Integrate historical production and software records without losing existing material.
8. Separate Library-wide catalog classification from MGU Public Records.
9. Establish consistent metadata, document status, versioning, and filing conventions.
10. Support future expansion without requiring structural redesign.

Root Cause

The original MGU documentation directory developed incrementally as new administrative, technical, and publishing requirements emerged.

Folder creation was driven primarily by immediate documentation needs rather than a formally approved institutional information architecture.

Consequently, the repository accumulated overlapping categories, incomplete indexes, historical naming conventions, and documents whose institutional ownership had not been explicitly defined.

The underlying problem was the absence of a governing framework specifying document types, category responsibilities, publication formats, and relationships between institutional records.

Steps Taken

1. Established the Computer Science content architecture. Defined the boundaries between departmental instruction, interactive developer tools, Library Reference, Library Tutorials, and Encyclopedia resources. Produced mgu-cs-plan.pdf, a ten-page institutional planning report.

2. Created the Department Planning index. Built department-planning/index.html and incorporated the Computer Science planning report as the initial published document.

3. Developed the MGU Public Records institutional architecture. Defined fifteen initial documentation functions across three divisions and produced the 21-page mgu-records-plan.pdf, containing institutional policies, category responsibilities, a proposed publication register, and implementation priorities.

4. Created the Institutional Planning index. Built institutional-planning/index.html and linked the institutional architecture report.

5. Renamed the repository's public identity. Replaced the designation *MGU Internal Documentation* with *MGU Public Records* to clarify that the materials concern internal institutional operations but are intended for public access.

6. Established the PDF-only documentary publication rule. Reserved HTML for navigational indexes and required institutional whitepapers, plans, procedures, technical specifications, and audit documents to remain in PDF format.

7. Reclassified Library cataloging. Renamed the former file-organization collection to library-catalog-codex and moved it outside MGU Public Records to /library/reference/library-catalog-codex/. This reduced the permanent Public Records taxonomy from fifteen to fourteen categories.

8. Standardized existing directory names. Adopted build-automation-deployment, production-records, and quality-assurance-audits in place of the previous build-workflow, worklog, and quality-control naming conventions.

9. Expanded the institutional taxonomy. Added five categories: Institutional Decisions and Directives; Editorial and Publication Standards; Digital Operations and Recovery; Research and Source Management; and Document Control and Versioning.

10. Rebuilt the main MGU Public Records index. Reorganized mgu-docs/index.html into three divisions, corrected category labels and relative paths, and included links to all fourteen permanent categories.

11. Created navigation indexes for the five new categories. Established their institutional purposes, filing boundaries, prospective publication types, and relationships to existing collections.

12. Consolidated historical subcollections. Moved software-release-notes beneath build-automation-deployment and weekly-updates beneath production-records, preserving their existing historical materials.

MGU's previously informal documentation collection was converted into a structured, three-division public institutional records repository with fourteen permanent categories, PDF-only substantive publications, and standardized navigational indexes.

The Library Catalog Codex now occupies its own Library reference location, preserving its distinct purpose as a prospective university-wide cataloging and cross-reference system.

Rules Going Forward

1. All substantive MGU Public Records documents must be published as PDF files. HTML is reserved for navigational indexes.
2. Every institutional document must have one canonical location based on its primary purpose.
3. Cross-category references should link to the canonical document rather than create duplicate copies.
4. Institutional Planning concerns university-wide initiatives, investments, facilities, staffing, governance development, and future offerings.
5. Department Planning concerns the expansion and implementation of established departmental programs.
6. Administrative Procedures define recurring operational processes rather than strategic investments.
7. Curriculum Frameworks establish common instructional standards across MGU.
8. Website Architecture defines digital system structure; Templates and Style Guides define presentation and reusable document specifications.
9. Production Records document completed work and institutional development history. Quality Assurance and Audits evaluates work against applicable standards.
10. AI-assisted assessments must be accurately identified and must not be represented as independent scholarly peer review without appropriate human review.
11. Historical technical documents must retain their publication dates, version applicability, and provenance.
12. Proposed, adopted, superseded, and archived documents must be clearly distinguished.
13. New directory names and relocations must be reflected in relevant navigational indexes.
14. Original documents should be preserved during migrations until classifications and replacement paths are validated.
15. The Library Catalog Codex remains a separate Library reference system rather than a subordinate MGU Public Records folder.
16. Institutional reports should maintain formal executive, academic, and technical writing conventions without conversion into casual instructional webpage prose.
